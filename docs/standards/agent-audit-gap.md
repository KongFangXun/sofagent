# 国标 Agent 审计对位 · 标准跟踪与差距表

> v1.5.7 · 2026-10-08 · [changelog/v1.5/v1.5.7.md 章七](../changelog/v1.5/v1.5.7.md)

> **本文档性质**：标准跟踪登记 + 对位差距表——**不是审计承诺，是差距登记**。逐条对照本仓已交付审计能力（28 条规则 + 能力面，见 [SECURITY · 28 条清单](../../SECURITY.md#28-条审计规则完整清单文档级-ssot)）与 Agent 相关标准条款，每条给「已覆盖 / 部分覆盖 / 未覆盖」结论 + 「对齐 / 暂不对齐 + 理由」两态阶段结论。
>
> **边界（红线）**：只做**对位引用**——不转述、不分发标准文本；不在标准正式发布前预设对齐动作。第三方基准的落差读数是参照不是背书。
>
> **标注纪律**：以公开知识登记；不确定的一律标「**待核**」——宁可待核不可编造。状态变更（草案→发布→生效）应进 decision-log（kind=CONFIG_CHANGE 起草时评估，届时按语义选 kind）。

## 二、对位差距表（能力面口径）

逐条对照判据：以 [SECURITY](../../SECURITY.md) 的 27 条规则清单 + 已交付能力面为「已覆盖」的证据源；条款级对位待标准正式文本可得后补（不预设条款号）。

| # | 审计能力面（标准侧关注点） | 本仓现状 | 结论 | 阶段结论（对齐/暂不对齐 + 理由） |
|---|---|---|---|---|
| 1 | 决策留痕完整性（每次 AI 行动可追溯） | decision-log 18 类决策 + HMAC 链 + 第三方可验签 | **已覆盖** | 对齐——已交付（v1.3.7 起），GB/T 45400 的身份标识位接入待该标准实施后评估 |
| 2 | 变更审计硬证据（做了什么改了什么） | git diff 驱动 27 条规则 + audit-history append-only | **已覆盖** | 对齐——已交付 |
| 3 | 生成式 AI 内容标识（AI 产出标注） | notify_session 带 `[sofagent]` 前缀；数据产物 E5 审计不含内容标识字段 | **部分覆盖** | 暂不对齐——理由：内容标识属**产物出口面**（模型输出层），本仓审计的是**变更过程面**；过程面已覆盖、出口面待生成式 AI 内容标识国标（草案线）定稿后按条款评估，现在对齐会预设未定条款 |
| 4 | Agent 身份与授权绑定（谁授权谁执行） | agent-identity + TOOL_GATE 门禁三态留痕 + mandate/凭证对账（CREDENTIAL_RECONCILE） | **已覆盖** | 对齐——已交付（v1.5.4 章七对账面） |
| 5 | 跨系统审计互认（审计证据跨组织可比） | HMAC 链验签工具独立于 sofagent 可运行（support-bundle 导出） | **部分覆盖** | 暂不对齐——理由：互认需要**多方协议**（对账格式/信任锚交换），单侧技术就绪≠互认成立；待国标/国际草案给出互认框架后评估接入，本仓不单方预设协议 |
| 6 | Agent 间通信安全（A2A 可信信道） | 联邦链路四层防线（AES-256-GCM + 三条配对 + 24h 轮换，SECURITY §ASI07） | **部分覆盖** | 暂不对齐——理由：已覆盖**本仓联邦链路**；外部 A2A 协议族（协议级国标草案线）未定稿，跨协议对位待核 |
| 7 | 审计数据生命周期（保留/清理/归档） | 归档轮转（v1.5.6）+ retention 天数上限 + LEGACY_CLEANUP 留痕 | **已覆盖** | 对齐——已交付 |
| 8 | 供应链安全（依赖引入审计） | A10 不引毒源 + E6 提示注入防护 + ASI/ATLAS 双编号映射 | **已覆盖** | 对齐——已交付（v1.5.7 章三补齐 ASI 映射） |
| 9 | 治理失败披露（fail-closed 纪律 / 失效标记） | INVALIDATION 失效标记（标记不是抹除）+ 守卫失明自检（exit 2 拒绝假绿） | **已覆盖** | 对齐——已交付 |
| 10 | 数据主权与跨境评估 | data-sovereignty 报告 + D1-D5 数据审计 + 敏感本地处理率 | **部分覆盖** | 暂不对齐——理由：技术指标已覆盖；**评估合规格式**（出境安全评估申报口径）属法规面申报动作，非仓内能力——登记为差距，由部署方按 GB/T 与《数据出境安全评估办法》自行申报 |

## 三、国际治理基准对照（生态侧参照系）

**边界**：只登记为参照系与差距表的补充维度（治理基准场景可反查本仓覆盖面），**不承诺跑分、不预设对齐动作**——是否实跑留待差距表结论后裁定。定性词与对位辨析按单点持有纪律见 [THANKS · 官方标准面](../THANKS.md)，本节不复写。

| 基准 | 一句话判据（公开知识口径） | 与本仓的对位读法 |
|---|---|---|
| AgentGovBench | NIST AI RMF 映射的治理基准——48 场景八类（身份传播/逐用户策略/委托溯源/范围继承/限流级联/审计完整性/fail-closed 纪律/跨租户隔离）；宣称测「模型周围的治理层」而非模型本身；自带 vanilla 基线 13/48 vs 治理完备 46/48 落差读数 | 与本仓「治理层不是模型」定位同题；八类场景可反查：身份传播/审计完整性/fail-closed 三类对应本仓 §二 #1/#4/#9 已覆盖面，限流级联/跨租户隔离对应多租户治理排期面（v2.x）——**待核**（场景到规则的逐条映射未实跑） |
| ST-WebAgentBench | ICLR 2026；CuP 指标 = 任务完成 × 政策合规**双轴**；3057 政策实例；三层政策层级 组织>用户>任务 | 「完成度与合规分列」与判定底座「分布内外分列」纪律同族；三层政策层级可对照本仓 config 三级 fallback + 任务级 scope——对照是叙事层，非跑分 |
| NIST CAISI（AI Agent Standards Initiative） | 三支柱 + NCCoE 四功能域（Identification/Authorisation/Delegation/Logging）；Delegation 要求委派链可回溯责任人、Logging 要求每次工具调用关联委派者 | 四功能域反查：Identification/Authorisation/Logging 对应 §二 #1/#4 已覆盖；Delegation 委派链（ORCHESTRATION + causedBy 因果边）部分覆盖——委派到人的绑定待 v1.6.0+ 判定底座（**待核**） |

## 维护规则

- 状态变更（任一标准从草案→发布→生效）：同批在 decision-log 落一条决策记录 + 更新 §一状态列。
- 新差距出现（标准新增条款/本仓能力退役）：§二登记行**不删不改结论**，追加新行（对齐失效标记纪律——失效是标记不是抹除）。
- 本文不引用标准文本原文——对位一律转写为本仓能力面语言。
