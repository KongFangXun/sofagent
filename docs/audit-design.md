# sofagent-audit 设计文档

> v0.91 · 2026-06-24 · 提交时审计 MVP

## 设计背景

sofagent v0.90 之前的架构是**运行时治理**——通过 MD 文件注入约束来指导 Agent 行为。这套架构有三个硬伤：

1. **依赖 Agent 配合**——Agent 不读 MD 文件就全失效（CLI 实测 0/16）
2. **不可跨平台**——Hook / 断路器只在 OpenClaw 生效
3. **Agent 可绕过**——CLI 场景 Agent 直接跳过加载链

v0.91 启动战略转向：**从预防转向检测**。提交时审计不依赖 Agent 配合——它看的是已经发生的 git diff，不是 Agent 声称它做了什么。

## MVP 规则集

从 10 条铁律中选出 4 条可程序化判定的，其余 6 条依赖 LLM 辅助（未来版本）。

| 铁律 | 判定逻辑 | exit code |
|------|------|:--:|
| #1 先读再用 | diff 中被修改的文件，修改前是否有 Read 操作记录（检查 .sofagent/task/logs/ 目录） | 2（违规） |
| #3 验证再干 | package.json / build.gradle 等构建文件变更后是否有 test/build 命令执行记录 | 2（违规） |
| #7 谨慎修改 | diff 中是否有不在 --task 描述关键词范围内的文件 | 1（警告） |
| #10 如实汇报 | commit message 是否为空 / 是否纯占位符（"fix"/"update"/"wip"） | 1（警告） |

不可程序化的铁律（#2/#4/#5/#6/#8/#9）——MVP 不覆盖，v0.92 加 LLM 辅助判定。

## 技术选型

**TypeScript**，不是 bash。

- git diff 解析需要结构化处理
- GitHub Action 集成需要 npm 包生态
- 零运行时依赖（只用 Node.js 内置模块：child_process、fs、path）

## 误报率红线

**< 10%**。如果 MVP 达不到，优先缩小检查范围（如只检查「先读再用」一条），不做广度优先全面检查。

## 焊死的门原则

检查规则独立只读——Agent 不可篡改检查标准。审计脚本扫的是 git diff（已经发生的历史记录），不是 Agent 的工作目录。Agent 即使在运行时绕过约束，审计仍能通过 diff 回溯发现问题。

监控四类篡改：
- 改断言匹配错误行为
- 删失败测试
- 加 lint-ignore 绕过检查
- 降低覆盖率阈值
