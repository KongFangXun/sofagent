第一章 · 交互变了

AI 时代，交互的主体变了

过去 40 年，人和软件交互靠 GUI——打开界面、找按钮、填表单。
AI 改变了底层逻辑：交互主体从人变成了 Agent。

GUI 时代
交互人点按钮
发现找菜单、看说明书
结果打开页面自己看
形态一个有界面的应用
LUI 时代
交互Agent 理解人的话
发现Agent 自己知道能做什么
结果结果推到你面前
形态对话就能调用的能力

软件不再是"能看到的东西"

传统软件价值在界面：仪表盘越好看，用户越离不开你。
LUI 时代价值在能力层：用户感知的是 Agent 帮他做的事情多可靠。

软件 = 一套"能被调用的能力"。

sofagent 没有图形界面——这不是缺陷，是设计决策。在 LUI 时代，建界面是走回头路。
第二章 · FDE

FDE 不只是一个岗位

来自 Palantir——工程师去客户现场，把产品装起来、调通、跑顺，然后离场。它是一种底层能力模型。未来所有人都在变成 FDE：

🧭
掌握完整上下文
理解全部业务关联，不靠别人传话。AI 让单人也能拿到全量世界模型。
🔧
打破岗位边界
不按岗位分工做事，按交付结果调资源。AI 淘汰的是「这不归我管」。
✅
对结果负责
可追溯、可验证、可问责。Agent 是非确定性系统——必须看证据链。
sofagent 的目标不是培养更多 FDE 工程师，而是让每个用户都具备 FDE 的工作方式。

FDE 怎么工作，价值在哪

进场 → 装好 → 教会 → 撤离

FDE 不是常驻外包——人走了，系统继续跑，知识继续长。

对客户
从"买了工具"到"真正在用"。解决 AI 最后一公里。
对企业自身
经验变可复制资产。workflow 文档、Skill 配置、knowledge 知识库——下个客户不从零开始。
对行业
39% 企业因 AI 裁员，55% 裁错。不是 AI 不行，是缺乏评估 AI 能力的机制。
第三章 · 落地

梳理 Workflow：问五个问题

不是画流程图，是拆解业务动作。逐个岗位、逐段流程地问——因为答案决定能不能交给 AI：

输入是什么能不能自动取到 → 数据源头
输出是什么能不能自动推 → 交付闭环
谁在做这个人最痛在哪 → 替换价值
花多长时间瓶颈在哪个环节 → ROI
最痛在哪规则能不能写清楚 → 能否交 AI

三条件全满足 = 自动执行节点。满足两个 = AI 辅助岗。

workflow 梳理本身就是管理动作——不是"为了上 AI"，是"梳理清楚才知道 AI 能帮什么"。

构建本体模型：AI 要理解业务

AI 不理解业务结构 → 只能给通用回答。理解了 → 给业务级精准指令。

举个例子——零售客户：

对象层
供应商 → 订单 → 仓库 → 门店
AI 知道了"谁跟谁有关"
动作层
补货→仓库，退货→供应商
AI 知道了"我能干什么"
约束层
单价超 5000 须总监审批
AI 知道了"什么不能干"

没有三层 → 通用回答。有了三层 → 业务级指令。

sofagent 本体轻量——daemon 自动合并，不是重 KG 工程（专职团队+图数据库+数月工期）。

第三章 · 核心概念

为什么模型越强，纪律层越值钱

AI 模型提供 90% 的智力输出——写代码、做分析、生成报告。
但企业敢不敢让 Agent 自主执行，取决于最后 10%

可靠性

Agent 说"做完了"——是声明还是证明？

可追溯性

出问题了——谁改的、什么时候改的？

可问责性

不是"模型错了"，是"系统验证过了"

模型越强，Agent 能做更多事——但"做错了怎么办"的代价也更大。
sofagent 在最后 10% 里：约束行为、审计变更、沉淀经验。

AI Agent 能做什么，不能做什么

✅ 能做
数据分析、报表、图表
文字撰写、翻译、校对
代码生成、审查、测试
信息检索、搜集、对比
❌ 做不了
物理世界动手操作
图像视频剪辑特效
面对面人际沟通
系统 GUI 鼠标点击

超出边界直接说「做不了」，但给替代方向。
确定性操作（去重/格式校验/文件清理）用脚本，不要让 Agent 做。

第四章 · sofagent 产品

sofagent 是什么

不是 Agent 运行平台 不是 IM 不是 RAG 不是低代码

= AI Agent 的纪律层

Agent 会越界、会编造、会改不该改的。sofagent 管的是：约束行为、审计变更、沉淀经验。

通用 Agent 平台

管「会不会做」——能力问题

sofagent

OpenClaw = 高速公路（路由调度）。sofagent = 交规+测速摄像头+驾校教练。

一底座·三引擎 = 配置 + 安装：fde.md 写规则、git hook 自动挂、daemon 常驻快照、cron 周度进化。全部 MD 文件和自动脚本，不是重型工程。

Agent 的记忆长在哪

传统 Agent：记忆在自己脑子里——关了没了，换一个从头来。
sofagent：每次启动是白纸，但读到的文件是上次运行的完整经验。

启动时四层加载链按序注入：
❶ SKILL.md（宪法）→ ❷ fde.md（规范）→ ❸ think.md（反思）→ ❹ knowledge/（知识）

Agent 做任何事之前，已经知道红线在哪、上次踩了什么坑、最佳实践是什么。
审计看 git diff，不看 Agent 自我报告——Agent 会自我辩护，文件不会说谎。

知识库不需要你搭

传统：组织人力写文章、维护目录、定期清理——费时费力没人看。
sofagent：AI 节点跑起来，知识库自动生长。

think.md
踩坑反思
task/logs
操作记录
eval.md
评分记录
knowledge/
结构化知识

FDE：装底座、让节点跑起来——不用写文章。
🔒 跨设备协同：A 踩过的坑 B 不重踩。AES-256-GCM 加密。

LOOP：Agent 用自己的工具开发自己

人类下任务 → Agent A（工程师）写代码+commit → 审计引擎自动扫 git diff → Agent B（审查员）读 diff + 出审查报告 → 人看报告做判断 → 通过/不通过→A 修复

为什么不让 A 自己审自己？银行转账——录入和复核是两个人。Agent 自我说服不是审查。

当前 human-in-the-loop。人的角色不是读代码——Agent 提炼了"该担心什么"，人只需确认。

🌐 OpenClaw · 后台引擎

OpenClaw 是后台引擎，不是用户界面。用户爱用什么 Agent 用什么，OpenClaw 在底层管住所有 Agent 的行为。

🔁 自动运行模式
企业设备上 7×24 跑。
需要 OpenClaw + sofagent 全栈。
Channel / control / orchestration / Webhook 全链路。
🧑‍💻 个人增强模式
第三方 Agent（WorkBuddy/Codex）+ sofagent。
不需要 OpenClaw。
Sub Agent 约束自加载，平台无关。
OpenClaw = 高速公路（路由调度）。sofagent = 交规+测速摄像头+驾校教练。

🏞️ River · 统一入口

模型像水（不受控的 AI 能力），Workflow 是管网（引水到业务），Subagent 是水龙头（让水作用）。
员工提任务 → 拓扑调度 → 同一入口返回——从头到尾同一个身份、同一段上下文。

层级定义比喻谁负责
River统一 Agent 入口大河——只有一个入口OpenClaw + sofagent + Channel
Workflow任务拆解与编排管网——引水到业务sofagent 内部编排工具
Subagent具体执行单元水龙头——让水作用sofagent Sub Agent 定义
不是技术架构
River 不是一套微服务或 API 网关。
它是业务关系可视化。
统一身份
同一个 Agent 身份贯穿所有 Workflow。
不会"换一段管网就换一个人"。
FDE 交付什么
节点之间怎么协作的完整地图。
管网怎么接到业务——可视化。
sofagent 不做 River 本身（堤坝，不是河床）——但确保 River 里的每一个 Sub Agent 都有纪律、可追溯、会反思。

所以——怎么能让客户知道？

🔍 为什么需要结果可见性

Harness 中间件最大的挑战不是技术——是存在感。

问题
引擎在正常工作——但用户看到好结果时，不知道是 harness 层在起作用。看到 ✅ PASS 以为是模型自己做的。
后果
没人知道你在工作 → 没人觉得你值钱 → 没人付钱。
这就是废墟功能：做了，但用户感知不到，等于没做。

更致命的是——sofagent 故意没有图形界面。
LUI 时代建界面是走回头路，所有存在感必须靠文本输出来建立。

签名就是 sofagent 唯一的存在形式。没有签名 = 没做。

三层签名——所有输出带 sofagent 名字

三层持续存在感机制

前面讲的"三层签名"是即时可见性——每次提交/推送都能看到 sofagent。
这一页讲的是长期感知——人走了之后，怎么让客户持续感知到价值。

人类永远在回路中

成功悖论说"你做了但没人知道"——那人类是不是该退场？
答案是正好相反。Agent 越强，人类越不能放弃思考。

验证责任不可替代
Agent 说"做完了"是声明不是证明。
审计 A8：要求可观测证据。
理解债
Agent 交付越快，理解鸿沟越大。
task/logs 只追加不修改，永远可回溯。
认知投降
最舒服的状态是不再有自己观点。
三道护栏保底。
三道护栏：fde.md 规则覆盖（保留人类话语权）· 编排可回滚（保留人类否决权）· 审计独立于 Agent（保留人类验收权）。
不是技术特性——是制度设计，确保人类永远是最终决策者。

FDE 走了之后，谁在管

概念、产品都讲完了。FDE 进场、装好、教会、撤离之后呢？
sofagent 内建两个 Agent 持续接管运维——不需要人每天盯着。

人走了，审计不停、规则不腐、知识照长。
