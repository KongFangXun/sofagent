## 执行序列（09-publish.md 逐步 · 全文按 SOP 跑，此处为锚点导航）

1. **步骤一 本机自装**：npm install → 本地 `node engine/audit/dist/index.js --help` 显示 v1.9.0
2. **步骤二 发布前检查**：lock 一致性（npm ci --dry-run）+ 内部依赖版本同步检查（无输出=同步；bump 落步骤五届时重跑）+ shellcheck + `bash tools/check/check-release-closeout.sh` EXIT=0
3. **步骤三 push 前置**：双 SHA 分叉防御（local/remote HEAD 核对；**130 笔积压一次推**）
4. **步骤四 push main + 等 CI 全绿**：前台轮询（每 60s 一查，严禁挂后台）；CI 红禁打 tag；verify 红按上表预期形态判
5. **步骤五 版本 bump + 安装入口同批**：`bash tools/release/bump-version.sh 1.8.0 1.9.0`（dry-run 已验 574 处）→ **C-5 install.sh 6 哈希回填（本批内、tag 同 commit）** → 触点挂账桶翻牌（#14 WIKI 当前版本行 / #17 各深读文档版本头 / #18-19 SKILL·AGENTS·GEMINI 头 / #25 dashboard 角标）→ bump 批 commit 前 `git status --porcelain` 检视暂存面（防旁生目录入批）
6. **步骤六 git tag v1.9.0 + push tag**：tag 指 bump commit；tag 前 CI 必全绿
7. **步骤七 gh release**：三道工序（生成→自检→上一版结构对照）——**--title "v1.9.0 — 🧩 判定底座消费与收口"**（勿裸号）；body 用 `~/Desktop/release-note-v1.9.0-body.md` 复核落终版（数字=冻结基线 7014/507/85/149；微调以本步骤终版为准并回写桌面文件）；触发 release.yml 自动 publish audit+mcp（坑 1/2 预案）
8. **步骤八 npm 手动 publish 其余 14 包 + 七款 DSH 插件 + 裸名总包**：publish-packages.sh（坑 4/5/6 已修）；全部以 --prefer-online 复核；C-2/C-4 若未在步骤五前批掉，publish 完成后立即补批（tag 后窗口）
9. **收尾**：发布后验证（check-release-closeout 推送后补核三 workflow）→ 触点反查（git grep "1\.8\.0" 介绍面零命中）→ 进阶段十分发
