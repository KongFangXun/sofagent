## 一、审查范围与方法

本轮为发版闸门**归并面**审查，把三条并行审查线的结论收口为一份可放行判定，遵循 **fail-closed** 原则：

3. **覆盖面**（`coverage.md`）：changelog 11 模块 × 424 场景索引对账，裁决 `PASS（条件）`，含 5 P1 / 7 P2。

归并规则：
- 任一面出现 P0 或 FAIL 判据 → 整体降级；
- 上游面声明的**降级条款**（coverage「两项须闭环否则本步骤应降为 FAIL」）在归并层**原样传递**，不做软化；
- 上游面的 P1 / P2 **保留原编号可溯源**，本报告重新编号为 C-*（阻塞相关）/ N-*（观察），并标注与上游的对应关系；
- 对上游分级做**独立复核**，允许下调（需写明理由），不允许无据上调。

### P1 — 应该修（发版前须闭环，C-1~C-3 未闭环则覆盖面降 FAIL 并连带本闸门降级）

#### C-1　`sofagent doctor` 裸命令被 quick 模式吞为 diff ref，且以收窄判据通过

- **来源**：coverage P1-4（`coverage.md` §二 P1-4）
- **文件路径**：CLI 单入口路由实现（对应 S472「单入口 CLI 路由」/ audit-first 回退）与 `--doctor` 参数解析处（摘要未给出具体源文件路径，须按 S472 / S454 锚点定位）
- **证据**：S454 原文明示 ——「`--doctor` 是 flag 非子命令（**裸 doctor 被 quick 模式当 diff ref 报「无法解析 diff 范围」**）；退出码语义 0=全健康 / 1=有健康项失败 ⇒ **可达性判据 rc∈{0,1}**」
- **描述**：用户输入 `sofagent doctor` 得到的是 diff 解析错误而非帮助提示，属**明确、用户可感知的产品缺陷**。审查侧的处理方式是把判据收窄至 `rc∈{0,1}` 使其转绿，缺陷本体仍在；根因与 S472 的「非域首参一律转 audit」策略同源。**这是本轮全部证据中唯一一处被证实的对外可用性缺陷。**
- **建议动作**：在 CLI 路由层对保留子命令词（`doctor` / `demo` 等）做显式归一，或输出「did you mean `--doctor`？」；随后将 S454 判据从 `rc∈{0,1}` 收紧回语义断言（输出含健康项、不含 diff 解析错误）。**若本版不修，必须在 changelog / devlog 中显式登记为「已知问题」并给出归属版本**——不得以收窄判据静默通过。
- **闭环时点**：v1.9.0 tag 前（覆盖面放行条件之一）

## 七、结论

1. **三面证据健康**：acceptance 507/507 EXIT 0、regression 85/85 PASS、coverage 424/424 全 PASS；**P0 = 0，不存在阻塞发版的证据**。
