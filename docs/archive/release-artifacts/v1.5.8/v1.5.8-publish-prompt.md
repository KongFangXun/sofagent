## 🔴 已知坑四处 + 处置（必读，否则会把成功读成失败）

1. **release.yml 的 npm publish 遇瞬时 E404**（PUT 根路径 404，二次确认不存在）→ 在 worktree 本地手动重发该包（登录态在开发者侧），**publish 日志出现 `+ <pkg>@<ver>` 入队行即成功**，CI 侧红不阻塞发布完成。
2. **E409 staged**（版本已 staged 未 publish 的冲突）→ 按 09-publish 步骤八对应节处置（先确认目标版本是否已存在，勿盲目重发）。
3. **裸 `npm view` 吃缓存误判漏发** → 一切 npm 对账**必加 `--prefer-online`**；传播延迟期 `--prefer-online` 仍可能长时间返回旧值——**终局判定改 curl 直查 registry**（判定序：先查 publish 日志入队行 → 再 curl 直查 → CLI 查询仅作辅助）。
4. **批量发布脚本「即时验证」因传播延迟误报全失败** → 不要用「脚本跑完立刻全量校验」当发布结论；按上条判定序，或等待后重查。

> 另：`check-npm-claims` 在 bump 后 publish 前必然红（窗口态）→ 按 09-publish 步骤十登记 `npm-claims-exempt.json` 锚式豁免（publish 后声称自动转真值）。
