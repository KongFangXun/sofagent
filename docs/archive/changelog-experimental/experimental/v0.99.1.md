## 编排引擎 A/B 对比机制

### 问题

编排引擎在 FDE 部署后，需要定期重新编排并与旧方案做 A/B 对比，以找到最优工作流模板。当前对比靠 Agent 读 think.md 做主观判断，不可复现。

### 实现

**新增 CLI 工具**：`sofagent/audit/src/orchestrate-compare.ts`（148 行）

- `sofagent-orchestrate-compare` 命令行工具，零运行时依赖
- 从 task/logs 中提取四项确定性指标做对比：运行次数、审计违规率、平均步数、首次通过率
- 输出结构化 Markdown 对比报告到 orchestrator/comparisons/ 目录
- 自动判定胜出方案（winner），标注置信度（confidence），给出下一步建议

**promote 子命令**（内置于同一文件）：
- `sofagent-orchestrate-compare promote` 将 candidate workflow 自动替换为 current，旧方案归档到 history/

**MCP 资源**：`orchestrator://latest-comparison`——通过 MCP Server 暴露最新 A/B 对比结果

**新增测试**：`tests/orchestrate-compare.test.ts`（19 个测试，含 compare + promote）

**目录结构**：
```
orchestrator/
├── current/          ← 当前生产方案
├── candidate/        ← 候选方案
├── comparisons/      ← A/B 对比报告
└── history/          ← 被替换的旧方案
```
