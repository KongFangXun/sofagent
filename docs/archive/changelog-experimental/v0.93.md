## 一、P0 修复（边角误报 — 合成测试发现）

v0.92 合成检测精度测试（`src/measure-detection.ts`，27 组用例）结果：FN=0% / FP≈11%。

3 个误报需修复：

### 1. deleted 文件触发 WARN（🟡 铁律 #1）

**触发条件**：diff 中只有 deleted 文件 + 无任务日志时，rule-01 返回 WARN。

**为什么是误报**：删除不需要先读——铁律 #1 的「先读再用」针对的是修改/新增文件。deleted 文件应直接 PASS。

**修复**：`rule-01-read-before-write.ts` 中，无日志 WARN 之前先检查是否只有 deleted 文件。如果 `modifiedFiles` 为空（全是 deleted），直接 PASS。

### 2. `hasTestOrBuildExecution` 漏掉 `docker build`（🟡 铁律 #3）

**触发条件**：日志中有 `docker build .` 命令，但 `hasTestOrBuildExecution` 没识别。

**为什么是漏检**：当前只匹配常见的 test/build 命令（`npm test`/`npm run build`/`yarn test`/`make` 等），`docker build` 不在列表中。

**修复**：`log-checker.ts` 的 test/build 命令列表新增：`docker build`、`docker-compose build`、`tsc`。

### 3. 低风险文件排除未生效（🟡 铁律 #7）

**触发条件**：diff 含 README.md + 一个任务相关文件时，rule-07 应排除 README 但没排除。

**原因**：低风险文件列表可能未包含 README.md，或排除逻辑在阈值计算前未生效。

**修复**：`rule-07-careful-modify.ts` 确认 LOW_RISK_FILES 含 `README.md`、`CHANGELOG.md`、`LICENSE` 等文档文件，且在计算不相关文件比例前先排除。

### 4. 新增 `--strict` 模式（🟡 铁律 #1 审计强化）

当前 rule-01 在无日志时返回 WARN（避免新项目误报），但这意味着恶意 Agent 只要不写日志就能绕过铁律 #1。

**修复**：`index.ts` 的 `parseArgs` 新增 `--strict` flag。strict 模式下 `logEntries.length === 0` → FAIL（exit code 2）。默认行为不变（无日志 → WARN）。CI 集成场景推荐使用 `sofagent-audit --strict`。

## 二、P1 工程迁移（bash → TypeScript）

### 迁移范围

| 脚本 | 行数 | 优先级 | 迁移后 |
|------|:--:|:--:|------|
| `verify-evidence.sh` | 45 | 🔴 第一个（最小、最安全） | `src/verify-evidence.ts` |
| `skill-safety-check.sh` | 301 | 🟡 最需要类型安全 | `src/skill-safety-check.ts` |
| `verify.sh` | ~900 | 🟢 等前两个稳定后 | 拆分为 3-4 个 TS 模块 |
| `install.sh` | ~900 | 🟢 最后 | 等 verify 拆分验证后再动 |

### 迁移原则

- 一个脚本一个 TS 文件，不改行为——只换语言
- 迁移完一个 + 测试通过 → 替换 install.sh 中的部署引用
- 旧 bash 脚本保留 1 个版本周期，标注 deprecated
- 不改 verify.sh 的逻辑结构（现有 check_pass/check_fail + 计数器模式保留）

### 实现记录（2026-06-25）

| 脚本 | 迁移后 | 测试 | 发现 |
|------|------|:--:|------|
| `verify-evidence.sh`（45行）| `src/verify-evidence.ts`（~120行）| 8 tests | **发现 macOS BSD grep bug**：`grep -ciE` 0 匹配时 exit 1→`\|\| echo "0"` → 变量含换行→算术错误。TS 版无此问题 |
| `skill-safety-check.sh`（301行）| `src/skill-safety-check.ts`（~300行）| 13 tests | 21 条规则逐条迁移。bash 版规则 #3 `curl.*\|.*sh(` 含未闭合括号→实际不生效。JS 版修复为 `curl.*\|.*\bsh\b` |

**交付验证**：
- `npm run build` ✅ exit 0
- `npm test` ✅ 7 files / 99 tests（+21 new）
- verify-evidence 三个正则与 bash 版完全一致
- skill-safety-check verdict/exitCode 与 bash 版完全一致
- 无 execSync/eval 引入
