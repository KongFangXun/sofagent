## 定位

**v1.2.7 是 DeerFlow 设计启发的第一批落地**——把 DeerFlow 在编排引擎和上下文工程上验证过的设计，移植到 sofagent 的 TypeScript/Node 栈。不是集成 DeerFlow 代码，是抄思路。

DeerFlow 自称 "super agent **harness**"，与 sofagent 的 Harness 中间件品类判断字面一致（详见 [PHILOSOPHY §十](../../PHILOSOPHY.md#deerflow-20大厂用harness命名的活样本2026-07-行业印证)）。它做运行时（River 比喻的「河」），sofagent 做堤坝——以下设计在它的运行时层验证过，我们移植到审计+约束层。

## P1：Session Goals — 会话完成条件

**痛点**：FORGE fresh-eyes-loop 的停止条件目前是"连续 2 轮无 P0/P1/P2 发现"——粗糙，要么过早停（漏审），要么过晚停（浪费 token）。

**DeerFlow 做法**：用 `/goal <completion condition>` 给当前线程附一个活跃完成条件，每次运行后用**非思考评估器模型**（便宜快速）评估对话是否满足条件，设安全上限（默认 8 次隐藏续接）。

**sofagent 移植方案**：
- FORGE fresh-eyes-loop 的 loop spec 加 `completion_condition` 字段（如"所有 P0/P1 已修复且 a-verify IS_PASS=YES"）
- 每轮结束后用轻量模型（如 GLM-4-flash 或 DeepSeek-chat）做 goal 评估，而非靠"连续 N 轮无发现"启发式
- 安全上限可配（默认 10 轮，与当前 max-rounds 一致）
- Dashboard 显示活跃 goal（v1.2.2+ 数据层消费）

**实现位置**：`engine/orchestrator/src/loop/` + `FORGE/SKILL/fresh-eyes-loop/loop.md`

## P2：手动上下文压缩 — `/compact`

**痛点**：memory 记录的 LangChain 消息只增不减——run-09 a-consolidate 100 步崩溃的根因。已有三层修复（a-consolidate 精确路径 + b-fix 禁止探索 + sf_read 500 行截断），但缺用户侧减压阀。

**DeerFlow 做法**：`/compact` 在 Web UI composer 中总结较旧上下文——保留完整聊天可见，但后续模型调用使用压缩摘要 + 最近消息。

**sofagent 移植方案**：
- FDE Agent 支持 `/compact` slash 命令——把当前 task/logs/*.md + think.md 压缩成摘要，写回 think.md 的"已压缩"段
- 不删原始文件（审计留痕），但 Agent 后续 prompt 注入用摘要版
- 与 A8（不逃验证）配合：压缩后仍需保留"验证证据"段不压缩

**实现位置**：`engine/core/src/` 新增 compact 模块 + SKILL.md slash 命令注册

## P3：Skill 渐进式加载

**痛点**：LIMITATIONS §一明确写了"加载链步进脆弱性"——SKILL.md 全量注入，第 2、3 层（think.md + fde.md）靠 Agent 自觉读取，非 OpenClaw 平台无法保证 100% 命中。

**DeerFlow 做法**：Skills 渐进式加载（progressive loading）——仅在任务需要时加载，技能目录是包边界，找到 `SKILL.md` 后嵌套的作为支撑数据。用户可通过 `/skill-name` 显式激活。

**sofagent 移植方案**：
- SKILL.md 拆成"核心铁律（始终注入）" + "岗位规范（按需加载）"两层
- FDE Agent 接到任务时，根据 task type 决定加载哪些岗位规范（如"审计任务"加载 audit agent 规范，"部署任务"加载 FDE 规范）
- 与 v1.2.1 的 custom/ 加载链保护闭环配合——按需加载不等于不加载，是"延迟加载"

**实现位置**：`SKILL/` 结构调整 + `engine/hooks/sofagent-load-chain/` 加载逻辑

## P4：--doctor 可操作修复提示（若 v1.2.6 未完成）

**痛点**：当前 --doctor 只报红绿，用户看到红不知道怎么修。

**DeerFlow 做法**：`make doctor` 验证设置并给出可操作修复提示。

**sofagent 移植方案**：--doctor 每项检查的红输出从"❌ 缺少 X"升级为"❌ 缺少 X → 修复：`npm install X` 或 `bash install.sh --repair`"。

**实现位置**：`engine/core/src/verify.ts`（如 v1.2.6 已做则此条作废）
