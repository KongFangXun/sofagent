# FDE 训练基线：什么时候该训，什么时候别训

> 一句话：**后训是能力阶梯的最后一格，不是第一格。** FDE 进场遇到「模型答不好」，先按四格基线逐级排查——四格都过不去，才轮到后训。

## 为什么需要这份基线

「效果不好就微调一个模型」是 FDE 现场最贵的误判：

- **模型 API 层能解决的**（提示词、few-shot、温度）——微调是杀鸡用牛刀；
- **结构化输出层能解决的**（JSON schema 约束、字段校验）——微调会把「格式」焊进权重，之后改一个字段名就要重训；
- **tool calling 能解决的**（模型自己查不到的让它去调工具）——微调出来的「记忆」会过期，工具不会；
- **RAG 能解决的**（企业私有知识、频繁变动的口径）——微调把知识烧进权重 = 企业数据进了模型，**数据主权直接出问题**。

这四格之外才是后训真正的主场：**风格、判定边界、领域推理模式**这类「说不清但看得出来」的东西。

## 能力阶梯（四格基线 + 一格后训）

| 格 | 手段 | 什么时候够 | 判定方式 |
|:--:|------|-----------|---------|
| 0 | **模型 API**（提示词 + few-shot） | 任务是通用常识、答案形态自由 | 冻结一组样本跑 `eval_suite`，人工看错例分布 |
| 1 | **结构化调用**（JSON schema / 输出约束） | 输出必须被机器消费（填表、写节点、生成配置） | schema 校验通过率 + 字段级错例归因 |
| 2 | **tool calling** | 答案取决于实时数据、内部系统，或需要算 | 工具调用成功率 + 参数正确率 |
| 3 | **RAG**（检索增强） | 答案取决于企业私有知识，且知识会变 | 检索命中率 + 引用可追溯率 |
| 4 | **后训**（SFT / QLoRA / RLHF 按场景选型） | 前四格都试过且到顶，要的是**风格 / 判定边界 / 领域推理**——不是知识，也不是格式 | 训前训后用**同一套** eval 集对比，差值即收益 |

**逐级走的两个硬理由**：

1. **成本**——0-3 格是小时级迭代，第 4 格是「备语料 → 跑训练 → 评 → 再跑」的周级循环；
2. **可回滚**——0-3 格改的是配置，改错回退一行；第 4 格产出的是权重，回退要动模型注册表 + 灰度回切（本仓为此提供 `model_register` / `model_switch`：按百分比灰度，切到 100% 强制人审）。

> 现场判据：**「错在哪」你说得出来但写不成规则，那是后训的对象；写得出规则，那是 0-3 格的对象。**

## 训之前必须冻结的三样

| # | 冻结什么 | 为什么 | 本仓机制 |
|:--:|---------|-------|---------|
| 1 | **eval 集** | 训前训后必须同一套，不许换——换测试集等于自证「变好了」 | `eval_suite`（模板 / 基线冻结 / 运行三段；改样本要显式升版本） |
| 2 | **语料来源与合规** | 语料没走导出与合规两步就训练 = 审计链断在这里 | `corpus_export`（六源样本 + 方法论锚点 + 规则编号位，带 HMAC 签名）；`train_compliance`（PII / 敏感字段 / 企业专有名词，严重级阻断提交） |
| 3 | **验收条件** | 没有机器可判定的验收条件 = 这次训练不可验收 | `define_acceptance` 写条件（test / build / grep-absent / schema），`check_acceptance` 跑 |

## 训完怎么算「成了」

三段对比，缺一不算：

| 段 | 比什么 | 不达标怎么办 |
|---|-------|------------|
| **训前基线** | 旧方案（不训 / 现用模型）在同一 eval 集上的分 | 没有基线就没有收益可谈——先补基线，别开训 |
| **训中曲线** | loss / reward 是否收敛到预设区间（`train_status` 看曲线与断点） | 不收敛先跑 `train_diagnose`（七类分类 + 上下文四源 + 修复处方），别靠调超参碰运气 |
| **训后验收** | 验收条件全过 **且** eval 分差为正 | 分差 ≤ 0 就是没收益——退回 0-3 格方案，权重不上线 |

> **模型的来源要能答得出**：`model_register` 登记 endpoint，`train_report` 归档数据 / 超参 / 曲线 / eval 对比四字段。审计链必须能回答「这个模型是怎么来的」——这是本仓与「只管元数据的模型库」的分界。

## 交付：验收依据与交付物一起给

训练不是终点，交付才是。`train_deliverable` 打五件包（配置模板 + 管道配置 + eval 基线 + 运维手册 + 权重清单）+ manifest + HMAC 签名，`verify` 校验完整性与环境兼容——**FDE 离场后客户自己要能复现**，否则这次训练依然是一次驻场，不是一项资产。
