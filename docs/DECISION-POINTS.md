# 决策点接入面清单（v1.8.0 §一 交付物）

> **定位**：判定件在本 harness 中的接入点**唯一清单**——逐点列六要素，防散落各处、防每次接入重新讨论输入与回落口径。
>
> **归属**：引擎治理面。本清单按**可随仓迁移**形态书写（路径一律相对仓根、不绑定本仓目录名），家族分仓后随之迁入目标仓并在其仓内维护。
>
> **与外部样板的关系**：清单形态对位 APUS `system3` 的七点枚举（入口路由 / 目标框架 / 完成审查 / 技能选择 / 预取 / 过程监督 / 内存选择），但**只借枚举纪律，不照搬点位**——我方点位由本仓既有模块决定，外部点位的采纳与否逐点写明理由。

## 零、判定口径（先定判据，再列点）

**六要素**：触发时机 / 输入（state 构造口径）/ 封闭候选集 / 弃权与回落 / 阈值来源 / 结果去向。

**未采纳点豁免三要素**：`state 构造口径`、`阈值来源`、`结果去向`（未采纳点没有输入面与去向可写）；其余三要素（触发时机 / 封闭候选集 / 弃权与回落）仍须齐——**不采纳也要说清它断在哪**，否则清单退化成愿望单。

**「判定件接入点」的判据**：该点是否**调用了判定件**（`DecisionChannel.judge` 或其本地实现）。纯规则/纯 schema 校验的点即便有形似六要素的结构，也**不计入**接入点——它们计入「非接入点的判定面」（§三）。


## 一、采纳点

### DP-1 · 判定通道选择（L0 / L1 / L2 三层）

> 本版首个**六要素完整落地**的点。对应 v1.8.0 §四「路由判定档接通」的接线上游。

| 要素 | 内容 |
|---|---|
| **触发时机** | 进入意图分流时（`IntentTriage.route`），且 L0 声明式映射**未命中** |
| **输入（state）** | `DecisionState{ text, refs?, evidenceReadiness }`——`text` 为待判定语义输入，`refs` 为结构化解引用（供 L0 先判），`evidenceReadiness` 为证据就绪度（未就绪不得启用受门控的判据） |
| **封闭候选集** | 三原语问句集（`DecisionQuestion[]`）：`choice` 候选 ≤5 且**必带兜底候选** / `score` 带量程 / `noul` 布尔。候选由调用方给定，判定件不得自造选项 |
| **弃权与回落** | 通道级失败（加载失败 / 权重缺失 / 通道异常 / 超时 / 输出类型不符）⇒ **降 L0 规则面兜底**（fail-closed，不静默放行）；答案级不可用（弃权 / 低置信）⇒ 见 §四「冲突登记 T-1」 |
| **阈值来源** | `config.l1MinConfidence`（L1 置信阈值，调用方注入）；分原语温度取自 `rl_agent_config.json` 的 `temperature`，按 `tempBucketKey(primitive, optionCount)` 分桶 |
| **结果去向** | `TriageResult{ layer, target, grade, confidence, routeReason, audit }`——`routeReason` 必带实现方名与分桶键（可追溯「谁判的、哪档校准判的」），审计随 `stateDigest` 挂链 |

**实现位置**：`router/intent-triage.ts`（分流与回落）+ `router/decision-channel.ts`（契约与回落面）+ `router/stdio-decision-channel.ts`（本地默认实现）。

**行为锁**：判定调用**不占本地主模型槽位**（判定跑独立进程 / 独立运行时，与主模型推理槽位零交集）。

### DP-2 · 弃权门槛（ABSTAIN 一等输出态）

| 要素 | 内容 |
|---|---|
| **触发时机** | 判定件已产出答案，但概率未达该档门槛；或判据缺证据无法判 |
| **输入（state）** | 同 DP-1 的 state；另有判定件返回的 `probability` 与 `evidenceReadiness` |
| **封闭候选集** | 不选候选——本点**只决定「判不判」**，输出是弃权三因之一（`low-confidence` / `out-of-domain` / `missing-criteria`） |
| **弃权与回落** | 弃权是**一等输出态**（不是三原语取值之一）；弃权后去向见 §四 T-1。弃权与「兜底候选命中」**分别留痕**，不得混记 |
| **阈值来源** | `router/abstain-policy.ts` 的分档门槛（峰位推导 + 预算反解 + 稳定化重读），行为锁锁死不得被调用方旁路 |
| **结果去向** | `DecisionAnswer.status='abstained'` + `abstainReason`，进 decision-log 三维聚合（原语 × 语言 × 档位） |

**实现位置**：`router/decision-abstain.ts`（语义）+ `router/abstain-policy.ts`（策略与门槛）。

### DP-3 · 决策下达校验（schema 门）

| 要素 | 内容 |
|---|---|
| **触发时机** | 判定产出转成「可执行决策」之前 |
| **输入（state）** | 判定结果 + 目标动作描述（非语义文本，故不走判定件） |
| **封闭候选集** | 五态档位 `ALLOW / ASK / ABSTAIN / DENY / SKIP` |
| **弃权与回落** | 坏格式 ⇒ **拒绝下达**（fail-closed），不得以默认档放行 |
| **阈值来源** | `DEFAULT_GRADE_THRESHOLDS`（档位阈值表），随校准登记表更新 |
| **结果去向** | 下达记录 + HMAC 挂链（`decision-dispatch.ts`） |

> 本点**不调判定件**（纯 schema + 档位映射），列在此处是因为它是「判定 → 执行」的必经闸门，六要素形态完整、便于对位；按 §零判据它属「非接入点的判定面」。


## 二、不采纳点（三要素 + 理由）

### DP-4 · 确定性规则前置（7 族：extremum/nearest/digit-sum/binary/edges/table/urgency）

| 要素 | 内容 |
|---|---|
| 触发时机 | 每次判定请求进入判定件**之前**（确定性优先） |
| 封闭候选集 | 无——规则直接复算给出答案，不进判定件候选面 |
| 弃权与回落 | 规则未命中 ⇒ 交判定件；规则命中即终结（模型零成本） |

**不采纳理由**：**L0 规则面本体**，判定件不参与。列入接入点会让确定性覆盖被误计入模型能力——复测裁决（见 [ROADMAP](./ROADMAP.md) v1.7.x 线）已明确数值面须单列（**口径不同不可合并**）。

### DP-5 · 任务 × 敏感度双维路由（`policy-engine.ts`）

| 要素 | 内容 |
|---|---|
| 触发时机 | 派活时（任务类型 × 数据敏感度） |
| 封闭候选集 | 三档目标：云端强档 / 本地执行档 / 本地管道档 |
| 弃权与回落 | 敏感数据强制本地（fail-closed，配置错误即拒绝执行） |

**不采纳理由**：纯规则映射，无判定件调用。其「候选档位枚举」形态与外部「入口路由」相似，但**判据不同**（本点是静态策略，外部点是逐输入动态枚举 + abstain），不可对位混记。

### DP-6 · `should-run` 五问（门控）

| 要素 | 内容 |
|---|---|
| 触发时机 | 动作放行前 |
| 封闭候选集 | 放行 / 不放行 |
| 弃权与回落 | 不放行即终止 |

**不采纳理由**：**门控性质 ≠ 过程监督**。它管「是否放行」（事前），外部 `processSupervision` 管「过程异常：重复失败 / 停滞 / 缺证据」（事中）。两者不可互相顶替——此条为 v1.8.0 devlog 明令登记项，防张冠李戴。

### DP-7 · 入口路由（逐输入候选枚举 + abstain + 回落基线）

| 要素 | 内容 |
|---|---|
| 触发时机 | 每次输入（尚不存在） |
| 封闭候选集 | 候选须声明 id / 描述 / provider / 执行域 / 数据类；`abstain` / `unknown` 为保留名（尚不存在） |
| 弃权与回落 | 低置信、超限（不截断）、隐私拒绝、provider 失败 ⇒ 一律回落基线（尚不存在） |

**不采纳理由（本轮）**：**这是我方明确缺口**，不是"不需要"。DP-1 只做到「三档通道可达」，缺「逐输入的候选枚举与弃权」。缺口成因：候选枚举依赖 provider 注册表与执行域声明，而本仓 provider 面尚未成型。**未来采纳条件**：§四 判定档接通 + provider 注册表落地后，作为独立点补入。

### DP-8 · 完成审查（completion review）

| 要素 | 内容 |
|---|---|
| 触发时机 | 目标达成判定时（尚不存在） |
| 封闭候选集 | 目标 + 逐条需求 yes/no（尚不存在） |
| 弃权与回落 | 拒绝额度封顶（`maxRefusals`）后强制收敛（尚不存在） |

**不采纳理由（本轮）**：本仓无「目标 / 需求」的结构化模型——任务书是 Markdown、需求无 ID 化，无可审查对象。**未来采纳条件**：任务书结构化（需求条目化）后重启评估。

### DP-9 · 预取 / DP-10 · 内存选择

| 要素 | 内容 |
|---|---|
| 触发时机 | 无（本仓无对应场景） |
| 封闭候选集 | 无 |
| 弃权与回落 | 无 |

**不采纳理由**：预取依赖「工具发现 + 沙箱」形态（本仓无沙箱发现面）；内存选择依赖「多轮记忆候选」（本仓无长期记忆候选池）。两者均为外部件的场景特化点，**不构成通用纪律**，登记不实施。


## 三、非接入点的判定面（不计入清单，但须可见）

| 面 | 位置 | 与接入点的区别 |
|---|---|---|
| 确定性规则 7 族 | `router/deterministic-judge.ts` | 规则复算，非模型判定（见 DP-4） |
| 决策下达 schema 门 | `router/decision-dispatch.ts` | 结构校验，非语义判定（见 DP-3） |
| 校准分桶与登记 | `router/calibration-report.ts` | 事后统计，不参与单次判定 |
| 槽位协同 | `router/slot-manager.ts` | 资源编排，不产生判定 |


## 四、冲突与缺口登记

**T-1（已裁 · 2026-11-01 · 弃权/低置信回落取 L0）**

v1.8.0 §一 要求「弃权与低置信亦须**统一回落 L0 基线**」，v1.5.4 原实现把二者送往 **L2 难例兜底**。裁定如下（依据实测数据，非偏好）：

| 判据 | 实测事实 |
|---|---|
| 默认配置下是否真有两路 | **否**——`l2Fallback` 内 `useCloud = l2Policy==='cloud-strong' && cloudAllowed`，而云端 provider 默认关闭 ⇒ 默认产出的 `target` 与 `grade` 与 L0 **同为本 + ASK**，差异仅在 `routeReason` 文案。属**假分流** |
| 本地重试能否救回 | **不能**——语义面漏判 575 条中 csqa 占 **270（47%）**（v17 三 seed 归因）；main01v6 已判 csqa 为本架构**容量受限面**（训练行自测 0.35/0.43）。同一模型重试对容量上限无增益 |
| 云端强档是否有据 | **无实测**——`cloud-strong` 在全仓无任何读数；且「弃权 → 自动外发重判」属论文稿所禁的「弃权变确定」**激进方向**，不得豁免 |

**裁定**：弃权 / SKIP / 低置信**默认回落 L0 基线**（ASK + 本地，不外发）；
仅当云端**显式开启**（`cloudAllowed && l2Policy==='cloud-strong'`）才转 L2 云端强档。

**落地**：`router/intent-triage.ts` 该分支加 `cloudOn` 判据；测试改为「显式开启 ⇒ L2 / 未开启 ⇒ L0（ASK + local-executor + routeReason 含『云端未开启』）」，并新增弃权路径同口径用例。

**T-2（缺口）**：DP-7 入口路由（逐输入候选枚举 + abstain）未实现，见该点理由与未来条件。

**T-3（缺口）**：DP-8 完成审查未实现，依赖任务书结构化。


## 五、维护规则

1. **新增接入点必须先在此登记六要素**，再改代码——未登记的接入点视为设计缺陷。
2. **不采纳点不得静默删除**：确需移除时，改为「已裁不采纳」并写明裁决日期与理由。
3. **本清单的判据（§零）变更属设计变更**，须同步 `docs/ARCHITECTURE.md` 的判定层章节。
