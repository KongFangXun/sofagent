# 模具厂报价单案例 · 没有本体结构的 AI 只是更快的错误生成器

> **类型：适用边界反面案例** | 日期：2026-07-30 | 来源：原创笔记（自有 IP）
> **结论：企业自身没有标准数据时，AI 学得越快错得越系统**

---

## 一句话

浙江某模具厂想用 AI 自动报价，但发现核心障碍不是模型不够强——**是企业自己几十年来从来没有统一的报价标准**。没有本体结构（Ontology），AI 只是更快地生成错误报价。

## 背景

| 维度 | 详情 |
|------|------|
| 企业 | 浙江某模具厂（张总），产品面向全国销售 |
| 痛点 | 手工 Word 报价单，格式五花八门，参数不统一，新人上手难 |
| 诉求 | AI 学习历史报价 → 输入参数 → 自动出参考价 + 生成报价单 |
| 硬约束 | 本地部署（核心商业数据不能传公开网络） |

## 隐藏障碍

企业没有明确的报价标准——历史报价有时参考原料成本，有时按客户关系调整，有时靠销售和老板经验判断。

> 没有标准数据 → 训练不出可靠 AI；正确参数与错误参数混杂 → **AI 学得越快，错得越系统**。

## 正确路径（三步）

1. **数据归类与清洗**——整理历史报价单/合同/订单，AI 提高效率，但最终必须由业务人员审核校验。产出：标准产品目录 + 参数库 + 报价依据
2. **搭建本地知识库 + 报价系统**——全公司统一通过系统查询产品、调用参数、生成报价单
3. **持续更新迭代**——产品升级、材料价格变化时及时更新

## 对 sofagent 的启示

这个案例印证了 FDE 方法论的第一步必须是**梳理**（Ontology 本体结构构建），而不是**部署**：

- sofagent 的审计引擎能审计 Agent 的行为（git diff），但**审计不了业务数据的质量**——如果输入的报价数据本身就是错的，审计规则 A1-A23 全过也救不了你
- 这正是 FDE 进场四阶段（梳理→挖掘→交付→离场）中**梳理在第一位**的原因：先帮企业建立本体结构，再上 Agent
- Ontology 本体结构不是可选的前置步骤——没有它，Agent 的"智能"只是把企业的混乱以更快的速度放大
