## 红队结论入口（透明仓 · 敌手自测）

「敌手自测」（自己打自己）的 run 结论是本目录的**正式入口之一**——
与上面「装了但失败」的反案例同属一条证据链：**没被打穿也要有记录**，否则等于没测。

| 来源 | 说明 | 落点 |
|---|---|---|
| 红队用例集（四类攻击面成对用例） | 篡改 history.jsonl / 伪造 HMAC 链 / 绕过 ToolGate / 恶意插件四最小用例 | [red-team/README.md](../red-team/README.md) |
| 红队首跑（2026-10-11） | 被拦 7 / 未拦·有检出证据 2 / 穿透 0 | [red-team/run-2026-10-11.md](../red-team/run-2026-10-11.md) |

> 判定口径：**被打穿 ⇒ 修（进 `playbook/regression-checklist.md` 回归清单）；
> 未被穿透 ⇒ 留证（本目录）**。执行器 `tools/check/red-team-runner.mjs`，
> 退出码 0=绿 / 1=有违规（存在穿透）/ 2=失明。
>
> 本次未拦但留有检出证据的两条已知边界（RT-06 services 桥运行时不强制授权声明面 /
> RT-08 入池审核三道门查存在性不查真实性）见红队首跑结论「已知边界」节——
> **显式登记为边界，不虚标为「已拦」**。

## 模板

新建案例时复制以下骨架：

```markdown
# 反案例：{一句话标题}

| 字段 | 内容 |
|------|------|
| 日期 | YYYY-MM-DD |
| 平台 | OpenClaw / WorkBuddy / ... |
| 任务 | 做了什么 |
| 期望 | 应该发生什么 |
| 实际 | 实际发生了什么 |
| 为什么没拦住 | 是约束不到位？拆解不对？还是单纯的模型能力不足？ |
| 修了吗 | 如果是 sofagent 的问题 — 修了没？哪个版本？ |
```
