## 场景对照

| 开发行为 | ❌ 无 sofagent | ✅ 有 sofagent |
|---------|:---:|:---:|
| 提交 `.env` 文件（含 API key） | ✅ 成功提交 — secret 入 git 历史 | ❌ A1 拦截 |
| 硬编码 OpenAI key | ✅ 成功提交 — secret 进生产代码 | ❌ A2 拦截 |
| 100 文件重构中藏 AWS key + GitHub token | ✅ 全部通过 — 无人审查 100 个文件 | ❌ A2 精准定位 2 个 secret |
| 200KB 构建日志含 OpenAI key | ✅ 成功提交 — 日志无人检查 | ❌ A2 扫描 |
| 重命名文件（sk-前缀） | ✅ 无警告 | ✅ 不误报 |
| 删除痕迹（试图掩盖） | ✅ 已太晚 — git 历史不可删除 | ✅ 完整 history.jsonl |
| 超过 50 个文件变更 | ✅ 无检查 | ⚠️ A11 告警 |

## 量化对比

| 指标 | ❌ 无 sofagent | ✅ 有 sofagent |
|------|:---:|:---:|
| Secret 检出数 | 0/5 | 5/5 |
| 误报数 | 0（没有工具） | 0 |
| 单 commit 审计耗时 | 0s（不审计） | 8.76s（100 文件） |

## 一句话

> 没有 sofagent，secret 泄露不是「会不会发生」的问题，而是「什么时候被发现」的问题——而通常发现时已经晚了。
