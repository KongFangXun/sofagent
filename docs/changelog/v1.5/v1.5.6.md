## 一、CLI 单入口收敛（13 个 bin → `sofagent <域> <动作>` · 2026-09-16 用户拍板排期本版）


> **形态归属**：`[非功能]`（重构·13 bin → 1 + 旧命令 shim 化；shim 退役部分属可拔契约执行面）｜ —
>
> 📋 **来源**：探索方向表「CLI 单入口收敛（叙事收敛批）」——实测当前 **13 个 bin 条目**（12 个 `sofagent-*` + 1 个裸名 `sofagent` 主入口，实测口径 = 根与各 `engine/*/package.json` 的 `bin` 字段并集），对用户是 13 个记忆点，新用户第一步摩擦有一半来自「我该用哪个命令」。收口为 `sofagent <域> <动作>` 单入口（`sofagent audit` / `sofagent train` / `sofagent ontology` …）。
>
> **现状与工作量**：裸名 `sofagent` 主入口**已在位**——本章补的是**子命令路由**（域分发到既有实现）与**旧命令 shim 化**，不是从零造入口。

| 组件 | 能力 |

## 二、数据生命周期治理（~/.sofagent/data 增长面收敛 · 2026-09-16 用户拍板排期本版）


> **形态归属**：`[主干]`（归档锚点重算 + decision-log 留痕 + doctor 判定）**+ `[通道]` 成分**（归档轮转与遗留文件清理的**执行动作**）｜ L1 关档
>
> 📋 **运行时数据实测发现**（2026-09-16 深挖）：`~/.sofagent/data` 332M 只增不减，三处结构性问题——① `memory/audit` 17178 个事实文件 67M 平铺单目录（dream-cycle `extract-facts` 按 key 前缀分桶后 bucket 内无二级分层、无归档、无轮转，已达文件系统性能退化区间）；② `audit/` 目录三个遗留备份文件 49M（`history.jsonl.bak×2` + `broken-*`）无生命周期策略接管；③ 审计链文件（history 52M / decision-log 56M）永久追加无归档机制。**边界**：只治理数据文件生命周期，不动链结构本身（HMAC 链只追加不删改是铁律——归档=移走历史段+锚点重算，非删除）。

### 交付

| 组件 | 能力 |
|------|------|
| **memory 事实二级分层** | bucket 内按日期（或哈希前缀）二级分目录，索引文件统一寻址——兼容现有 key 读取（读侧按索引查，不依赖目录遍历） |
| **memory 归档与轮转** | 事实级记忆按 updatedAt 冷热分层：N 天未更新移归档目录；归档不进常规检索（显式 `--archive` 才查）——对齐「记忆遗忘机制」 |
| **审计链归档机制** | history.jsonl / decision-log.jsonl 支持历史段归档：超阈值（如 50MB）把头部段移入 `archive/` 子目录 + 重算链锚点（锚点链头指向新末尾，归档段带独立锚点指纹可独立校验——与 [v1.5.2 第二章](./v1.5.2.md) 独立验签器语义衔接） |
| **遗留备份接管** | `*.bak-*` / `*.broken-*` 文件按时间上限清理（默认保留 30 天），清理动作进 decision-log 留痕 |
| **doctor 检查项** | 新增 data 目录健康检查：单目录文件数超阈值（如 1 万）黄色告警 + 总量趋势提示 |
| **沉淀记忆的项目作用域（跨项目不自动）** | 审批入池的沉淀记忆（skill / 经验）**作用域默认钉到项目**（按仓库解析），跨项目与用户全局沉淀**不自动共享**——一个项目里验证过的经验直接污染另一个项目是记忆面的越权。确需跨项目复用走显式导出/导入（带血缘与审批留痕，对齐 G1 模板五件套通道）。与租户隔离互补：租户隔离管「企业间不串」，项目作用域管「项目间不串」——两层都默认关，显式才开 |
| **文档预算收敛 · B 层瘦身（2026-10-02 登记）** | 本轮巡检实测：**B 开发者参考层 10648 / 10650 行，余量仅 2 行**（同批 A 6302/7480 · E 3904/4000）⇒ 任何 A/B 层净增都会爆线，落盘被迫全部绕道 `docs/changelog/**`（零预算面）。⇒ 本版按「存量收敛」主题**主动瘦身**（目标**净增为负**，把余量重新拉开），**不调上限**——上限是机械护栏，调上限等于拆护栏；应让内容回落而非放宽尺子。**范围**：开发者参考层的重复表述 / 过期示例 / 可由 changelog 承载的叙事段，逐文件对账后**归并或外移**。⚠️ 外移目标须为**零预算面**或**既有同事实持有处**——**不得为腾行数而制造第二套口径**（同一事实两套口径比缺失更糟）。**验收**：check-docs §4 的 B 层余量恢复到**两位数行级别**，且 A/B 层零净增。**登记理由（对齐「不做的事也要有落点」）**：本条是**已裁定**（不做「调上限」，改做「内容回落」），非待定项。**处置更新（2026-10-02 同日）**：余量危机的**根因**已定位并修掉——B 层硬上限覆盖了 `FORGE/LEDGER.md`（自述「**追加 only 的跨 run 永久索引**」的 append-only 台账，长度由**跑过的轮数**决定、不由作者决定），与既有 `FORGE/lessons/` 排除同源（给台账设硬上限 = 多跑一轮审查即撞墙）。按**归层修正**移出硬预算、改由新增的 **F-ledger 软读数**兜底（10648 → **10242 / 10650，余 408 行**）⇒ **本行「余量恢复到两位数行级别」的验收已达成（超额）**。**归层 ≠ 调上限**：上限值与判定尺子一字未动，改的是「该由作者决定长度的内容才进硬预算」这条归层口径。**内容收敛**随之从「为腾余量」降为**常规文档卫生**，不再作本版硬性主题（避免为达标而做无谓删减） |
