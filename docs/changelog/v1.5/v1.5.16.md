## 一、自进化写面的审计覆盖（prompt / memory 两面补盲 · RSI 治理的地基章）

> **形态归属**：`[主干]`（判定·留痕——自进化变更面的审计取证）｜ **不可拔**（审计地基：拔掉它，Agent 改自己的 prompt 与 memory 就彻底逃逸审计视野，RSI 治理失去立足点）
>
> 📋 **缺口实测（2026-09-19）**：审计地基是「不信任自我报告，只看 git diff 硬证据」（[ARCHITECTURE](../../ARCHITECTURE.md) 核心叙事），v1.5.1 规划第二通道（调用意图 + 结果文本）。但 RSI 的四个可写面里——**权重面**（v1.4.4 manifest + sha256 验签）与 **skill 面**（eval-gate 收编门 + v1.4.9 执行时 skill 快照）已有覆盖，**prompt 面与 memory 面完全在审计视野外**：Agent 改了自己的 system prompt、往记忆里写了一条「经验」，不留任何可举证的变更记录——**自我改进最大的两个写面恰恰是我们唯一没有硬证据的地方**。行业对位：Meta-RSI 把可写面明确为 data/harness/model 三类并要求保护面独立于所有写面——本章是「保护面如何真的看得见写面」的工程答案。

### 交付

| 组件 | 能力 |
|------|------|
| **写面变更留痕** | prompt 面（SKILL.md / fde.md / overrides 配置变更）与 memory 面（think.md / knowledge / 记忆事实写入）的每次变更落一条可举证记录：变更前后值摘要 + 发起人（Agent 实例 id / 人）+ 触发来源（自我改进 / 人工 / 系统）+ 时间戳 |
| **写面 diff 语义** | 为两类非代码写面定义 diff 契约（配置面按字段级 before/after；记忆面按条目级新增/修订/失效），与既有 git diff 规则并列为第三通道——**规则判定逻辑不变，只扩输入面**（对齐 v1.5.1 双通道的同款纪律） |
| **与改进链绑定** | [v1.5.14 第二章](./v1.5.14.md) 与 [v1.5.15 第二章](./v1.5.15.md) 的晋级 / 考核动作自动产生写面变更记录（改了什么 → 留痕自动发生，不靠调用方自觉）；无留痕的写面变更 ⇒ 回退并告警（fail-closed） |
| **举证面** | 写面变更记录可导出具证（对齐 [v1.5.2 第二章](./v1.5.2.md) 约束导出与独立验签语义——第三方无需安装 sofagent 即可举证） |

## 二、能力基线版本线（四层状态快照 · 出事能回答「当时它是怎么做事的」）

> **形态归属**：`[主干]`（留痕·能力状态可复现基线）｜ L1 关档
>
> 📋 **缺口实测（2026-09-19）**：v1.4.9 已交付**执行时** skill 快照（单次执行级可复现——执行前打包、执行后清理），但缺**跨时间**的能力基线：Agent 进化三个月后与当初判若两人，出事故时无人能回答「当时的它是哪个状态」。审计的可复现要求（举证要能还原当时条件）在 RSI 时代需要一条**能力版本线**，而不是只靠单次执行快照。

### 交付

| 组件 | 能力 |
|------|------|
| **基线快照** | 每次能力变更（晋级/回退/写面变更）前打包四层状态：prompt 配置版本 + skill 集合版本 + memory 事实锚点 + 权重 manifest 引用——形成可寻址快照 id |
| **版本线** | 快照按时间成链（前驱指针），任一时点可回答「当时 Agent 的完整能力状态」；与 v1.4.9 执行级快照分工：执行级管单次可复现，本版管跨时间可追溯 |
| **基线回滚** | 按快照 id 回滚四层状态（复用既有 snapshot/restore 语义，不新建回退机制）；回滚动作本身落 decision-log |
| **举证面** | 快照 id 可被引证记录引用（「事故发生在基线 X 下」——举证不止于代码版本，而是能力版本） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/evolve/src/baseline-snapshot.ts` | 新建 | 四层状态打包 + 版本链 + 回滚 |
| `engine/evolve/src/__tests__/baseline-snapshot.test.ts` | 新建 | 快照完整性 / 版本链前驱 / 回滚可举证单测 |

### 验收标准

- [ ] 能力变更自动生成四层基线快照（可寻址 id）
- [ ] 版本线可回溯任一时点能力状态
- [ ] 按快照 id 可回滚四层状态（复用既有机制）且回滚留痕
- [ ] 举证记录可引用快照 id（能力版本可举）
- [ ] `npm test` 全绿
