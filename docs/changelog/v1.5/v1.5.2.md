## 定位


> 🔍 **审计模块 · 对外开放面**——审计对外可消费的两面：**数据面**（history 可查——MCP `audit_query` 只读 + 事件订阅推送）与**规则面**（ruleset 可导出——机器可读 JSON，导出格式即加载格式双向可逆），外加**举证面**（独立验签工具——第三方无需安装 sofagent 即可验 HMAC 链）。本版是审计模块「从内部审计走向对外可举证」的收口。

> 🔍 **审计模块 · 判定链与结论语义**——把「判定」管两头：**开工前**（五问判定链——健康 / 人审 gate / 证据等待 / 专注等待 / 配额，任一不过则挂起等条件满足，挂起非失败）与**结论后**（失效语义——结论不是永久有效，授权变更 / 压缩不兼容 / 风险升级三触发即标失效，失效结论不当新证据用）。与 [v1.5.3](./v1.5.3.md) 同属「审计模块自我完善」：那里保证规则**加载时**是对的，本版保证判定**开工前**成立、结论**消费时**还有效。

> 🌐 **审计模块 · 出口治理（数据主权「管出」翼 · 2026-09-22 归位再分配迁入）**——Agent 能访问哪些 host 无人管时，数据外泄通道敞开。本版补上「管出」翼：host 白名单声明面（默认空全拒，opt-in——对齐 G10 模式）+ 出站裁决审计挂链（与「管进」读取审计对称）+ 拦截器接口（裁决契约留约束层、实现在外，对齐 TrainChannel 通道形态）。出口裁决事件契约可导出——判定底座（v1.6.0+）就位后自然成为 `Noul` 判定输入源；AI 节点（[v1.5.4 第五章](./v1.5.4.md)）是第一个实装消费方。

> 🔒 **审计模块 · 事前授权补环（自探索方向迁入 · 2026-09-22 用户拍板）**——现有审计是**事后**环（变更 → git diff → 规则 → 留痕可举证），缺**事前**环。本版补上 mandate：Agent 动手前先领一张**有限且可归属**的授权（范围 + 时效 + 审批人），越界在**执行前**拦下而非事后追责。与本版第三章「开工前五问」复用同一副判定骨架、不新建第二套；与 [v1.5.1](./v1.5.1.md) 门禁三态补齐**互补而非依赖**（三态让未授权执行事后可判，mandate 让越界动作事前可拦）。

>
> 📋 **2026-09-16 并入验签工具**（用户拍板）：与「规则可被外部消费」同属约束对外可消费面——审计证据链目前只能由 sofagent 自身校验，作为举证材料的可信度依赖维护方中立性；独立验签器把可信根从「信任 sofagent」换成「信任密码学」，且三仓共用（平台层 PR 审阅举证 / 模型层训练信号溯源 / 开源用户合规举证）。**边界**：只读校验，无写权限、不加载引擎代码。

| 组件 | 能力 |
|------|------|

| **规则语义元数据** | 每条规则附训练消费元数据（rule_id + 检测意图 + 违规样例 + 严重级别）——训练管线可直接把「约束」构建为 reward 信号或 SFT 语料 |

| **版本与指纹** | 导出物带规则集版本号 + 内容指纹（对齐 v1.4.1 可复现指纹——训练任务引用规则集版本可追溯） |

| **独立验签工具** | 单文件零依赖的哈希链校验器（`tools/verify/verify-chain.mjs`，裸 node 可跑）——输入 `history.jsonl` + 链头指纹，独立重算并校验 HMAC 链完整性；第三方（审计师 / 监管 / 法院技术顾问）无需安装 sofagent 即可举证。**输出三态**：链完整 / 某条断裂（给出条目号与期望值）/ 链头不匹配 |

## 四、审计结论失效语义（Codex Guardian 启发 · 2026-09-16 用户拍板排期本版）


> **形态归属**：`[主干]`（判定·失效词汇表与触发）｜ L1 关档
>
> 📋 **研究收编**（codex-rs [guardian/](https://github.com/openai/codex/tree/main/codex-rs/core/src/guardian) 源码核验）：Codex 给审查结论定义了一套**失效条件**（`GuardianReviewReason`）——`FreshRequired`/`StaleScore`/`AuthorizationChanged`/`IncompatibleCompaction`/`ElevatedRisk`/`ScoringFailure`。本仓现状：审计结论（history.jsonl）与 HITL 授权一经产生即视为永久有效，下游消费方无法判断「这条结论还能不能信」。与 [v1.5.3 第二章](./v1.5.3.md) 自测 schema 同属「审计模块自我完善」主题：那里保证规则**加载时**是对的，本章保证结论**消费时**还是对的。
>
> ⚠️ **马鞍边界（四问过筛已过，边界在此）**：只吸收「失效原因词汇表」与判定逻辑——属共享账本层豁免（词汇表不是执行器）。**不吸收** Guardian 的 reviewer pool / 同步审查会话 / 预热机制（那是审查的马场：换 fresh-eyes 或任何外部审查器，本失效语义价值不受损）。

### 交付

| 组件 | 能力 |
|------|------|
| **失效原因词汇表** | 审计结论 schema 新增 `invalidationReason` 字段（枚举：授权变更/压缩不兼容/风险升级/分数过期/需新鲜结论），对齐 Guardian 六原因语义取子集 |
| **失效判定钩子** | 三个事件触发失效标记：①授权或白名单配置变更（AuthorizationChanged）②压缩/摘要事件发生（IncompatibleCompaction——对应 L2 工具输出总结、加载链压缩）③后续轮次风险升级（ElevatedRisk——同一对象后续被更严规则命中） |
| **下游消费语义** | 带失效标记的结论不作为后续判定的输入（fresh-eyes 审查输入、HITL 免检依据、治理 KPI 统计均须过滤）——「过期结论不当新证据用」 |
| **留痕不删除** | 失效结论保留原文 + 失效标记（对齐 HMAC 链只追加不删改——失效是标记不是抹除） |

**一、四款 OpenClaw 插件 projectRoot 配置静默失效（已修 · `7cfa3627`）**

- **根因（OpenClaw 2026.6.1 源码实证）**：运行时插件 API 顶层带 `pluginConfig`（本插件配置，经 configSchema 校验注入），且仅在 `register` 期可达；而 agent 类 hook 的 ctx 由宿主 `buildAgentHookContext` 白名单显式构造（只展开 15 个字段，**不含 config**）。四款的读法全错——rollback / audit 硬编码 `process.cwd()`（配置无人读，回滚工具指错仓库属高危面）；inject / evolve 读 `ctx?.config?.plugins?.entries?...`（**恒 undefined**，「配置写了不生效」由此而来）。
- **修法**：register 期读 `api.pluginConfig` 解析一次并缓存，工具/hook 内回落 cwd；evolve 的 `projectRoot` 撤出 manifest（think.md 落点由数据根 `dataDir` SSOT 决定，与宿主项目根无关，保留声明只误导部署方），`reflectHint` 开关同源修复。测试补 projectRoot 读取用例并以负向探针验证能拦回退（vi.mock 拦不到动态 require，改 `vi.spyOn` 真实模块对象）。
- **附带**：四款 README 发布命令去硬编码版本（原写死 `--version 1.4.0`，漂移三版 → 改取 package.json，`2538408e`）。
- **分发限制（ClawHub 平台特性）**：ClawHub **不允许覆盖已发布版本**（`Version 1.5.1 already exists`，rollback/evolve 双验）——与 SkillHub skill 通道「同版本可更新」行为不同。故本修复对 ClawHub 用户面须**随 v1.5.2 版本号重发**才能生效；rollback 在 1.5.1 上的 `scan=suspicious`（llmAnalysis 对「manifest 承诺 projectRoot 而运行时用 process.cwd()」的 concern 评分，即本 bug 的扫描面投影）同样随新版重发消解。

**二、sofagent-evolve 工具假成功（已修 · `abd6d0b2`）**

- **病根**：OpenClaw 侧 evolve 工具调 `generateThinkEntry([], { rules: [], summary }, task)` 传**空 diff**，而该函数首行 `if (diffFiles.length === 0) return;` → **实际零写入**，工具却返回「反思条目已写入 think.md」——假成功谎报，进化闭环数据源空转。
- **对照**：DSH 侧同族插件（cordis-plugin-sofagent-evolve）链路正确——`parseDiff('HEAD', root)` → `runRules({ diffFiles })` → `generateThinkEntry(真实 diff, 真实 results)`，空 diff 即返回不沉淀。
- **修法（定案并落地）**：`@sofagent/think` 新增公开 API `appendManualThinkEntry`（task + summary 直书条目，绕过 diff 判定——OpenClaw 工具的用户语义就是「口述沉淀」，与 DSH 的「自动收尾沉淀」是两种入口形态），并返回**写入回执**：`written` 以「追加后字节数 > 追加前字节数」判定，不信任「调过 API 就算成功」——那正是本缺陷的根因形态；空 summary 不写盘、如实返回 `empty-lesson`。OpenClaw 工具改调该 API 并**按回执分支**回报（成功报字节数，未写入报原因）。条目格式与清洗顺序（截断 → 折行 → trim）与既有手动写入先例 `write_think` 逐字对齐，该顺序由一条精确值用例锁死（旧顺序在同输入下必红）。**未改 `engine/mcp/**`**——`write_think` 保持原样，两者条目文本仍是两处同源，归并留作后续版本事项。
- **涉及文件**：`engine/think/src/think-generator.ts`（新 API + 回执类型）· `engine/think/src/index.ts`（分级导出）· `engine/openclaw-plugins/sofagent-evolve/src/index.ts`（改调用 + 按回执回报）· 同包 `README.md` 与 `src/index.test.ts`（回归 4 条：成功路径 / 未写入路径 / 真实路径反证 / 清洗顺序钉）· `docs/ARCHITECTURE.md`（@public 符号口径 2652；磁盘基线 public-api-baseline.json 仍为 2549（v1.4.9 时代生成），基线重建列入发版清单——发版时以 live 提取重建后回填终值）。

**四、审计报告模板与分桶的规格耦合（已修 · 待本版发版生效）**

- **病根**：数据主权报告的「模型路由分布」段按**具体模型规格**写死文案与字段名（云端 32B+ / 云端快速 / 本地 7B / 本地 0.5B，字段 `local7b` / `local05b`）——路由档位是**抽象槽位**，模型规格是**部署选型**，二者耦合后换一次模型，报告文案即失真。
- **修法**：模板与生成器统一改用档位名（云端强档 / 云端快档 / 本地执行档 / 本地管道档），字段名同步去规格（`local7b`→`localExecutor`、`local05b`→`localPipeline`），并如实标注该分布**按模型名启发式归因、非精确档位统计**（防阅读者当作档位精确计数用）。

**五、路由档位与模型选型耦合 + block 档语义混装（已修 · 待本版发版生效）**

- **病根**：路由层把「路由档位」与「模型规格」当成一回事（`cloud-strong` / `local-executor(7B)` / `local-pipeline(0.5B)`），配置 schema 又强制 `model` 非空——等于组件预设了厂商选型；同时 `block` 与四个模型档并列为 `RouteTarget`，而 `block` 根本不是模型档，是敏感数据本地不可用时的 fail-closed 拦截出口。混装的既有缺陷：block 走到模型选型分支即被当常规档处理。
- **修法**：档位语义显式化——四个模型档位纯化为抽象槽位（具体模型由 `data/config/model-router.json` 或 model-registry 决定），`model` 字段改允许空串表示「未配置」，降级骨架不写死任何选型；`block` 拆出为独立拦截目标并显式注释「非模型档」；新增 `decision-model` 判定档（决策模型直接出类型化答案，不经生成模型，不参与「敏感度 × 复杂度」自动路由矩阵）。

**六、全局分支审计哈希基准口径错配（已修 · 待本版发版生效）**

- **病根**：commit-msg hook 的**全局解析分支**与**开发仓分支**算的是两个不同对象（前者=全局包 dist，后者=本仓 dist），却共用同一个哈希基准 `~/.sofagent/internal/audit-dist-hash.txt`，而该文件由 `tools/audit-baseline-sync.sh` 按**本仓口径**写入。后果：只要「全局包 dist ≠ 本仓 dist」（开发机常态；worktree 无本地 dist 时必然落到全局分支），提交即被判「可能被投毒」拦死——文案指向投毒，实为口径错配的假阳性。
- **修法**：全局分支改用独立基准 `audit-global-dist-hash.txt`（`bash tools/audit-baseline-sync.sh --global` 生成），两口径各读各的、互不污染；基准缺失的报错由泛化的「跑 doctor」改为直指生成命令（对齐 P1-A3 fail-loud——报错须可执行而非兜圈子）。

### 施工增录（二轮 · 独立复核发现并修复 · 2026-09-23）

> 一轮交付为「七款插件摘 `private` + 加 `files` 白名单 + 发布脚本补插件段」。独立复核用 `npm pack` 实测**单包安装路径**（而非只看仓内加载），发现阻断级缺口——原形态下七款插件从 registry 装完第一步挂载即失败。

- **病根**：六款原子插件以**静态相对路径** `'../../plugin-kit/dist/index.js'` 引用适配层基座，而该基座 `private: true`、不登记 workspace、不在 `files` 白名单 ⇒ 不随包发。从 registry 单装的插件解析不到该路径：`MODULE_NOT_FOUND: Cannot find module '../../plugin-kit/dist/index.js'`（实测对照：仓内同目录 LOAD OK，解进模拟 `node_modules` 即失败）。⇒ 本章验收第「干净环境实装」一条必红，而「不满足单独可用的不得发布」是本章纪律 ⇒ **不能带病发布**。
- **修法（kit 一起发）**：适配层基座转 npm 发布物 `@sofagent/dsh-plugin-kit`——登记根 workspace、摘 `private`、加 `files`；六款原子插件改包名引用并在 `dependencies` 声明（**不能放 `optionalDependencies`**：该字段是生成器字段，会被 `gen-plugin-manifests.mjs` 覆盖）；越包相对引用守卫的豁免台账随之瘦身（kit 族条目清零，改为断言「该形态已不再存在」——判定取**未过台账的真实违规**，故重新登记回台账也洗不绿）；发布脚本的「按前缀猜目录」与 load-chain 特例改为**根 workspaces 查表**（kit 目录不在 `engine/<pkg>` 布局，旧写法会静默错位），并补 `SOFAGENT_PUBLISH_TAG` dist-tag 分道。
- **验收（终极判据）**：kit 与七款插件分别 `npm pack`，解进**同一个**假 `node_modules` 逐款 `require` ⇒ 七款全 LOAD OK（修前为 `MODULE_NOT_FOUND`）；反向对照抽走 kit 即复现失败 ⇒ 缺口闭环。
- **连带订正（事实错误）**：本页原「`@sofagent/rollback` 引擎包首发」一行**全仓无此包**——`engine/` 无 rollback 目录、代码面零引用、registry 无此名（双方的独立复核同结论）。旧表述的推理链「名字查不到 ⇒ 该包未发布」正是误判源头：真实 registry 缺口是**适配层基座**，已按实订正。
- **附带修复**（复核中定位，非本章交付面）：`docs/changelog/releasing/09-publish.md` 两处文档缺陷——① 游离围栏致「步骤五」标题被吞进代码块（自 v1.5.1 起的**存量**，非本轮引入）；② artifact 对账表第 3 行误写不存在的 `@sofagent/harness`，导致漏验 `inject`。同批把发布面口径从 22 包重算为 **23 包**（15 个 `@sofagent/*` + 七款插件 + 1 个裸名总包）。

## Release Notes · v1.5.2

> 面向用户的发布说明。**本节存在性 = 阶段六定稿必备项**（06 §铁律十一）。GitHub Release body 与本段**同源同构**——生成动作在阶段九按 [09-publish.md 三道工序](../releasing/09-publish.md) 执行，**禁止把本段直接复制当 body**。

🔍 审计模块「从内部审计走向对外可举证」——审计数据可查（MCP `audit_query` 只读查询 + 事件订阅推送）、规则可导出（`ruleset_export` 机器可读 JSON 双向可逆 + 训练消费元数据 + 版本指纹）、证据可外验（独立验签器 `verify-chain` 零依赖三态校验——第三方无需安装 sofagent 即可举证 HMAC 链）；判定语义补两头：开工前五问判定链（健康/人审/证据/专注/配额，挂起非失败自动恢复）与结论失效语义（授权变更/压缩/风险升级三触发即标失效，失效结论不当新证据用）；数据主权补「管出」翼（host 白名单默认全拒 + 出站裁决挂链）；事前授权补环（mandate 三元素缺一不受理，越界执行前拦截）；DSH 插件 npm 首发面（kit + 七款 `cordis-plugin-sofagent-*` 仓内可发布就绪）；v1.5.1 发版后审查修复批（35 条目收编，含 6 条安全 fail-open 收口）。MCP 工具 **105→107**（新增 `audit_query` / `ruleset_export`）。

**TL;DR (EN):** The audit module goes externally provable — audit data queryable (read-only MCP `audit_query` + event subscription push), rulesets exportable (machine-readable JSON, round-trip reversible with training-consumption metadata and content fingerprint), and evidence externally verifiable (a zero-dependency standalone chain verifier — third parties can validate HMAC chains without installing sofagent). Decision semantics get both ends: a five-question should-run gate before work starts (suspend-not-fail with auto-resume) and conclusion invalidation semantics (three triggers mark stale conclusions so they stop feeding downstream). Plus the egress governance wing (default-deny host allowlist + outbound裁决 HMAC-chained), a pre-authorization mandate loop (scope/expiry/approver, rejected before execution), the DSH plugin npm debut surface (kit + seven plugins publish-ready), and the v1.5.1 post-release review fix batch (35 items incl. six fail-open closures). MCP tools 105→107.
