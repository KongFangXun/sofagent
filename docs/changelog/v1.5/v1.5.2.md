## 一、事件驱动执行触发

> 📋 **探索方向表 2026-08-24 新增**：与 v1.3.8 cron + 依赖图同向但更彻底——触发源泛化到业务事件。等 v1.4.x 训练引擎稳定后评估 → 本版收编。

### 交付

| 组件 | 能力 |
|------|------|
| **事件源适配器** | 三类触发源：上游节点产出事件（workflow 内部）/ 外部事件（webhook 入站：邮件到达/表单提交/IM 消息）/ 定时器（v1.3.8 cron 既有） |
| **事件路由规则** | workflow 节点声明 `on:` 事件订阅（YAML 内声明式配置）——事件到达自动派发下游节点 |
| **事件总线** | 轻量事件总线（进程内 pub/sub + 落盘事件队列），事件投递全程审计留痕（每条事件可追溯触发链） |
| **死信与重试** | 事件处理失败进死信队列（复用 v1.3.1 stop_reason 分类 + 退避），死信可重放 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/events/bus.ts` | 新建 | 事件总线（pub/sub + 落盘队列） |
| `engine/orchestrator/src/events/adapters.ts` | 新建 | 三类事件源适配器 |
| `engine/orchestrator/src/events/router.ts` | 新建 | 事件→节点路由（读 workflow `on:` 声明） |
| `engine/mcp/src/tools/workflow-submit.ts` | 修改 | workflow schema 支持 `on:` 事件订阅字段 |

### 验收标准

- [ ] 上游节点产出自动触发下游节点（workflow 内部事件链）
- [ ] webhook 入站事件（≥2 类：表单提交/IM 消息）可触发节点
- [ ] 事件投递全程审计留痕（每条事件触发链可追溯）
- [ ] 失败事件进死信队列，可重放
- [ ] `npm test` 全绿
