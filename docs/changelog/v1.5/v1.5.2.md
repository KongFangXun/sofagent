## 九、双规则引擎统一（2026-09-08 排入 · 消除 ARCHITECTURE 悬空承诺）

> **形态归属**：`[非功能]`（重构——两处规则引擎收敛为一，不新增能力面）｜ —
>
> 📋 **背景**：`engine/rules/`（tool-level 规则，3 条）与 `engine/audit/src/rules/`（git-diff 规则，24 条）历史上并行维护，均含 secret-leak 检测，存在行为不一致风险。v1.3.0 已部分收敛（正则模式共享至 `@sofagent/core`），但**规则引擎仍是两套**，ARCHITECTURE 记载「统一排期见 ROADMAP」而 ROADMAP 此前无此单元格——属悬空承诺，本版补上落点。
>
> 统一方式：以 `ruleType` 字段在两种触发模式下复用同一套规则定义（tool-level 在调用前拦截、audit 在 commit 后审计），收敛为单一规则引擎 + 两种执行时机。
>
> **纪律外延（2026-09-08 补）**：判定规则**只有一个事实源**。企业侧若另建判定点（自建模型网关/代理做流量侧 PII 过滤与敏感度分流），必须集成本引擎的同一套规则与检测器（v1.4.9 第八章检测器插槽即可嵌入组件），**不得另起一套**——每多一处独立实现，就是一次口径分裂风险。

### 交付

| 组件 | 能力 |
|------|------|
| **单一规则引擎** | 两套规则定义合并为一套（含 `ruleType` 触发时机标记），tool-level 与 git-diff 两种执行模式共用 |
| **行为一致性回归** | 统一前后对同一输入的判定结果必须一致（回归锁，防统一过程引入行为漂移） |
| **ARCHITECTURE 同步** | 「已知技术债：双规则系统重叠」段改写为已排期指向本版 |

## 十、审计规则自测 schema（Codex execpolicy 启发 · 2026-09-15 用户拍板排期本版）

> **形态归属**：`[主干]`（判定·规则自测正负样例）｜ L1 关档
>
> 📋 **研究收编**（OpenAI Agents API 公测 + codex 仓源码核验，2026-09-15）：[codex-rs/execpolicy](https://github.com/openai/codex/blob/main/codex-rs/execpolicy/README.md) 把「规则正负成对自检」做成**引擎级机制**——每条 prefix_rule 强制携带 `match`（必须命中的样例）与 `not_match`（必须不命中的样例）字段，**加载时即校验**（官方原话 "think of them as unit tests"）：规则写错（锚串消失/误命中）立刻爆，不靠人记。本仓「假门禁五形态」反模式（正向探针空转/锚串消失静默跳过/门禁块吞退出码）一直靠纪律级 checklist 防（回归清单「自检/守卫正负成对」条目）——本章把该纪律升级为 schema 强制。与第九章天然衔接：**双规则统一后的单一规则定义正是携带正负样例的最佳载体**（一套定义，两种触发时机，样例同源）。

### 交付

## 十三、审计结论失效语义（Codex Guardian 启发 · 2026-09-16 用户拍板排期本版）

> **形态归属**：`[主干]`（判定·失效词汇表与触发）｜ L1 关档
>
> 📋 **研究收编**（codex-rs [guardian/](https://github.com/openai/codex/tree/main/codex-rs/core/src/guardian) 源码核验）：Codex 给审查结论定义了一套**失效条件**（`GuardianReviewReason`）——`FreshRequired`/`StaleScore`/`AuthorizationChanged`/`IncompatibleCompaction`/`ElevatedRisk`/`ScoringFailure`。本仓现状：审计结论（history.jsonl）与 HITL 授权一经产生即视为永久有效，下游消费方无法判断「这条结论还能不能信」。与第十章自测 schema 同属「审计模块自我完善」主题：第十章保证规则**加载时**是对的，本章保证结论**消费时**还是对的。
>
> ⚠️ **马鞍边界（四问过筛已过，边界在此）**：只吸收「失效原因词汇表」与判定逻辑——属共享账本层豁免（词汇表不是执行器）。**不吸收** Guardian 的 reviewer pool / 同步审查会话 / 预热机制（那是审查的马场：换 fresh-eyes 或任何外部审查器，本失效语义价值不受损）。

| **失效判定钩子** | 三个事件触发失效标记：①授权或白名单配置变更（AuthorizationChanged）②压缩/摘要事件发生（IncompatibleCompaction——对应 L2 工具输出总结、加载链压缩）③后续轮次风险升级（ElevatedRisk——同一对象后续被更严规则命中） |

**一、四款 OpenClaw 插件 projectRoot 配置静默失效（已修 · `7cfa3627`）**

- **根因（OpenClaw 2026.6.1 源码实证）**：运行时插件 API 顶层带 `pluginConfig`（本插件配置，经 configSchema 校验注入），且仅在 `register` 期可达；而 agent 类 hook 的 ctx 由宿主 `buildAgentHookContext` 白名单显式构造（只展开 15 个字段，**不含 config**）。四款的读法全错——rollback / audit 硬编码 `process.cwd()`（配置无人读，回滚工具指错仓库属高危面）；inject / evolve 读 `ctx?.config?.plugins?.entries?...`（**恒 undefined**，「配置写了不生效」由此而来）。
- **修法**：register 期读 `api.pluginConfig` 解析一次并缓存，工具/hook 内回落 cwd；evolve 的 `projectRoot` 撤出 manifest（think.md 落点由数据根 `dataDir` SSOT 决定，与宿主项目根无关，保留声明只误导部署方），`reflectHint` 开关同源修复。测试补 projectRoot 读取用例并以负向探针验证能拦回退（vi.mock 拦不到动态 require，改 `vi.spyOn` 真实模块对象）。
- **附带**：四款 README 发布命令去硬编码版本（原写死 `--version 1.4.0`，漂移三版 → 改取 package.json，`2538408e`）。
- **分发限制（ClawHub 平台特性）**：ClawHub **不允许覆盖已发布版本**（`Version 1.5.1 already exists`，rollback/evolve 双验）——与 SkillHub skill 通道「同版本可更新」行为不同。故本修复对 ClawHub 用户面须**随 v1.5.2 版本号重发**才能生效；rollback 在 1.5.1 上的 `scan=suspicious`（llmAnalysis 对「manifest 承诺 projectRoot 而运行时用 process.cwd()」的 concern 评分，即本 bug 的扫描面投影）同样随新版重发消解。

**二、sofagent-evolve 工具假成功（开工前待修）**

- **病根**：OpenClaw 侧 evolve 工具调 `generateThinkEntry([], { rules: [], summary }, task)` 传**空 diff**，而该函数首行 `if (diffFiles.length === 0) return;` → **实际零写入**，工具却返回「反思条目已写入 think.md」——假成功谎报，进化闭环数据源空转。
- **对照**：DSH 侧同族插件（cordis-plugin-sofagent-evolve）链路正确——`parseDiff('HEAD', root)` → `runRules({ diffFiles })` → `generateThinkEntry(真实 diff, 真实 results)`，空 diff 即返回不沉淀。
- **修法方向**：`@sofagent/think` 新增「自由文本写反思条目」公开 API（task + summary 直书条目，绕过 diff 判定——OpenClaw 工具的用户语义就是「口述沉淀」，与 DSH 的「自动收尾沉淀」是两种入口形态）；或 OpenClaw 侧对齐 DSH 链路取真实 diff。涉及 `@public` 基线变更，与第五章（运行时 should-run 判定链）联动评审后定案。
- **涉及文件（预估）**：`engine/think/src/think-generator.ts`（新 API）· `engine/openclaw-plugins/sofagent-evolve/src/index.ts`（改调用）· 两包测试。

**三、orchestrator 上游断链钉（已修 · `ae282410`）**

- **病根**：`@deepseek-ai/dsh` 以 caret `^0.1.5-rc.2` 依赖 `dsh-web-app`，后者 rc.3 把 `documentpreview` 需求抬到 `^0.1.5-rc.3`，而该包从未发布 rc.3（registry 最高 rc.2）——无 lock 的全新安装解析到 rc.3 即 ETARGET。`sofagent` 总包 / `@sofagent/orchestrator` 1.4.9 / 1.5.0 / 1.5.1 三版全部同样失败（时间性上游 skew，非本版回归）。受影响路径：`npm i -g sofagent`、`@sofagent/mcp`、`@sofagent/daemon`、`@sofagent/orchestrator`；`@sofagent/audit` 路径（install.sh 主链）不受影响。
- **修法**：`engine/orchestrator/package.json` dependencies 精确钉 `"@deepseek-ai/dsh-web-app": "0.1.5-rc.2"`（该传递边钉死，附解析锚点注释注明上游补齐 rc.3 后可移除）。
- **分发限制（npm 版本不可变）**：修复对 registry 用户面须**发新版**才生效——`npm i -g sofagent` 主入口在 1.5.1 上持续 ETARGET 直至本版发布（用户拍板接受该窗口）。
