## 一、模型路由层（Harness 路由 · 云端/本地分流）

> 📋 **ROADMAP 分层模型架构**：云端 32B+ 负责规划推理 → 本地 7B 执行多步 workflow → 本地 0.5B 跑管道层。**引擎层只做模型路由（model-router.ts 已有四档插槽），精调 pipeline 属模型层非开源范围。路由层不依赖精调模型——对接现有云端 API + 本地推理服务（Ollama 等）即可交付。**

### 交付

| 组件 | 能力 |
|------|------|
| **路由策略引擎** | 任务分级路由：规划类→云端大模型 / 执行类→本地 7B / 管道类（模板/格式/字段提取）→本地 0.5B——按任务类型+数据敏感度双维决策 |
| **敏感度路由** | 数据分级（公开/内部/敏感）自动决定可否走云端——敏感数据强制本地（fail-closed） |

| **本地端点注册** | model-registry 注册本地推理服务端点（Ollama 兼容协议），云端/本地统一注册面 |

## 四、单节点执行状态机（SKILL.state 机制收编 · arXiv:2608.26263 · EMNLP · 2026-09-03 用户拍板）

> SKILL.state 把技能执行从聊天记录改成状态机：每步模型只收 P（不可变技能说明）+ Σt（结构化状态 JSON）+ ot（最新观察），输出推理轨迹 Rt / 状态补丁 ΔΣt / 动作 at；运行时确定性校验合并 Σt+1 = Σt ⊕ ΔΣt 后**推理轨迹永久丢弃**——单步 prompt O(1)、累计 token O(T)。论文实测：16.2 倍 token 压缩（1,062,387→65,408）、抗噪 ≥0.97（ReAct 崩到 0.53）、状态恢复零步数、InterCode CTF 54.2%（+7.8 且省 60.4% token）；**预算对齐控制实验实锤赢在结构化不在压缩**（同预算下：滑窗截断 0.18 / LLMLingua 0.22 / SKILL.state 0.94）。
>
> **sofagent 的增量空间在节点内部**：编排层（LoopGraphState + artifacts 浅合并 reducer）已是 sofagent 版的 Σt⊕ΔΣt，checkpoint 已支持状态恢复；但 `node-executor.ts` 用 createReactAgent，节点内部是消息历史式滚雪球（无 trimMessages），长任务 token O(T²) 与上下文中毒风险与论文基线相同。
>
> **sofagent 天生的落地底气**：wrapToolCall 运行时审计在每步动作发生时实时落记录——推理轨迹可弃而行为仍可溯，**轨迹可弃、行为可溯**，这是论文没有、sofagent 独有的审计前提。

### 交付

| 组件 | 能力 |
|------|------|
| **试点节点执行状态机** | refine-agent 优化循环（几十轮、多步工具调用、contamination-guard/snapshot-manager 邻接基建在位）加「执行状态 JSON」：每步产出 ΔΣt（已做/待办/关键事实），代码确定性合并 Σt+1=Σt⊕ΔΣt，下一步 prompt 只带 P+Σt+ot，推理轨迹合并后即弃 |
| **审计闸门前置** | Rt 丢弃前落一条审计摘要（动作 + 状态补丁 + 因果边）——wrapToolCall 通道接线，原则「轨迹可弃、行为可溯」写进 DEVELOPMENT.md 执行层章节 |
| **领域级执行状态 schema** | 论文「100 道题共用 5 字段 schema」启示——为「代码修复循环」「审查循环」「文档批处理」三领域各定义一个执行状态 schema，schema 是领域资产沉淀进 SKILL/ 设计文档，非任务级配置 |
| **试点度量** | token 曲线（对齐论文 O(1) 平线）/ 轮次稳定性 / 结果质量不降——试点数据说话，通过后评估推广 engineer/checker/reviewer 长任务节点（不提前铺开，不提前抽象纪律） |
