## 定位


> 🔍 **审计模块 · 规则引擎统一与自测**——先收敛再自检：把两处规则引擎（tool-level 3 条 + git-diff 24 条）合并为单一引擎（一套定义、两种触发时机），再给规则本身装上**自测**——每条规则强制携带 `match` / `not_match` 正负样例，加载时断言 fail-closed（规则写错立刻爆，不靠人记），FAIL 报文强制附替代建议、多规则命中取最严。A24 交付物落点规则是自测 schema 落地后的**首个新规则**：出生即带正负样例，不留旧账。

## 一、双规则引擎统一（2026-09-08 排入 · 消除 ARCHITECTURE 悬空承诺）


> **形态归属**：`[非功能]`（重构——两处规则引擎收敛为一，不新增能力面）｜ —
>
> 📋 **背景**：`engine/rules/`（tool-level 规则，3 条）与 `engine/audit/src/rules/`（git-diff 规则，24 条）历史上并行维护，均含 secret-leak 检测，存在行为不一致风险。v1.3.0 已部分收敛（正则模式共享至 `@sofagent/core`），但**规则引擎仍是两套**，ARCHITECTURE 记载「统一排期见 ROADMAP」而 ROADMAP 此前无此单元格——属悬空承诺，本版补上落点。
>
> 统一方式：以 `ruleType` 字段在两种触发模式下复用同一套规则定义（tool-level 在调用前拦截、audit 在 commit 后审计），收敛为单一规则引擎 + 两种执行时机。
>
> **纪律外延（2026-09-08 补）**：判定规则**只有一个事实源**。企业侧若另建判定点（自建模型网关/代理做流量侧 PII 过滤与敏感度分流），必须集成本引擎的同一套规则与检测器（v1.4.9 第八章检测器插槽即可嵌入组件），**不得另起一套**——每多一处独立实现，就是一次口径分裂风险。

### 交付

| 组件 | 能力 |
|------|------|
| **单一规则引擎** | 两套规则定义合并为一套（含 `ruleType` 触发时机标记），tool-level 与 git-diff 两种执行模式共用 |
| **行为一致性回归** | 统一前后对同一输入的判定结果必须一致（回归锁，防统一过程引入行为漂移） |
| **ARCHITECTURE 同步** | 「已知技术债：双规则系统重叠」段改写为已排期指向本版 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/audit/src/rules/` | 修改 | 吸收 tool-level 规则，统一规则定义与 `ruleType` |
| `engine/rules/` | 修改 | 收敛为触发时机适配层（不再独立维护规则正则） |
| `engine/audit/src/__tests__/rules-unified.test.ts` | 新建 | 单测（两套触发下判定一致 / secret-leak 行为不漂移） |

### 验收标准

- [ ] tool-level 与 git-diff 两种触发共用同一套规则定义
- [ ] 统一前后 secret-leak 等重叠规则判定结果一致（回归锁）
- [ ] ARCHITECTURE 技术债段改写为明确排期指向（无悬空承诺）
- [ ] `npm test` 全绿

## 二、审计规则自测 schema（Codex execpolicy 启发 · 2026-09-15 用户拍板排期本版）


> **形态归属**：`[主干]`（判定·规则自测正负样例）｜ L1 关档
>
> 📋 **研究收编**（OpenAI Agents API 公测 + codex 仓源码核验，2026-09-15）：[codex-rs/execpolicy](https://github.com/openai/codex/blob/main/codex-rs/execpolicy/README.md) 把「规则正负成对自检」做成**引擎级机制**——每条 prefix_rule 强制携带 `match`（必须命中的样例）与 `not_match`（必须不命中的样例）字段，**加载时即校验**（官方原话 "think of them as unit tests"）：规则写错（锚串消失/误命中）立刻爆，不靠人记。本仓「假门禁五形态」反模式（正向探针空转/锚串消失静默跳过/门禁块吞退出码）一直靠纪律级 checklist 防（回归清单「自检/守卫正负成对」条目）——本章把该纪律升级为 schema 强制。与第一章天然衔接：**双规则统一后的单一规则定义正是携带正负样例的最佳载体**（一套定义，两种触发时机，样例同源）。

### 交付

| 组件 | 能力 |
|------|------|
| **规则 schema 扩展** | 规则定义新增 `examples: { match: string[], not_match: string[] }` 必填字段——每条规则强制声明「必须命中」与「必须不命中」的输入样例（静态定义类规则可豁免，豁免须显式标记） |
| **加载时断言** | 规则集加载时逐条跑样例断言：match 样例未命中 / not_match 样例误命中 → 拒绝加载并报规则 id（fail-closed，对齐 execpolicy "validated at load time"） |
| **FAIL 报文替代建议** | forbidden/FAIL 级规则报文强制携带修复建议字段（对齐 execpolicy「forbidden 必附 justification 替代建议」——如 "Use `jj` instead of `git`"）；b-fix 轮次可直接消费，降低审查-修复循环轮数 |
| **多规则裁决语义** | 同一输入命中多条规则时取最严（forbidden > warn > allow，对齐 execpolicy "strictest severity across all matches"）——裁决语义显式化并配单测 |
| **导出联动** | [v1.5.2 第二章](./v1.5.2.md) `ruleset_export` 的训练消费元数据（违规样例字段）与本章 `examples` 同源——导出即正负样例对，训练管线侧消费零转换（SFT 对/reward 判据直接用） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/audit/src/rules/` | 修改 | 规则定义加 `examples` 字段（24 条默认规则逐条补正负样例） |
| `engine/audit/src/rule-loader.ts`（或等效加载入口） | 修改 | 加载时样例断言 + fail-closed 拒载 |
| `engine/audit/src/__tests__/rule-selftest.test.ts` | 新建 | 单测（正样例命中/负样例不命中/锚串删除后拒载/最严裁决） |

### 验收标准

- [ ] 24 条默认规则每条含 match/not_match 样例（或显式豁免标记）
- [ ] 加载时断言生效：注入「锚串被删」的规则集 → 拒绝加载非 0 退出（故障注入实证）
- [ ] FAIL 级报文携带替代建议
- [ ] 多规则命中取最严有单测锁

## 四、doctor 修复闭环（Omarchy refresh 模式启发 · 自探索方向收编 · 2026-08-31 用户拍板）


> **形态归属**：`[主干]`（完整性检测判定）**+ `[通道]` 成分**（refresh 的备份 / 重置执行动作，产出备份目录，四问①答「是」）｜ L1 关档（旧包移除属退役动作，归可拔契约执行面）
>
> 📋 **探索方向表收编**：「检查→一键修复」的自然演进——doctor 已有 repairHint 提示（v1.4.3 补 Ontology 完整性检查后检查项已稳定），本版补 refresh 模式「备份+一键重置到默认」。对标 `omarchy refresh`（自动备份时间戳 + 拷贝默认 + 按需重启）。

### 交付

| 组件 | 能力 |
|------|------|
| **doctor refresh** | 检查发现可修复项 → `sofagent doctor --refresh`：自动备份当前配置（时间戳目录）→ 重置到默认 → 报告前后 diff——修复动作全程审计留痕 |
| **备份保留** | refresh 备份目录保留最近 N 份（默认 3），可回滚 |
| **旧包退役收尾** | 移除 `@sofagent/evolve` 的 workspace 引用（v1.4.8 已 npm deprecate 并指向 `@sofagent/evolve`）——**breaking 收尾，随本项「备份+重置」语义一并收**：移除前先经 refresh 备份，异常可回滚。承接关系双向在位（v1.4.8 ⑩-2 声明「将在 v1.5.2 移除」——该承诺落点经地基期拆版顺延至本版，本章为落地点） |

### 验收标准

- [ ] `doctor --refresh` 一键修复可用（备份 → 重置 → diff 报告）
