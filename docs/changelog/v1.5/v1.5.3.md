## 二、审计结论失效语义（Codex Guardian 启发 · 2026-09-16 用户拍板排期本版）

> **形态归属**：`[主干]`（判定·失效词汇表与触发）｜ L1 关档
>
> 📋 **研究收编**（codex-rs [guardian/](https://github.com/openai/codex/tree/main/codex-rs/core/src/guardian) 源码核验）：Codex 给审查结论定义了一套**失效条件**（`GuardianReviewReason`）——`FreshRequired`/`StaleScore`/`AuthorizationChanged`/`IncompatibleCompaction`/`ElevatedRisk`/`ScoringFailure`。本仓现状：审计结论（history.jsonl）与 HITL 授权一经产生即视为永久有效，下游消费方无法判断「这条结论还能不能信」。与 [v1.5.4 第二章](./v1.5.4.md) 自测 schema 同属「审计模块自我完善」主题：那里保证规则**加载时**是对的，本章保证结论**消费时**还是对的。
>
> ⚠️ **马鞍边界（四问过筛已过，边界在此）**：只吸收「失效原因词汇表」与判定逻辑——属共享账本层豁免（词汇表不是执行器）。**不吸收** Guardian 的 reviewer pool / 同步审查会话 / 预热机制（那是审查的马场：换 fresh-eyes 或任何外部审查器，本失效语义价值不受损）。

### 交付

| 组件 | 能力 |
|------|------|
| **失效原因词汇表** | 审计结论 schema 新增 `invalidationReason` 字段（枚举：授权变更/压缩不兼容/风险升级/分数过期/需新鲜结论），对齐 Guardian 六原因语义取子集 |
| **失效判定钩子** | 三个事件触发失效标记：①授权或白名单配置变更（AuthorizationChanged）②压缩/摘要事件发生（IncompatibleCompaction——对应 L2 工具输出总结、加载链压缩）③后续轮次风险升级（ElevatedRisk——同一对象后续被更严规则命中） |
| **下游消费语义** | 带失效标记的结论不作为后续判定的输入（fresh-eyes 审查输入、HITL 免检依据、治理 KPI 统计均须过滤）——「过期结论不当新证据用」 |
| **留痕不删除** | 失效结论保留原文 + 失效标记（对齐 HMAC 链只追加不删改——失效是标记不是抹除） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/audit/src/decision-schema.ts` | 修改 | 结论 schema 加 `invalidationReason` 枚举字段（可选，缺省=有效） |
| `engine/audit/src/invalidation.ts` | 新建 | 三钩子：授权变更/压缩事件/风险升级 → 标记既有结论失效 |
| `engine/audit/src/__tests__/invalidation.test.ts` | 新建 | 单测（三触发路径/失效结论被下游过滤/原文保留） |

### 验收标准

- [ ] 失效原因词汇表落地（schema 字段 + 枚举值）
- [ ] 三触发钩子生效：授权变更/压缩事件/风险升级 → 既有结论标记失效
- [ ] 失效结论被下游过滤（fresh-eyes 输入/HITL 依据/KPI 统计）
- [ ] 失效结论原文保留（HMAC 链不破坏）
- [ ] `npm test` 全绿
