## 一、SMB 场景审计扩展（数据处理/报表生成）

> 📋 **探索方向表收编**：审计从代码开发扩展到数据处理/报表生成——SMB（中小企业）没有代码仓库，但报表生成/数据清洗同样需要审计（数字对不对/来源可溯/口径一致）。

### 交付

| 组件 | 能力 |
|------|------|
| **数据产物审计规则** | 新审计维度：AI 生成报表/数据产物时审计——数值一致性（合计/明细勾稽）、来源可溯（每个数字可回溯源数据）、口径一致（同名字段同口径） |
| **DecisionKind 扩展** | 新增 DATA_PRODUCT 决策类型（data 产物审计的决策分类） |
| **SMB onboarding 模板** | FDE 模板库新增 SMB 场景模板（无代码仓库的纯数据节点部署路径） |
| **治理 KPI 复用** | v1.5.0 治理 KPI 面板对 SMB 场景同样可用（审计覆盖率/问题率照常统计） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/audit/src/rules/data-product-rules.ts` | 新建 | 数据产物审计规则（勾稽/溯源/口径） |
| `engine/core/src/decision-log.ts` | 修改 | DecisionKind 加 DATA_PRODUCT |
| `FDE/templates/smb-onboarding.md` | 新建 | SMB 场景 onboarding 模板 |

### 验收标准

- [ ] AI 生成数据产物触发数据审计（勾稽/溯源/口径三类规则）
- [ ] DATA_PRODUCT 决策类型落 decision-log

- [ ] 治理 KPI 面板覆盖 SMB 场景

## 四、FDE 进场记忆目录工程化（自探索方向迁入 · 2026-08-29 用户拍板）

> 📋 **探索方向表迁入**（fdeops-arch 启发）：每客户一个 `data/fde-sessions/<client-id>/` 目录 + 10 文件各司其职 + session-stop 自动捕获——方法论已在 FDE/GUIDE §5.8b 记录，工程化（自动捕获 hook + 跨 session 恢复）原与 v1.3.5 instinct 自动进化合并评估，现落本版。

### 交付

| 组件 | 能力 |
|------|------|
| **session 目录工程化** | `data/fde-sessions/<client-id>/` 标准 10 文件结构自动初始化（fde_interview 首次调用触发） |
| **session-stop 自动捕获** | session 结束自动捕获状态文件（对齐 v1.3.7 load-chain hook 模式） |
| **跨 session 恢复** | 新 session 启动时检测既有客户目录 → 自动恢复上下文（FDE 进场记忆） |

### 验收标准

- [ ] fde_interview 首次调用自动初始化客户目录（10 文件结构）

## 五、运行时 should-run 判定链（自探索方向迁入 · 2026-08-29 用户拍板）

> 📋 **探索方向表迁入**（Loop Engineering 控制面启发 · 2026-08-19 新增）：每轮开工前统一问一遍的判定链：健康 → 人审 gate → 证据等待 → 专注等待 → 配额，全部通过才执行——断路器（v1.3.7）两态的丰富形态。

### 交付

| 组件 | 能力 |
|------|------|
| **五问判定链** | 节点执行前统一五问（健康/人审 gate/证据等待/专注等待/配额），任一不通过则挂起等待——与 v1.5.2 事件总线的派发前置检查集成 |
| **挂起原因可查** | 判定不过时挂起原因落 decision-log（对齐「只提示不阻断」——挂起非失败，条件满足自动恢复） |

### 验收标准

- [ ] 五问判定链集成事件总线派发前置
- [ ] 挂起原因可查（decision-log 记录）
- [ ] 条件满足自动恢复执行
- [ ] `npm test` 全绿
