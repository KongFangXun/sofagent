## 定位


> 🔍 **审计模块 · 规则引擎统一与自测**——先收敛再自检：把两处规则引擎（tool-level 3 条 + git-diff 24 条）合并为单一引擎（一套定义、两种触发时机），再给规则本身装上**自测**——每条规则强制携带 `match` / `notMatch` 正负样例，加载时断言 fail-closed（规则写错立刻爆，不靠人记），FAIL 报文强制附替代建议、多规则命中取最严。A24 交付物落点规则是自测 schema 落地后的**首个新规则**：出生即带正负样例，不留旧账。**同版补两处规则面地基**：判决类记录**成对完整**的机械扫描（只记单边即报红——补上「无记录」这一盲区）与审计**范围语义一等公民化**（规则从 `AuditScope` 取输入、不再各调各的 git）。

## 一、双规则引擎统一（2026-09-08 排入 · 消除 ARCHITECTURE 悬空承诺）


> **形态归属**：`[非功能]`（重构——两处规则引擎收敛为一，不新增能力面）｜ —
>
> 📋 **背景**：`engine/rules/`（tool-level 规则，3 条）与 `engine/audit/src/rules/`（git-diff 规则，24 条）历史上并行维护，均含 secret-leak 检测，存在行为不一致风险。v1.3.0 已部分收敛（正则模式共享至 `@sofagent/core`），但**规则引擎仍是两套**——本版增量即引擎合并本身。
>
> ⚠️ **存量已就位（悬空承诺已收口）**：`docs/ARCHITECTURE.md` 技术债段与设计依据段均已直指「统一为单一规则引擎已排期本版第一章」，ROADMAP 亦有对应单元格。故本章不承担「补上落点」的动作，验收第 3 条实为**存量核验**（跑一次确认零回归即可，不新建改写动作）。
>
> 统一方式：以 `ruleType` 字段在两种触发模式下复用同一套规则定义（tool-level 在调用前拦截、audit 在 commit 后审计），收敛为单一规则引擎 + 两种执行时机。
>
> **纪律外延（2026-09-08 补）**：判定规则**只有一个事实源**。企业侧若另建判定点（自建模型网关/代理做流量侧 PII 过滤与敏感度分流），必须集成本引擎的同一套规则与检测器（v1.4.9 第八章检测器插槽即可嵌入组件），**不得另起一套**——每多一处独立实现，就是一次口径分裂风险。
