## 定位


> ⚡ **执行模块 · 全节点执行状态机**——节点内部从「消息历史滚雪球」改为「结构化状态机」：每步只带 P（不可变技能说明）+ Σt（结构化状态 JSON）+ ot（最新观察），模型输出 ΔΣt 由运行时代码确定性合并（Σt+1 = Σt ⊕ ΔΣt），推理轨迹合并后即弃——单步 prompt O(1)、累计 token O(T)。**sofagent 的独有底气**：wrapToolCall 运行时审计在每步动作发生时实时落记录——**轨迹可弃、行为可溯**。

> 📋 **文档连带（2026-09-26 预普查）**：[fde-activation-chain](../../guides/fde-activation-chain.md) Phase 2/3 的旧执行状态设计（LangGraph State 三字段 currentOrder/nodeStatus/exceptions + interrupt_before HITL 四步描述）与本机制冲突——施工时同批改写为 SKILL.state 三输入形态

> ⚡ **执行模块 · Tool search 按需加载**——工具定义不再全量进上下文：按任务描述语义检索召回 top-K + 按节点域过滤注入子集 + 执行中可分步追加加载，并以「命中被实际调用的比率 + 工具注入 token 曲线」给出「按需加载是否值得」的实证数据。**与 [v1.5.4](./v1.5.4.md) 同属调用侧上下文供给**：路由决定「用哪个模型」，tool search 决定「带哪些工具」。

> ⚡ **执行模块 · 多 Agent 阵型调度**——把 [v1.4.8](../v1.4/v1.4.8.md) 交付的阵型**库面**接进建队与派发路径：`team.yml` 声明 `formation: <name>`（`members` 可缺省）⇒ 建队即按阵型模板装配成员拓扑 + 交接边落 `formation.json`，交接事件挂 decision-log。**与本章一的关系**：章一管「单个节点怎么执行」，本章管「多个 Agent 按什么拓扑协作」——同属执行面；**兜底**：未声明阵型走既有全量成员路径，行为零变化。

## 一、全节点执行状态机（SKILL.state 机制收编 · arXiv:2608.26263 · EMNLP · 2026-09-03 用户拍板：全面推广不试点）


> SKILL.state 把技能执行从聊天记录改成状态机：每步模型只收 P（不可变技能说明）+ Σt（结构化状态 JSON）+ ot（最新观察），输出推理轨迹 Rt / 状态补丁 ΔΣt / 动作 at；运行时确定性校验合并 Σt+1 = Σt ⊕ ΔΣt 后**推理轨迹永久丢弃**——单步 prompt O(1)、累计 token O(T)。论文实测：16.2 倍 token 压缩（1,062,387→65,408）、抗噪 ≥0.97（ReAct 崩到 0.53）、状态恢复零步数、InterCode CTF 54.2%（+7.8 且省 60.4% token）；**预算对齐控制实验实锤赢在结构化不在压缩**（同预算下：滑窗截断 0.18 / LLMLingua 0.22 / SKILL.state 0.94）。
>
> **sofagent 的增量空间在节点内部**：编排层（LoopGraphState + artifacts 浅合并 reducer）已是 sofagent 版的 Σt⊕ΔΣt，checkpoint 已支持状态恢复；但 `node-executor.ts` 用 createReactAgent，节点内部是消息历史式滚雪球（无 trimMessages），长任务 token O(T²) 与上下文中毒风险与论文基线相同。
>
> **sofagent 天生的落地底气**：wrapToolCall 运行时审计在每步动作发生时实时落记录——推理轨迹可弃而行为仍可溯，**轨迹可弃、行为可溯**，这是论文没有、sofagent 独有的审计前提。
>
> **全面推广判据（2026-09-03 用户拍板，不做单点试点）**：① 风险已被 sofagent 自己消解——wrapToolCall 审计通道在位，轨迹丢弃的审计风险天然兜底，无需靠试点验证安全性；② 论文已在三个基准族（仓库管理 SkillExecBench/InterCode CTF/τ-Bench）跨域验证协议通用性，「先试一个域再推广」的验证价值已被论文做完；③ 兜底不靠试点靠**全局降级开关**——所有节点默认带降级路径，任何节点出问题单独回退消息历史式，不影响其他节点，等效于每节点自带「试点失败保险」，且比先试一点的方案更快拿到全量收益。

>
> **形态归属**：`[主干]`（账本·确定性合并）｜ **不可拔**（状态不可复现则审计无锚，属命脉件）
### 交付

**执行协议规范（SKILL.state 采纳形态——先定协议，再写代码）**

| 协议要素 | sofagent 落地形态 |
|------|------|
| **P（技能说明，不可变）** | 现有 system prompt / SKILL.md 注入内容，执行期只读恒定 |
| **Σt（执行状态 JSON）** | 每个节点类型定义结构化状态（见下方基础 schema + 领域扩展），随执行逐步演化，是唯一跨步携带的记忆 |
| **ot（最新观察）** | 上一步工具返回（截断至 token 预算内），只看最新一条，历史观察不进 prompt |
| **ΔΣt（状态补丁）** | 模型每步随动作输出 JSON Patch 子集（`{op: add/remove/update, path, value}`），**由运行时代码执行合并** Σt+1 = Σt ⊕ ΔΣt，schema 校验不过即拒绝该补丁——状态合并不靠模型自觉，靠代码保证 |
| **Rt（推理轨迹，即弃）** | 步内 CoT 完整保留供本步推理，状态转移验证通过后**不进下一步 prompt**；丢弃前先落审计摘要（动作 + ΔΣt + 因果边）进 wrapToolCall 通道 |
| **降级路径（全局开关）** | 每节点带 `executionMode: stateful | legacy` 配置，补丁连续校验失败 N 次自动降级 `legacy` 并审计告警；环境变量 `SOFAGENT_STATEFUL_EXEC=off` 一键全回退——单节点故障不扩散，协议层 bug 不卡死任何任务 |

**基础状态 schema（全节点通用底座，六字段）**：

```json
{
  "goal": "本节点任务目标",
  "done": ["已完成步骤（带结果摘要）"],
  "todo": ["待办步骤"],
  "facts": ["工具观察到的关键事实（不含原始输出）"],
  "files": ["已改动文件路径"],
  "blockers": ["阻塞项与绕行决策"]
}
```

**节点类型 schema 扩展表**（基础六字段 + 各节点领域字段）：

| 节点 | 领域扩展字段 | 说明 |
|------|------|------|
| engineer | `tests: {pass, fail, skipped}`、`reviewComments: [{file, line, status}]` | 代码修复循环——测试状态与审查意见回链 |
| checker | `checkRuns: [{rule, verdict, evidence}]`、`falsePositives: []` | 审查循环——规则判定留状态不留原始日志 |
| reviewer | `issuesBySeverity: {p0, p1, p2}`、`coveredFiles: []` | 审查循环——覆盖度与问题分级实时账 |
| refine-agent | `qualityScores: [{round, score}]`、`triedStrategies: []` | 优化循环——已试策略防重复（对齐 failure-ledger 精神） |
| 通用长任务 | 基础六字段即可 | 文档批处理/数据处理等默认形态 |

**推广范围**：`node-executor.ts` 全部 createReactAgent 节点（engineer/checker/reviewer/parallel_wave 单元）+ refine-agent 优化循环 + loop-agent driver——**所有长任务节点一次性切换到执行协议**，短平快节点（单次工具调用）不改造（改造收益低于成本）。

| 组件 | 能力 |
|------|------|
| **执行状态机执行器** | `node-executor.ts` 改造为协议执行器：每步产出 ΔΣt，代码确定性合并，下一步 prompt 只带 P+Σt+ot，推理轨迹合并后即弃；`executionMode` 双模式在位（stateful 默认 / legacy 保底） |

> **形态归属**：`[非功能]`（工程治理·依赖面收口——dsh-only 裁剪安装不背编排依赖树）｜ L1 关档
>
> 📋 **背景与立场**：执行后端工厂默认 `preferred='dsh'`，DSH 可用时全程不 import LangGraph（`execution-backend.ts` 双适配器 + 动态 import）——但 `@langchain/langgraph` 仍声明在 orchestrator `dependencies`，dsh-only 裁剪安装白背一棵依赖树。**编排层立场不变**：StateGraph DAG 结构不换——确定性审计（git diff 硬证据 + HMAC 链 + 波次卡关）依赖预先画好的 DAG，DSH 事件驱动无显式执行路径（[ARCHITECTURE](../../ARCHITECTURE.md) §二「为什么不把整个编排层也换成 DSH」）。本项只治理**依赖面**，不改编排引擎。

### 交付

| 组件 | 能力 |
|------|------|
| **optionalDependencies 降级** | `@langchain/langgraph` 自 orchestrator `dependencies` 移至 `optionalDependencies`（对齐 root F-18 惰性加载先例：运行时动态 import 的跨包依赖声明为 optional，裁剪安装不断言） |
| **缺失语义显式化** | LangGraph 缺失时两条主线路径**明确报错含指引**（非 stack trace 静默）：① `loop` 子命令（StateGraph 节点级流转 + checkpoint resume）② 激活链 Phase 2/3 编排（buildTopology）——文案指引「安装 @langchain/langgraph 或使用 DSH 执行后端」 |
| **dsh-only 路径实证** | DSH 在场 + LangGraph 缺失的裁剪安装态：执行后端主力路径 + 审计 + 插件全绿（依赖树实测对账，零 LangGraph import） |
