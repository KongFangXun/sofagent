## 一、经验池接训练管道（instinct→数据集→TrainChannel · 打通 Data-RSI 断链）

> **形态归属**：`[主干]`（判定·数据入池资格与血缘锚点）**+ `[通道]` 成分**（数据集构造与通道提交的执行动作）｜ L1 关档
>
> 📋 **缺口实测（2026-09-19）**：`engine/train/src/dataset-builder.ts` 只吃外部 CSV/XLSX/JSON/文本，**不消费 instinct 池**——Data 面与 Model 面各自为政，一体机数据飞轮（session→分拣→脱敏→数据集→训练→灰度）在「数据集」一环断了内部供给。行业对位：Meta-RSI 的 Data-RSI 是「三算子的共同底料」，其产出同时喂 Harness-RSI 与 Model-RSI。

### 交付

| 组件 | 能力 |
|------|------|

## 二、进化准入判据（检验-生成差距 · 验证便宜的域才自动进化）

> **形态归属**：`[主干]`（判定·准入门）｜ **不可拔**（进化准入门是防「放养式自进化」的缰绳，拔掉它进化链失去安全边界）
>
> 📋 **研究收编**（行业综述定律）：自提升仅在「验证比生成便宜」的域成立——代码/数学有测试套件当免费验证器，开放式写作验证与生成同价、循环空转。对位 sofagent：空房间错误分流器已分「客观错误 vs 主观偏好」，本章把该判据从归因层上移到**准入层**——evolve/skill 晋升在启动前先判定目标域有没有廉价验证器。

### 交付

| 组件 | 能力 |
|------|------|
| **域验证器登记** | 技能/进化目标域声明其验证方式：`deterministic`（测试/编译/断言——廉价）/ `model-judge`（LLM 评分——有成本）/ `human-only`（开放式——必须 HITL）三档 |
| **准入判定** | evolve 晋升与 instinct 注入前按域档位分流：deterministic→全自动走 eval-gate；model-judge→评分 + 采样人审；human-only→强制 HITL，无自动晋升 |
| **fail-closed 语义** | 域未登记验证方式 ⇒ 按最高档（human-only）处理——宁可不进化，不盲目进化 |
| **进化成本门禁** | 进化循环（出题/考核/晋升/训练构造）纳入 v1.4.8 成本 quota 事前门禁——改进本身也烧钱（行业实证：循环又贵又慢是调度器改进的动因）；超预算按既有 WARN/HARD 双模式处置，不做第二套预算机制 |
| **收益停滞检测** | 连续 N 轮进化的 eval 提升低于阈值 ⇒ 停止自动进化并转人审（行业实证：改进存在边际效应递减）——**检测与提示，不自动决策该改什么**（那是调度器的活，本版不做） |

|------|------|------|
| `engine/evolve/src/domain-verifier-registry.ts` | 新建 | 域档位登记 + 准入判定纯函数 |
| `engine/evolve/src/__tests__/domain-verifier.test.ts` | 新建 | 三档分流 / fail-closed / 未登记默认最高档单测 |

### 验收标准

- [ ] 域验证器三档登记可配置（deterministic/model-judge/human-only）
- [ ] 准入判定按档位分流（human-only 域零自动晋升）

## 三、三层晋级判据（注入租用 → skill 半持久 → 微调摊销 · 显式化）

> **形态归属**：`[主干]`（判定·晋级规则与台账）｜ L1 关档
>
> 📋 **研究收编**（两 substrate 成本模型）：context 更新「每次推理重付」（租用——注入即付 token），权重更新「一次付清」（摊销——训练一次推理免费），skill 介于两者（加载链常驻=半持久）。三条路已事实存在（instinct 注入 / evolve 晋升 / TrainChannel 微调），但没有显式晋级判据——何时从注入升 skill、从 skill 升微调，目前靠人拍。行业对照：Meta-RSI 的调度器先 Harness 后 Model（「先改便宜的，高频重要规则才内化」）。

### 交付

| 组件 | 能力 |
|------|------|
| **晋级判据纯函数** | 输入：条目注入频次 × 存续期 × 验证态（考核通过率/eval 分数）；输出：`keep-inject` / `promote-skill` / `promote-train` 三态建议 |
| **晋级台账** | 每次晋级判定落 decision-log（当前层→建议层 + 判据快照）——与 v1.4.5 skill-impact 台账同源扩展 |
| **人审门** | promote-train 建议**只提示不执行**（对齐「只提示不阻断」）——进 FDE 确认队列，确认后才走第一章管道 |

| **进化收益曲线** | 「做 1000 次任务后是否比第一次更强」的量化落地（PHILOSOPHY 既有承诺）：四指标可定义可量化可记录——**任务通过率趋势**（acceptance/ab-history 既有数据源）/ **错题本复发率**（同类失败重犯间隔）/ **skill 复用率**（调用次数 / 产生次数）/ **纠偏介入率**（人工干预频次趋势）。指标定义与记录属本章判定面（数据从既有台账取，不造新数据源）；曲线呈现挂 v1.5.0 治理 KPI 面板（复用六卡框架，不另做 UI 面） |

## 四、出题考核器（instinct 反向生成验证题 · 双成功才入池）

> **形态归属**：`[主干]`（判定·考核规则与入池资格）｜ **不可拔**（考核是经验池的质检门，拔掉等于未经检验的经验直接进训练数据——比放养式自进化更糟）
>
> 📋 **研究收编**（Meta-RSI Data-RSI 环节）：归因→出题→考核三步——按场景/步骤/难度自己写题与答案，只看题尝试复现，「答案成立 + 复现成功」双成功才进全局经验池。对位 sofagent：instinct 链有提取与置信度评分，**缺出题考核环节**——passRate 是被动统计（历史通过率），考核是主动验证（专门构造复现场景）。

### 交付

| 组件 | 能力 |
|------|------|
| **出题器** | 达阈值 instinct 条目反向生成考核题（按 pattern 构造复现场景 + 期望结果），题目落考核队列 |
| **考核执行器** | 只看题不看答案跑复现（deterministic 域跑实际命令/测试；model-judge 域跑评分；human-only 域出题给人） |
| **双成功入池** | 答案校验 + 复现成功双通过 ⇒ 条目标记 `verified` 进经验池（第一章导出器只收 verified 态）；任一失败 ⇒ 降置信度并记失败原因 |
| **与既有链衔接** | 考核态作为 scorer 置信度的新输入维（verified 加权 / failed 减权） |

## 六、自进化写面的审计覆盖（prompt / memory 两面补盲 · RSI 治理的地基章）

> **形态归属**：`[主干]`（判定·留痕——自进化变更面的审计取证）｜ **不可拔**（审计地基：拔掉它，Agent 改自己的 prompt 与 memory 就彻底逃逸审计视野，RSI 治理失去立足点）
>
> 📋 **缺口实测（2026-09-19）**：审计地基是「不信任自我报告，只看 git diff 硬证据」（[ARCHITECTURE](../../ARCHITECTURE.md) 核心叙事），v1.5.1 规划第二通道（调用意图 + 结果文本）。但 RSI 的四个可写面里——**权重面**（v1.4.4 manifest + sha256 验签）与 **skill 面**（eval-gate 收编门 + v1.4.9 执行时 skill 快照）已有覆盖，**prompt 面与 memory 面完全在审计视野外**：Agent 改了自己的 system prompt、往记忆里写了一条「经验」，不留任何可举证的变更记录——**自我改进最大的两个写面恰恰是我们唯一没有硬证据的地方**。行业对位：Meta-RSI 把可写面明确为 data/harness/model 三类并要求保护面独立于所有写面——本章是「保护面如何真的看得见写面」的工程答案。

### 交付

| 组件 | 能力 |
|------|------|
| **写面变更留痕** | prompt 面（SKILL.md / fde.md / overrides 配置变更）与 memory 面（think.md / knowledge / 记忆事实写入）的每次变更落一条可举证记录：变更前后值摘要 + 发起人（Agent 实例 id / 人）+ 触发来源（自我改进 / 人工 / 系统）+ 时间戳 |
| **写面 diff 语义** | 为两类非代码写面定义 diff 契约（配置面按字段级 before/after；记忆面按条目级新增/修订/失效），与既有 git diff 规则并列为第三通道——**规则判定逻辑不变，只扩输入面**（对齐 v1.5.1 双通道的同款纪律） |
| **与改进链绑定** | 第三、四章的晋级/考核动作自动产生写面变更记录（改了什么 → 留痕自动发生，不靠调用方自觉）；无留痕的写面变更 ⇒ 回退并告警（fail-closed） |

## 七、能力基线版本线（四层状态快照 · 出事能回答「当时它是怎么做事的」）

> **形态归属**：`[主干]`（留痕·能力状态可复现基线）｜ L1 关档
>
> 📋 **缺口实测（2026-09-19）**：v1.4.9 已交付**执行时** skill 快照（单次执行级可复现——执行前打包、执行后清理），但缺**跨时间**的能力基线：Agent 进化三个月后与当初判若两人，出事故时无人能回答「当时的它是哪个状态」。审计的可复现要求（举证要能还原当时条件）在 RSI 时代需要一条**能力版本线**，而不是只靠单次执行快照。

### 交付

| 组件 | 能力 |
|------|------|
| **基线快照** | 每次能力变更（晋级/回退/写面变更）前打包四层状态：prompt 配置版本 + skill 集合版本 + memory 事实锚点 + 权重 manifest 引用——形成可寻址快照 id |
| **版本线** | 快照按时间成链（前驱指针），任一时点可回答「当时 Agent 的完整能力状态」；与 v1.4.9 执行级快照分工：执行级管单次可复现，本版管跨时间可追溯 |
| **基线回滚** | 按快照 id 回滚四层状态（复用既有 snapshot/restore 语义，不新建回退机制）；回滚动作本身落 decision-log |
| **举证面** | 快照 id 可被引证记录引用（「事故发生在基线 X 下」——举证不止于代码版本，而是能力版本） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/evolve/src/baseline-snapshot.ts` | 新建 | 四层状态打包 + 版本链 + 回滚 |
| `engine/evolve/src/__tests__/baseline-snapshot.test.ts` | 新建 | 快照完整性 / 版本链前驱 / 回滚可举证单测 |

### 验收标准

- [ ] 能力变更自动生成四层基线快照（可寻址 id）
- [ ] 版本线可回溯任一时点能力状态
- [ ] 按快照 id 可回滚四层状态（复用既有机制）且回滚留痕
- [ ] 举证记录可引用快照 id（能力版本可举）
- [ ] `npm test` 全绿

## 八、验证器自身老化检测（元验证 · 进化越久门越松的反向治理）

> **形态归属**：`[主干]`（判定·验证集有效性）｜ L1 关档
>
> 📋 **缺口实测（2026-09-19）**：进化循环靠 eval 验证集当门，但**验证集自己会老化**——项目既有叙事已点破同一现象（[guides/loop-development](../../guides/loop-development.md)「测量衰退：测试数据老化 95% 通过率是假象」）。RSI 时代这个风险被放大：进化循环持续跑，样本被反复消费，通过率越来越好看而能力未必提升——**越进化，门越松**。行业对位：验证器必须独立于写面，但「独立」不等于「永远有效」——验证器自身也要被检验。

### 交付

| 组件 | 能力 |
|------|------|
| **验证集老化指标** | 每组验证集记「样本消费次数 / 通过率趋势 / 上次人工复检时间」，形成老化度（对齐 v1.5.4 能力面五维健康度同款思路：低价值技能能退役，老化验证集也要能退役） |
| **收益归因对照组** | 进化收益的**反事实基线**：进化开启前先冻结一份对照配置（不改 skill / 不注入 / 不训练），收益曲线四指标同时跑「进化组 vs 对照组」——差值才是进化的净贡献（防「环境变好了」冒充「进化有效」：任务变简单、模型升级、季节波动都会让通过率上涨，无对照的收益声明不可信）。对照组按周期轮换重置（防止对照组本身过时），轮换留痕 |
| **验证漂移三态** | 考核失败时区分「真失败 vs 环境漂移」（对齐 checkHistoryChainDetailed 三态先例——`tampered`/`unverifiable`/`insufficient-history`）：考核环境本身变了（依赖版本/路径/权限）导致复现失败 ≠ 经验失效。漂移态不降经验置信度、不触发回退，但必须告警并标记待环境复核——**宁可挂起，不误杀好经验** |
| **老化告警** | 通过率连续上升但真实任务指标未改善（或消费次数超阈值且长期无复检）⇒ 告警并建议冻结该验证集的自动晋升资格——**只提示不阻断**（对齐「只提示不阻断」铁律） |
| **验证集复检入口** | 提供人工复检通道：标记样本失效/新增样本，复检动作留痕（与 v1.5.2 审计结论失效语义同族——失效的不当新证据用） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/evolve/src/validator-health.ts` | 新建 | 老化度计算 + 告警 + 复检标记 |
| `engine/evolve/src/__tests__/validator-health.test.ts` | 新建 | 老化度 / 告警阈值 / 复检留痕单测 |

### 验收标准

- [ ] 验证集老化度可计算（消费次数 / 通过率趋势 / 复检时间）
- [ ] 收益归因对照组在位（进化组 vs 对照组差值 = 净贡献；轮换留痕）
- [ ] 考核失败三态可分（真失败 / 环境漂移 / 证据不足——漂移不误杀、挂起告警）
- [ ] 老化告警只提示不阻断（建议冻结自动晋升资格，交人决策）
- [ ] 验证集可人工复检且复检留痕
- [ ] `npm test` 全绿
