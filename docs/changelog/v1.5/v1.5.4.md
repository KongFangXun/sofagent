## 四、能力面使用率治理（技能 SkillOps 五维 + 工具使用率遥测 · 自 v1.5.2 后移 · 2026-09-15 / 09-16 用户拍板）

> 📋 **研究收编**（Google《Towards a Systems Foundation for Agentic Skills》arXiv:2608.29596）：技能库存储借鉴 OS 虚拟内存思想，SkillOps 提出五维技能库健康度治理——**剪除低价值技能、偿还「技能技术债」**。本仓现状：SKILL 库只进不出（instinct→skill 单向晋升），无退役机制——技能熵只增不减。综述同时实证「技能效用相当脆弱」（SkillsInWild 3.4 万技能测量）+「弱模型进化技能对强模型负迁移」（WikiSkill 4B 技能把 Gemini-3.5-Flash 从 50.5% 拉到 18.1%——v1.4.8 modelScope 门控已防）。与 v1.5.2 第八章 ruleset_export / 第十章自测 schema 同属「规则与技能的治理面」主题。
>
> 📋 **并入工具使用率遥测**（用户拍板）：同一治理面从技能扩到工具——104 个 MCP tools 目前**无调用遥测**，静态引用密度只能证明文档完备、不能证明被调用（104 tools 盘点实测：`orchestrator/workflows`、`task/plans` 等子系统零运行时痕迹，但无法据此判断其余工具的冷热）。退役与加码决策需要真实调用数据，故补工具面使用率；**后置本版**的理由是遥测需一段数据积累期才能产出可用结论。

### 交付

| 组件 | 能力 |
|------|------|
| **五维健康度指标** | 按综述 SkillOps 框架落五维（候选：使用频率 / eval 分数趋势 / modelScope 覆盖面 / 依赖健康（引用的工具/接口是否还在）/ 年龄与版本漂移）——`skill-health report` 输出，Dashboard 可见 |
| **低价值技能退役** | 五维连续 N 期低于阈值 → 退役候选清单（进 FDE 人工确认，不自动删——对齐「只提示不阻断」）；退役技能归档不物理删（可回滚） |
| **技能技术债台账** | 每技能记「上次 eval 验证时间 / 当前分数 vs 历史最优 / 待还债清单」——与 v1.4.5 skill-impact 台账同源扩展 |
| **工具使用率遥测** | 每次 MCP tool 调用追加一行到 `~/.sofagent/data/tool-usage.jsonl`（**tool 名 + 时间戳 + 会话标识**，不含调用参数与内容——隐私边界）；**纯本地存储、无任何上报路径**（对齐数据主权铁律「记忆/日志/决策记录永不离开本地」）；遥测默认开、配置可关 |
| **工具使用率盘点** | `sofagent stats --tools` 输出三视图：被调用 / 零调用 / 频次分布——为工具退役与加码提供数据依据（与五维使用频率同源消费） |
| **与 evolve 门控联动** | dream-cycle 晋升面照常，本项补**出口**：晋升进来就有健康度追踪，降级/退役有据 |

## 五、数据生命周期治理（~/.sofagent/data 增长面收敛 · 2026-09-16 用户拍板排期本版）

> 📋 **运行时数据实测发现**（2026-09-16 深挖）：`~/.sofagent/data` 332M 只增不减，三处结构性问题——① `memory/audit` 17178 个事实文件 67M 平铺单目录（dream-cycle `extract-facts` 按 key 前缀分桶后 bucket 内无二级分层、无归档、无轮转，已达文件系统性能退化区间）；② `audit/` 目录三个遗留备份文件 49M（`history.jsonl.bak×2` + `broken-*`）无生命周期策略接管；③ 审计链文件（history 52M / decision-log 56M）永久追加无归档机制。**边界**：只治理数据文件生命周期，不动链结构本身（HMAC 链只追加不删改是铁律——归档=移走历史段+锚点重算，非删除）。

### 交付

| 组件 | 能力 |
|------|------|
| **memory 事实二级分层** | bucket 内按日期（或哈希前缀）二级分目录，索引文件统一寻址——兼容现有 key 读取（读侧按索引查，不依赖目录遍历） |
| **memory 归档与轮转** | 事实级记忆按 updatedAt 冷热分层：N 天未更新移归档目录；归档不进常规检索（显式 `--archive` 才查）——对齐「记忆遗忘机制」 |
| **审计链归档机制** | history.jsonl / decision-log.jsonl 支持历史段归档：超阈值（如 50MB）把头部段移入 `archive/` 子目录 + 重算链锚点（锚点链头指向新末尾，归档段带独立锚点指纹可独立校验——与 v1.5.2 第八章独立验签器语义衔接） |
| **遗留备份接管** | `*.bak-*` / `*.broken-*` 文件按时间上限清理（默认保留 30 天），清理动作进 decision-log 留痕 |
| **doctor 检查项** | 新增 data 目录健康检查：单目录文件数超阈值（如 1 万）黄色告警 + 总量趋势提示 |
