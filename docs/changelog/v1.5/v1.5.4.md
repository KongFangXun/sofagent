#### 计数口径注（两数的**机械定义** · 供独立复算）

> 本节两数（`acceptance 可腾上限 = 16` / `checklist 内容行重合度上限 = 0.100`）按下列**机械定义**复算——勿与「路径集 Jaccard」或宽松提取口径混排：
>
> - **验收可腾上限 = 16 行** 的口径 = **连续公共运行**（长度 `L`、复用 `K` 块）中「可抽出为共享 helper 的行数」，**净腾 = `L(K−1) − K`**；按此口径（含「每块 ≥1 行才抽」的抽取门槛与 helper 落点成本）实测 acceptance 上限 = **16 行**（需求 21 ⇒ 不足）。
> - **checklist 内容行重合度上限 = 0.100** 的口径 = 把每个维度块解析成「**内容行**集合」，全体两两算 **内容行 Jaccard**（交集/并集）后取最大值；checklist 侧 = **0.100**（路径强候选对里最高仅 0.022）。
>
> ⚠️ **宽松口径并列（另一数、各自标注，勿合成第三值）**：若改采**更宽松**的提取口径——凡「**≥12 行重复且 ≥2 块**」即计入可腾——则 QA 独立复算得 `acceptance 可腾 = 114 行` / `checklist 脚手架可腾 = 28 行`（同口径下 checklist 内容行 Jaccard 上界可至 `0.2857`）。**该宽松口径不改变结构结论**：checklist 单侧真实可腾（≈3 行，见上表佐证）已 `<< 需求 98`，单独一项即足以否决「本版对销」路径——故本节结论（7 项移 v1.5.5）与「采信哪一轮口径」无关。

> 防「只试一种方法就下结论」：即使按**最乐观**口径把两条路叠加——① 共壳「外壳归并」（不依赖内容重复，只搬断言、省块壳 ~5–15 行/处；取 4 处非重叠 ≈ 40 行）＋ ② 脚手架 DRY 可腾（连续公共运行上限）：

#### 共壳候选法口径注（供 v1.5.5 复用该法时避坑）

**路径提取须三查，否则候选数系统性失真**：

1. **归一 `$VAR/` 前缀**——`$PROJECT_ROOT/<示例路径>` 与仓内相对路径 `<示例路径>` 是**同一引用**；未归一 ⇒ 同一文件被算成两个 token（**虚高**）。

3. **相似度栏须标清「路径集 Jaccard」还是「内容行 Jaccard」**——两者不可混排。

### DecisionChannel 接口契约（判定源接入规范）

> **定义方 = 引擎（本仓）**，实现方 = 判定件提供方（AIR 侧判定件、用户自带 provider）。托管微调侧的成对契约见 [TrainChannel 适配规范](../../guides/train-channel-spec.md)——两份规范同族同纪律（通道而非依赖、凭据走引用、实现方自测清单）。

**接口签名**（本版新建 `engine/orchestrator/src/router/decision-channel.ts`）：

| 动作 | 签名 | 语义 |
|------|------|------|
| `judge` | `(state, questions) → DecisionResult` | **一次前向**出全部问句的类型化答案 + 校准概率 |

**三问题原语**（语义固定，实现可换）：

| 原语 | 问句形态 | 输出 |
|------|---------|------|
| `choice` | 候选集固定（**必带兜底候选**） | 选中项 + 全候选分布 |
| `score` | 打分维度 + 量程 | 分值 + 区间 |
| `noul` | 真值命题 | 真值概率 |

**输入契约**：

| 参数 | 字段 | 必填 | 说明 |
|------|------|------|------|
| `state` | `text` | ✓ | 待判定语义输入（工作流节点上下文 / 工具调用参数 / 变更描述） |
| | `refs` | — | 结构化解引用（workflow 节点 id / 规则编号）——供 L0 规则面先判，命中则不进入判定 |
| | `evidenceReadiness` | ✓ | 证据就绪度（`structural` / `trace` / `none`）——判据启用门控；未就绪不得启用该判据 |
| `questions[]` | `id` | ✓ | 问句标识（回填与留痕用） |
| | `primitive` | ✓ | `choice` / `score` / `noul` |
| | `options` | choice 必填 | 候选集（**选项数 ≤5**；必带兜底候选——兜底与弃权**分别留痕**） |
| | `range` | score 必填 | 量程 |

**批量纪律**：同一 `state` 下的全部问句**一次提交**，实现须单次前向内出全部答案——禁止逐问句多次调用（延迟与槽位占用翻倍，且破坏「不占本地主模型槽位」的可测性）。

**输出契约**：

```
DecisionResult = {
  answers: [{
    id, value,
    probability,                    // 校准后概率/置信，[0,1]
    distribution?,                  // choice 全候选分布（和 ≈ 1）
    interval?,                      // score 区间
    status: 'answered' | 'abstained',
    abstainReason?: 'low-confidence' | 'out-of-domain' | 'missing-criteria'
  }],
  modelVersion,                     // 判定件代次号（如 sofa-s1m-v2）
  tempBucket,                       // 本次采用的分桶键（原语 × 选项数）
  latencyMs
}
```

**档位语义（五态 → 执行面）**——判定不直接执行，经授权档位落到执行面：

| 档 | 触发 | 执行面行为 |
|----|------|-----------|
| `ALLOW` | 高置信 + 域内 | 自动放行 |
| `ASK` | 中置信 / ⚡ 节点 | 转人批（HITL 中断点） |
| `ABSTAIN` | 弃权（三因） | 升级 HITL——**不许在坏选项里被迫挑一个** |
| `DENY` | 红线命中（规则面先行） | 拦截 |
| `SKIP` | 不在判定域内 | 不判定，走 L0 兜底 |

**升档判据**：`confidence < 1 − 升级成本/判错代价` ⇒ 向上一档升级（本地 → 云端 → 人审）。阈值**由代价反推**，不由拍脑袋常数给定。

**校准契约**：分桶温度按「（原语 × 选项数）」分桶拟合；选项数上限 5（超限拆问句）；**ECE 达阈为发布硬线**——未校准 + 未温度拟合前不得用于任何分流决策；每次判定回填 `tempBucket`，分布漂移可被检测（漂移 → 重标触发）。

**审计挂链**（落 decision-log，随审计链留痕）：`stateDigest`（state 摘要，**不落原文**——防敏感信息入链）· `questionIds` · `answer` / `probability` / `status` / `abstainReason` · `modelVersion` / `tempBucket`（可追溯「用哪个模型、哪档校准判的」）· `escalate` / `threshold`。

**决策下达面**（引擎 → router，与本表上方「决策下达面」行同源）：去向决策按标准 schema 下达（目标模型 / 降级路径 / 槽位归属），**schema 校验 fail-closed**（坏格式拒绝下达而非静默放行），与 v1.4.9 承接面构成双向闭环。

**实现边界（硬性）**：

1. **不占本地主模型槽位**——判定期间零本地主模型推理请求（行为锁，可测）
2. **不进信任地基**——决策模型可被 state 内容操纵（已知失灵面），只坐确定性规则之后的语义兜底层；25 条审计规则判定面零改动
3. **云端 opt-in 默认关**——判定特征出站须经有界脱敏投影；组织禁外部评估时可指内部兼容实现或整体跳过（跳过不阻断捕获）
4. **fail-closed**——通道不可用 / 超时 ⇒ 降级 L0 规则面兜底，不得静默放行
5. **凭据不落明文**——云端 provider 走用户 key 引用（同 TrainChannel `credentialRef` 纪律）
