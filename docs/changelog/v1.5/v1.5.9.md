## 一、Tool search 按需加载（OpenAI Agents API 启发 · 2026-09-15 用户拍板排期本版）

> **形态归属**：`[主干]`（注入面·工具选择即信任边界）｜ L1 关档（回落全量注入）
>
> 📋 **研究收编**（[OpenAI Agents API](https://openai.com/index/introducing-the-agents-api/) 公测，2026-09-10）：工具定义不全量注入——Agent 按任务需要检索并加载相关工具 schema，官方收益「reduce token usage and cost while preserving the model's cache」。本仓 TOOLS=104 已进适用区间（loop-development 已有判断：「工具数上百时瓶颈不在推理而在工具描述歧义」）；v1.4.8 plugin-gate/ToolGate 管的是「能不能用」（权限面），本章管「要不要装进上下文」（供给面）——两者正交。与 [v1.5.6 第一章](./v1.5.6.md) 模型路由层同属**调用侧上下文供给**：路由决定「用哪个模型」，tool search 决定「带哪些工具」。

### 交付

| 组件 | 能力 |
|------|------|
| **工具检索索引** | 工具注册表（tool-registry）之上建语义检索索引（名称/描述/标签），按当前任务描述召回 top-K 候选工具 |
| **节点域注入** | 按 workflow 节点类型注入工具子集（复用业务图谱节点级权限模型——节点绑定工具域，域外工具不进上下文）；手动指定工具可显式覆盖检索结果 |
| **分步按需加载** | 单节点执行中途可追加加载工具（模型第一步发现缺工具 → 检索加载 → 继续执行，对齐 Agents API tool search 的任务中检索语义） |
| **预算与命中率度量** | 检索命中被实际调用的比率 + 工具注入 token 曲线（对比全量注入）落 metrics——为「按需加载是否值得」提供实证数据 |
| **静态重叠检测联动** | v1.1.0 规划的静态重叠检测（防工具描述歧义）与本章共用索引底座——先去重后检索 |
