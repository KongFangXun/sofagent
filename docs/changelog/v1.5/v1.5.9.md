## 定位


> ⚡ **进化模块 · 写面审计与能力基线**——补上 RSI 治理最大的盲区：**prompt 面与 memory 面**的变更此前完全在审计视野外（权重面 manifest 验签、skill 面 eval-gate 已覆盖），本版为两类非代码写面定义 diff 契约并落可举证记录（与 git diff 并列为第三通道，规则判定逻辑不变）；同时把「单次执行可复现」升级为「**跨时间可追溯**」——能力基线版本线，出事能回答「当时它是怎么做事的」。

> ⚡ **进化模块 · 配置面契约与元验证**——把「门本身」管起来：**配置面**（加载链四层字段 SSOT + 所有权唯一 + 越界检测——判据不是「能配置」而是「配置面无死角」）与**验证器自身**（进化越久门越松——验证集老化度、收益归因对照组、验证漂移三态、评估器与执行模型解耦三级精判、判定件作验证器的自评禁则，老化只提示不阻断）。

> 🥊 **审计可信度的攻防两面（自探索方向迁入 · 两项合流）**——审计系统的可信度靠「**被打过而没被打穿**」证明：**敌手自测**定期以攻击者视角尝试绕过审计（篡改 `history.jsonl` / 伪造 HMAC 链 / 绕过 ToolGate），结果进 anti-cases；**透明仓**把治理原始记录（含误报与翻案）实时公开，「审查自己也在被审计」。两项触发条件同一（第三方首次独立审查）故合流成章；透明仓开仓另受**误报率红线**（<5%）闸门与人工确认双控。

## 一、自进化写面的审计覆盖（prompt / memory 两面补盲 · RSI 治理的地基章）

> 🔗 **承载场景（章↔场景双向登记）**：**S481** `playbook/acceptance-test.sh`——写面留痕模块在位（write-surface-log 16 导出）+ core 侧钩子。

> **形态归属**：`[主干]`（判定·留痕——自进化变更面的审计取证）｜ **不可拔**（审计地基：拔掉它，Agent 改自己的 prompt 与 memory 就彻底逃逸审计视野，RSI 治理失去立足点）
>
> 📋 **缺口实测（2026-09-19）**：审计地基是「不信任自我报告，只看 git diff 硬证据」（[ARCHITECTURE](../../ARCHITECTURE.md) 核心叙事），v1.5.1 规划第二通道（调用意图 + 结果文本）。但 RSI 的四个可写面里——**权重面**（v1.4.4 manifest + sha256 验签）与 **skill 面**（eval-gate 收编门 + v1.4.9 执行时 skill 快照）已有覆盖，**prompt 面与 memory 面完全在审计视野外**：Agent 改了自己的 system prompt、往记忆里写了一条「经验」，不留任何可举证的变更记录——**自我改进最大的两个写面恰恰是我们唯一没有硬证据的地方**。行业对位：Meta-RSI 把可写面明确为 data/harness/model 三类并要求保护面独立于所有写面——本章是「保护面如何真的看得见写面」的工程答案。

## 四、验证器自身老化检测（元验证 · 进化越久门越松的反向治理）

> 🔗 **承载场景（章↔场景双向登记）**：**S481**——验证器老化模块在位（validator-health）。

> **形态归属**：`[主干]`（判定·验证集有效性）｜ L1 关档
>
> 📋 **缺口实测（2026-09-19）**：进化循环靠 eval 验证集当门，但**验证集自己会老化**——项目既有叙事已点破同一现象（[guides/loop-development](../../guides/loop-development.md)「测量衰退：测试数据老化 95% 通过率是假象」）。RSI 时代这个风险被放大：进化循环持续跑，样本被反复消费，通过率越来越好看而能力未必提升——**越进化，门越松**。行业对位：验证器必须独立于写面，但「独立」不等于「永远有效」——验证器自身也要被检验。**形式化锚（RQGM）**：自改进 agent 的搜索普遍假设**评价标准静止**（固定 verifier / 基准 / 标注集）——「The Red Queen Gödel Machine」（[arXiv:2606.26294](https://arxiv.org/abs/2606.26294)）给出受控效用演化的形式化：搜索分 epoch、**epoch 内判据固定**、只允许在 epoch 边界更新效用，使「自改进保证按 epoch 成立」；其对位读数＝最强基线评审员**过度接受 AI 生成论文达人类率的 1.91×**（对抗目标可纠正）。本章的老化指标 + 复检入口正是该命题在治理面的落法：判据集的「epoch 边界」＝人工复检留痕，自动消费只发生在 epoch 内。

### 交付

| 组件 | 能力 |
|------|------|
| **验证集老化指标** | 每组验证集记「样本消费次数 / 通过率趋势 / 上次人工复检时间」，形成老化度（对齐 [v1.5.7 第四章](./v1.5.7.md) 能力面五维健康度同款思路：低价值技能能退役，老化验证集也要能退役） |
| **收益归因对照组** | 进化收益的**反事实基线**：进化开启前先冻结一份对照配置（不改 skill / 不注入 / 不训练），收益曲线四指标同时跑「进化组 vs 对照组」——差值才是进化的净贡献（防「环境变好了」冒充「进化有效」：任务变简单、模型升级、季节波动都会让通过率上涨，无对照的收益声明不可信）。对照组按周期轮换重置（防止对照组本身过时），轮换留痕 |
| **验证漂移三态** | 考核失败时区分「真失败 vs 环境漂移」（对齐 checkHistoryChainDetailed 三态先例——`tampered`/`unverifiable`/`insufficient-history`）：考核环境本身变了（依赖版本/路径/权限）导致复现失败 ≠ 经验失效。漂移态不降经验置信度、不触发回退，但必须告警并标记待环境复核——**宁可挂起，不误杀好经验** |
| **老化告警** | 通过率连续上升但真实任务指标未改善（或消费次数超阈值且长期无复检）⇒ 告警并建议冻结该验证集的自动晋升资格——**只提示不阻断**（对齐「只提示不阻断」铁律） |
| **验证集复检入口** | 提供人工复检通道：标记样本失效/新增样本，复检动作留痕（与 [v1.5.2 第四章](./v1.5.2.md) 审计结论失效语义同族——失效的不当新证据用） |
| **评估器解耦与三级精判** | ① **自评禁令**：评估 / 反思角色**不得复用被考核的执行模型**（同一模型既做题又判题＝自评失效——行业实证：自评判与环境真值一致率 0.88，而价值估计误差同样 0.88，评判准确度与下一步改进几乎零相关，[S³Gym](https://arxiv.org/abs/2608.31100)）；② **三级精判**：规则/格式预筛（廉价、覆盖全量）→ 独立评估模型精判（有成本、覆盖疑难）→ 关键样本人工抽检（**定标权在 `human` 档**，对齐 [v1.6.0 §七](../v1.6/v1.6.0.md) 教师蒸馏的定标纪律）；③ **评估模型选型**：稳定、可复现、便宜优先——反思/评估不需强创造力，须与执行模型解耦（对齐 [v1.8.0 §三](../v1.8/v1.8.0.md) 实现路线不绑定） |
| **判定件作为验证器（优先级与自评禁则）** | 判定件（类型化概率 · 单次前向 · 可校准）是 `model-judge` 档的**首选形态**——它是 [v1.5.8 第一章](./v1.5.8.md)「验证比生成便宜」这条准入判据的最优解，也是**判定面与 RSI 循环的结构耦合点**：有判定件的域，进化循环才真跑得起来（无廉价验证器的域，循环空转）。三条边界：① **能判不能出题**——判定件只出结论与概率、不生成文本，故它作**判题器**不作**出题器**（出题仍归 [v1.5.8 第四章](./v1.5.8.md) 的出题器；两者混用会让「自己出题」从机制上复活）② **自评禁则**——判定件不得为**自身所属判定面**的进化当裁判（含自身微调、含同判据集上的判据变更），是本行上一项自评禁令在判定面上的展开 ③ **跨面互审**——判定件可验证其他判定面与其他可写面（prompt / memory / skill / 配置）的进化产物，跨面关系须在域验证器登记里**显式声明**；无声明 ⇒ 按自评处理（fail-closed） |
| **验证者链三机制（2026-10-02 登记 · 补入上一行自评禁令）** | 上一行「自评禁令」解决**谁不能当裁判**；本条补**裁判怎么被使用**的三条机制（外部同题系统的做法，本仓取其形状）：① **每次判定用全新实例**——验证者不复用同一会话/上下文，避免被前一次判定锚定（复用实例等于让裁判带着上一题的印象判下一题）；② **判负必须回抛原因**给生产者的会话去修——判定结果不是一个 bool，而是一条可行动的反馈（只报「不过」会让生产者靠猜）；③ **不需要外部执行就能判定的不变量放进格式校验层，而不是再加一个验证者**——验证者数量与判定成本必须与「是否真需要执行证据」对齐，否则门会越加越多而每一道都更松。三条与既有「评估器解耦与三级精判」同属验证面，**不新立角色、不新增档位** |
