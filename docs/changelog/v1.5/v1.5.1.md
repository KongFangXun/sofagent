## 定位

> ⚡ **编排引擎 · 事件驱动**——业务节点从「指令驱动」升级为「事件驱动」：上游节点产出、外部事件（邮件到达/表单提交/定时器）自动触发下游节点，编排引擎从「人来派活」变成「事件来了自己跑」。与 v1.3.8 cron + 依赖图同向但更彻底：触发源泛化到业务事件。外加理解债务应对——审计已覆盖「发生了什么」，补「为什么这么做」。

## 一、事件驱动执行触发

> 📋 **探索方向表 2026-08-24 新增**：与 v1.3.8 cron + 依赖图同向但更彻底——触发源泛化到业务事件。等 v1.4.x 训练引擎稳定后评估 → 本版收编。

### 交付

| 组件 | 能力 |
|------|------|
| **事件源适配器** | 三类触发源：上游节点产出事件（workflow 内部）/ 外部事件（webhook 入站：邮件到达/表单提交/IM 消息）/ 定时器（v1.3.8 cron 既有） |
| **事件路由规则** | workflow 节点声明 `on:` 事件订阅（YAML 内声明式配置）——事件到达自动派发下游节点 |
| **事件总线** | 轻量事件总线（进程内 pub/sub + 落盘事件队列），事件投递全程审计留痕（每条事件可追溯触发链） |
| **死信与重试** | 事件处理失败进死信队列（复用 v1.3.1 stop_reason 分类 + 退避），死信可重放 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/events/bus.ts` | 新建 | 事件总线（pub/sub + 落盘队列） |
| `engine/orchestrator/src/events/adapters.ts` | 新建 | 三类事件源适配器 |
| `engine/orchestrator/src/events/router.ts` | 新建 | 事件→节点路由（读 workflow `on:` 声明） |
| `engine/mcp/src/tools/workflow-submit.ts` | 修改 | workflow schema 支持 `on:` 事件订阅字段 |

### 验收标准

- [ ] 上游节点产出自动触发下游节点（workflow 内部事件链）
- [ ] webhook 入站事件（≥2 类：表单提交/IM 消息）可触发节点
- [ ] 事件投递全程审计留痕（每条事件触发链可追溯）
- [ ] 失败事件进死信队列，可重放
- [ ] `npm test` 全绿

## 四、设备 OTA 远程升级（G12 · 升级指令走事件总线 + 设备 daemon 拉取验签）

> 📋 **自 v2.x 设备联邦前移**（2026-09-01 用户拍板）：G9/G10/G11 管「数据通道」，G12 管「运维通道」——一体机/节点设备卖出去后引擎怎么升级（发新版/打补丁/规则更新）。不掌握升级通道的设备会逐渐脱管，G12 是设备生命周期的最后一块拼图。**升级指令下发复用本版第一章事件总线**（升级 = 一类事件），**设备身份/健康复用 v1.4.9 G9**（升级面向已注册设备，心跳离线的设备挂起等待）。

### 交付

| 组件 | 能力 |
|------|------|
| **升级事件类型** | 事件总线新增 `device.upgrade` 事件类型（payload：目标版本 + 组件清单 + 灰度策略 + 截止窗口），平台/租户管理员发布 |
| **skill/模板下发（`device.deploy`）** | 事件类型扩展 `device.deploy`（与 upgrade 同构的平台→设备推送面）——商业平台 §2.4 执行链第一步「平台下放 skill」的引擎侧通道：payload 携带 skill/workflow 模板包（G1 五件套格式），设备 daemon 订阅 → 验签 → 落盘注册（缺口 C，2026-09-01 对账补）——平台→设备的「内容下发」与「版本升级」共用一套推送底座 |
| **daemon 升级执行器** | 设备 daemon 订阅升级事件 → 拉取新版包（npm registry / 制品库）→ 验签（复用 v1.4.9 G9 Ed25519 身份码验签链，包签名校验 fail-closed）→ 灰度执行（先升级非核心组件，健康探针通过再升级核心）→ 失败自动回滚 |
| **升级窗口策略** | 设备侧配置升级窗口（业务低峰时段执行；窗口外挂起等待）+ 手动确认模式（高风险版本需设备侧 HITL 确认） |
| **升级审计留痕** | 升级全生命周期进 audit history（谁发布/哪台设备/从什么版本到什么版本/验签结果/回滚记录）——HMAC 链覆盖 |
| **版本清单上报** | 升级完成后设备版本清单上报（G11 通道回传，平台设备面板可见） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/events/types.ts` | 修改 | 事件类型加 `device.upgrade` |
| `engine/daemon/src/ota/upgrade-executor.ts` | 新建 | 拉取 + 验签 + 灰度 + 回滚执行器 |
| `engine/daemon/src/ota/upgrade-policy.ts` | 新建 | 升级窗口/手动确认策略解析 |
| `engine/daemon/src/__tests__/ota-upgrade.test.ts` | 新建 | 单测（验签失败拒绝 / 灰度次序 / 回滚触发 / 窗口外挂起） |

### 验收标准

- [ ] 窗口外/离线设备挂起，恢复后自动补升
- [ ] 升级全程审计留痕（HMAC 链可追溯）
- [ ] `device.deploy` 下发 skill/workflow 模板到设备（验签 + 落盘注册可用）
