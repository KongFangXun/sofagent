## 二、本体数据双时态事实（Semantica 启发 · 时点快照查询）

> 📋 **探索方向表 2026-08-29 收编**。本体数据实体加 validFrom/validTo 时间区间，支持「时点快照」查询（系统在某天知道什么）——审计回溯场景「当时依据的版本」目前靠 git snapshot 只覆盖 worktree，本体实体无时间语义。设计级变更（本体数据包 schema + 查询层），收益在长周期企业运营后显现。

### 交付

| 组件 | 能力 |
|------|------|
| **实体时间区间** | ontology 实体 schema 增加 `validFrom` / `validTo` 可选字段（不填 = 永久有效） |
| **时点快照查询** | `stateAt(date)` 查询接口：返回该时点有效实体集——「上个月报价单上的联系人是谁」可回答 |
| **审计回溯联动** | decision-log 引用实体时记录当时 validFrom/validTo——决策「当时依据的版本」不再靠 git snapshot |
| **导入兼容** | ontology_import 对无时间字段旧数据自动补 validFrom=导入时刻 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/ontology/src/schema.ts` | 修改 | 实体 schema 加 validFrom/validTo |
| `engine/ontology/src/query.ts` | 新建 | stateAt 时点快照查询 |
| `engine/mcp/src/tools/ontology-import.ts` | 修改 | 旧数据兼容（自动补 validFrom） |
| `engine/mcp/src/tools/create-entity.ts` 等 | 修改 | 实体 CRUD 记时间区间 |

### 验收标准

- [ ] 实体 schema 支持 validFrom/validTo（可选字段，不填=永久）
- [ ] `stateAt(date)` 时点快照查询可用
- [ ] decision-log 引用实体时记录时间区间快照

## 四、决策因果链（decision-log 平面日志 → Semantica 式因果图）

> 📋 **2026-08-29 排期（Semantica record_decision + CAUSED/INFLUENCED 边启发）**。当前 decision-log 是平面 JSONL——决策之间无因果关系结构。升级为因果图：决策成为一等图节点，可追溯「这个决定是因为哪个上游决定」。

### 交付

| 组件 | 能力 |
|------|------|
| **决策记录升级** | decision-log 条目增加 `causedBy`（上游决策 ID 列表）+ `influencedBy`（弱因果参考）字段 |
| **因果链查询** | `trace_decision_chain(id)`：向上追溯完整祖先链（每步带决策上下文） |
| **相似决策检索** | 基于类别/场景/结果的相似历史决策检索（审批先例参考——「上次类似情况怎么批的」） |

### 涉及文件（预估）

## 六、存量清扫（退场不清扫债务一次收编）

> 📋 **2026-08-29 排期（用户拍板：不能只加新的，老的要淘汰）**。四件历史退役残留 + 一件重叠工具一次收编，全部来自存量功能考察（证据见各节）。

### 交付

### 一）ao 工具链探测删除（engine/core/src/run-envs.ts）

**证据**：`run-envs.ts:111` 仍探测 `['ao', '0.7.5']`——ao 已于 v1.0.7 退役，探测成死代码。

**改动**：删除 ao 探测行 + 对应测试断言。

### 二）composeWithDeepAgents 更名（engine/orchestrator/src/composer.ts）

**证据**：注释称「ao 完全退役，createReactAgent 为唯一编排引擎」，但 @public API 还叫 `composeWithDeepAgents`（`index.ts:14` 导出），实现早已全走 createReactAgent——名不副实。

**改动**：`composeWithDeepAgents` 重命名为 `composeWithReactAgent`；旧名保留一版 @deprecated 别名（转发调用 + 文档指向新名）；orchestrator-compare.ts / launcher.ts 调用点同步替换。

### 三）fde_compose 收窄为 workflow-only（engine/mcp/src/tools/fde-compose.ts）

**证据**：fde_compose 的 `action=ontology` 与 v1.4.2 六引擎之一 `fde_derive` 完全重叠（五要素→ontology 草稿落盘）；fde_compose 是 v1.3.7 旧交付，fde_derive 是新主入口。两者并存徒增发现成本。

**改动**：fde_compose 收窄为 workflow-only；`action=ontology` 返回迁移提示（指向 fde_derive）；tool-registry 描述同步收窄；相关测试同步收窄。

### 四）checkHistoryChain 旧 API 退役（engine/core/src/audit-history.ts:396）

**证据**：已标 @deprecated（「布尔语义无法区分篡改/历史不可复验/不可信，新代码请用 checkHistoryChainDetailed」），后继 API 已交付多版。

**改动**：本版移除 deprecated API（breaking change，minor 版本内提前一个版本公告于 CHANGELOG 索引）。

### 五）吃自己狗粮：commons_retire scan 自扫（一次性工程动作）

**证据**：仓库自带 `commons_retire scan`（low_invoke/low_rating 退役候选扫描），但从未对自己跑过。

**改动**：发版前对 commons 全量 tool 跑一次 scan，产出退役候选清单归档（候选者下版评估，不阻塞发版）。

### 验收标准

- [ ] ao 探测删除，run-envs 输出无 ao 条目
- [ ] `composeWithReactAgent` 可用，旧名 @deprecated 别名转发
- [ ] fde_compose 仅响应 action=workflow，ontology 返回迁移提示
- [ ] checkHistoryChain 移除，全仓 grep 无调用残留
- [ ] commons_retire scan 自扫报告落盘 `data/commons/retire-scan-<date>.json`
- [ ] `npm test` 全绿
