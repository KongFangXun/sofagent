## 概述

v0.82 做了五平台实测 5/5，v0.83 修完了实测暴露的断裂。但 ROADMAP 里挂着一条 P0 待办一直没动：

> **A/B benchmark 数据（10 任务 × 带不带 sofagent，含 token / 调用次数 / 循环状态）—— 2 周内**

这条是 v0.82 评审挖出来的最大短板：**效果没数据**。我们说「减少 token 浪费」「降低偏离率」，全是定性感受。

v0.84 就一件事：**把证据补上**。

> **理论可读、代码可抄，唯有实践数据是时间壁垒。**

Loop Engineering 的理论谁都能读到，纯 bash + MD 的实现有经验的工程师 1-2 周能复刻。但「跨 5 个平台、实际跑了 N 个任务、带 vs 不带 A/B 对照」——这组数据只有跑过的人才有，抄不走。EVIDENCE.md 那 11 个 Case 不是太少，是**深度不够**：全是一次性测试，没有持续使用 ≥1 周的样本，没有 A/B 对照。v0.84 就是在补这两层缺口。

```
v0.83 修完了断裂
   ↓
但效果数据还是空的——benchmark 模板 10 个任务全是「待独立验证」
v0.82 平台测试只测了「能不能装」，没测「装了有没有用」
   ↓
v0.84 目标：让测试同学拿着操作手册，明天就能开始跑
```

## 背景与动机

### 为什么要专门发一个版本做这件事

v0.82 评审的核心结论是「概念验证成立，但效果证据为零」。评审者看了 EVIDENCE.md 11 个 Case，说了句大实话：

> 「这些 Case 证明 sofagent 能跑，但没证明 sofagent 跑得更好。」

缺的是**对照数据**——同一个任务，带 sofagent 和不带 sofagent，token 消耗差多少、偏离率差多少、错误恢复差多少。这组数据一旦有了，README 的「效果」段就从定性感受变成定量证据。

### 为什么不能自己测

v0.75 的 benchmark 模板已经建好了 10 个标准化任务，但一直是「自测 + 循环论证」——Agent 跑 Agent 评自己，说服力约等于零。

> 反案例 001 已经诚实记录了这个局限：「单会话自测模式下无法模拟卸载后的行为，诚实比假数据重要。」

v0.84 的核心动作是把测试**交给独立的测试同学**，用标准化操作手册，减少测试人主观判断空间。

### v0.84 vs v0.9 的边界

v0.9 是企业级 + Beta 公测，体量大。v0.84 是 v0.9 前的证据补全版本：

| 维度 | v0.84（本版本） | v0.9（未来） |
|------|----------------|-------------|
| 目标 | 补证据 + 补打磨 | 企业级 + 招募 Beta 用户 |
| 新功能 | ❌ 不加 | ✅ 加加密/审计/多用户 |
| Bash 重构 | ✅ 部分（daemon-lib jq 迁移） | ✅ 完整（install/verify 拆公共库） |
| 测试 | A/B benchmark + 平台回归 | Beta 用户 30 天试用数据 |
| 风险 | 低（不改运行时逻辑） | 中高（改数据层） |

**决策依据**：直接跳 v0.9 风险太大——没有证据就招 Beta 用户，等于让人家空手试。v0.84 先把证据补全，v0.9 再招人。

## 计划工作项

### 工作项 1：A/B Benchmark 测试文档（测试同学执行）

**要解决什么**：benchmark 模板 10 个任务全是「待独立验证」，需要一个标准化操作文档让测试同学明天就能开始跑。

**交付物**：
- `docs/v0.84-test-plan.md` — 独立测试需求文档
- 覆盖三部分：
  - **Part A** — v0.83 修复验证（5 平台安装回归，确认 P0 断裂已修）
  - **Part B** — A/B Benchmark（10 任务 × 带/不带 sofagent，量化对比）
  - **Part C** — 平台专项验证（daemon 检测、加载链、治理加固）

**设计原则**：
- 测试同学不需要读 SKILL.md / ARCHITECTURE 就能执行
- 每个测试有明确的：前置条件 → 操作步骤 → 预期结果 → 判定标准 → 记录表
- 结果表用统一模板，跑完直接填数字

**状态**：📋 本版本交付（文档先行，测试同学明天开始跑）

### 工作项 2：Bash 重构 Phase 1 — daemon-lib.sh 迁移 jq

**要解决什么**：daemon-lib.sh 的 JSON 读写用 grep + sed 手搓，v0.83 加了大括号配对校验兜底，但不是长久之计。ROADMAP v0.9 排了完整的 bash 重构，v0.84 先做 daemon-lib 一个文件。

**交付物**：
- daemon-lib.sh 的 `set_json_field()` / `get_json_field()` 改用 `jq`
- 保留大括号配对校验作为 jq 不可用时的降级路径
- daemon.json 迁移触发条件注释更新（从「字段 >10」改为「已迁移，jq 为硬依赖」）

**约束**：
- 只改 daemon-lib.sh 一个文件
- 不动 install.sh / verify.sh / task-orchestrate.sh（留给 v0.9 完整重构）
- jq 不可用时自动降级到 grep + sed，不报错退出

**状态**：⏳ 测试文档交付后启动

## 测试策略

v0.84 的测试和之前不同——**测试人不再是我们自己**。

### 三层测试

| 层级 | 谁来跑 | 跑什么 | 预期周期 |
|------|--------|--------|---------|
| **回归测试** | 测试同学 | Part A：v0.83 修复验证（5 平台安装） | 1-2 天 |
| **效果测试** | 测试同学 | Part B：A/B Benchmark（10 任务对照） | 3-5 天 |
| **专项验证** | 测试同学 | Part C：daemon + 加载链 + 治理加固 | 2-3 天 |

### 诚实声明

- 测试同学不一定有全部 5 个平台的环境
- 没有环境的平台标「未测」，不编数据
- A/B Benchmark 的「不带 sofagent」组，必须用**全新会话**（不能在同一会话里卸载再装）
- 所有结果截图或导出日志，不靠记忆
