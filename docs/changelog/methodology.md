## 这个项目是怎么做出来的？

说到底是场实验——AI 模型们能不能在迭代中互相校验，写出一个像样的技术产品？

作者代码写得很糟糕，所以换了一种方式：DeepSeek V4 Pro 和 GLM-5.2 各自写代码，也各自审对方的代码——两个模型都在写、都在审、都在改。作者也不跳出这个循环，坐在中间跟着一起滚：定约束、看产出、做终审。整个项目在「模型 A 写 → 模型 B 审 → 模型 A 改 → 再审」的循环里打磨出来。

大力出奇迹的代价是 token 消耗是正常写代码的 3-5 倍，烧 token 换项目产出与质量保证。好处是人不需要碰代码——设计决策、经验积累、方向判断，这些是人能做的。至于这种模式能不能稳定复现，说实话还不知道——所以这既是项目，也是实验。

## 双轮评审（GLM-5.2 + DeepSeek V4 Pro）

v0.93 起，每个版本发布前接受两轮独立评审：

- **GLM-5.2**：交付总监视角——关注完整性、可交付性、用户体验
- **DeepSeek V4 Pro**：GitHub/CTO 视角——关注工程质量、安全、可维护性

两轮评审合并去重后形成问题清单，按 P0/P1/P2 排程落地。这个流程本身就是 Ralph 循环的活体验证——GLM 定框架 → DeepSeek 写实现 → GLM 审查 → DeepSeek 修复 → 下一轮。10 天 17 个版本，在传统软件工程里是灾难信号，在 AI Loop 语境下恰恰是产品价值的证据。
