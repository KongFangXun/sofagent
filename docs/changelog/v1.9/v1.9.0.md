## 定位


> 🧩 **判定底座 · 既有判定面收敛**——阶段四第一版，回答「**已有的那些判定能力怎么办**」。实测普查（2026-09-20）的结论是：引擎里 Choice / Score / Noul 三种原语的**形状全都已经存在**——`fde_classify` 的「三问输入 → 三选一输出」已是 Choice + Noul 的组合、`evaluate` / `quality-judge` 是 Score、`shouldAllow` 是 Noul——**但三者共缺同一个维度：校准概率**。本版把已有判定面接上判定底座，同时完成一件更重要的诚实性工作：**把「假概率」正名**。

> 📊 **判定底座 · 判据面扩展与四层性能标准**——阶段四第二版，回答「**怎么证明它真的有用**」。判定能力的正确性不由通用榜单定义，而由**自有判据集上的分层性能**定义——本版把判据面从审计规则扩到 workflow / 本体数据 / 路由判定。同时给出**四层性能标准**与**第四方对照**，把判定能力的证据链首次公开。**纪律**：性能以自有判据集为准，**不比通用 benchmark**（通用榜单与判定任务不同构，比了也无解释力）。第六章补上这套证据链**失效时**的探测器——判定坏掉时它不会报错，只会安静地答错。

> 🏁 **判定底座 · 施工期收口与全站口径对齐**——施工期最后一版，回答「**收没收口、能不能进 V2.0**」。本版不新增判定能力，只做三件事：判定四阶段是否全部达阈、全站口径是否对齐、以及**把弹性机制写死**——后续若仍有开发量剩余，**加版本而不挤版本**。

## 二、假概率正名（诚实性工作 · 不伪造校准）


> **形态归属**：`[主干]`（判定·数值语义正名）｜ **不可拔**（数值语义失真会误导下游门槛设计）

### 实测现状（2026-09-20 普查）

引擎内散布的置信度数值，**没有一个是校准概率**，且分三类不同性质：

| 性质 | 实测样例 | 正确处置 |
|------|----------|----------|
| **硬编码常数** | 根因分析内 `confidence: 0.7` / `confidence: 0.6` 等直接写死的数值 | 属**启发式权重**，非概率——**正名为权重**，或接入校准后替换 |
| **枚举映射出的数值** | PR 触发绑定两态枚举映射为 `1.0` / `0.5`；决策 schema 的 `'high' \| 'med' \| 'low'` 三态 | 属**序数等级**，非概率——**保留等级语义**，导出数值时标注为序数而非概率 |
| **真概率字段** | **全仓零命中** | 本版起由判定底座补齐 |

### 交付

| 组件 | 能力 |
|------|------|
| **语义正名** | 按上表三类分别处置：能校准的接校准（v1.7.0 能力），本质是权重/等级的**正名为权重/等级**——**不把权重伪装成概率** |
| **调用侧可分辨** | 数值携带语义标记（`probability` / `heuristic-weight` / `ordinal-level`）——下游按标记决定能否进概率门槛，**标记缺失按不可信处理** |
| **门槛口径校正** | 既有以这些数值为门槛的判定（若有）重新校准口径：用权重当概率设门槛的，门槛含义须改写为「按经验阈值」而非「按错误率」——**说清它是什么** |
| **普查清单落盘** | 全部既有置信度数值逐条登记（位置 / 当前值 / 性质 / 处置），落文档可核对——**数量与位置如实落数，不概括为「若干处」** |
| **不静默改行为** | 正名**不改变既有判定行为**（只改语义标记与文档口径）；需要改行为的，单独列变更并留痕 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/audit/src/audit-root-cause.ts` | 修改 | 硬编码数值正名为权重语义 |
| `engine/audit/src/pr-store.ts` | 修改 | 两态映射数值标注为序数等级 |
| `engine/audit/src/decision-schema.ts` | 修改 | `confidence` 三态语义标注（`@public` 契约变更须谨慎） |
| `engine/core/src/calibration-registry.ts` | 修改 | 登记表补语义标记字段 |
| `docs/ARCHITECTURE.md` + `docs/LIMITATIONS.md` | 修改 | 普查清单 + 语义口径说明 |

### 验收标准

- [ ] 既有置信度数值**逐条**登记（位置 / 值 / 性质 / 处置），数量如实落数
- [ ] 数值携带语义标记（概率 / 启发式权重 / 序数等级），缺失按不可信处理
- [ ] 以权重当概率的门槛口径已改写（不再暗示错误率含义）
- [ ] 正名**不改变既有判定行为**（回归测试证明行为一致）
- [ ] `@public` 契约字段变更按 breaking 流程处理（如需）
- [ ] `npm test` 全绿

### 风险与前置假设

> ⚠️ **本版的产出是「诚实」而非「更强」**。正名后的数字可能看起来「更弱」（从 `0.7` 变成「一个启发式权重」），但这是必要的——把权重当概率用于分流门槛，会让门槛的含义从根本上失真，错误率无法预测也无法举证。
>
> ⚠️ **本版不改判定行为**。行为收敛若需要，属后续版本独立评估——把「语义正名」与「行为改变」混在一版，会让回归问题无法定位。

## 三、判据面扩展（从审计规则扩到三类判定域）


> **形态归属**：`[主干]`（判定·判据面）｜ **不可拔**（判据面是能力的边界声明）

### 交付

| 组件 | 能力 |
|------|------|
| **workflow 判据面** | 编排任务的判定判据（该不该触发 / 该走哪条支路 / 该不该升级）——判据来自 v1.5.1 事件驱动与 v1.5.4 判定分层的既有语义 |
| **本体数据判据面** | 本体实体/关系操作的判定判据（该不该建 / 该不该合 / 该不该失效）——对接 v1.5.0 双时态与 Validation Engine 既有语义 |
| **路由判定判据面** | 请求难度与敏感度的判定判据（该走哪档）——对接 v1.5.4 路由层与 [v1.8.0 第四章](../v1.8/v1.8.0.md) 判定档 |
| **判据集分层声明** | 各判据域的能力边界显式声明：**哪些域已校准、哪些域只是接口在**——未校准域的输出不得进决策路径（沿用 v1.7.0 门禁） |
| **决策模式词表查漏（对照业界已收敛分类法）** | 三类判定域定稿前，对照业界已收敛的**决策模式词表**做一次查漏：工具选择 / 意图路由 / 上下文压缩 / 安全闸门 / 输出校验 / 重试控制 / 人工升级 / 模型路由 / 并行扇出（speculative fan-out）。该词表由生态索引仓以**单源数据文件分发**（README / 站点 / 工具全读同一份防漂移——与本仓 SSOT 纪律同构）。**用法是对查不是照抄**：逐模式问「本仓判据面有没有对应的判据落点」，答不上的登记为缺口或显式声明不属本域——防的是「自认为三类域已覆盖，实际漏了整类模式」（如重试控制与并行扇出在我们三类域里没有显式落点，须逐个裁定归属或显式排期） |
| **域的适用边界** | 明确判定底座**未验证的域**（开放式写作、主观偏好、长链推理）——不在无验证器的域宣称判定能力（对齐「验证差距」纪律：验证比生成便宜才有自动化的前提）。判据面的**扩展**须以**分布外表现**为前置输入——生态实测的泛化落差约 24 个百分点（已训练任务族可用不等于新任务类型可用），口径见 [v1.6.0](../v1.6/v1.6.0.md) 分布内外分列 |
| **判定不适用面（不是所有决策都该交给判定）** | 判定**不是决策层的默认件**，有明确不该交给它的情形：① **要生成散文** → 用生成模型，判定不写字 ② **需多轮推理或工具调用** → 用 Agent，判定只做单跳判断 ③ **决策是结构化输入的纯函数、能用确定性代码直接写出** → **去写代码**；判定只处理「代码已经开始变形」的那一类（正则与手工阈值越缠越深的地方），代码清楚的场景交给判定是白增一层不可审计的间接 ④ **延迟预算在十毫秒量级** → 判定件本身在数百毫秒档，这种场合**答案是小分类器**。一句话：**判定的价值来自「输入没法写死、但答案空间可以写死」**——两侧任一不成立，即回到确定性代码或生成模型 |
| **三层级联（判定在系统中的位置）** | 判定**既不替换**生成模型、**也不替换**确定性代码，而是坐在两者之间：**判定先做便宜的判断与分类 → 确定性代码处理它能处理的部分 → 生成模型只接剩下的难例**。这与「判断与生成分离」是同一件事的两面——**判定管内环**（分类 / 重排 / 门控 / 路由，输出供代码分支），**生成模型管外环**（理解用户 / 调工具 / 综合答复，输出供人阅读），两者**不是竞争者，是不同层**。生态共识表述为「**判定只判断，执行归代码**」：门槛、风险否决与执行动作**一律留在确定性代码**，判定只提供带概率的判断 |

## 四、四层性能标准（判据级 / 校准级 / 分流级 / 端到端）


> **形态归属**：`[主干]`（判定·性能标准）｜ **不可拔**（性能标准是能力声明的依据）

### 交付

| 层 | 度量 | 说明 |
|----|------|------|
| **判据级** | 逐判据准确率 / 一致率 | 与 v1.6.0 / v1.7.0 同数据集同评测器口径（对照不漂移） |
| **校准级** | ECE / 分桶可靠图 | 概率可信度独立度量，**不与判据级合并** |
| **分流级** | 三段门控（高自动 / 中复核 / 低转人工）的实际错误率 | 门槛对应的**真实错误率**落数（这是门槛是否有意义的唯一证据）。**须与其对偶量成对落数**（见下一行）——只报错误率回答不了采购方的问题 |
| **分流级错误率的对偶量** | **固定错误预算下的可实现覆盖率**——在某错误率上限下能**自动放行**的比例（回落到中复核 / 低转人工的部分不计入） | 与上一层**必须成对出现**：**错误率是成本上限，覆盖率是自动化收益**——同一门槛的两面，缺任一面都无法定价。生态已有**完全同名维度**可同口径对照——`AbdelStark/jev-benchmarks`（Apache-2.0）的「Selective automation」维度自述为 *Maximum threshold-realizable coverage at a fixed empirical error budget*（**只记维度名与定义**；其数字本仓未复算，不引用）。**同向纪律**：与「弃权是一等输出」及第五章[「高精度不得单独作可用性依据」](#五第四方对照不是自说自话)同源——覆盖率同样**不得单独报**，须连同错误预算一并给出 |
| **端到端** | 判定延迟（单次 / 批量 / 并发劣化）+ 判定失败率 + 降级次数 | 一体机实测（v1.8.0 落数的正式化），**按硬件档位分列**——至少「有独立 GPU 的服务器档」与「无独立 GPU 的单机档」两行（与 [v1.8.0 第三章](../v1.8/v1.8.0.md)「最低可用档」同口径）；**禁用单一机型的读数代表全部档位**——两档实测差可到数量级（生态读数：同一件在 M5 Pro 64 GB 上为 444 ms、在 H100 上为 106 ms） |
| **端到端 · 治理开销（与判定延迟分列）** | 注入 / 审计 / 回溯 / 沉淀 各自的实际开销，**按「每次变更」计而非「每次判定」计** | 五能力触发时机互不相同（启动前 / 变更时 / 事后快照 / 批量 / 周度 cron），**都不在判定热路径上**——判定是单次非自回归前向（最低可用档实测稳态 p50 在毫秒个位数，[Case 023](../../evidence/cases/node-inference-stack-2026-09-23/README.md)），治理写路径是 append-only 留痕 + 事件触发。**两者不得相加报成单一「总延迟」**——量纲不同，拼合出的第三个数不是任何一方的读数（同「多源数字禁拼合」纪律）。**「不在热路径」是架构事实，不是免于落数的理由**：治理开销须有独立读数，否则「插了治理会不会拖慢判定」这类问题将无法回答 |
| **判定调用密度** | 每任务的**判定调用次数**（调用总量 / 任务数）——判定不是免费的：调用密度既是成本指标，也是**设计质量的信号**（一次任务调二十次判定，通常意味着问句该合并、或该拆到确定性代码里去）。成熟形态的量级是「单任务打分次数仅数次」 |
| **打包并发的成本杠杆** | 同一份 `state` 下的多个问句**须打包成一次请求**，不得串行多次调用——这是判定层**最大的单点成本优化**：生态实测把五次串行调用合并为一次打包后，**延迟降约五倍、成本降约一个数量级**（另一组十三问口径给出同量级结论）。因此**调用密度指标须区分「串行调用次数」与「打包请求数」**——只报前者会把打包成效记成假象。**收益与代价须同批落数**：收益是延迟与成本，代价是**概率偏移**——打包把多个问句塞进一次前向，跨打包模式的概率读数会漂（生态实测最坏绝对差 **0.018**；其基准容差 0.03 且自述是**测试容差不是校准保证**；另一件在 bf16 与 fp32 之间测到至多 **0.017**、最优选项未变——两个独立制品在两个不同维度上给出的偏移量级都落在 0.017–0.018）。⇒ **偏移不得按零假定**，须与校准级、分流级同批落数，且**校准按哪种口径拟合、评测就用哪种口径** |

### 交付要点

- 四层**分别落数、分开报告**（禁止压成单一分数——合并会掩盖「判得准但概率不可信」「概率可信但太慢」这类危险组合）
- 每层给出**阈值**与**未达阈的处置**（未达阈不得对外宣称该层能力）
- 性能标准写入 `docs/VALIDATION.md`，作为对外能力声明的唯一依据
- **可复算产物**：四层落数的每个数字须附生成脚本与结果文件入仓；不可复算的数字标注「单次运行 / 私有数据」口径，**不与可复算数字并列展示**
- **成本的主体是输入而非输出**：判定件的输出通常计价自由或近乎自由，账单几乎全部由**输入 token** 构成——成本优化的着力点是**问句与 state 的尺寸**（合并问句 / 裁剪 state / 复用前缀缓存），而不是压缩输出。生态共识：**贵的是你的提示词，不是模型**
- **「能跑」必须带档位**：单机档的落数须连带给出**可承载与可训练的规模随可用内存的对照关系**，不是只报一句「某机型能跑」——可训规模由可用内存决定而不由机型品牌决定，只报机型等于过度承诺；**且「单机」须分清推理侧与训练侧**（生态实测：推理侧笔记本档已可直接服务，训练侧小档已跑通、大档仍在云卡），把推理侧读数当训练侧依据是同族过度承诺
- **延迟的用途是职责边界**：端到端延迟不只报毫秒，须同时给出「该延迟下判定可承担的职责层级」（与 [v1.8.0 第三章](../v1.8/v1.8.0.md) 职责频率分层同口径）

### 对照纪律

- **确定性基线先行（判定件之前的判定）**：任何判据面落数前，**必须先跑完确定性基线**——正则 / 关键词表 / 词频统计 / 简单规则引擎，把它们的准确率与延迟一并落数。生态实测给出过教训：垃圾邮件集上 TF-IDF 基线 98.39% 与某判定件 98.33% **打平**、两行正则在特定钓鱼检测上**胜过**判定件的单大问。判定件只在「确定性基线到不了的那一档」才有存在意义——不先量出基线在哪，就没法证明判定件贵得有理由。这与「纯函数型常数留代码、不判定化」同一条纪律的落数面
- **同判据集、同评测器**（口径一致是可比的前提；口径不可比时**只列数字不排名**）
- 公开报告须同时给出**准确率 / 校准 / 延迟 / 成本**四维（只报有利维度即失去意义）
- 引用第三方数字时**标注来源与口径**（自报 vs 独立实测须区分）
- **分布内外分列**：本版落数须沿用 v1.6.0 的分布内外口径——在**已训练任务族内**与**从未见过的任务类型**上分别报数（生态实测的落差量级约 24 个百分点，合并会掩盖判据面扩展的真实风险）
- **多语分列（语言是分布的另一维）**：判定件落数须按**语言与书写系统分列**报告召回与误报——生态厂商自报实证：Llama Guard 4 输出过滤 recall 英语 69% vs 七种非英语平均 43%（误报 11% / 3%，模型卡自报、本仓未复算）；「英文档在非拉丁脚本上高置信度失效」与 laya 反例（英文 checkpoint 在非英语上崩塌且置信度照高）同族。工程含义：先假设英文档在中文 / 代码混写上不成立，按语言分别建标注集，**禁止聚合数掩盖失效段**——对「中文优先」路线这不是可选项，是硬口径
- **对手格式破坏率的机理解释须一并入档**：跨厂商对照中对手的格式失败率可达**两位数百分比**（实测两例为 17.00% 与 45.50%），这**不是对手能力差**，而是**对照通道本身的偏置**——判定件走类型化接口（结构由契约保证），对手走文本通道，其结构约束只能靠提示与重试维持。**对手方适配器亦自承该对照「并不构成一次公平测试」**（拿不到对手的原始输出分布，只能请求字符串、不中重问）。这一条须写进对照说明，**否则格式失败会被误读为能力差距**
- **同一对象的多源数字冲突时并列各源原值，禁自行拼合**：同一判定件的公开数字在不同来源间可相差一档（实测：同一发布物在不同来源的基准口径下出现过**十个百分点级**的准确率差异，另有一来源给出完全不同的精度口径）——**各源各自是有效读数，拼合出的第三个数不是任何一个来源的读数**。处置：**逐源列出原值 + 出处 + 口径**，交由读者裁定，**不得合成一个取舍后的数字**
- **公开实测存档须含「判定件被推到能力边界」的实例**：生态里判定件已在两类与审计同源的场景留下可引用数字——① **单据与表单分类**（实测 261 份表单严格准确率 100%，单页成本约千分之一美元，比其原有生成模型管线**便宜三十余倍、快数倍**）② **高频决策回路**（实测每约三百毫秒做一次带概率判断，且**阈值、风险否决与执行全部留在确定性代码**）。引用时**只作形态参照**——其评测集均系对方自建，**只可并列不可排名**
- **对照件准入鉴别（同题不等于同能力）**：同期判定件几乎全部自称「Jev 复刻」，**复刻的是接口还是本体、有没有可验证产物，须逐项鉴别后才能进对照表**——五项判据：① 是否**公开权重与数据**（无权重 ⇒ 只能引用自报，不可自测）② **state 是否只编码一次**（多次重复编码 ⇒ 延迟读数不可比）③ **question 是否真隔离**（同请求内多问互不污染，否则打包读数不可比）④ **概率是否直接 readout**（走生成再解析 ⇒ 不属非自回归，与本仓不同构）⑤ **benchmark 可否复现**（能否用其仓内产物重算）。任一项缺 ⇒ 降为「接口参考」，**不入对照表、不作排名依据**。具名来源、许可与三面评估见 [THANKS · 判定与校准](../THANKS.md)
- **对照数字须带对照系版本锚，并定期复验**：引用任何第三方数字必须同时记录**对照系版本号**与**引用时点的口径**——同期赛道迭代极快（实测两件判定件在同一周内相继发布，其后数日仍有版本更新），**对手发新版即把旧对照标记为不可比**，不得继续作为当期依据；复验触发条件为「对照件发版」或「本仓对照回合重跑」。与 [v1.7.0 §三](../v1.7/v1.7.0.md)「判定制品四件套的联合版本锚点」同族——任一件变更即旧锚点不可比，只是粒度落在**跨仓对照**上
- **不利结论照录**：第三方实测已显示判定件的准确率可能低于前沿生成模型一档——这类结论**进 VALIDATION 而非删去**，判定件的卖点是延迟与成本，不是准确率。**第二个实例（独立横评）**：某项独立横评（5 suites / 60 cells / **花费与 raw log 全公开 / 无厂商赞助**）给出三条对我们不利或需修正认知的结论——① **厂商宣称的 40–200× 倍率在独立口径下不成立**：对**最快**的 LLM 档只快约 1.2×，那个倍率只在「拿自己与**留在最慢默认模式**的 LLM 比」时才成立；② **「没有一类在质量上胜出」**——多类任务上受限 LLM 与判定件互有胜负，部分 LLM 档甚至低于多数类基线；③ **选项上限真实且陡峭**（选项一多，优势迅速消失）。🔴 **引用纪律**：该横评所在仓库**仓库根无 LICENSE**（实测 `license=null`）⇒ 本仓**只作读数参照，不作对照件、不引其数据入仓**，亦不排名（与上条「对照件准入鉴别」同向）；**只陈述结论方向与口径，不抄其具体百分数**（本仓未复算）
- **对照须为「预注册非劣性检验」，不是事后择优**：判定件 vs 生成式 judge 的对照，应在**预先注册的 margin** 下做**非劣性检验**（事先声明「允许差多少算打平」），而不是跑完一堆配置再挑最好的一次去比——后者是**事后择优**，对照组的可比性会被「挑」掉。**正面范例（可逐行读）**：某第三方工作把「小判定件（LoRA 微调 + 温度标定 softmax readout，单次前向、无生成文本）」与「LLM judge 基线」在**预注册 margin** 下判**非劣**，并**主动自曝该配方带着测试集暴露（test-set exposure）选出**、样本全为合成数据。⇒ **「预注册 margin + 自曝测试集暴露」正是「谱系声明三件套」的正面范例**（[v1.7.0 §三「数据集谱系声明」](../v1.7/v1.7.0.md)）：这里的「污染声明」不是事后补的脚注，而是**作者自己先说出来**。出处：`arXiv:2609.23959`（判定件小模型 + 校准 readout）。**引用同规**：只落口径与方法，不抄其具体数字（本仓未复算）

- [ ] 跨厂商对照中**对手格式破坏率与通道偏置说明**一并入档（不使格式失败被读成能力差距）
- [ ] 同一对象出现多源数字时**逐源并列入档**（含出处与口径），无拼合后的单一数字
- [ ] 公开实测存档条目均标注**评测集归属**（对方自建 ⇒ 只并列不排名）
- [ ] 权重可下载的对照件**已用本仓评测器自测**（非仅引用自报数字），且架构与参数量档位记录在案。**「同判据集」按 [v1.6.0 §五](../v1.6/v1.6.0.md) 的跨域映射口径执行**（本仓评测器与用例集均在位，缺的是跨域口径与适配层）：判据按**认知负载类型**归等价类，类内同 state / 同金标 / 同评测器，**类间不比**；对照件经**双向适配**接入（仓内 `diffFiles[].lines` + `task` → state 文本；对照件输出 → `result`）；**仅 `result`（PASS/FAIL）一维参与对照**——`rules_triggered` 与 `severity` 为审计域投影，**显式声明不可比**；至少保留一组**桥接判据**作跨域硬锚点
- [ ] 每条第三方数字带**对照系版本锚**（版本号 + 引用时点口径），复验触发条件写明
- [ ] 对照件已过**准入五项鉴别**（公开权重与数据 / state 单次编码 / question 隔离 / 概率直接 readout / benchmark 可复现），未过者降为接口参考、不入表不排名

### 风险与前置假设

> ⚠️ **对照可能显示判定件并不占优**——同类开源判定件（基于 9B 基座做微调，参考标签一致率从基座 66.36% 提升到 90.12%，其闭源参照为 93.21%）提示：判定能力对**数据质量**的敏感度远高于参数量。若我们的数字落后，如实落数并定位原因（判据质量 / 数据量 / 训练方法），**不通过更换评测口径来美化**。
>
> ⚠️ **本版带叙事章，但叙事只讲形态与验证方式，不讲「比 X 好」**。性能对比归 VALIDATION 的落数，叙事不做结论性宣称。

## 六、静默失败监控与判定使用度量


> **形态归属**：`[主干]`（判定·可观测性）｜ **不可拔**（静默失败是判定层最危险的失效形态——无报错、无异常、答案照出，监控是唯一防线）

前三章回答「判定有多好」，本章回答「**判定坏掉时我们怎么知道**」。判定层的失败多数**不抛异常**：类型对了、结构对了、答案出来了——只是答错了。因为**类型安全意味着没有解析器会替你报警**：一个返回了合法 `Choice` 分布的模型，从类型系统看与一个答对的模型完全一样。这一章是判定层与「能跑」之间最后一道缝。

### 交付

| 组件 | 能力 |
|------|------|
| **静默失败四探针** | 产出级探测（与 v1.4.5 的 `providerStatus` 产出级探测同族，探测对象从「进程活着」深化为「判定还有效」）：① **输出分布漂移**（某判据的选项分布突变为单峰或均匀）② **概率分布异常**（长期贴 0.5 或长期贴 1.0——两者都是未校准或模式坍塌的特征）③ **弃权率突变**（骤升或骤降）④ **输入长度与延迟的异常相关**（提示触发了截断或降级）。超阈**告警不阻断**，但告警必须**可见**（面板 + 周报），不允许只落日志 |
| **入口前置分流（判定通道在选择点就定）** | 判定通道的选择必须在**任何模型加载之前**完成，**分流决定与理由可查**——不得静默走默认路径。**为什么单列**：四探针是**事后**探测（分布漂移 / 概率异常 / 弃权突变 / 长度-延迟相关），全都发生在「已经跑起来之后」；而「一开始就选错路径」在事后探针里表现为正常输出，**探针抓不到**。外部对照：Laya 在任何模型加载前完成路由，其 docstring 明写「typed-decisions 不应成为静默默认」——把路径选择提到加载之前，才有资格谈「选得对不对」 |
| **判定使用度量** | 判定被调用后下游**采纳了多少**：判定值采纳率 / ASK 率 / DENY 率 / **被人工推翻率**（推翻率是判定质量最直接的外部信号）。**「已上线但无人消费」与「上线即被推翻」必须能区分**——前者是集成问题，后者是质量问题，混成一个数字则两者都无法处置。**红旗群**：ASK 率趋近于零 · **获批率恒为 100%** · **审批时延落在提示后 1–2 秒** · **人均审批量异常高**——四者同时出现即门控退化为形式（与 v1.7.0 门控健康度同族，此处是观测侧的落地）。**作弊观测位（旁路指标，独立于优化目标）**：对参与晋级/自进化循环的判定面，加**奖励作弊率**观测——留出集上「分数升而独立任务质量证据未升」的样本占比（行业实证：AIDE² 8 天自主运行作弊率 55%→32% 而**循环从未显式优化该指标**——作弊解在隐藏评测上不稳、被留出选择当作泛化噪声筛掉，[arXiv:2609.26457](https://arxiv.org/abs/2609.26457)；本仓读法：作弊率上升＝代理目标被利用的可见信号，与 [v1.5.8 §二](../v1.5/v1.5.8.md) 四门槛互为表里——门槛管「不接受可疑收益」，本探针管「发现已溜进来的」）。只观测不阻断，超阈告警进治理周报 |
| **设计有效性与运行有效性分列** | 判据齐全、正负样例在位是**设计有效性**；实际判过、留痕在位是**运行有效性**——**两者须分列报告，并显式报告两者之差**。生态实证：对 Agent 的控制只能从**运行记录**测其运行有效性，而**运行证据缺失本身就是一条 finding**——「无法证明它没乱来」对一个自治系统而言与「它乱来了」是同级治理缺陷。这与本版「判定质量 / 概率可信度分列」同族：**禁合并** |
| **压缩留痕完整性** | 上下文压缩（v1.4.8 自动压缩，实现于 `engine/inject/src/load-chain/compactor.ts`）是**有损**的，但判定依据的留痕必须**无损**：压缩后判定当时依据的证据须仍可在审计链上还原——留痕保存**压缩前的判据输入引用**而非压缩后摘要。**为什么这是判定层的问题而非文档问题**：被压掉的很可能正是判定所依据的那条证据，留痕若只剩摘要，审计就无法回答「当时凭什么这么判」 |
| **四层性能标准的持续采集面** | §四 的四层落数依赖**稳定采集**而非一次性跑分——本版为其提供持续采集与趋势视图（判据级 / 校准级 / 分流级 / 端到端各自的时序曲线），使「能力退化」在版本之间就可见，而不是等下一次评测才发现 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/router/judge-observability.ts` | 新建 | 静默失败四探针 + 判定使用度量采集 |
| `engine/inject/src/load-chain/compactor.ts` | 修改 | 压缩时保留判据输入引用（压缩前证据可还原） |
| `tools/dashboard/` | 修改 | 判定使用度量面板（采纳率 / 推翻率 / 探针趋势） |
| `engine/orchestrator/src/__tests__/judge-observability.test.ts` | 新建 | 探针触发 / 度量口径 / 压缩留痕完整性单测 |

### 验收标准

- [ ] 静默失败四探针在位且各有触发用例（分布漂移 / 概率异常 / 弃权突变 / 长度-延迟相关）

## 九、版本弹性机制（后续开发量剩余的处置方式）


> **形态归属**：`[非功能]`（排期纪律——**本版首次落盘**）｜ —

### 机制

| 情形 | 处置 | 理由 |
|------|------|------|
| **阶段内开发量超出预期** | 在**该 minor 内增补补丁位**（`vX.Y.1`），不挤后续 minor | 阶段内主题一致、依赖连续，增补成本最低；跨阶段挤压会破坏「每版可独立验收」的前提 |
| **出现新识别的工作面** | 在阶段之间**插入新阶段**（如 `v1.10.x`），并保持原四阶段编号不变 | 编号稳定便于引用；插入而非重排可避免全仓版本号重写 |
| **V2.0 时点** | **不锁死在 v1.9.0 之后**——V2.0 在「四阶段收口达阈」时点到来，之前不停留 | 形态宣告的时点由**达阈状态**决定，不由版本号决定；形式上成立却内容未达阈时宣告，等于把叙事跑在实现前面 |
| **单版内容上限** | 每版内容以「**可独立验收的交付单元**」为界，不以「章数」硬凑 | 颗粒度细化的目的就是让每版能独立停、独立验 |
| **不允许** | 把多个阶段的工作挤进一版；或为了「按计划进 V2.0」而放宽达阈标准 | 前者破坏可验收性，后者破坏证据链 |

### 验收标准

- [ ] 弹性机制写入 ROADMAP 与 changelog 目录说明（后续版本增补有据可依）
- [ ] 已增补 / 已插入的版本记录在册（版本号不复用、不重排）
- [ ] V2.0 时点表述统一为「四阶段收口达阈时」（非「v1.9.0 之后」）
- [ ] `docs/changelog/README.md` 记录阶段与版数关系

### 风险与前置假设

> ⚠️ **弹性机制可能被滥用为「无限延后」**。约束是：每次增补补丁位**须有明确的未达阈项或新识别工作面作为依据**，并在 changelog 中记录增补理由——「感觉还没做完」不构成增补依据。
>
> ⚠️ **本版仍不改对外产品身份**。身份切换是 V2.0 的动作，本版只把口径铺平。若本版提前宣告身份，会让 V2.0 失去「一次定义到位」的意义（P18 拍板：形态成立时点 = V2.0，不设中间成立点）。
