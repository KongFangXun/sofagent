## 定位


> 🧩 **判定底座 · 既有判定面收敛**——阶段四第一版，回答「**已有的那些判定能力怎么办**」。实测普查（2026-09-20）的结论是：引擎里 Choice / Score / Noul 三种原语的**形状全都已经存在**——`fde_classify` 的「三问输入 → 三选一输出」已是 Choice + Noul 的组合、`evaluate` / `quality-judge` 是 Score、`shouldAllow` 是 Noul——**但三者共缺同一个维度：校准概率**。本版把已有判定面接上判定底座，同时完成一件更重要的诚实性工作：**把「假概率」正名**。

> 📊 **判定底座 · 判据面扩展与四层性能标准**——阶段四第二版，回答「**怎么证明它真的有用**」。判定能力的正确性不由通用榜单定义，而由**自有判据集上的分层性能**定义——本版把判据面从审计规则扩到 workflow / 本体数据 / 路由判定。同时给出**四层性能标准**与**第四方对照**，把判定能力的证据链首次公开。**纪律**：性能以自有判据集为准，**不比通用 benchmark**（通用榜单与判定任务不同构，比了也无解释力）。第六章补上这套证据链**失效时**的探测器——判定坏掉时它不会报错，只会安静地答错。

> 🏁 **判定底座 · 施工期收口与全站口径对齐**——施工期最后一版，回答「**收没收口、能不能进 V2.0**」。本版不新增判定能力，只做三件事：判定四阶段是否全部达阈、全站口径是否对齐、以及**把弹性机制写死**——后续若仍有开发量剩余，**加版本而不挤版本**。

## 一、三原语既有实现补概率（形状已有，补上第三维）


> **形态归属**：`[主干]`（判定·既有面收敛）｜ **不可拔**（判定输出契约）

### 交付

| 既有能力 | 现状（实测） | 本版收敛 |
|----------|-------------|----------|
| **`Choice`**——`fde_classify` | 三问布尔输入 → 三选一（🔄自动 / ⚡强化 / 👤暂不动），**无概率** | 保留三选一语义，补**全候选项分布**；输入三问由布尔升级为**可带概率**（保留纯布尔兼容路径，不破坏既有调用方） |
| **`Score`**——`evaluate` / `evaluate_output` / `quality-judge` | 裸分值，**无不确定度** | 补**可信区间**（校准备用）与档位序信息；分值口径与既有保持不变，纯增量 |
| **`Noul`**——`shouldAllow` / 规则 verdict | 纯布尔（`allow: boolean` + `requireApproval: boolean`），**无概率** | 保留布尔结果（**执行语义零改动**），并列输出**判定成立概率**——布尔仍是执行依据，概率是复核与分流的输入 |
| **判定源统一** | 三处各自实现，无共同底座 | 三类判定统一路由到判定底座（`DecisionChannel`）；**降级路径保留**（判定底座不可用时退回既有确定性实现，行为与今日一致） |
| **确定性规则不动** | 全部审计规则判定面（现行 SSOT 为 28 条） | **零改动**（本版只补概率维度，不改规则语义与执行顺序——确定性规则在前，语义判定在后） |

## 二、假概率正名（诚实性工作 · 不伪造校准）


> **形态归属**：`[主干]`（判定·数值语义正名）｜ **不可拔**（数值语义失真会误导下游门槛设计）

### 实测现状（2026-09-20 普查）

引擎内散布的置信度数值，**没有一个是校准概率**，且分三类不同性质：

| 性质 | 实测样例 | 正确处置 |
|------|----------|----------|
| **硬编码常数** | 根因分析内 `confidence: 0.7` / `confidence: 0.6` 等直接写死的数值 | 属**启发式权重**，非概率——**正名为权重**，或接入校准后替换 |
| **枚举映射出的数值** | PR 触发绑定两态枚举映射为 `1.0` / `0.5`；决策 schema 的 `'high' \| 'med' \| 'low'` 三态 | 属**序数等级**，非概率——**保留等级语义**，导出数值时标注为序数而非概率 |
| **真概率字段** | **全仓零命中** | 本版起由判定底座补齐 |

> **生态实例佐证（2026-09-25 补录）**：「非常确定地答错」已有具名实测——某开源本地判定件在 40 条冻结中文工单上，把「企业版年付多少钱、要正式报价单」（应分售前）以**接近 100% 的置信度**判成账单类：不是犹豫着错，是**坚定地错**。这印证本章正名的必要性：一条置信度门槛拦得住「拿不准」，拦不住「有偏见的错」——9 毫秒做出的错决定依然是错决定；正名 + 校准 + 弃权三件缺一不可（正名让它说清自己是什么，校准让数值可验证，弃权给「判不了」出口）。

### 交付

| 组件 | 能力 |
|------|------|
| **语义正名** | 按上表三类分别处置：能校准的接校准（v1.7.0 能力），本质是权重/等级的**正名为权重/等级**——**不把权重伪装成概率** |
| **调用侧可分辨** | 数值携带语义标记（`probability` / `heuristic-weight` / `ordinal-level`）——下游按标记决定能否进概率门槛，**标记缺失按不可信处理** |

### 风险与前置假设

> ⚠️ **本版的产出是「诚实」而非「更强」**。正名后的数字可能看起来「更弱」（从 `0.7` 变成「一个启发式权重」），但这是必要的——把权重当概率用于分流门槛，会让门槛的含义从根本上失真，错误率无法预测也无法举证。
>
> ⚠️ **本版不改判定行为**。行为收敛若需要，属后续版本独立评估——把「语义正名」与「行为改变」混在一版，会让回归问题无法定位。

## 三、判据面扩展（从审计规则扩到三类判定域）


> **形态归属**：`[主干]`（判定·判据面）｜ **不可拔**（判据面是能力的边界声明）

### 交付

| 组件 | 能力 |
|------|------|
| **workflow 判据面** | 编排任务的判定判据（该不该触发 / 该走哪条支路 / 该不该升级）——判据来自 v1.5.1 事件驱动与 v1.5.4 判定分层的既有语义 |
| **本体数据判据面** | 本体实体/关系操作的判定判据（该不该建 / 该不该合 / 该不该失效）——对接 v1.5.0 双时态与 Validation Engine 既有语义。**召回链路三问（生态应用先例，2026-09-25 登记）**：本体数据域的判定消费形态可参照「本体（世界状态）→ 判定（召回三问）→ 程序闸门（校验/拦截/人工）→ 生成」四段链路——判定件对每条候选证据依次回答：① **Choice 认类**（该认哪一类 / 走哪条召回链路——「客户」在销售域与风控域是不同对象，字面相似不等于同类）② **Score 贴合度**（证据与问题打几分）③ **Noul 准入**（该不该进上下文 / 要不要人工复核）——把「找相似的」升级为「认对类 → 决定捞不捞」。**关键边界**：判定只出判断不写库、不生成答案，证据进上下文必须过程序闸门（与本仓「判定建议不具执法力」「证据面不扩大」同源）；没有本体骨架时判定件退化为换皮分类器——**骨架先挡类、判定再拍板、闸门管使用**，三者缺一即退化。该链路是本体数据判据面在知识库场景的首选消费形态。**「重排+门控」二合一模式（2026-10-13 登记 · 外部一手蒸馏）**：Jev+RAG 生态实证了判定件在检索管线的标准接法——**查询为共享状态、各检索候选为独立候选项**，一次带类型提问（「这段文字是否有助于回答该查询？」）对全部候选并行出概率，替代传统 reranker；应用侧双阈值：**高于阈值的候选进 LLM 上下文、低于者移除**（重排序），同一请求再判**可回答性**（answerability）——低于阈值直接返回「不在文档中」**跳过 LLM 调用**（省生成成本 + 消灭「从薄弱证据生成看似合理答案」）。**边界同款成立**：判定不动检索本身（「检索决定上限，判定救不回从未进入候选集的段落」）、不替换嵌入模型/向量库/生成模型。对本仓的落点：本体数据判据面的召回三问（认类/贴合/准入）正是该模式的**三原语特化**——Choice 认类、Score 贴合度、Noul 准入一一对应重排+门控两职能；判据落地时按「共享状态 + 候选并行 + 双阈值」模式验收（来源：TypeSafe 官方 Jev+RAG 用例文档，经公众号转述发现、一手核对，@2026-10-13）。**「检索前判定」补全三段式（2026-10-13 晚登记 · Jev Search 实证）**：上述重排+门控只覆盖「结果回来之后」，Jev Search（`superagents-lab/jev-search`，MIT，Search1API 出品非 TypeSafe 官方）实证了**检索之前**的判定职能——判定件先做**意图判断**（该查什么：来源选择 / 时间窗口 / 检索词构造，12 类来源按问题自动组合而非全量并发），执行仍归 Search1API，页面保留原始链接+摘要+相关度分+可改筛选（模型判断只是默认值，用户可覆盖——「判定出建议、人执最终选择」的消费形态样本）。与我们门控纪律同款的三条工程细节：① **故障隔离**——单来源超时显式警告，不伪装成「无结果」（与「静默失败」防线同族）；② **去重防放大**——重复来源请求前去重，不能靠重复填写放大调用次数（成本纪律）；③ **failover 白名单窄**——仅 402/429/5xx 切换 provider，400/401 原样暴露（配置错误不自动掩盖）。落点：v1.8.0 判定档接通后「意图判定→检索→重排门控」三段全链路的判据面登记——**判定件在检索管线的完整形态 = 前置意图判定 + 后置重排门控，中间执行归确定性代码**（经公众号转述发现，一手为仓库 README+代码审查帖，@2026-09-22） |
| **路由判定判据面** | 请求难度与敏感度的判定判据（该走哪档）——对接 v1.5.4 路由层与 [v1.8.0 第四章](../v1.8/v1.8.0.md) 判定档 |

| **域的适用边界** | 明确判定底座**未验证的域**（开放式写作、主观偏好、长链推理）——不在无验证器的域宣称判定能力（对齐「验证差距」纪律：验证比生成便宜才有自动化的前提）。判据面的**扩展**须以**分布外表现**为前置输入——生态实测的泛化落差约 24 个百分点（已训练任务族可用不等于新任务类型可用），口径见 [v1.6.0](../v1.6/v1.6.0.md) 分布内外分列 |
| **判定不适用面（不是所有决策都该交给判定）** | 判定**不是决策层的默认件**，有明确不该交给它的情形：① **要生成散文** → 用生成模型，判定不写字 ② **需多轮推理或工具调用** → 用 Agent，判定只做单跳判断 ③ **决策是结构化输入的纯函数、能用确定性代码直接写出** → **去写代码**；判定只处理「代码已经开始变形」的那一类（正则与手工阈值越缠越深的地方），代码清楚的场景交给判定是白增一层不可审计的间接 ④ **延迟预算在十毫秒量级** → 判定件本身在数百毫秒档，这种场合**答案是小分类器**。一句话：**判定的价值来自「输入没法写死、但答案空间可以写死」**——两侧任一不成立，即回到确定性代码或生成模型。**成本面的双刃剑（杰文斯悖论，2026-09-25 登记）**：判定便宜到输出免费（$0.042/百万输入 token）后，**原本因成本不做的大量语义判断会被大规模加进系统**——消耗量随效率爆炸增长；但这枚硬币的反面是**「更快更便宜地重复错误」**：判据本身有偏差时，便宜只会让同一个错判得更频繁、更难察觉。对策不在限速而在**质量闸**——判定使用度量（本章第六章）与静默失败监控就是为「判断量暴涨后仍可审计」设计的：采纳率 / 被推翻率 / 输出分布漂移在判断密度上升时**必须跟着看**，不可只看吞吐 |
| **选项互斥性（问题定义质量是判定上限）** | 判定件**不会替调用方修复混乱的选项表**——候选项重叠（如「物流延迟」与「申请退款」可同时成立，一因一果硬做成单选）时，模型只能在错误的问题上给出自信的答案；state 信息不全时同样补不出缺失的证据（识别退款意图是语言题，批不批准退款是事实+规则+授权题——两道题混在一道里判定，职责就悄悄放大）。**判据 lint 增补软项⑦「选项互斥性」**：`Choice` 候选两两可同时成立即提示（软项不阻断——互斥性业务上常不可机械判定，交 lint 提示 + 判据评审人工把关），与既有软项⑤可校准性/⑥判据重复度同族；问句集限定（v1.6.0 §一）管「类型不越界」，本条管「问题本身不畸形」——**接口再快，问题定义质量就是判定质量的上限** |
| **三层级联（判定在系统中的位置）** | 判定**既不替换**生成模型、**也不替换**确定性代码，而是坐在两者之间：**判定先做便宜的判断与分类 → 确定性代码处理它能处理的部分 → 生成模型只接剩下的难例**。这与「判断与生成分离」是同一件事的两面——**判定管内环**（分类 / 重排 / 门控 / 路由，输出供代码分支），**生成模型管外环**（理解用户 / 调工具 / 综合答复，输出供人阅读），两者**不是竞争者，是不同层**。生态共识表述为「**判定只判断，执行归代码**」：门槛、风险否决与执行动作**一律留在确定性代码**，判定只提供带概率的判断 |

### 交付

| 层 | 度量 | 说明 |
|----|------|------|
| **判据级** | 逐判据准确率 / 一致率 | 与 v1.6.0 / v1.7.0 同数据集同评测器口径（对照不漂移） |
| **校准级** | ECE / 分桶可靠图 | 概率可信度独立度量，**不与判据级合并** |
| **分流级** | 三段门控（高自动 / 中复核 / 低转人工）的实际错误率 | 门槛对应的**真实错误率**落数（这是门槛是否有意义的唯一证据）。**须与其对偶量成对落数**（见下一行）——只报错误率回答不了采购方的问题 |
| **分流级错误率的对偶量** | **固定错误预算下的可实现覆盖率**——在某错误率上限下能**自动放行**的比例（回落到中复核 / 低转人工的部分不计入） | 与上一层**必须成对出现**：**错误率是成本上限，覆盖率是自动化收益**——同一门槛的两面，缺任一面都无法定价。生态已有**完全同名维度**可同口径对照——`AbdelStark/jev-benchmarks`（Apache-2.0）的「Selective automation」维度自述为 *Maximum threshold-realizable coverage at a fixed empirical error budget*（**只记维度名与定义**；其数字本仓未复算，不引用）。**同向纪律**：与「弃权是一等输出」及第五章[「高精度不得单独作可用性依据」](#五第四方对照不是自说自话)同源——覆盖率同样**不得单独报**，须连同错误预算一并给出 |
| **端到端** | 判定延迟（单次 / 批量 / 并发劣化）+ 判定失败率 + 降级次数 | 一体机实测（v1.8.0 落数的正式化），**按硬件档位分列**——至少「有独立 GPU 的服务器档」与「无独立 GPU 的单机档」两行（与 [v1.8.0 第三章](../v1.8/v1.8.0.md)「最低可用档」同口径）；**禁用单一机型的读数代表全部档位**——两档实测差可到数量级（生态读数：同一件在 M5 Pro 64 GB 上为 444 ms、在 H100 上为 106 ms） |
| **端到端 · 治理开销（与判定延迟分列）** | 注入 / 审计 / 回溯 / 沉淀 各自的实际开销，**按「每次变更」计而非「每次判定」计** | 五能力触发时机互不相同（启动前 / 变更时 / 事后快照 / 批量 / 周度 cron），**都不在判定热路径上**——判定是单次非自回归前向（最低可用档实测稳态 p50 在毫秒个位数，[Case 023](../../evidence/cases/node-inference-stack-2026-09-23/README.md)），治理写路径是 append-only 留痕 + 事件触发。**两者不得相加报成单一「总延迟」**——量纲不同，拼合出的第三个数不是任何一方的读数（同「多源数字禁拼合」纪律）。**「不在热路径」是架构事实，不是免于落数的理由**：治理开销须有独立读数，否则「插了治理会不会拖慢判定」这类问题将无法回答 |
| **判定调用密度** | 每任务的**判定调用次数**（调用总量 / 任务数）——判定不是免费的：调用密度既是成本指标，也是**设计质量的信号**（一次任务调二十次判定，通常意味着问句该合并、或该拆到确定性代码里去）。成熟形态的量级是「单任务打分次数仅数次」 |
| **部署体验（FDE 形态标准 · 非性能层 · 2026-10-15 立）** | 前四层量**推理质量**，本行量**「部署到可用」**——外部件（个人形态）的对应优势是「**下载即用**」（Electron 包，数分钟可用）；本仓形态是**驻场部署**，故须以**显式标准**替代「开箱即用」的默认体验。**五项可测指标**（数值与四层标准同批落数，按硬件档分列）：① **部署时长**（硬件就位 → 服务可用，含模型加载）② **首次可用**（客户**在无交付方协助下**完成首个任务：首个判定 + 首个交付物可查 + 审计链可导）③ **自证能力**（客户可自行导出审计链并**独立验证**，不依赖交付方）④ **断网可用**（切断外网后判定与审计仍可用——数据主权红线的**体验面**）⑤ **可替换演练**（客户可自行替换判定件或模型并验证契约不变）。**为什么单列**：五项均不属「性能」，但决定**客户能否自主使用**——它们是采购方的验收问题，不是工程指标 |
| **打包并发的成本杠杆** | 同一份 `state` 下的多个问句**须打包成一次请求**，不得串行多次调用——这是判定层**最大的单点成本优化**：生态实测把五次串行调用合并为一次打包后，**延迟降约五倍、成本降约一个数量级**（另一组十三问口径给出同量级结论）。因此**调用密度指标须区分「串行调用次数」与「打包请求数」**——只报前者会把打包成效记成假象。**收益与代价须同批落数**：收益是延迟与成本，代价是**概率偏移**——打包把多个问句塞进一次前向，跨打包模式的概率读数会漂（生态实测最坏绝对差 **0.018**；其基准容差 0.03 且自述是**测试容差不是校准保证**；另一件在 bf16 与 fp32 之间测到至多 **0.017**、最优选项未变——两个独立制品在两个不同维度上给出的偏移量级都落在 0.017–0.018）。⇒ **偏移不得按零假定**，须与校准级、分流级同批落数，且**校准按哪种口径拟合、评测就用哪种口径** |

### 交付要点

- 四层**分别落数、分开报告**（禁止压成单一分数——合并会掩盖「判得准但概率不可信」「概率可信但太慢」这类危险组合）
- 每层给出**阈值**与**未达阈的处置**（未达阈不得对外宣称该层能力）
- 性能标准写入 `docs/VALIDATION.md`，作为对外能力声明的唯一依据
- **可复算产物**：四层落数的每个数字须附生成脚本与结果文件入仓；不可复算的数字标注「单次运行 / 私有数据」口径，**不与可复算数字并列展示**
- **成本的主体是输入而非输出**：判定件的输出通常计价自由或近乎自由，账单几乎全部由**输入 token** 构成——成本优化的着力点是**问句与 state 的尺寸**（合并问句 / 裁剪 state / 复用前缀缓存），而不是压缩输出。生态共识：**贵的是你的提示词，不是模型**
- **「能跑」必须带档位**：单机档的落数须连带给出**可承载与可训练的规模随可用内存的对照关系**，不是只报一句「某机型能跑」——可训规模由可用内存决定而不由机型品牌决定，只报机型等于过度承诺；**且「单机」须分清推理侧与训练侧**（生态实测：推理侧笔记本档已可直接服务，训练侧小档已跑通、大档仍在云卡），把推理侧读数当训练侧依据是同族过度承诺
- **延迟的用途是职责边界**：端到端延迟不只报毫秒，须同时给出「该延迟下判定可承担的职责层级」（与 [v1.8.0 第三章](../v1.8/v1.8.0.md) 职责频率分层同口径）

| **同冻结集跨件对照（中文工单先例 · 2026-09-25 登记）** | 另一组可横比读数：同一批 **40 条冻结中文工单**先测商业云端件（对 38 条），后测开源本地件（对 31 条）——差距不在边界清晰的场景（物流类两边都对），集中在**售前 / 技术 / 账号等跨部门边界**；云端件 400+ ms 含网络往返、本地件稳态 8–9 ms，「快 50 倍」实为**两种等法不同**（网络 vs 推理），不得当纯推理加速比引用。两组数字系测者自建评测集，只并列不排名；其价值在**跨部门边界是中文判定件的共同弱区**这一结构信号——本仓中文判据集（v1.6.0 §八–九）的困难样本采集应加 weight 到跨域边界类（与九类困难样本采集点「上下文取舍 / 对齐分歧」同族）。对照方法论可复用：**同一冻结集先后测多件**是最小成本的同口径对照形态。**同面另有一手论文（2026-10-02 登记）**：[Chinese-Jev: Bringing System One Model to Chinese-Language Tasks](https://arxiv.org/abs/2609.36965) 把 System One 形态整体迁到中文任务（第三方论文、作者自报、本仓未复算）⇒ 本行所依据的「中文工单先例」由**测者自建评测集**升级为「**同面已有公开论文**」，但**两者不可横比**（不同集、不同件、不同口径），故并列陈述、不排名。**对本仓的用法不变**：中文判据集（[v1.6.0 §八–九](../v1.6/v1.6.0.md)）的困难样本仍以**跨部门边界类**加权采集 |

### 对照纪律

- **确定性基线先行（判定件之前的判定）**：任何判据面落数前，**必须先跑完确定性基线**——正则 / 关键词表 / 词频统计 / 简单规则引擎，把它们的准确率与延迟一并落数。生态实测给出过教训：垃圾邮件集上 TF-IDF 基线 98.39% 与某判定件 98.33% **打平**、两行正则在特定钓鱼检测上**胜过**判定件的单大问。判定件只在「确定性基线到不了的那一档」才有存在意义——不先量出基线在哪，就没法证明判定件贵得有理由。这与「纯函数型常数留代码、不判定化」同一条纪律的落数面
- **同判据集、同评测器**（口径一致是可比的前提；口径不可比时**只列数字不排名**）。**第三个必对齐变量是推理预算（2026-09-27 登记）**：独立对照实测给出——同一尺寸的生成模型在**开启数千 token 的思考预算**时明显强于判定件，而**同一模型关掉思考后骤降**；这意味着「判定件 vs 生成式模型」的对照若不声明并固定对手的思考预算，**比的是对手的推理档位而不是架构本身**。⇒ 本条扩为**同判据集、同评测器、同推理预算**三对齐；判定件的正当对照是「对手在其**目标部署档位**」上的读数，而非其最强档（第三方独立对照、本仓未复算，只落变量纪律不引数字）
- 公开报告须同时给出**准确率 / 校准 / 延迟 / 成本**四维（只报有利维度即失去意义）
- 引用第三方数字时**标注来源与口径**（自报 vs 独立实测须区分）
- **分布内外分列**：本版落数须沿用 v1.6.0 的分布内外口径——在**已训练任务族内**与**从未见过的任务类型**上分别报数（生态实测的落差量级约 24 个百分点，合并会掩盖判据面扩展的真实风险）
- **多语分列（语言是分布的另一维）**：判定件落数须按**语言与书写系统分列**报告召回与误报——生态厂商自报实证：Llama Guard 4 输出过滤 recall 英语 69% vs 七种非英语平均 43%（误报 11% / 3%，模型卡自报、本仓未复算）；「英文档在非拉丁脚本上高置信度失效」与 laya 反例（英文 checkpoint 在非英语上崩塌且置信度照高）同族。工程含义：先假设英文档在中文 / 代码混写上不成立，按语言分别建标注集，**禁止聚合数掩盖失效段**——对「中文优先」路线这不是可选项，是硬口径
- **对手格式破坏率的机理解释须一并入档**：跨厂商对照中对手的格式失败率可达**两位数百分比**（实测两例为 17.00% 与 45.50%），这**不是对手能力差**，而是**对照通道本身的偏置**——判定件走类型化接口（结构由契约保证），对手走文本通道，其结构约束只能靠提示与重试维持。**对手方适配器亦自承该对照「并不构成一次公平测试」**（拿不到对手的原始输出分布，只能请求字符串、不中重问）。这一条须写进对照说明，**否则格式失败会被误读为能力差距**
- **同一对象的多源数字冲突时并列各源原值，禁自行拼合**：同一判定件的公开数字在不同来源间可相差一档（实测：同一发布物在不同来源的基准口径下出现过**十个百分点级**的准确率差异，另有一来源给出完全不同的精度口径）——**各源各自是有效读数，拼合出的第三个数不是任何一个来源的读数**。处置：**逐源列出原值 + 出处 + 口径**，交由读者裁定，**不得合成一个取舍后的数字**
- **公开实测存档须含「判定件被推到能力边界」的实例**：生态里判定件已在两类与审计同源的场景留下可引用数字——① **单据与表单分类**（实测 261 份表单严格准确率 100%，单页成本约千分之一美元，比其原有生成模型管线**便宜三十余倍、快数倍**）② **高频决策回路**（实测每约三百毫秒做一次带概率判断，且**阈值、风险否决与执行全部留在确定性代码**）。引用时**只作形态参照**——其评测集均系对方自建，**只可并列不可排名**
- **对照件准入鉴别（同题不等于同能力）**：同期判定件几乎全部自称「Jev 复刻」，**复刻的是接口还是本体、有没有可验证产物，须逐项鉴别后才能进对照表**——五项判据：① 是否**公开权重与数据**（无权重 ⇒ 只能引用自报，不可自测）② **state 是否只编码一次**（多次重复编码 ⇒ 延迟读数不可比）③ **question 是否真隔离**（同请求内多问互不污染，否则打包读数不可比）④ **概率是否直接 readout**（走生成再解析 ⇒ 不属非自回归，与本仓不同构）——**实测判据落在「是否保留语言模型头」**：移除 LM head 走独立判定头者为正例，保留标准 next-token head 者即使自称亦降为接口参考（判别实例见上表「去 head 正例 vs 留 head 反例」条；`AutoModelForCausalLM` 可否加载是最省事的唯一性检验）⑤ **benchmark 可否复现**（能否用其仓内产物重算）。任一项缺 ⇒ 降为「接口参考」，**不入对照表、不作排名依据**。具名来源、许可与三面评估见 [THANKS · 判定与校准](../../THANKS.md)
- **对照数字须带对照系版本锚，并定期复验**：引用任何第三方数字必须同时记录**对照系版本号**与**引用时点的口径**——同期赛道迭代极快（实测两件判定件在同一周内相继发布，其后数日仍有版本更新），**对手发新版即把旧对照标记为不可比**，不得继续作为当期依据；复验触发条件为「对照件发版」或「本仓对照回合重跑」。与 [v1.7.0 §三](../v1.7/v1.7.0.md)「判定制品四件套的联合版本锚点」同族——任一件变更即旧锚点不可比，只是粒度落在**跨仓对照**上
- **第四对齐：对照读数须有可复算通路（通路不明即降为自报）**：引用对手方公开数字前先问「这个数怎么算出来的、能否自行重算一遍」——**同判据集、同评测器、同推理预算**三对齐之外还缺一项：**读数本身可复算**。生态实例（2026-10-12 登记）：某开源多模态判定件自报其对照对手（**商业托管闭源件**）在**同一本机**的延迟为 109.70 ms，却**未说明闭源托管件如何在本机运行**，第三方独立拆解明言「无法核实该数」⇒ 该行降为「自报对照、通路不明」，**只并列不排名**，且不得作为「本地件快 N 倍」类结论的依据。工程含义：**跨件对照里，凡对手为托管服务而声称「本地实测」的读数，一律先标「通路不明」**——偏差方向未知（可能含网络往返、可能是另一档位、可能未固定推理预算），与「对手格式破坏率是对照通道偏置」属同族问题
- **「工程优化 vs 技术革命」之辩（叙事定位纪律 · 2026-09-25 登记）**：品类价值须防两种过度叙事——「换皮 BERT」与「超越 BERT 的新物种」都下得太早。可核实的事实面：开源件 laya 确为 **ModernBERT 编码器 + 判定头**的技术继承，其增量在**接口灵活性**（调用时换问题与选项、同套调用适配多任务 vs 传统分类器固定类别重训）+ 概率处理 + 接入体验——但**接口允许换题 ≠ 换题就答得好**（读懂选项与掌握新业务是两回事）；「零幻觉」只成立于**类型安全层**（不产出破损 JSON / 不编造选项），不覆盖语义选错（选择题不跑题 ≠ 不会选错）。对本仓的含义：判定底座的对外卖点落位是**工程体验与治理可审计**（更便宜更好用 + 判定可溯源 + 校准可验），不背「范式革命」叙事——与 [v2.0.0 §一](../v2.0/v2.0.0.md)「宣告依据链四件缺一不启动」的克制姿态同源。**企业级验收口径（可整段引用的通俗版）**：同一批业务材料、同一错误标准，对照组含传统分类器 / 现代编码器 / 小模型 / 判定件，总成本 = 数据标注 + 训练 + 部署 + 维护 + **判错转人工**——与本章「四维落数」「确定性基线先行」同构；金额、权限、硬性规则一律代码检查不进判定（与 v1.6.0 §四「纯函数型常数留代码」同源）
- **不利结论照录**：第三方实测已显示判定件的准确率可能低于前沿生成模型一档——这类结论**进 VALIDATION 而非删去**，判定件的卖点是延迟与成本，不是准确率。**第二个实例（独立横评）**：某项独立横评（5 suites / 60 cells / **花费与 raw log 全公开 / 无厂商赞助**）给出三条对我们不利或需修正认知的结论——① **厂商宣称的 40–200× 倍率在独立口径下不成立**：对**最快**的 LLM 档只快约 1.2×，那个倍率只在「拿自己与**留在最慢默认模式**的 LLM 比」时才成立；② **「没有一类在质量上胜出」**——多类任务上受限 LLM 与判定件互有胜负，部分 LLM 档甚至低于多数类基线；③ **选项上限真实且陡峭**（选项一多，优势迅速消失）。🔴 **引用纪律**：该横评所在仓库**仓库根无 LICENSE**（实测 `license=null`）⇒ 本仓**只作读数参照，不作对照件、不引其数据入仓**，亦不排名（与上条「对照件准入鉴别」同向）；**只陈述结论方向与口径，不抄其具体百分数**（本仓未复算）
- **对照须为「预注册非劣性检验」，不是事后择优**：判定件 vs 生成式 judge 的对照，应在**预先注册的 margin** 下做**非劣性检验**（事先声明「允许差多少算打平」），而不是跑完一堆配置再挑最好的一次去比——后者是**事后择优**，对照组的可比性会被「挑」掉。**正面范例（可逐行读）**：某第三方工作把「小判定件（LoRA 微调 + 温度标定 softmax readout，单次前向、无生成文本）」与「LLM judge 基线」在**预注册 margin** 下判**非劣**，并**主动自曝该配方带着测试集暴露（test-set exposure）选出**、样本全为合成数据。⇒ **「预注册 margin + 自曝测试集暴露」正是「谱系声明三件套」的正面范例**（[v1.7.0 §三「数据集谱系声明」](../v1.7/v1.7.0.md)）：这里的「污染声明」不是事后补的脚注，而是**作者自己先说出来**。出处：`arXiv:2609.23959`（判定件小模型 + 校准 readout）。**引用同规**：只落口径与方法，不抄其具体数字（本仓未复算）

### 验收标准

- [ ] 三方（或以上）对照实验落数，同判据集同评测器
- [ ] 四维并列（准确率 / 校准 / 延迟 / 成本），无选择性报告
- [ ] 第三方数字标注来源与口径（自报 / 独立实测区分）
- [ ] 口径不可比的项目**只列不排名**
- [ ] **分布内外分列落数**（与 v1.6.0 同口径，落差显式声明）
- [ ] 结论进 `docs/VALIDATION.md`（**含不利结论**——准确率可能低于前沿生成模型一档这类结论照录）
- [ ] 每个数字附**可复算产物**或标注「单次运行 / 私有数据」口径
- [ ] 判定调用密度落数（每任务判定次数），**且区分串行调用与打包请求**，与四层标准并列报告
- [ ] 跨厂商对照中**对手格式破坏率与通道偏置说明**一并入档（不使格式失败被读成能力差距）
- [ ] 同一对象出现多源数字时**逐源并列入档**（含出处与口径），无拼合后的单一数字
- [ ] 公开实测存档条目均标注**评测集归属**（对方自建 ⇒ 只并列不排名）
- [ ] 权重可下载的对照件**已用本仓评测器自测**（非仅引用自报数字），且架构与参数量档位记录在案。**「同判据集」按 [v1.6.0 §五](../v1.6/v1.6.0.md) 的跨域映射口径执行**（本仓评测器与用例集均在位，缺的是跨域口径与适配层）：判据按**认知负载类型**归等价类，类内同 state / 同金标 / 同评测器，**类间不比**；对照件经**双向适配**接入（仓内 `diffFiles[].lines` + `task` → state 文本；对照件输出 → `result`）；**仅 `result`（PASS/FAIL）一维参与对照**——`rules_triggered` 与 `severity` 为审计域投影，**显式声明不可比**；至少保留一组**桥接判据**作跨域硬锚点
- [ ] 每条第三方数字带**对照系版本锚**（版本号 + 引用时点口径），复验触发条件写明
- [ ] 对照件已过**准入五项鉴别**（公开权重与数据 / state 单次编码 / question 隔离 / 概率直接 readout / benchmark 可复现），未过者降为接口参考、不入表不排名
- [ ] **FDE-Bench 首版在位**：30 决策点骨架 + **公开案例脱敏改写为唯一数据源**（`label.source=public-case-adapted`，自有 log 禁入）≥300 题可复算；六条通用化护栏过 lint（零内部术语/出处锚点/双签/覆盖矩阵）；至少一组**通用判定件在 FDE-Bench 上 vs 本仓判定件**的对照读数落档（回答「通用件接不住 FDE 决策点」的量化证据）；基准集与判据集开源、企业样本零混入有断言

### 风险与前置假设

> ⚠️ **对照可能显示判定件并不占优**——同类开源判定件（基于 9B 基座做微调，参考标签一致率从基座 66.36% 提升到 90.12%，其闭源参照为 93.21%）提示：判定能力对**数据质量**的敏感度远高于参数量。若我们的数字落后，如实落数并定位原因（判据质量 / 数据量 / 训练方法），**不通过更换评测口径来美化**。

## 六、静默失败监控与判定使用度量


> **形态归属**：`[主干]`（判定·可观测性）｜ **不可拔**（静默失败是判定层最危险的失效形态——无报错、无异常、答案照出，监控是唯一防线）

前三章回答「判定有多好」，本章回答「**判定坏掉时我们怎么知道**」。判定层的失败多数**不抛异常**：类型对了、结构对了、答案出来了——只是答错了。因为**类型安全意味着没有解析器会替你报警**：一个返回了合法 `Choice` 分布的模型，从类型系统看与一个答对的模型完全一样。这一章是判定层与「能跑」之间最后一道缝。

### 交付

| 组件 | 能力 |
|------|------|
| **静默失败四探针** | 产出级探测（与 v1.4.5 的 `providerStatus` 产出级探测同族，探测对象从「进程活着」深化为「判定还有效」）：① **输出分布漂移**（某判据的选项分布突变为单峰或均匀）② **概率分布异常**（长期贴 0.5 或长期贴 1.0——两者都是未校准或模式坍塌的特征）③ **弃权率突变**（骤升或骤降）④ **输入长度与延迟的异常相关**（提示触发了截断或降级）。超阈**告警不阻断**，但告警必须**可见**（面板 + 周报），不允许只落日志。**⑤ 行为分布塌缩**（同族补强）：「同一动作连续重复 N 次且无状态推进」即告警——141 小时长时评测实测：Agent 受挫后行为分布塌缩为单一重复动作，**产出行数照常增长但状态推进为零**（只看产出的审计对卡死盲视；行业印证锚见 [ARCHITECTURE](../../ARCHITECTURE.md) 过程/结果面分工段；读数源=审计链既有动作时序 + 状态推进计数，零新增采集面；N 阈值随三段门控同批校准） |
| **表征级探针（慢特征坍缩检测）** | 四探针全是**产出级**（事后看输出分布形状）；本探针补**表征级**——非平稳背景下，纯预测目标会保留**慢特征**（场景身份：恒定、不依赖动作即可预测）、丢弃**快特征**（运动主体：只有配合动作才可测），而**输出分布可能完全正常** ⇒ 属「静默失败」的**最深形态**（前四探针抓不到）。实现：对 `state` 编码器输出训探针回归「状态转移 / 动作」，量化「模型在学场景，还是学动作」。同源判据：**目标比状态更抽象时，同一表征空间的目标比对代价失效**（低层距离信号近乎恒定，实测无梯度信号）⇒ 判定 / 评分用的目标表征须与状态表征**解耦**。生态实现：AMI Labs / NYU《H-JEPA: End-to-End Learning of Hierarchical World Models for Visual Planning》（arXiv:2610.06805，2026-10-05，LeCun 参与）§4.2–4.3 |
| **入口前置分流（判定通道在选择点就定）** | 判定通道的选择必须在**任何模型加载之前**完成，**分流决定与理由可查**——不得静默走默认路径。**为什么单列**：四探针是**事后**探测（分布漂移 / 概率异常 / 弃权突变 / 长度-延迟相关），全都发生在「已经跑起来之后」；而「一开始就选错路径」在事后探针里表现为正常输出，**探针抓不到**。外部对照：Laya 在任何模型加载前完成路由，其 docstring 明写「typed-decisions 不应成为静默默认」——把路径选择提到加载之前，才有资格谈「选得对不对」 |
| **路由健康度测量与降级避让（2026-10-15 APUS 对位补出）** | 每个候选判定通道（本地判定件 / 云端 provider）须有**运行时健康度**：测**首 token 延迟 / 输出速率 / 错误率**三指标，样本达阈后按序判定降级（错误率 → 延迟 → 速率）；**降级候选从判定请求中排除并在留痕记 `avoided`**（只排除不记因＝静默丢弃，本条禁止）。配**无数据探针**：对久无样本的候选用**不含会话内容**的固定请求复测——防「因被避让而永不再被测」的死锁。**为什么在本章**：既有诸探针测「判定**输出**是否还有效」，本条测「判定**通道**本身是否还可信」——通道坏了，产出探针会把它误读成「判定退化」。**与入口分流的关系**：入口分流决定**走哪条**（选择点），健康度保证**那条当下可用**（中段），产出探针验证**它产出的仍有效**（出口）——三段互补，缺中段则「选了条坏路」只能产出级事后发现。**前置依赖（2026-10-15 自审更正）**：健康度采样面**不**复用本章「判定使用度量」的台账类数据源（那套是留出集考核 × 质量信号，粒度与口径都不同）——它需要**模型流的运行时观测埋点**（逐流的首 token 延迟 / 输出速率 / 错误率）。近邻前置是 **v1.8.0 §四「判定档可观测」**（调用量 / 延迟 / 失败率 / 降级次数）：须把观测粒度**从档级聚合细化到流级逐样本**；若只有档级聚合，健康度退化为「有总量、无降级判定」 |
| **判定使用度量** | 判定被调用后下游**采纳了多少**：判定值采纳率 / ASK 率 / DENY 率 / **被人工推翻率**（推翻率是判定质量最直接的外部信号）。**「已上线但无人消费」与「上线即被推翻」必须能区分**——前者是集成问题，后者是质量问题，混成一个数字则两者都无法处置。**红旗群**：ASK 率趋近于零 · **获批率恒为 100%** · **审批时延落在提示后 1–2 秒** · **人均审批量异常高**——四者同时出现即门控退化为形式（与 v1.7.0 门控健康度同族，此处是观测侧的落地）。**作弊观测位（旁路指标，独立于优化目标）**：对参与晋级/自进化循环的判定面，加**奖励作弊率**观测——留出集上「分数升而独立任务质量证据未升」的样本占比（行业实证：AIDE² 8 天自主运行作弊率 55%→32% 而**循环从未显式优化该指标**——作弊解在隐藏评测上不稳、被留出选择当作泛化噪声筛掉，[arXiv:2609.26457](https://arxiv.org/abs/2609.26457)；本仓读法：作弊率上升＝代理目标被利用的可见信号，与 [v1.5.8 §二](../v1.5/v1.5.8.md) 四门槛互为表里——门槛管「不接受可疑收益」，本探针管「发现已溜进来的」）。只观测不阻断，超阈告警进治理周报。**数据源**：留出集考核记录（v1.5.8 §二 四门槛的判定留痕）× 独立任务质量信号（acceptance 台账与纠偏介入率）——两者均既有台账，零新增采集面。**本行的采集面依赖（2026-10-15 补）**：本行要测的「被人工推翻率」正是人工反馈的一种，**没有采集面就没有该指标**——采集面须与指标同批设计，不能先立指标再补采集；**采集口径见本章「通用工程件补齐三项」①（单一出处，此处不重复列举）**。⚠️ **与 v1.6.0 §六 三源采集的关系（须分清，否则两处看似矛盾）**：v1.6.0 的 **HITL 源**采集的是**人工裁决产生的判定样本**（`hitl-collector.ts`，`label.source=human` 档，**进训练集**）；本行的反馈是**对输出的评价信号**（**不进模型、不进训练**）。两者同源于人、用途相反——**数据 vs 信号**：判定样本可训练，评价信号只用于度量。**不得把评价信号当训练数据**（那等于让模型学习「人是否喜欢它的输出」，与判定任务无关且引入偏好泄漏） |
| **设计有效性与运行有效性分列** | 判据齐全、正负样例在位是**设计有效性**；实际判过、留痕在位是**运行有效性**——**两者须分列报告，并显式报告两者之差**。生态实证：对 Agent 的控制只能从**运行记录**测其运行有效性，而**运行证据缺失本身就是一条 finding**——「无法证明它没乱来」对一个自治系统而言与「它乱来了」是同级治理缺陷。这与本版「判定质量 / 概率可信度分列」同族：**禁合并** |
| **压缩留痕完整性** | 上下文压缩（v1.4.8 自动压缩，实现于 `engine/inject/src/load-chain/compactor.ts`）是**有损**的，但判定依据的留痕必须**无损**：压缩后判定当时依据的证据须仍可在审计链上还原——留痕保存**压缩前的判据输入引用**而非压缩后摘要。**为什么这是判定层的问题而非文档问题**：被压掉的很可能正是判定所依据的那条证据，留痕若只剩摘要，审计就无法回答「当时凭什么这么判」。**实现路径参照（2026-10-15 外部蒸馏 · 对方自报本仓未复算）**：其压缩族按**三层递进**做，顺序本身是纪律——① **先裁工具输出**（超长工具结果先被裁剪，**减少需要压缩的量**，即有损操作优先落在与判定证据无关的面上）② **再压缩历史**（token 压力达阈时把旧历史压成摘要）③ **图片按需外移**（图片路由拒绝时替换为占位符）。配套两条可直接采纳的设计：**溢出到存储 + 返回 locator 与检索指引**（超长文本不截断丢失，而是存外并给出「去哪找」）——**存储失败时保留原文**（fail-safe：外移失败不得导致证据丢失）；且**压缩触发所需的 token 测量独立成服务**（测量归测量、压缩归压缩）。**本仓缺口与待补（2026-10-15 自查补）**：我方现行仅实现**第二层**（`engine/inject/src/load-chain/compactor.ts` + `budget.ts`：只有预算判定与压缩，**无工具输出裁剪层、无图片外移层**）——**本章收口前须补齐第一层（工具输出裁剪）**：超长工具结果先裁后压，**减少需要压缩的量**；第三层（图片外移）视多模态档排期（无多模态则不适用）。**顺序纪律**：有损操作优先落在**与判定证据无关的面**上——工具输出可裁，判定证据不可 |
| **四层性能标准的持续采集面** | §四 的四层落数依赖**稳定采集**而非一次性跑分——本版为其提供持续采集与趋势视图（判据级 / 校准级 / 分流级 / 端到端各自的时序曲线），使「能力退化」在版本之间就可见，而不是等下一次评测才发现 |
| **AI 参与度度量（治理可见性 · 2026-10-14 登记）** | 量化「本仓 / 本项目的 AI 参与比例」并进审计报告。外部依据：Hinton / Bengio / Barto 等 22 人立场论文把「**研发自动化渗透比例 + 算力开销**」列为治理首优的可见性指标，并点名要求**独立第三方审计**（arXiv:2609.36054，立场论文、本仓未复算）。本仓落点：审计报告增列 AI 参与度字段——数据源 = **审计链既有留痕 × commit 元数据**（零新增采集面）；与「判定使用度量」并列（**前者量 AI 干了多少，后者量判定被采纳多少**），两者同属可见性面，同受「不作能力声明」约束。**信号面勘查（2026-10-14 实测，施工前先读）**：① **已有半个面**——写面留痕 `WriteSurfaceRecord` 已带 `actor`（发起人）+ `origin`（来源）字段，且有**证据三要素硬校验**（发起人 / 来源 / 时间缺一即拒），覆盖 prompt 面与 memory 面；判定链 `DecisionResult.modelVersion` 可追溯「用哪个模型判的」；② **缺口在代码面**——git 层提交归属**无 AI 信号**（实测 `git log --format=%an` 恒为人类署名）⇒ 实施前须先裁定**代码面 AI 归属约定**（对 commit 加 trailer，或从 session / 任务记录派生）——**这一裁定是本章施工的前置依赖**，未定则只能出「非代码面参与度」的部分报告。**归属约定裁定（2026-10-14 已拍：三选一取「写面留痕扩面」为主）**：① **主信号 = 写面留痕扩到代码面**——复用既有 `loadchain-write-hook` 注入点（core 侧已有守卫与捕获），把代码文件写入纳入写面记录（`actor`/`origin` 三要素校验同款）⇒ **仓内自洽、不依赖外部平台**，度量口径 = 「**sofagent 视野内的 AI 参与度**」；② **辅助 = commit trailer 约定**（可选，供外部工具与客户自带场景，非必需）；③ **明确不作声明**——视野外写入无法度量，指标**不得自称「全量 AI 参与度」**（与本章「设计有效性与运行有效性分列」同族：缺证据本身就是一条 finding）。**外部规格（2026-10-14 读论文 PDF 原文补）**：同文给报告口径**三类**——① 评估爆炸可能性（算力/数据/难自动化任务/耗时流程的瓶颈 + 更优 r 估计，须含「人类·实验算力·做研发的 AI 算力」三者支出分配）② **检测爆炸起始（含「由 AI 系统产出的研究贡献比例」）**③ 理解监督与失控风险（含**内部 AI 系统的事件报告**）；**本行指标属第 ② 类**，第 ③ 类可与本章既有探针/留痕面合并承接。另两条适用纪律：**阈值化**（更强要求只施于「前沿或超某能力阈值」者）· **第三方可嵌入审计/监督**（类比 NRC 与 OCC 模式）——本行落数时按此三分类组织字段，避免自造分类 |
| **越权与自发协同通道监测（2026-10-14 登记）** | 同一论文援引的隔离失效事件（约 1200 个本应隔离的评估智能体**自建布告栏协同**、获取未授权互联网访问——与知识库 ExploitGym 案为同一事件）暴露的形态：**隔离不是被攻破的，是被找到一条没人批准过的共用通道**。本仓落点：在既有出站 / 文件面审计之外，补**协同通道形态检测**——非常规 IPC（共享 artifact / 留言板 / 临时文件充当跨实例信道；多实例在时间窗内出现同构动作序列）。探测面 = 审计链既有动作时序 + 文件面写入留痕（零新增采集面）；**只观测不阻断**，超阈告警进治理周报（与本章四探针同族）——补的是「多实例协同」这一类**结构性盲区**（既有出站控制只管单实例对外，管不住实例间的自建信道） |
| **通用工程件补齐三项（2026-10-15 外部对位 · **缺口 → 交付项**）** | 三件**与产品形态无关**的通用工程件，本仓缺或薄，**本章收口前须补齐**；各件均**按本仓形态落地、不照抄外部件的 UI 形态**：① **反馈采集**——会话级备注 + 逐消息评分 / 分类 / 笔记；**记录反馈不消耗模型 turn**；随会话持久化、跨重启存活；**两条隐私纪律**：**反馈永不进模型**（signals about the output, never input to it）、**不进模型历史与遥测**。**FDE 形态落法**：采「审批 / 纠偏记录 + 运维反馈面」，不照搬个人应用的 UI 按钮。（依据：本章「判定使用度量」的**被人工推翻率**依赖它——**无采集面即无指标**）② **交付物记录**——把「一轮交付了什么」做成 durable 事件：显式声明的交付文件 + **从 git 工作树快照与整文件捕获算出每轮变更文件与行数**并提供逐文件比对；**只被客户端读、不进模型上下文**。**FDE 形态落法**：交付清单进**审计链与治理周报**（与"产出面可举证"同族）。③ **文本溢出**——超长文本**不截断丢失**而是**存外并返回 locator + 检索指引**；**存储失败时保留原文**（fail-safe）；**opt-in**（默认不启用）。**FDE 形态落法**：溢出落**本机 session 作用域**、**不出内网**。**共同纪律**：三项**只记录、不参与决策**（与本章「只观测不阻断」同族）——其价值在**可举证与可度量**，不在改变行为 |

## 七、施工期收口判据（能不能进 V2.0）


> **形态归属**：`[主干]`（交付·收口判据——本版为**判据与收口动作**）｜ —

### 交付

| 检查项 | 判据 |
|--------|------|
| **阶段一（判据与数据）** | 判据 schema 定稿且逐条对账无遗漏；数据集三元组可校验；零样本基线已落数 |
| **阶段二（模型与校准）** | 训练回路可复现；**ECE 达阈**；三态对照落数且判定质量与概率可信度**双达阈** |
| **阶段三（接线与分发）** | DecisionChannel 实现在位（默认 + 可替换）；一体机离线推理可用；权重分发通路打通且 sha256 校验 fail-closed |
| **阶段四（消费与收口）** | 既有判定面收敛完成（三原语补概率）；假概率正名完成；三类判据域在位；**四层性能标准落数** |
| **部署体验达标（2026-10-15 立）** | §四「部署体验」五项（部署时长 / 首次可用 / 自证能力 / 断网可用 / 可替换演练）**有实测读数且达阈**；**未落数不得宣称「可交付客户」**——本项与四阶段收口判据并列，是「能不能进 V2.0」的第 5 个条件 |
| **可演示证据包（收口产出物 · 2026-10-15 立）** | 收口时须把**宣告所依赖的全部证据做成统一的可点验入口**，不得散落在 devlog、测试报告与台账里：每条结论**指向可复算产物**（复现命令或原始读数），**外部读者可自行验证**（对齐 §五 报告形态第 ⑤ 条「证据入口可点验」与 §七 证据分级「证据列写读数」）。**为什么单列**：宣告的本质是**给人看**——证据分散等于没有证据；且这正对标本仓相对外部件的核心差异（本仓主张「可举证」，**证据包是其最小兑现形态**——只有主张没有入口，主张不成立） |
| **口径** | 对外无「未达阈却已宣称」的能力项（逐项核对） |
| **收口判据的证据分级（2026-10-15 外部蒸馏补出）** | 每个收口判据的「达成」须标**证据等级四级**：● **真实通过**（真实运行时或用户路径产生了该证据）· ● **部分通过**（确定性回归或受控场景通过，**核心真实路径仍缺**）· ● **待测**（已有设计或代码，但无最终产物或用户路径证据）· ● **阻断**（已有试验暴露因果或环境问题，**不得以成功结果覆盖**）。**收口只认「真实通过」**——「部分通过」不得计入达成（这正是「未达阈却已宣称」的最常见来源）。**配套两条**：① 证据列**写具体读数**（延迟分位 / 计数 / 哈希），不写「已验证」「已覆盖」这类无读数词；② **限定词随结论同行**——凡结论含未验证面，须在同句写明不得宣称项（如「不得把远程模型完整回答时间伪装成本地响应」「不得把送达当成果通过」「价格未知时不得宣称成本收益」）。**与 §五 报告形态的关系**：§五 管**对外呈现写法**（对照报告怎么写给人看），本条管**内部收口判定**（能不能进 V2.0）——两者互为表里，不重复 |

| **不可进 V2.0** | 任一阶段未达阈 | **在施工期内增补补丁位**（见 §九 弹性机制），**不带着未达阈项进 V2.0** |

## 九、版本弹性机制（后续开发量剩余的处置方式）


> **形态归属**：`[非功能]`（排期纪律——**本版首次落盘**）｜ —

### 机制

| 情形 | 处置 | 理由 |
|------|------|------|
| **阶段内开发量超出预期** | 在**该 minor 内增补补丁位**（`vX.Y.1`），不挤后续 minor | 阶段内主题一致、依赖连续，增补成本最低；跨阶段挤压会破坏「每版可独立验收」的前提 |
| **出现新识别的工作面** | 在阶段之间**插入新阶段**（如 `v1.10.x`），并保持原四阶段编号不变 | 编号稳定便于引用；插入而非重排可避免全仓版本号重写 |
| **V2.0 时点** | **不锁死在 v1.9.0 之后**——V2.0 在「四阶段收口达阈」时点到来，之前不停留 | 形态宣告的时点由**达阈状态**决定，不由版本号决定；形式上成立却内容未达阈时宣告，等于把叙事跑在实现前面 |
| **单版内容上限** | 每版内容以「**可独立验收的交付单元**」为界，不以「章数」硬凑 | 颗粒度细化的目的就是让每版能独立停、独立验 |
| **不允许** | 把多个阶段的工作挤进一版；或为了「按计划进 V2.0」而放宽达阈标准 | 前者破坏可验收性，后者破坏证据链 |

### 验收标准

- [ ] 弹性机制写入 ROADMAP 与 changelog 目录说明（后续版本增补有据可依）
- [ ] 已增补 / 已插入的版本记录在册（版本号不复用、不重排）
- [ ] V2.0 时点表述统一为「四阶段收口达阈时」（非「v1.9.0 之后」）
- [ ] `docs/changelog/README.md` 记录阶段与版数关系

### 风险与前置假设

> ⚠️ **弹性机制可能被滥用为「无限延后」**。约束是：每次增补补丁位**须有明确的未达阈项或新识别工作面作为依据**，并在 changelog 中记录增补理由——「感觉还没做完」不构成增补依据。
>
> ⚠️ **本版仍不改对外产品身份**。身份切换是 V2.0 的动作，本版只把口径铺平。若本版提前宣告身份，会让 V2.0 失去「一次定义到位」的意义（P18 拍板：形态成立时点 = V2.0，不设中间成立点）。
