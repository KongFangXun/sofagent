## 定位

> 📊 **判定底座 · 判据面扩展与四层性能标准**——阶段四第二版，回答「**怎么证明它真的有用**」。判定能力的正确性不由通用榜单定义，而由**自有判据集上的分层性能**定义——本版把判据面从审计规则扩到 workflow / 本体数据 / 路由判定。同时给出**四层性能标准**与**第四方对照**，把判定能力的证据链首次公开。**纪律**：性能以自有判据集为准，**不比通用 benchmark**（通用榜单与判定任务不同构，比了也无解释力）。第四章补上这套证据链**失效时**的探测器——判定坏掉时它不会报错，只会安静地答错。

## 一、判据面扩展（从审计规则扩到三类判定域）

> **形态归属**：`[主干]`（判定·判据面）｜ **不可拔**（判据面是能力的边界声明）

### 交付

| 组件 | 能力 |
|------|------|
| **workflow 判据面** | 编排任务的判定判据（该不该触发 / 该走哪条支路 / 该不该升级）——判据来自 v1.5.1 事件驱动与 v1.5.6 判定分层的既有语义 |
| **本体数据判据面** | 本体实体/关系操作的判定判据（该不该建 / 该不该合 / 该不该失效）——对接 v1.5.0 双时态与 Validation Engine 既有语义 |
| **路由判定判据面** | 请求难度与敏感度的判定判据（该走哪档）——对接 v1.5.6 路由层与 v1.8.1 判定档 |
| **判据集分层声明** | 各判据域的能力边界显式声明：**哪些域已校准、哪些域只是接口在**——未校准域的输出不得进决策路径（沿用 v1.7.1 门禁） |
| **域的适用边界** | 明确判定底座**未验证的域**（开放式写作、主观偏好、长链推理）——不在无验证器的域宣称判定能力（对齐「验证差距」纪律：验证比生成便宜才有自动化的前提） |

## 二、四层性能标准（判据级 / 校准级 / 分流级 / 端到端）

> **形态归属**：`[主干]`（判定·性能标准）｜ **不可拔**（性能标准是能力声明的依据）

### 交付

| 层 | 度量 | 说明 |
|----|------|------|
| **判据级** | 逐判据准确率 / 一致率 | 与 v1.6.2 / v1.7.2 同数据集同评测器口径（对照不漂移） |
| **校准级** | ECE / 分桶可靠图 | 概率可信度独立度量，**不与判据级合并** |
| **分流级** | 三段门控（高自动 / 中复核 / 低转人工）的实际错误率 | 门槛对应的**真实错误率**落数（这是门槛是否有意义的唯一证据） |
| **端到端** | 判定延迟（单次 / 批量 / 并发劣化）+ 判定失败率 + 降级次数 | 一体机实测（v1.8.1 落数的正式化） |

### 交付要点

- 四层**分别落数、分开报告**（禁止压成单一分数——合并会掩盖「判得准但概率不可信」「概率可信但太慢」这类危险组合）
- 每层给出**阈值**与**未达阈的处置**（未达阈不得对外宣称该层能力）
- 性能标准写入 `docs/VALIDATION.md`，作为对外能力声明的唯一依据

### 验收标准

- [ ] 四层各自落数并与阈值比较（指标口径固定，可复算）
- [ ] 四层**分开报告**（无单一合成分数）
- [ ] 未达阈项显式标注且不进对外声明
- [ ] 端到端延迟与并发劣化曲线来自一体机实测（非推算）
- [ ] `npm test` 全绿

## 三、第四方对照（不是自说自话）

> **形态归属**：`[主干]`（判定·外部对照——本版为**对照实验**）｜ —

### 交付

| 对照方 | 说明 |
|--------|------|
| **高能力本地模型档** | 同级可本机部署的通用模型（如 30B 级 MoE 档） |
| **大参数量云端模型档** | 大参数开源模型存档（用于「小判定件 vs 大通用件」的性价比对照） |
| **云端快档通用模型** | 云端快档（对照「判定件 vs 通用快档」的延迟/成本/准确率三角） |
| **同类开源判定件** | 同期开源判定模型的公开数字（**引用其自报口径并标注口径差异**，不直接横比） |

### 对照纪律

- **同判据集、同评测器**（口径一致是可比的前提；口径不可比时**只列数字不排名**）
- 公开报告须同时给出**准确率 / 校准 / 延迟 / 成本**四维（只报有利维度即失去意义）
- 引用第三方数字时**标注来源与口径**（自报 vs 独立实测须区分）

### 验收标准

- [ ] 三方（或以上）对照实验落数，同判据集同评测器
- [ ] 四维并列（准确率 / 校准 / 延迟 / 成本），无选择性报告
- [ ] 第三方数字标注来源与口径（自报 / 独立实测区分）
- [ ] 口径不可比的项目**只列不排名**
- [ ] 结论进 `docs/VALIDATION.md`（含不利结论）

### 风险与前置假设

> ⚠️ **对照可能显示判定件并不占优**——同类开源判定件（基于 9B 基座做微调，参考标签一致率从基座 66.36% 提升到 90.12%，其闭源参照为 93.21%）提示：判定能力对**数据质量**的敏感度远高于参数量。若我们的数字落后，如实落数并定位原因（判据质量 / 数据量 / 训练方法），**不通过更换评测口径来美化**。
>
> ⚠️ **本版带叙事章，但叙事只讲形态与验证方式，不讲「比 X 好」**。性能对比归 VALIDATION 的落数，叙事不做结论性宣称。

## 四、静默失败监控与判定使用度量

> **形态归属**：`[主干]`（判定·可观测性）｜ **不可拔**（静默失败是判定层最危险的失效形态——无报错、无异常、答案照出，监控是唯一防线）

前三章回答「判定有多好」，本章回答「**判定坏掉时我们怎么知道**」。判定层的失败多数**不抛异常**：类型对了、结构对了、答案出来了——只是答错了。因为**类型安全意味着没有解析器会替你报警**：一个返回了合法 `Choice` 分布的模型，从类型系统看与一个答对的模型完全一样。这一章是判定层与「能跑」之间最后一道缝。

### 交付

| 组件 | 能力 |
|------|------|
| **静默失败四探针** | 产出级探测（与 v1.4.5 的 `providerStatus` 产出级探测同族，探测对象从「进程活着」深化为「判定还有效」）：① **输出分布漂移**（某判据的选项分布突变为单峰或均匀）② **概率分布异常**（长期贴 0.5 或长期贴 1.0——两者都是未校准或模式坍塌的特征）③ **弃权率突变**（骤升或骤降）④ **输入长度与延迟的异常相关**（提示触发了截断或降级）。超阈**告警不阻断**，但告警必须**可见**（面板 + 周报），不允许只落日志 |
| **判定使用度量** | 判定被调用后下游**采纳了多少**：判定值采纳率 / ASK 率 / DENY 率 / **被人工推翻率**（推翻率是判定质量最直接的外部信号）。**「已上线但无人消费」与「上线即被推翻」必须能区分**——前者是集成问题，后者是质量问题，混成一个数字则两者都无法处置 |
| **压缩留痕完整性** | 上下文压缩（v1.4.8 自动压缩，实现于 `engine/inject/src/load-chain/compactor.ts`）是**有损**的，但判定依据的留痕必须**无损**：压缩后判定当时依据的证据须仍可在审计链上还原——留痕保存**压缩前的判据输入引用**而非压缩后摘要。**为什么这是判定层的问题而非文档问题**：被压掉的很可能正是判定所依据的那条证据，留痕若只剩摘要，审计就无法回答「当时凭什么这么判」 |
| **四层性能标准的持续采集面** | §二 的四层落数依赖**稳定采集**而非一次性跑分——本版为其提供持续采集与趋势视图（判据级 / 校准级 / 分流级 / 端到端各自的时序曲线），使「能力退化」在版本之间就可见，而不是等下一次评测才发现 |

### 验收标准

- [ ] 静默失败四探针在位且各有触发用例（分布漂移 / 概率异常 / 弃权突变 / 长度-延迟相关）

- [ ] 压缩留痕完整性：压缩后判定依据仍可从审计链还原（有单测，含引用不丢）

- [ ] `npm test` 全绿

> ⚠️ **本章的指标都是「坏消息探测器」，不是成绩单**。采纳率高不等于判得准（可能只是没人复核），弃权率低不等于判得好（可能是阈值失效）。落数时须与 §二 四层标准并列阅读，**不得把本文指标单独用作能力声明**。
