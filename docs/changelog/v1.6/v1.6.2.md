## 一、基座编码器与判定头接线（编码器路线 · 非生成路线）

> **形态归属**：`[主干]`（判定·推理底座）｜ **不可拔**（判定底座本体）

### 交付

| 组件 | 能力 |
|------|------|
| **编码器基座接入** | 采用 **encoder-only** 路线（不接 decoder 生成模型）——判定任务不需要逐 token 生成，这是与「用生成模型做判定」的根本分野。接入方式为本地可跑、可离线，不依赖外部 API |
| **判定头（marker 式）** | 在编码器输出之上挂**类型化判定头**，按原语类型分发：choice 头（候选项打分 + 归一）/ score 头（序回归）/ noul 头（伯努利概率）。三头共享编码器，**不共享输出层** |
| **多问并行** | 同一 `state` 下的多个独立问句一次编码、多头并行出答案（v1.6.0 schema 的批量形态在此落地），避免逐问重复编码 |
| **基座选型口径** | 基座规格（参数量 / 上下文长度 / 语言覆盖面）**在本版定稿并记录理由**，但不写进对外文档的能力声明——对外只说「本机能跑的判定底座」。**接口层不绑定具体基座**：换基座不改判定头契约与 `DecisionChannel` 契约 |
| **接入形态** | 跑在一体机已有的本地推理栈上（**零新增运行时组件**），与既有本地模型槽位管理（v1.5.6 槽位信号量）协同；判定**不占本地主模型槽位** |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/router/judge-heads/`（目录） | 新建 | 三原语判定头（choice / score / noul） |
| `engine/orchestrator/src/router/judge-runtime.ts` | 新建 | 编码器接入 + 多头并行 + 槽位协同 |
| `engine/orchestrator/src/router/decision-model-registry.ts` | 修改 | 判定底座基座注册（复用既有 model-registry 纪律） |
| `engine/orchestrator/src/__tests__/judge-runtime.test.ts` | 新建 | 多头分发 / 批量并行 / 不占主模型槽位（行为锁）单测 |

### 验收标准

- [ ] 三原语判定头各自可用，输出结构与 v1.6.0 类型定义一致

## 二、零样本基线落数（如实记录 · 不修饰）

> **形态归属**：`[主干]`（判定·基线度量）｜ 本版为**度量动作**，非能力交付

### 交付

| 组件 | 能力 |
|------|------|
| **零样本评测器** | 在 v1.6.1 数据集上跑零样本推理（基座不微调），按判据逐条统计：命中率 / 一致率 / 各原语分别的表现 |
| **基线报告** | 产出结构化基线报告：逐判据准确率 + 混淆分布 + **失败模式分类**（哪类判据完全跑不动、哪类边界模糊）——失败模式清单是阶段二训练的重点输入 |
| **校准现状探测** | 在零样本条件下同时记录**候选概率的校准状况**（分桶可靠图 / ECE），用以确认阶段二校准的必要性与起点 |
| **基线落数与归档** | 基线数字进版本日志并归档，作为阶段二「提升幅度」的对照基准（**对照必须同数据集、同评测器**，防口径漂移） |
| **诚实性纪律** | 基线数字**不得修饰**：低就是低。基线难看是预期内的（编码器零样本在细粒度判据上普遍偏弱），其价值在于把「训练能带来多少提升」变成可量化问题 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/router/judge-eval.ts` | 新建 | 零样本评测器（逐判据统计 + 失败模式分类） |
| `engine/orchestrator/src/router/calibration-report.ts` | 新建 | 分桶可靠图 + ECE 计算（阶段二复用同件） |
| `engine/orchestrator/src/__tests__/judge-eval.test.ts` | 新建 | 评测器单测（统计口径 / 分桶边界） |

### 风险与前置假设

> ⚠️ **零样本判定力可能显著不足，这是预期而非异常**。既有同类开源判定模型的零样本表现已实测偏低（52 语言扫描曾出现「准确率 0.000 而置信度 0.952」的极端情形）——这恰恰印证了两件事：① 判定能力必须靠**有监督 + 校准**训练，零样本不可依赖；② **未校准的置信度数字具有严重误导性**，校准不是锦上添花而是可用性前提。
>
> ⚠️ **本版不产出任何可对外宣称的能力**。阶段一三版（v1.6.0–v1.6.2）的累计产物是「判据 + 数据 + 基线」三件内部资产，对外口径零变化。
