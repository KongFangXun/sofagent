## 定位


> 🧭 **判定底座 · 判据 schema 定稿**——施工期第一版，只做一件事：**把「判定」从代码里的匹配逻辑，变成可训练、可校验、可举证的判据数据**。本版**不训练、不接线、不出权重**——它的产物是一份定稿的 schema 与一份逐条对账过的判据清单。**为什么它是第一版**：校准概率的前提是有「可被优化的判定目标」，而目标必须先是显式数据；schema 未定而先训练，等于拿噪声当标签。**本版同时写下整条产品线的边界**（§四）——边界先于能力落盘，是防判定面静默扩张为应用面的唯一手段。

**施工期四阶段全景**（本版属阶段一）：

| 阶段 | 目录 | 主题 | 版数 |
|------|------|------|------|

| 四 | `v1.9/` | 消费与收口——让概率进入既有判定面 | v1.9.0 |

> 🧱 **判定底座 · 数据集三元组与三源采集**——阶段一第二版（合为本版第五–七章）。本版第一至二章定义了「要判断什么」，本版第五–七章解决「**拿什么训练**」：把判据样本化为统一三元组，并从约束层**已有的运行痕迹**里采集标注，而不是靠人工从零标注。**关键洞察**：约束层自己就在生产训练数据——history 轨迹、HITL 人工裁决、PR 审阅结论都是天然标签，本版只是把它们接起来。**但采到不等于能用**——本版同时把数据可用性升级为四道可断言的机器门，并把样本挑选从被动汇聚升级为主动选样（§七）：校准能否达成取决于**困难样本**有没有被采到，而困难样本在任何自然分布里都是少数。

> 🧪 **判定底座 · 编码器基座与零样本基线**——阶段一收口版。**本版不训练任何参数**，只做三件事：把基座编码器与类型化判定头接起来、在真实判据样本上跑通零样本推理、把基线数字**如实落数**。基线**中英分列**——中文判据面弱于英文是已知弱点，而目标客户场景是中文环境，落差必须落数而非被合并遮蔽。**产物的性质必须说清：这是基线（baseline）不是成果（result）**——它定义的是「不训练能到哪」，其存在意义是为阶段二的训练提供对照，而不是可对外宣称的能力。

## 一、三原语类型化（Choice / Score / Noul 的 typed answer 定稿）


> **形态归属**：`[主干]`（判定·类型契约）｜ **不可拔**（类型是判定面的根契约，拔掉则判定结果无法被审计消费）

### 交付

| 组件 | 能力 |
|------|------|
| **`Choice` answer** | 从候选项里做选择——输出选中项 + **全候选项概率分布**（不是只输出一个选项）。语义对齐既有 `fde_classify` 的「三选一」形态（🔄自动 / ⚡强化 / 👤暂不动），但把无概率的枚举升级为带分布的类型化答案 |
| **`Score` answer** | 按标准打分——输出分值 + **区间/不确定度**。语义对齐既有 `evaluate` / `evaluate_output` / `quality-judge` 的打分面，但把裸分值升级为「分值 + 可信区间」 |
| **`Noul` answer** | 给出某判断成立的概率——输出**真值概率**。语义对齐既有 `shouldAllow` 的布尔判定与 `fde_classify` 的三问布尔输入，但把 `boolean` 升级为概率 |
| **问题集限定** | 判定请求携带**限定回答类型的问句集**（问题与原语类型绑定，运行时不可越界）——保证输出「类型正确」，模型无法自作主张产出未声明类型（对齐 Jev 的「不编出选项 D」这一层保证） |
| **`Choice` 必带兜底项** | 每个 `Choice` 问句的候选集**必须包含一个兜底候选**（「以上都不是」/「信息不足」类），且与弃权态**分开留痕**。**它与弃权互补、不等价，两处都要有**：**弃权**是模型自己给出的**态**（`ABSTAIN`）；**兜底项**是问句集里的一个**候选**，需要模型**选中**它。只有弃权而无兜底项 ⇒ 模型面对「选项都不合适」时被迫在坏选项里挑一个（把「无从判断」压成一次错误选择，而错误选择在概率面上与真实偏好无法区分）；只有兜底项而无弃权 ⇒ 「选中兜底项」与「不确定」在记录里同形，弃权率与门控健康度全部失真。schema 层**强制**兜底项在位（缺项即拒载该问句）——这是把「选项集不完备」这类问题从运行期事故降级为加载期错误 |
| **多问并行** | 同一份状态下的多个**相互独立**问题一次前向出全部答案（非逐问循环）——这是判定模型相对生成模型的结构性优势，schema 层须预留批量形态 |
| **与既有置信度并存** | 新类型与既有 `confidentiality` / `TriggerConfidence` / `'high'\|'med'\|'low'` 等枚举**并存不冲突**，映射口径落文档；既有 HMAC 链 schema 本版零改动 |

### 涉及文件（预估）

|------|------|------|
| `engine/orchestrator/src/router/decision-primitives.ts` | 新建 | 三原语类型定义 + 问句集限定 + 批量形态 |

## 二、24 条审计规则判据重述（从匹配逻辑到「判据 + 证据」）


> **形态归属**：`[主干]`（判定·判据集）｜ **不可拔**（判据集是训练目标本体）

### 交付

| 组件 | 能力 |
|------|------|
| **逐条重述** | 既有**全部** git-diff 审计规则（当前 24 条；v1.5.3 落地后 25 条含 A24——**以开工时规则集实际条数为准**，不写死数字）逐条重述为「**判据**（要判断什么）+ **证据**（据什么判断）」两段式数据，与规则实现逐条对账，**不允许静默遗漏** |
| **判据 schema 校验器** | 加载时断言：判据字段齐全、证据字段可解析、类型与原语匹配；任一不满足 → **拒绝加载**（fail-closed），不降级为「跳过该条」 |
| **判据质量 lint** | schema 校验管**格式**合规，lint 管**质量**可用——**三条硬**判据 fail-closed：① **可判别性**（正负样例互不矛盾——同一样例同时出现在 `match` 与 `notMatch` 即拒载该条并报红）② **可举证性**（证据字段须指向可复现的采集来源，以「人工判断」类自由文本充数即拒载）③ **概率来源可追溯**（概率须来自**输出分布的读数**；由模型生成出来的数字不构成概率——它测的是「自述与现实的差距」，与真实频率无因果关系，越训只会越像自述而非越准。来源不可追溯的判据**拒载**，因为它既不可校准也无法举证）。**第 ④ 条硬判据（问句可分解性）**：一个问句混装多个独立判断（如「这线索是否有价值、紧急且会买」）即拒载——须拆成原子问句、由代码按业务权重合成；改权重系数重跑即可，改问句措辞则可能静默破坏其他判据。两条**软**判据只提示不阻断：⑤ **可校准性**（该判据能否给出概率目标而非只能二值——不能的进「硬标签清单」，训练侧不为其做校准）⑥ **判据重复度**（语义重复的判据提示合并）。软项产出**待修清单**，与 v1.5.9 验证器老化检测同族纪律——质量问题要暴露，但不阻断整批加载 |
| **正负样例继承** | 复用 v1.5.3 的 `match` / `notMatch` 正负样例格式——**同一份样例既服务规则自测，又成为判据集的首批标注种子**（一份数据两用，不另起格式） |
| **证据就绪度标定** | 每条判据须标 **`evidenceReadiness`**：`ready`（当前可采）/ `gated:<版本>`（待某能力面采）/ `unavailable`（当前通道不可采）。**非 `ready` 者不得启用**——否则得到的是永远弃权或永远放行的**假规则**，「看起来覆盖了」比明说缺口更危险。三处结构盲区正是这一字段的三个实例：凭证范围 `gated:v1.5.4`、序列累积效应 `gated:v1.5.1`、动作授权状态 `gated:v1.5.1`（门禁留痕三态补齐）。**为什么**：判据能不能启用取决于证据能不能采，是同一件事的两面；不标就绪度，规则重述完成后**无人知道哪条真正生效** |
| **判决类记录成对完整（证据面纪律）** | 作为「证据源」的记录必须**双边完整**：门禁只记告警不记放行 ⇒ 「无记录」无法区分「合法放行」与「绕过门禁」，判据拿到的是**不可解释的空集**。凡**判决类**记录（放行/拦截、批准/拒绝、通过/失败、命中/未命中）**只记单边即视为证据面缺陷**——先修记录、再谈判据。**为什么**：这是从 `TOOL_GATE` 实例抽象出的通用形态——**「只记异常」是一类系统性偏差**，它让缺口看起来像「没有事件」而不是「没有记录」。**边界**：本章只立判据侧纪律（判据不得建立在单边记录上），**记录面的机械扫描、逐类补齐与门禁实现归 [v1.5.3 第六章](../v1.5/v1.5.3.md)**——本行是那句「先修记录」的指认，不是它的实现 |
| **判据面边界声明** | 明确本版判据面**只覆盖审计规则**（workflow / 本体数据 / 路由判定面的判据扩属 v1.9.0）；边界写进文档，防后续静默扩张 |
| **判据间依赖显式化** | 判据不是平铺集合——部分判据要以另一些判据的**输出**为输入（成熟形态：风险矩阵先行 → 据风险选证据 → 再定严重度 → 再条件路由）。有依赖的判据须**显式声明依赖**并在 `questions` 中把前置判据的结果作为后置判据的输入，**串行执行**；无依赖的才并行。**不得依赖自动推断**——隐式依赖会让「为什么这次判得不一样」无法回答 |
| **判定化范围收敛（纯函数留代码）** | 逐条复核常数阈值，区分**纯函数型**与**语义型**：长度 / 行数 / 文件数 / 注释率类常数是**结构化输入的纯函数**，**保持确定性判定、不判定化**——改概率是白增一层不可审计的间接（多一个要校准、要留痕、会静默失效的环节，信息增量是零）；其真实缺陷「系数来源不可追溯」以**记来源**修正。只有语义型常数才换校准概率。这是判定化范围的**收敛**而非扩张 |
| **调用级风险绑定** | 判据输入须含**调用级参数位**——风险是**工具 + 参数**的属性，不是规则的属性：同一次写操作，写沙箱临时目录与写生产配置不是同一个风险。判据须能表达「在什么参数条件下升档」。**参数位含三样**：① **结构化参数向量**（argv 式，不是拼好的命令串——字符串匹配可被引号、转义、变量展开规避）② **执行体解析路径**（同名工具的不同路径不是同一风险；精确匹配优先，basename 回退须在白名单内）③ **shell 包装串的拆分结果**（`bash -lc "…"` 可拆则按底层动作逐条判，拆不动则整串从严，不得因「看不出动作」而放行） |
| **判据集版本可举证** | 判据集会随校准重标与门槛重标而变——每次变更须产生新的**判据集修订标识**（内容哈希），并随判定结果落 decision-log。**为什么**：生态实证（策略引擎的 decision log 带 bundle 修订哈希）表明「这条判定当时用的是哪版规则」是审计最先会问的问题；没有修订标识，留痕只证明「判过」，不证明「按哪版判的」 |
| **防线归属标注** | 逐条判定属于哪道防线：**该不该做**（动作门——因果链与业务策略）/ **数据能不能出去**（出站门——域名、协议、方法、参数分别管，**允许域名不等于允许任意数据**）/ **最多能碰到什么**（沙箱与最小权限）。一条判据里混装两道防线者即拆开 |
| **档位五态与弃权独立归因** | 档位集合定为 **ALLOW / ASK / ABSTAIN / DENY / SKIP**——`ABSTAIN`（判不了）**不得**塞进 `ASK`（判了但需人批），否则下游无法区分「该调阈值」与「该补判据」；`ABSTAIN` 带**三源归因**（置信不足 / 域外 / 判据缺失） |
| **选项表弃权位（强制选择的第四选项）** | `Choice` 强制在给定选项内挑选，**不回答「是否有选项合适」**——选项表本身缺「无合适项」时，模型会在含糊输入上自信地选错。凡强制选择问句，选项表**必含一个「无合适项→转人工」位**（作为选项表的 schema 约束，与模型侧弃权 `ABSTAIN` 分立：`ABSTAIN` 是模型说「判不了」，第四选项是**选项面承认「都不对」**——两者互补，不可互相替代）。含糊度先验问句（「输入是否足以路由」Noul）作为伴生手段鼓励但非强制。**选项互斥性（软项⑦ · 2026-09-25 增补，消费侧落 [v1.9.0 §三](../v1.9/v1.9.0.md)）**：候选两两**可同时成立**即提示（生态实例：「物流延迟」是因、「申请退款」是果，硬做成互斥单选则问题本身畸形——模型只能自信地答一道错题）；本条管**问题定义质量**（类型限定管「不越界」，互斥管「不畸形」）。软项不阻断：互斥性常不可机械判定，交 lint 提示 + 判据评审人工把关 |
| **三处结构盲区登记（条数不动）** | 按动作门六维检查清单做覆盖扫描后，登记三处**无人管辖**：**凭证范围**（凭证是否为本任务的最小授权——A22 查「有没有提权」，缺的是权限与任务的**匹配度**）、**动作授权状态**（动作是否走过该走的授权）与**序列累积效应**（每个单步合规、合起来的序列是否造成不可接受的系统性变化；含隐蔽升级）。24 条的检查对象是变更产物 / 动作形态 / 声明清单三类，**改不动这三件事**——**登记为盲区而非新增规则**，并**指认既有归属**而不另开出处（SSOT——同一概念不长成两个入口）：**凭证范围**归口 ARCHITECTURE「权限四原则」第 1 条，且**证据面**随 v1.5.4 凭证 Vault 关闭（该版补入**凭证范围声明**产出）；**动作授权状态**归口**审计输入面**——`TOOL_GATE` 决策补齐「拦截 / 放行 / 告警」三态（现只落「告警」，放行不留痕）+ 人审支路 `hitl/resolved` 纳入规则消费（门禁判决「只记异常」使「无记录」无法区分「合法放行」与「绕过门禁」）；**序列累积效应**的**证据面**归口 v1.5.1 审计输入面（意图流使动作时序可观测）。三处的**判定面**与「为何不加规则」见下一行。第三方读数锚：生态已给出同命题的公开基准落差——某 8B 判定件单轮中英分类属 SOTA 档，但多步轨迹风险检测 Avg-F1 仅 14.63 / Unsafe-F1 0.38（同表 ShieldAgent 65.49 / 92.10——第三方实践者文章转述、本仓未复算，只作方向与量级参照，不引百分数进对照表）；其补偿方案「单轮分类 + 轨迹级审计 + 逐步骤硬规则拦截」与本仓「单步判定 + 序列证据面另行建设」同构 |
| **盲区即证据面缺口（不是规则面缺口）** | 三处盲区（凭证范围 / 动作授权状态 / 序列累积效应）的共同本质是**证据面缺口**——规则 = 判据 + 证据，**事实不可观测时加一条规则只会得到一条永远弃权或永远放行的假规则**，增加的不是覆盖而是「看起来覆盖了」的假绿。故处置顺序是**先让证据可采、再谈判据**：凭证范围的证据面随 v1.5.4 凭证 Vault 关闭（该版补入**凭证范围声明**产出）、序列累积效应的证据面随 v1.5.1 审计输入面关闭（意图流使动作时序可观测）、动作授权状态随审计输入面补齐 `TOOL_GATE` 三态（门禁判决现只落「告警」一态）并纳入人审记录消费而关闭。**判定面**：两处折进既有规则的语义层（`A22-2` 凭证与任务的匹配度 / `A17-2` 序列是否构成异常累积效应），一处**不靠新增规则而靠补记录**（24 条检查对象为变更产物 / 动作形态 / 声明清单三类，**声明 ≠ 授权**——`TOOL_GATE` 补齐三态后即可与意图流对账判「未授权执行」，折进 `A16` 语义层）——**据此 24 条条数一条不动**。**证据未可采前，三条语义层判据（`A22-2` / `A17-2` / `A16-2`）不得启用**。**序列累积效应的判定形态参照（时序关联）**：`A17-2` 的实现不是「逐事件独立判再汇总」，而是**会话域 + 时间窗 + 多步序列**的关联判定——生态检测规则标准同构（先读敏感文件、再在时间窗内外发即报「读密钥→外传」关联发现，两事件各自合规、组合即违规）。单事件匹配抓不住「每步都对、合起来不对」，这正是不加新规则也能判序列效应的机制形态 |
| **门槛纪律入判据面** | 凡带门槛的判据：门槛**按原语分档**（`Noul` / `Choice` / `Score` 置信剖面不同，同一门槛值在不同原语上是不同严格度）、**绑定当前分布**（换基座或漂移须重标）、**健康度两极端告警**（过严 ⇒ 全量落入 ASK 等于没分流；过松 ⇒ 形同虚设。门槛设错不报错，只静默失效） |

### 判据模板与范例（逐条重述的开工规范）

> ⚠️ **排期纪律：本版是规划（📋 规划中），判据逐条落数是本版实施期的工作。** 文档期只定**规范**（模板字段 / 范例 / 纪律），**不在文档期开工落数**。两条理由：① 判据落数依赖**开工时规则集的实际条数**（v1.5.3 落地后为 25 条）与**证据就绪度标定**，两处前提未定时先落数必然返工；② 先落数会绕开本版**前置门**（判据不可用则本版不发版，且 v1.7.0 不启动），使「规划」偷跑成「实现」。

24 条规则逐条重述为「判据 + 证据」两段式数据面时，**一条规则不必等于一条判据**——规则内部的**纯函数层与语义层**应拆成不同判据，否则会把「根本不是判断的东西」硬推给判定层。逐条重述按下列字段规范统一落数。

| 字段 | 作用 | 取值/约束 |
|------|------|-----------|
| `id` | 判据标识 | 规则号 + 判据序号（如 `A19-2`）——**一条规则可拆多条判据** |
| `question` | 要判断什么 | 问句形态；**不带判据名**（问句标识不上行） |
| `primitive` | 原语 | `Noul` / `Choice` / `Score` |
| `options` / `scale` | 答案空间 | `Choice` 须给**全候选**（超词表上界走分块 + 「以上都不是」槽）；`Score` 须给 **2–10 个具体基准级别**（层级独立评判、模型看不到编号） |
| `evidence[]` | 证据项 | 每项含 `source`（采集通道）+ `locator`（可复现定位）+ `reproducible`（布尔）。**以「人工判断」类自由文本充数即拒载** |
| `evidenceReadiness` | 证据就绪度 | `ready` / `gated:<版本>` / `unavailable`——**非 `ready` 者不落数、不得启用**（与 `deps[]` 同源思想：可用性靠显式声明，不靠推断） |
| `inputParams[]` | 调用级参数位 | 三样：结构化参数向量 / 执行体解析路径 / shell 包装拆分结果 |
| `disposition` | 判定化范围 | `留代码` / `换校准概率`——**纯函数型常数须标 `留代码` 并记系数来源** |
| `probabilitySource` | 概率来源 | `distribution`（输出分布读数）/ `head`（打分头）/ `denoise`（去噪）——**未校准的 `head` 不得直接当概率消费** |
| `defenseLine` | 防线归属 | `action`（该不该做）/ `egress`（数据能否出去）/ `sandbox`（最多能碰什么）——**一条判据只属一道** |
| `thresholds` | 门槛 | 按原语分档 + 标注**绑定哪个分布** + 重标触发条件（换基座 / 数据漂移） |
| `abstainTriggers[]` | 弃权可能 | 三源归因：置信不足 / 域外 / 判据缺失 |
| `examples` | 正负样例 | `match[]` / `notMatch[]`——复用 v1.5.3 格式，一份样例两用 |
| `justification` | 拦截理由 | 附**替代建议**（FAIL 报文用） |
| `deps[]` | 判据间依赖 | 前置判据 id——**有依赖串行，不靠自动推断** |
| `revision` | 版本可举证 | 判据集修订标识（内容哈希）——随判定落 decision-log |

**范例一 · A19（msg 质量）：演示「一条规则拆成留代码 + 判定化」**

| 项 | `A19-1` | `A19-2` |
|---|---------|---------|
| `question` | 变更说明长度与黑名单命中是否达标 | 这条说明是否传达本次变更的意图 |
| `primitive` | —（确定性） | `Noul` |
| `disposition` | **`留代码`** | `换校准概率` |
| 落数 | `msg.length >= N` 是结构化输入的纯函数，**保留确定性判定**；`N` 须记**系数来源**（由哪批真实提交统计得出） | 交判定层；`probabilitySource: distribution` |
| 理由 | 换成概率是**白增一层不可审计的间接**——多一个要校准、要留痕、会静默失效的环节，信息增量是零 | 语义判断，阈值须有校准依据 |

**范例二 · A15（不盲动）：演示「双判据 + 显式依赖」**

| 项 | `A15-1` | `A15-2` |
|---|---------|---------|
| `question` | 本次变更是否包含未被声明的动作 | 每个实际动作是否被声明覆盖 |
| `primitive` | `Noul` | `Choice`（候选 = 实际动作全集） |
| `evidence[]` | `source`：声明文件 + 调用日志；`locator` 到行；`reproducible: true` | 同左，另含动作定位 |
| `inputParams[]` | 结构化参数向量 + 执行体解析路径（同名工具不同路径不同判） | shell 包装拆分结果（可拆则逐条判，拆不动整串从严） |
| `deps[]` | — | **`[A15-1]`**——前置输出为后置输入，**串行执行** |
| `abstainTriggers[]` | 域外（声明整体缺失） | 置信不足 |
| `defenseLine` | `action` | `action` |
| `thresholds` | `noul` 分档 | `choice` 分档——**与 `noul` 取不同值**（多选重排普遍不确定，门槛须更低） |
| `revision` | 修订标识随判定落 decision-log | 同左 |

**三条固定纪律**（对全部规则适用）：① **`留代码` 与 `换校准概率` 的对账清单须逐条落数**——两者的比例本身就是「判定化范围收敛」的度量；② **判据重述若暴露规则自身的语义歧义，逐条记录、不在本版偷偷改规则语义**（作为下一版修正输入）；③ **证据就绪度全表标定在前、判据落数在后**——任一判据的 `evidenceReadiness` 非 `ready` 即**只登记待采、不落数**，否则会给出一条永不启用或永不放行的**纸面判据**，把真实缺口掩盖成「已覆盖」。

## 三、理念升级驱动的文档重构（触发条件与分层口径）


> **形态归属**：`[非功能]`（文档治理·重构）｜ —（重构不改能力边界，不涉可拔面）

文档的事实基础是**理念**，不是代码。代码变更只让某一段描述过时；理念升级会让一整批文档的**断言口径**同时失效——判定层接管后，「24 条审计规则各自判定」这句话本身不再成立（降为「判据声明 + 证据采集器」），而 SECURITY / ARCHITECTURE / audit README 三处都在说这句话。**只改被触发的那一处，等于把同一个事实分散在三处继续漂移。** 所以文档重构不是「有空再做的清理」，而是随触发它的那一版同批交付的交付面——它与本版第二章同源：判据重述改变了规则的文档口径，文档口径的重构就必须同批完成。

### 交付

**触发条件**（满足任一即触发重构评估，而非延后清理）：

| 触发 | 判据 | 处置 |
|------|------|------|
| 理念升级改变断言基础 | 新理念使既有文档的断言不再是当前事实 | 全站扫描该断言的**全部**承载面，同批改写 |
| 术语更名 | 术语 SSOT 变更 | 改名即刻全站扫描升级，不留新旧并存 |
| 版本线新增 | 版本数量级变化（施工期拆版等） | 版本叙事层重整：目录 / 索引 / 互引 |
| 分层预算触顶 | A / B / E 任一层无余量承载本批改动 | 先**归层**（把开发者参考面移出用户文档层），再考虑上限 |

**分层口径**（哪一层承载什么、按什么口径重构）：

| 层 | 承载什么 | 重构口径 |
|----|---------|---------|
| A 用户文档 | README（双语）/ CHANGELOG / SECURITY / ARCHITECTURE / ROADMAP 等 | 断言以**当前事实**为准；历史沿革下沉 changelog |
| B 开发者参考 | FORGE / playbook / agents / .github / engine hooks | 规则文档**只写规则**——不带版本号、行号与日期 |
| E 运维指南 | `docs/guides/**` | 操作口径优先；非核心文档按「零信息删除」压缩 |
| 历史事实区 | `docs/changelog/**` | **不计入预算**——它是重构的落点，不是重构的对象 |

**版本关系纪律**：

| 纪律 | 内容 |
|------|------|

## 四、判定底座的边界（做马鞍，不做马场）


> **形态归属**：`[主干]`（判定·边界声明）｜ **不可拔**（边界是能力声明的护栏——拔掉则判定面可静默扩张为应用面）

判定底座是**治理能力的载体**，不是**应用能力的容器**。判据的工作是把**已有判断**显式化并校准，不是**引入新场景**。这条区分必须在施工期第一版写死：边界先于能力落盘，后续每一版才有对照物——否则「顺手多做一个域」永远看起来比「先修判据质量」更像进展。完整边界陈述见 [ARCHITECTURE · 判定底座的边界](../../ARCHITECTURE.md#判定底座的边界做马鞍不做马场)，本章只落**版本级口径**（边界 SSOT 唯一，两处互引不重复）。

### 交付

| 组件 | 能力 |
|------|------|
| **四条边界判据** | ① **约束 vs 扩张能力**——既有判定面的判据已存在（只是隐式、未校准），底座做显式化与校准；为新场景从零造判定即越界 ② **判定面治理 vs 判定应用**——治理「判定怎么被做」，不决定「判定被用来做什么」 ③ **是否把判定变对外服务**——判定只在引擎内部被消费，不作为对外服务提供 ④ **是否承担模型提供者角色**——交付底座与通道且实现可替换，不承担模型性能承诺 |

## 五、数据集三元组格式（状态 / 问题集 / 标注答案）


> **形态归属**：`[主干]`（判定·数据格式）｜ **不可拔**（格式是数据集契约，拔掉则标注无法被校验）

### 交付

| 组件 | 能力 |
|------|------|
| **三元组定义** | `(state, questions, answers)`——`state` 为非结构化输入快照、`questions` 为限定原语类型的问句集、`answers` 为类型化答案（含概率目标）。与本版第一章三原语类型同构，**不另立格式** |
| **标注来源三档** | `label.source` 三档与 v1.5.8 域验证器口径一致：`deterministic`（自动判据/测试断言 → 廉价可信）/ `model-judge`（模型评分 → 有成本）/ `human`（HITL 裁决、PR 审阅 → 最贵最可信）。**分档随样本走**，训练时可按档加权 |
| **概率目标表达** | `answers` 须能表达**概率目标**（choice 的分布 / score 的区间 / noul 的真值概率），而非单一硬标签——这是阶段二校准训练的前置条件。只有硬标签的数据集**训不出校准**，格式层必须预留 |
| **血缘锚点** | 每条样本记录反向锚点（轨迹 id / instinct id / PR 号 / HITL 会话 id），与 v1.5.8 数据集血缘同族——训练产物可反向追溯至样本源头 |
| **租户隔离** | 样本按 `enterpriseId` 分区（对齐 v1.4.7 多租户路径纪律），跨租户混入默认禁止 |
| **公开对照集具名（只作对照，不进训练集）** | 判定底座的对外读数须能对照**业界通用三源**：判断题 XNLI / 选择题 MASSIVE / 打分题 STS-B（回归打分）。这三源覆盖三原语各自的形态，是「我们的判据集之外」的独立标尺——**只作对照集校准口径，不混入训练集**（训练数据主权纪律不变）。中英分列对照（XNLI 有中文子集；MASSIVE/STS-B 以英文为主，中文侧对照缺口如实登记） |
| **判据跨域映射口径** | 本仓判据集与外部**文本判定件**不同形：本仓输入是仓内原生结构（`diffFiles[].lines` 为 unified-diff 行数组）、输出契约是 `{result, rules_triggered, severity}`；外部判定件消费「一段 state 文本」、输出概率。故「同判据集」按三层定义：① 按**认知负载类型**（二分判定 / 多类选择 / 序数评分）把两侧判据归入同一**等价类**——类内用同一份 state、同一份金标、同一评测器，**类间不比**；② 对照件接入须经**双向适配**（`diffFiles[].lines` + `task` → state 文本；对照件输出 → `result`）；③ **逐条声明不可比项**——输入侧 `logEntries` / `diffFiles[].status` 方向语义、输出侧 `rules_triggered`（规则 ID）与 `severity`（`ruleClass` 投影，**且 WARN 触发时 P0 封顶降 P1**——该截断是审计域语义，对照域无对应位）均为审计域特有，**仅 `result`（PASS/FAIL）一维参与对照**；④ **判据实体尚未实现的（已排期未落地的规则）不进映射表**，标「待规则落地后补录」——**根因是判据不存在，不是映射方法失败**，两者对落盘的指向不同（前者等规则，后者改方法）。口径不可比者只列数字不排名 |
| **格式校验器** | 数据集加载时断言：三元组齐全、问句类型合法、答案类型与问句匹配、概率目标合法（分布归一 / 区间有序 / 概率 ∈ [0,1]）；不合规 → **拒绝加载** |

**对比样本（contrastive pair）的构造纪律**——自然采集只能覆盖「判据判过什么」，覆盖不了「**判据为什么该改判**」。对比对补的正是这一面：**同一份 state，只改一处事实，正确答案翻转**。生态已验证这条路可行（公开复刻件用不到三千条对比样本把 9B 基座的判定一致率从 66% 提到 90% 量级），故本版把构造纪律写进格式层：

| 条目 | 纪律 |
|------|------|
| **四步构造** | ① **查规则**——写出规则依赖的基础事实，确认该规则能导出**不同**答案（不能导出的规则不产对比对）② **造对**——两句证据、**都必需**；**最多改 8 个词**（改动即焦点事实）③ **双检**——分别检事实、政策一致性、**无答案暗示**；再**轮流删掉一句**，确认焦点事实**变为未知** ④ **出标签**——由**代码用已查规则 + 已查事实算出**，**不由模型出标签**（模型出标签即把不可举证的数字写进训练集，与本版第二章「概率来源可追溯」同源纪律） |
| **「8 词」是机械局部性检查，不是「只改了一个事实」的证明** | 生态作者自己写明了这一点——本版照抄其**用途**（防止改动面失控），**不得**在文档或验收里把它表述成「已证明单点改动」。承认工具边界比假装它更强更省事 |
| **删句样本只作校验、不进训练** | 删掉一句后焦点事实变未知 ⇒ 该句是必需证据（用于校验成对样本的**必要性**）。但**「缺失信息」从不自动等于「信息为假」**——把删句样本当负例训练，会教出「看不见就当假的」，这是判定面最危险的一类错误先验。故：**删句样本仅供校验，不入训练集** |
| **事实三态随行** | 每条样本随行 `evidence_certificate`：每个事实命题标 **`supported` / `refuted` / `unknown`**，并记录**基线态 / 反事实态 / 删左态 / 删右态**四组。三态而非两态，是「未知」与「为假」在数据里必须可分的唯一手段（两态会把「没查到」压成「是假的」） |
| **家族级防泄漏** | 切分**按来源家族**而非按样本——对比对与同源家族**整体留同一侧**。否则同源对比对一半在训练一半在评测，测到的是记忆不是能力（与第七章门二同族，此处是**家族**粒度） |
| **标签由代码算** | `deterministic` 档的标签一律由已查规则 + 已查事实在代码里导出，可复算、可复现；不由模型生成 |

> 🔴 **与「概率目标」的关系：拆两路，不混装**。对比对产出的是**硬标签**（正确/翻转），而归一化分布那类概率目标**给不出来**。若把两类混进同一路，会直接撞上第七章门四：**硬标签样本不进校准集**。故本版明确：**对比对进训练集**（教「哪条证据才该改变判定」），并标 `no-probability-target`、**不参与 ECE 计算**；**校准集的概率目标须另有来源**（`human` 档人工裁决 / 能表达分布与区间的标注通道）。这一条写成格式层的字段约束，不靠流程纪律维持——**流程纪律会腐烂，字段约束不会**。

| **冷启动来源通道（门一的唯一例外，须显式声明）** | 门一默认拒收外来样本，但**判定面首版训练前生产痕迹尚未积累**——冷启动必须有通道，否则采集设计在第一天就空转。通道限定为**三类且逐类定边界**：① **仓内既有审计链历史**（回溯/审计/PR 审阅的既有记录 —— 属「真实运行痕迹」，可直接采）② **真实 state + `model-judge` 标注**（教师模型给**真实输入**打标签——样本来源真实、标注档为模型，进训练集并按档加权，**不进校准集**）③ **合成 state（教师生成）**——**只用于扩面，不用于定标**；标 `synthetic`，既不进校准集也不参与任何对外数字。**开源数据集的定位**：**不进训练集**——门二要求与公开基准 / 厂商评测集**零交集**，且公开样本会被厂商纳入评测训练，届时测到的是记忆而非能力；其正当用途只有两个：**基座与路线选择时的对照参照**、**判据形态的抽象参考**（看别人怎么定义判定问题，不搬其数据）。**与谱系声明的衔接**：任何冷启动来源须在数据集谱系中逐类列明（来源构成 / 行数对账 / 污染声明，[v1.7.0 §三](../v1.7/v1.7.0.md)）——冷启动不是免于声明的理由，恰恰是**最需要声明**的一段 |
| **去重与泄漏防护** | 采集侧做近重复检测；**同一轨迹不得同时进训练集与验证集**（数据泄漏防护）——切分按轨迹/租户粒度而非样本粒度 |
| **采集可观测** | 各源采集量 / 各档占比 / 拒收原因分布可查询（数据面健康度可见，数据本地不出门） |

**九类补充采集点**（三源采的是「自然发生」的样本；而困难样本在任何自然分布里都是少数——自然采集必然偏易判样本，校准曲线因此失真。所以这九类必须**点名采**，每类写清「采什么」与「**判定它属于本类的判据**」——判据不写清，采集点就退化成关键词匹配）：

| 采集点 | 采什么 | 判定它属于本类的判据 |
|--------|--------|----------------------|
| **弃权记录** | 判据因证据不足而**弃权**、或 `Choice` 落到兜底项的样本 | 输出态为 `ABSTAIN`，或选中项为问句集兜底项；样本须同记**当时的概率与门槛**——不记就无法区分「真不确定」与「门槛设错」，而后者的修法是改门槛不是补样本 |
| **上下文取舍** | 同一 state 的**最小可判定前缀**版本与**截断 / 检索过滤后**版本成对出现、且答案发生变化的样本 | 成对可比：两份输入的差异**只在被取舍的片段**；且须过**必要性检查**——删去该片段后焦点事实**不变为未知**则说明它并非必需证据，该对**不构成取舍样本**（防把冗余当取舍，否则训出的是「信息越多越好」的错误先验） |
| **路由对比** | 同一 state 下 L0 声明式映射 / L1 语义分类 / L2 难例兜底给出**不同结论**的样本 | 同一份输入在三档判定层中得到不同答案；**分歧本身就是标签**——须同时记录既有确定性规则的结论作参照，否则无法判断哪一侧该被修正 |
| **措辞不变性** | 语义等价的同义改写 / 语序调整 / 中英对译后**答案发生漂移**的样本 | 改写前后**语义等价性须经确认**（未确认的改写只是新样本，不是不变性样本）；漂移量按改写类型**分列落数**，不合并成一个「鲁棒性得分」 |
| **OOD（分布外）** | 从未出现在训练判据域内的**任务类型**样本 | 该样本的**判据域**不在本版判据集内——按域登记而非按形态登记；落数须**分布内外分列**，合并成一个总准确率会把泛化落差平均掉 |
| **漂移探测** | 跨时间重复采样中**标定失准**的判据（概率与真实频率分离）的样本 | 同一判据在两个时点的分桶可靠图出现**单向偏移**；须同记**时点**，否则不可复现 |
| **对抗** | ① state 内容**诱导答案偏移**的样本 ② 企图让判定**越出判断权限**的样本（要求它执行动作而非给出判断） | ① 同一事实换个措辞答案就变 ② 输入中携带「授权 / 政策」类文本——**权限政策由代码持有，外部文本只能作证据不得作政策来源**（不可信观察分层）。此类样本是「判定面可被 state 内容操纵」这一**已知失灵面**的证据面，**不是要修的 bug**——采它是为了给它设防线，不是为了训掉它 |
| **对齐分歧** | 模型判定与人工裁决**不一致**的样本 | 两侧标签档不同（`model-judge` 与 `human` 冲突）——按第七章门三**进人工复核队列，不取多数票静默裁决**。**与第七章「分歧优先」的分工**：本采集点负责**定义分歧、落成样本、登记分歧原因**（证据面）；第七章负责**决定优先标谁**（选样策略）。两者衔接不重复 |
| **出站裁决**（第九类） | 白名单外 host 请求的裁决样本——[v1.5.2 §五](../v1.5/v1.5.2.md) 可导出的出站裁决事件契约：**该不该放行这个出站**（`Noul`）+ **裁决依据是否充分**（`Choice`：白名单命中 / 域相似 / 证据不足） | 消费方是 v1.5.2 出口治理面的事件导出——裁决事件天然带「输入（host/请求）→ 结论（放行/拦截）→ 依据（哪条白名单）」三元组，正是 `(state, questions, answers)` 的现成实例；白名单外请求是**天然困难样本**（多数类失衡：绝大多数请求合规放行，拦截是稀有正例，点名采才够） |

> 🔗 **与弃权的关系（互补，不等价——两处都要有）**：**弃权**是模型自己给出的**态**；**兜底项**是问句集里的一个**候选**（如「以上都不是」/「信息不足」），需要模型**选中**它。只有弃权而无兜底项 ⇒ 模型面对「选项都不合适」时被迫在坏选项里挑一个；只有兜底项而无弃权 ⇒ 「选中兜底项」与「不确定」在记录里无法区分。问句集的兜底项定义见本版第一章（问句集限定），本章负责**把选中兜底项的样本采回来**并**与弃权态分开留痕**。

### 风险与前置假设

> ⚠️ **本版产出的样本量可能不足**——三源采集依赖真实运行积累，早期客户环境样本稀疏。若样本量不足以支撑阶段二校准，则**下调阶段二目标（只出判定不出校准）并把校准后移**，不硬训。样本量实测结论作为本版第九章的基线输入之一。
>
> ⚠️ **语言面是隐性稀疏项**——判定模型普遍以英文为主训练，中文判据样本即使在三源里也天然稀少（真实运行痕迹的业务语言分布决定）。本版采集侧须**分别落数中英文样本占比**，不合并成一个「样本总量」——否则「样本够」的结论会掩盖「中文不够」，而中文正是本版第九章中文基线的输入。
>
> ⚠️ **九类采集点在早期环境里的命中数可能为零——「零命中」必须与「采集点未就位」可区分**。九类困难样本依赖真实运行积累，早期客户环境很可能某几类长期为零。若只记「采到了几类」，则「采集点已就位但该类确实没有」与「采集点根本没接上」在数据面上**完全同形**——这与本版第二章「判决类记录成对完整」是同一个失效形态：**「只记异常」会让缺口看起来像「没有事件」而不是「没有记录」**。故本版采集侧须为**每一类分别落数**（命中数 + 最后一次命中时点），零值也落，不省略。

## 七、采集质量门与主动学习选样（数据可用性的前置判定）


> **形态归属**：`[主干]`（判定·数据质量）｜ **不可拔**（质量门是样本可信的前提——不过门的样本进训练等于把噪声固化成能力）

采到了不等于能用。本版把「数据可用性」从人工判断升级为**四道可断言的机器门**，并把「样本怎么挑」从被动汇聚升级为**主动选样**——两者的共同前提是同一个事实：**校准能否达成，取决于困难样本有没有被采到**，而困难样本在任何自然分布里都是少数。

### 交付

**四道质量门**：

| 门 | 判据 | 处置 |
|----|------|------|
| **门一 · 来源真实性** | 只收经审计链锚定的真实运行痕迹 | 合成 / Agent 自述 / 未建链来源标记后**默认拒收**（与 v1.5.8 防自证污染同源） |
| **门二 · 跨集泄漏** | 切分按**轨迹**粒度而非样本粒度；样本带**私有哈希** | 同一轨迹不得同时进训练集与验证集；近重复检测**跨集**执行；与公开基准 / 厂商评测集**零交集**（有交集则测到的是记忆而非能力）。另须防**回放泄漏**——同一轨迹内，**切分点之后才产生的信息**（事后复盘、已结案工单、事后标签、结论性备注）不得进入切分点之前的输入，否则评测会系统性高估判定能力（生态实证：这是回放式评测最主要的效度威胁）。切分点须显式定义并留痕 |
| **门三 · 标签噪声对账** | 同一样本多档标签是否一致 | `deterministic` 与 `human` 冲突 ⇒ 进人工复核队列，**不取多数票静默裁决** |
| **门四 · 校准标注** | 样本能否表达概率目标 | 只有能表达概率目标的样本进**校准集**；硬标签样本归训练集并标 `no-probability-target`，不参与 ECE 计算 |

**主动学习四类选样**（被动汇聚会让样本集中在易判样本上，校准曲线反而失真）：

| 选样 | 判据 |
|------|------|
| **不确定优先** | 概率接近 0.5 的样本优先——最接近决策边界，标注收益最大 |
| **分歧优先** | 模型判定与人工裁决不一致的优先（对齐分歧样本） |
| **代表优先** | 覆盖判据域稀疏区域的优先——防样本集中在少数判据上 |
| **漂移优先** | 跨时间重复采样中标定失准的判据优先补样 |

**困难样本的主动构造（与选样互补，不是替代）**：四类选样是从既有池子里**挑**，但「决策边界附近的样本对」（仅一个焦点事实不同、判定相反）在自然分布里近乎不存在——只能**造**。构造法：取一条真实样本，**只翻转一个焦点事实**，问句、政策与无关证据逐字保持不动，配对成「焦点翻转对」；训练时模型被迫把「变的那个事实」与「变的那个判定」绑定，而不是靠无关特征蒙对。**两条边界**：① 构造出的对是**扩面样本**（提高边界分辨率），不是定标样本——定标权仍在真实痕迹与 `human` 档（对齐下文优先序）② 被翻转的事实须取自真实痕迹而非凭空编造，否则「对比」教的是虚构规律。**来源**：同期判定件 **Bespoke Nimble** 的公开数据 recipe 已把该法当主训练目标（其自报 2,676 对 / 训练 1 轮即达参考标签一致率 90.12%；具名来源与许可见 [THANKS · 判定与校准](../../THANKS.md)）。

**集分档**（三集分工，不混用——同一个集既挑模型又调阈值，等于用同一把尺子量两件不同的事）：

| 集 | 用途 | 构造纪律 |
|----|------|----------|
| **候选集**（挑模型用） | 比较基座 / 实现路线 / 训练档的优劣 | 覆盖真实流量分布 + **必须含边缘与对抗样本**；**评测集训练痕迹重则泛化差**——公开基准上的高分不构成选用依据 |
| **刻度集**（调阈值用） | 定分流门槛的位置 | **必须来自生产流量分布**：门槛设在**数据实际峰值所在、且达到精度目标**的位置，而非「所有任务上看都还过得去」的位置 |
| **免调集**（不该继续调的任务） | 登记为不值得继续优化的任务并**移出循环** | 须写明「为什么移出」，避免它反复回到排期里空耗注意力 |

**门槛是分布的函数**：换基座或数据漂移时须**重新校准门槛**，不得沿用旧值——门槛绑定的从来不是任务名，而是**该任务在当前分布下的概率峰位**。

**集的两条纪律**：

- **冻结即单调**：候选集一经冻结不得追加（分数**只能降不能升**）——冻结的意义正是堵住「偷塞简单样本抬分」这条路。样本增补走**新建集**，并声明新旧集**不可横比**。
- **私有锚定**：集内样本带**私有哈希**，与任何公开基准 / 厂商评测集**零交集**——公开样本会被厂商纳入评测训练，届时测到的是记忆而非能力。**外部印证（2026-09-25 登记）**：品类侧独立第三方榜把「公开半集」与「密封半集」**分列并施加惩罚**（公开集与密封集准确率差 >25 个百分点即扣减该维得分），对方在榜前自行声明「公开半集可被训练、也可被择优，故密封半集须随领域变化**持续演进**」。⇒ 本条的落地面除「零交集」外还须含**换代机制**（新增样本走新建集、新旧集声明不可横比）——**钉了哈希的集不是一劳永逸的**（与 [v1.5.8 防投毒行](../v1.5/v1.5.8.md) 同源）。
- **对照面的冻结镜像（NeoHorse-Jev 评测协议印证，2026-09-25）**：本仓「冻结防污染」在对外对照侧的镜像已有同期品类实证——NeoHorse-Jev 开源把**评测子集冻结置于模型对比之前**（Nimble/VitaminC/MASSIVE 的样本 ID 与记录在对比前先冻结、上游采样钉死随机种子、冻结规则在 README 显式声明「仅作评分参考不作模型输入」），并在聚合口径上自曝「AVG 为六组等权平均、**非逐题合并准确率**」、游戏演示分不计入文本聚合——与本章「冻结即单调 / 私有锚定」与 [v1.9.0 §五](../v1.9/v1.9.0.md)「同判据集同评测器」构成品类两侧的同源纪律。其协议全文（jev/ 目录）可作 [v1.9.0 §五](../v1.9/v1.9.0.md) 对照口径的参照件。**口径**：对方协议观察，本仓纪律不因此改动——两条纪律先行在仓，此条只登记外部印证。

**优先序纪律**（选样不是等权，谁先补有次序）：

| 纪律 | 内容 |
|------|------|
| **中文优先** | 中文判据面近乎无人占据——先补中文，英文判据面竞争充分且非我方差异点 |
| **人审 > 合成** | `human` 档样本不可替代；合成样本只用于**扩面**，不用于**定标** |
| **教师蒸馏的用法与防线** | 冷启动期用教师模型造标注是**可接受的起步**（生态共识：任务明确 + 少量种子样本即可启动，教师标注远比人工便宜），但三条边界须同时成立：① **学生不能超过教师**——教师能力须先自证（先跑教师自己的验收），否则蒸馏只是把教师的错固化成学生的错；② **防校准欺凌**——教师对错误类别报高分会把过度自信传给学生，故须用**概率标签 / 温度 / 标签平滑**削弱硬标签的 bully 效应；③ **两阶段切换**——冷启动靠蒸馏起步，真实痕迹到位后**切回真实样本持续训练**（生态实测该两阶段路线的学生最终可超过教师与纯监督基线）。**定标权始终在真实痕迹与 `human` 档手里**，蒸馏不参与定标 |
| **对抗必备** | 对抗样本不是可选项——state 被当数据不当敌意内容是已知失灵面，无对抗样本则校准数字无解释力 |
| **弃权 / 分歧 > 一致** | 一致样本信息量低；弃权与分歧样本才是校准曲线的形状来源 |

## 八、基座编码器与判定头接线（编码器路线 · 非生成路线）


> **形态归属**：`[主干]`（判定·推理底座）｜ **不可拔**（判定底座本体）

### 交付

| 组件 | 能力 |
|------|------|
| **编码器基座接入** | 采用 **encoder-only** 路线（不接 decoder 生成模型）——判定任务不需要逐 token 生成，这是与「用生成模型做判定」的根本分野。接入方式为本地可跑、可离线，不依赖外部 API |
| **判定头（marker 式）** | 在编码器输出之上挂**类型化判定头**，按原语类型分发：choice 头（候选项打分 + 归一）/ score 头（序回归）/ noul 头（伯努利概率）。三头共享编码器，**不共享输出层** |
| **多问并行** | 同一 `state` 下的多个独立问句一次编码、多头并行出答案（本版第一章 schema 的批量形态在此落地），避免逐问重复编码 |
| **基座选型口径** | 基座规格（参数量 / 上下文长度 / 语言覆盖面）**在本版定稿并记录理由**，但不写进对外文档的能力声明——对外只说「本机能跑的判定底座」。**接口层不绑定具体基座**：换基座不改判定头契约与 `DecisionChannel` 契约。**参数量档位的实测参照**：同类判定件的实测分布横跨**千万级到十亿级**——极小 BERT 风格件 **2000 万级**可服役、安全判定件 **3 亿级**可超过比它大数十倍的件、通用判定件 **3–4 亿级**为主流、**1B 档**是通用小模型的生产甜蜜点。**判定件不必对标生成模型规模**：「低于 4B 不可靠」的结论来自**生成式**判定件（要理解 + 逐 token 生成判断），与编码器判定件的分类评分形态不同源，**不得直接套用**。**语言覆盖面是硬约束而非加分项**：目标客户为中文场景，基座中文能力须与英文**分别落数**（本版第九章口径），英文为主的编码器在非拉丁脚本上会**高置信度失效**（生态实测：英文档在非拉丁语言上准确率趋零而置信度仍高）——故须选中文强的多语编码器档，或按语种分档交付 |
| **接入形态** | 跑在一体机已有的本地推理栈上（**零新增运行时组件**），与既有本地模型槽位管理（v1.5.4 槽位信号量）协同；判定**不占本地主模型槽位** |

|------|------|------|
| `engine/orchestrator/src/router/judge-heads/`（目录） | 新建 | 三原语判定头（choice / score / noul） |
| `engine/orchestrator/src/router/judge-runtime.ts` | 新建 | 编码器接入 + 多头并行 + 槽位协同 |
| `engine/orchestrator/src/router/decision-model-registry.ts` | 修改 | 判定底座基座注册（复用既有 model-registry 纪律） |
| `engine/orchestrator/src/__tests__/judge-runtime.test.ts` | 新建 | 多头分发 / 批量并行 / 不占主模型槽位（行为锁）单测 |

## 九、零样本基线落数（如实记录 · 不修饰）


> **形态归属**：`[主干]`（判定·基线度量——本版为**度量动作**，非能力交付）｜ —

### 交付

| 组件 | 能力 |
|------|------|
| **零样本评测器** | 在本版第五–七章数据集上跑零样本推理（基座不微调），按判据逐条统计：命中率 / 一致率 / 各原语分别的表现 |
| **基线报告** | 产出结构化基线报告：逐判据准确率 + 混淆分布 + **失败模式分类**（哪类判据完全跑不动、哪类边界模糊）——失败模式清单是阶段二训练的重点输入 |
| **校准现状探测** | 在零样本条件下同时记录**候选概率的校准状况**（分桶可靠图 / ECE），用以确认阶段二校准的必要性与起点 |
| **分布内外分列（泛化落差）** | 基线须区分**工具/演示任务族内**与**从未见过的任务类型**两种口径分别落数。**为什么必须分开**：生态实测已给出这个落差的量级——某公开复刻在其演示任务族上 98.8%（ECE 0.003），而在从未训练过的任务类型上只有 74.8%，相差约 24 个百分点。合并成一个数字会把这个最重要的风险信号平均掉，而它直接决定 v1.9.0 的判据面扩展能否成立 |
| **基线落数与归档** | 基线数字进版本日志并归档，作为阶段二「提升幅度」的对照基准（**对照必须同数据集、同评测器**，防口径漂移） |
| **诚实性纪律** | 基线数字**不得修饰**：低就是低。基线难看是预期内的（编码器零样本在细粒度判据上普遍偏弱），其价值在于把「训练能带来多少提升」变成可量化问题 |
| **可复算产物随数交付** | 基线每个数字都须附**可复算产物**（生成脚本 + 结果文件入仓，路径可指），而非截图或散文叙述——**不可复算的数字等于自报**。以「单次运行」「私有数据」得出的数字须**显式标注该口径**，不与可复算数字并列展示 |

### 风险与前置假设

> ⚠️ **零样本判定力可能显著不足，这是预期而非异常**。既有同类开源判定模型的零样本表现已实测偏低（52 语言扫描曾出现「准确率 0.000 而置信度 0.952」的极端情形）——这恰恰印证了两件事：① 判定能力必须靠**有监督 + 校准**训练，零样本不可依赖；② **未校准的置信度数字具有严重误导性**，校准不是锦上添花而是可用性前提。
>
> ⚠️ **本版不产出任何可对外宣称的能力**。阶段一（v1.6.0）的累计产物是「判据 + 数据 + 基线」三件内部资产，对外口径零变化。
