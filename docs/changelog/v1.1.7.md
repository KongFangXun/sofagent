# v1.1.7 开发日志 — Dream Cycle 6 阶段管道 + sensitivity

> 状态：规划中 · 孔放勋 · 2026-07-15
> 前置依赖：v1.1.6（conflict-check 已就绪）

## 背景

v1.1.6 能检测知识库的毛病了，但知识本身还是靠 daemon 两个老脚本（weekly-report / lessons-extract）散点生成。v1.1.7 用 gbrain 的 Dream Cycle 精简版（6 阶段 pipeline）替换它们，把知识沉淀从散兵升级为流水线。同时给 knowledge/ 加 sensitivity 字段，为后续联邦查询的安全过滤铺路。

### 设计输入：操作型本体论的读写回路

> 来自 Palantir 操作型本体论系列研报（2026-07）的启发。

Palantir 操作型本体论的核心是一个 5 节点闭环的**读写回路**：读（数据集成）→ 逻辑（规则编排）→ 写（事务回写）→ 反馈（持续学习）→ 治理（全链路审计）。传统知识图谱只覆盖前两节点——能查询，不能操作，不能反馈，不能治理。

sofagent 的 Dream Cycle 本质上是在做一个**迷你读写回路**：

| Palantir 回路 | Dream Cycle 对应 | v1.1.7 实现 |
|------|------|------|
| 读 | Ledger 层原始数据 | think.md + audit history（已有） |
| 逻辑 | 从原始数据提取模式 | extract_facts → extract_atoms → cluster_patterns（新增） |
| 写 | knowledge/ 写入 | synthesize_concepts → knowledge/ entities/（新增） |
| 反馈 | 持续学习回路 | skillopt_backfill → fde.md 优化（新增） |
| 治理 | 全链路审计 | conflict-check + sensitivity 过滤（v1.1.6 已有 + 本版增强） |

**关键差异**：Palantir 依赖集中式 Ontology OS + 重度物化索引。sofagent 走分布式路线——每个设备维护自己的 knowledge/，联邦查询按需获取。**我们不建中央本体，我们让每个 Agent 自己长出本体**。

## 交付一：Dream Cycle 6 阶段（P0）

gbrain 21 阶段的精简版——对约束沉淀真正有用的前半段：

```
extract_facts → extract_atoms → cluster_patterns
             → synthesize_concepts（喂 @sofagent/ontology）
             → skillopt_backfill（回灌自进化）
             → embed（向量化，供未来检索）
```

- `@sofagent/daemon`：stage 状态机替换 weekly-report / lessons-extract
- `@sofagent/ontology`：加 synthesize 接口
- `@sofagent/skillopt`：加 backfill 钩子

## 交付二：sensitivity frontmatter（P1）

entity/concept 的 frontmatter 新增 `sensitivity: public | internal | restricted` 字段。联邦查询时按 sensitivity 过滤结果。

## LUI 感知

用户通过 Agent 对话感知：「Agent 自动把我踩的坑整理成经验（fact→atom→concept）。敏感知识自动分级，不该看的人看不到。」
