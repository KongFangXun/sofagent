# v1.1.4 开发日志 — LOOP 工具执行 + 条件路由

> 状态：规划中 · 孔放勋 · 2026-07-15
> 前置依赖：v1.1.3（StateGraph + HITL 已就绪，但 engineer/reviewer 节点走 composer 零工具路径，只能说话不能干活）

## 背景

v1.1.3 的 LOOP 有一个结构性缺口：engineer 和 reviewer 的默认实现走 `spawnSubAgent → composeWithDeepAgents → createDeepAgent({ tools: [] })`——DeepAgent 带着零工具上线，只能输出文字建议，**不能真的读写文件、跑测试、改代码**。v1.1.4 的核心任务：给这两个节点装上手脚，让 LOOP 从"会说话的规划引擎"变成"能干活的开发引擎"。

## 交付一：LOOP 工具注入（P0）——路 A

engineer 和 reviewer 节点不再走 composer 的零工具路径，而是直接调用 `createDeepAgent` 并注入 sofagent 自有的工具集。

### 新增文件：`orchestrator/src/tools.ts`

定义 6 个工具，每个工具内嵌 A1-A17 约束：

| Tool | 对应能力 | 内置约束 |
|------|------|------|
| `read_file` | Read | A7 先读再改 |
| `write_file` | Write | A1 不碰敏感 · A3 不改越界 · A16 非授权文件 |
| `edit_file` | Edit | 同上 |
| `run_bash` | Bash | A6 不坏构建 · A11 不滥资源 |
| `search_code` | Glob / Grep | — |
| `run_test` | npm test | A8 不逃验证 |

### 修改文件：`orchestrator/src/graph/nodes.ts`

- `defaultRunEngineer`：不再调 `spawnSubAgent`，直接 `createDeepAgent({ tools: [read, write, edit, bash, search, test], systemPrompt: buildConstrainedSystemPrompt(ENGINEER_AGENT), maxTurns: 20 })`
- `defaultRunReviewer`：同上，注入审查专用工具子集 + REVIEWER_AGENT

### 设计原则

- **tools 的 description 就是约束**——每个 tool 的 schema description 写清楚"什么能做、什么不能做"，模型读到 description 后自然遵守
- **约束底座完整性**：tool 执行前不额外做 hook 拦截（hook 留给 git commit 时触发），但在 prompt 中注入完整的 A1-A17 规则（通过 `buildConstrainedSystemPrompt` 的四层加载链）
- **兜底**：如果 `deepagents` 不可用或模型 API 不可达，优雅降级为旧路径（走 composer），在报告注明

## 交付二：条件路由升级（P1）

v1.1.3 已有 FAIL→engineer 回环路由，v1.1.4 补齐两个缺口：

- **PASS → reviewer**：审计通过后自动进入审查节点（v1.1.3 已有，验证稳定即可）
- **WARN → human_confirm 标注**：审查报告中附带 WARN 标注，不阻断自动流转
- **blocked 终态接入 audit history**：blocked 时写入 history.jsonl，可追溯

## 端到端验证（P0）

用一个真实任务跑通 LOOP 闭环：

> 任务：「在 `SECURITY.md` 第 5 行后加一条 HTML 注释 `<!-- v1.1.4 LOOP 验证 -->`」

验证点：
- [ ] engineer 节点能自己 Read SECURITY.md → Edit 加注释 → 产出 diff
- [ ] audit 节点检测到 diff → 跑 A1-A17 规则 → 判定 PASS（注释不含敏感内容）
- [ ] reviewer 节点审查变更 → 确认最小变更 → IS_PASS: YES
- [ ] HITL 节点弹出审查报告 → 等 y 确认 → END
- [ ] 如果人为在注释里加 `API_KEY=sk-...` → A2 FAIL → 回 engineer 修复 → 重新 audit → 最多 3 轮 → blocked

## 交付三：USB federation（P2）

daemon 检测 `SOFAGENT` 标签的 USB 存储设备 → 自动读取 `federation.json` → 写入 `~/.sofagent/` → 重启 daemon。无头设备零交互入网。

CLI：`sofa-federation export-usb` 将配置写入 U 盘。

## 交付四：审计闭环加固（P1）——垃圾文件事件驱动

> 背景（v1.1.3 发版期真实事件）：测试审计功能时在主仓库产生了 a.txt/b.txt/new-name.txt 三个垃圾 commit（message 为 "add"/"add a file"）。审计引擎 A3 正确检测到越界并判 WARN，但 WARN 放行后**无人跟进**，垃圾文件在 main 里躺了 1.5 小时才被人工发现。结论：审计的价值不在"检测"而在"闭环"——检测到但没人管，等于没检测。

### 新增规则 A20 垃圾文件检测

根目录（或任意非测试目录）新增匹配临时文件名模式的文件 → WARN（能力拐杖级，不阻断）：

- 模式：`^[a-z]\.(txt|md|js|ts)$`（单字母文件名）、`^(test|tmp|temp|foo|bar|aaa)[0-9]*\.`、`^(new|old)-name\.`
- 豁免：`test/`、`tests/`、`__tests__/`、`*.test.ts` 等正规测试路径
- ruleClass：`能力拐杖` → runner 优先级：**extended 层**（排在 A16 之前）——纯 git-diff 检查，比 E 组工程规范更靠近 A 组，比 A16 更轻量
- evidenceMode：`git-diff`
- 实现文件：`sofagent/audit/src/rules/rule-a20-junk-file.ts` + `index.ts` 注册 + `runner.ts` AUDIT_PRIORITY.extended 插入

### 新增规则 A21 commit message 质量

零信息量 commit message → FAIL（业务底线级，阻断）：

- message 长度 < 8 字符 → FAIL（如 "add"、"fix"、"test"、"update"）
- message 完全匹配黑名单词 → FAIL：`add`/`fix`/`test`/`update`/`change`/`wip`/`tmp`/`asdf`
- 理由：A3 靠 message 做越界对照——message 越空洞，A3 越形同虚设。message 质量是整个审计链的地基
- ruleClass：`业务底线` → runner 优先级：**critical 层**（排在 A4 之后——比 A4 稍轻但同属 critical 阻断级；排在 A3 之前是为了 message 不合格就直接阻断，不用再跑 A3 越界检测）
- evidenceMode：`git-diff`（仅从 `commitMsg` 参数判定，不读 diff 内容）
- 实现文件：`sofagent/audit/src/rules/rule-a21-commit-msg-quality.ts` + `index.ts` 注册 + `runner.ts` AUDIT_PRIORITY.critical 插入

### daemon WARN 累积报告

补上"检测→跟进"的闭环：

- daemon 定期扫描 `history.jsonl` 中 exitCode=1（WARN）的记录
- 连续 N 条 WARN 未处理（后续 commit 没有清理动作）→ 生成 `daemon-notice.md` 告警条目
- 周期汇总："本周 X 条 WARN，其中 Y 条涉及文件至今仍在仓库" + 文件清单
- 复用 v1.1.0 的 daemon 主动巡检框架，新增 WARN 分析器

### v1.1.4 审计规则集全局视图

> v1.1.4 新增 A20/A21 后，审计引擎共 **21 条规则（A 组 19 条 + E 组 4 条 = 23 条，含空缺）**。以下是按 fast-fail 执行顺序排列的完整规则集，标注了 ruleClass、v1.1.4 的变更和编号空缺的决策依据。

#### 规则编号空缺决策

| 空缺编号 | 原因 | 计划 |
|:--:|------|------|
| A12 | v0.99.4 审查修复时合并到 A11（"不滥资源"已涵盖其检测范围） | 不恢复 |
| A13 | 同上——v0.99.4 合并 | 不恢复 |
| A18 供应链安全 | ROADMAP 探索方向——依赖变更审计（`package-lock.json` 非预期变更检测） | v1.1.5 或 v1.1.6 评估 |
| A19 文件权限 | ROADMAP 探索方向——`chmod 777` / `chown root` 等危险权限操作检测 | v1.1.5 或 v1.1.6 评估 |

#### v1.1.4 完整规则执行顺序（按 fast-fail 优先级排列）

```
┌─ critical 层（FAIL 即停，后续 SKIPPED）────────────────────┐
│ A1  不碰敏感     业务底线  git-diff   敏感文件路径检测       │
│ A2  不泄密钥     业务底线  git-diff   密钥/Token 泄漏检测     │
│ A9  不纳注入     业务底线  git-diff   中文注入/指令劫持检测   │
│ A4  不删配置     业务底线  git-diff   .sofagent config 删除   │
│ A21 🆕 msg 质量  业务底线  git-diff   commit message 黑名单   │
├─ warning 层（全部跑完，WARN/FAIL → exitCode）───────────────┤
│ A3  不改越界     能力拐杖  git-diff   diff vs message 对照    │
│ A5  不瞒真相     业务底线  git-diff   诚实度检测             │
│ A6  不坏构建     能力拐杖  git-diff   build/test 破坏检测    │
│ A10 不引毒源     业务底线  git-diff   恶意依赖/毒包检测      │
│ A11 不滥资源     业务底线  git-diff   批量文件操作检测       │
├─ crutch 层（依赖日志，FAIL→WARN，不阻断）──────────────────┤
│ A7  不存盲改     能力拐杖  hybrid     Read-before-Write      │
│ A8  不逃验证     能力拐杖  hybrid     Verify-before-Continue  │
├─ extended 层（扩展规则，不阻断）───────────────────────────┤
│ E3  不滥删除     能力拐杖  git-diff   大文件删除检测         │
│ E1  不落测试     能力拐杖  git-diff   测试文件遗漏检测       │
│ E2  不空标记     能力拐杖  git-diff   TODO/FIXME 标记检测    │
│ E4  不低注释     能力拐杖  git-diff   注释率检测             │
│ A15 不越约束     能力拐杖  hybrid     action 越权检测        │
│ A14 知识库越权    能力拐杖  hybrid     knowledge 跨域访问     │
│ A20 🆕 垃圾文件  能力拐杖  git-diff   临时文件名模式检测     │
│ A16 非授权变更    工程规范  git-diff   敏感目录非授权变更     │
│ A17 异常批量      工程规范  filesystem 短时间内大量文件变更   │
└─────────────────────────────────────────────────────────────┘
```

> **设计原则**：critical 层优先阻断（msg 不合格→A3 不用跑）；warning 层全部跑完给全貌；crutch 层因依赖日志单独分组；extended 层 E 组规范优先于 A 组扩展（E1-E4 覆盖基础工程质量，A14-A17 覆盖 Agent 专属审计），A20 插入 A16 之前（垃圾文件检测比敏感目录检测更轻量、更靠前）。
