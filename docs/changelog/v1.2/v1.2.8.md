## 🚪 release-gate-loop 新增 F（修复者）角色

### 定位

v1.2.7 的 release-gate-loop 是线性 5 步跑完即出 PASS/FAIL。FAIL 之后人工修，修完手动重跑——闸门只发现问题，不参与修复。

v1.2.8 在 release-gate-loop 内部新增 **F（修复者，Fixer）** 角色：V 验证 FAIL 后，F 读 verdict 报告 → 定位根因 → 改代码 → 跑 audit → 回到 V 重验。V 和 F 形成**验-改循环**，直到 V 出 PASS 或达到最大轮次（3 轮）。

### 设计

```
round N:
  V 验证（5 步线性，现有）
    acceptance → regression → coverage → consolidate → verdict
    verdict = PASS → 出 loop，可以发版 ✅
    verdict = FAIL ↓

  F 修复（新增）
    step 6: f-diagnose  — F 读 verdict.md，定位根因，写修复方案到 fix-plan.md
    step 7: f-fix       — F 按方案改代码（最小改动），写 fix-summary.md
    step 8: f-audit     — driver 自动跑 sofagent-audit --diff（铁律：变更必审）
                          audit FAIL → 打回 F 重修（不进 V）
                          audit PASS → 进入 round N+1

  收敛条件：V 出 PASS / 达到 3 轮上限 → 出"需人工介入"报告
```

### 与 fresh-eyes-loop A/B 的镜像关系

| | fresh-eyes-loop | release-gate-loop |
|---|---|---|
| 主角色 | A（审查者）| V（验证者）|
| 副角色 | B（工程师）| F（修复者）|
| 触发 | 固定多轮 | verdict FAIL 触发 |
| 收敛 | 连续 2 轮 clean | V 连续 PASS / 3 轮上限 |

## 🔍 FORGE 全 loop 接入 audit（dogfooding 铁律）

### 定位

sofagent 的核心卖点是"审计每次变更"。但 v1.2.7 的两个 FORGE loop（fresh-eyes-loop / release-gate-loop）改代码后都只跑 `npm test`，**全程不跑 sofagent-audit**。这是纯粹的遗漏——driver 零提及 audit，loop.md 零提及，b-fix prompt 零提及。

v1.2.8 补齐：所有 FORGE loop 里改代码的步骤，改完必须跑 `sofagent-audit --diff`，audit 不通过打回重修。

### 交付

| 文件 | 改动 | 说明 |
|------|------|------|
| `FORGE/src/fresh-eyes-driver.mjs` | 修改 | b-fix 步骤后插入 audit 检查（新步骤 b-audit）|
| `FORGE/SKILL/fresh-eyes-loop/prompts/b-fix.md` | 修改 | 补充"改完代码后跑 audit"指令 |
| `FORGE/src/release-gate-driver.mjs` | 修改 | F 步骤内置 f-audit（见上方 ⑤）|
| `FORGE/src/driver-base.mjs` | 修改 | 新增 `runAuditGate()` 公共函数（两个 driver 共用）。内部自动 git commit + 跑 audit |

### audit 检查内容

F/B 改完代码后，driver 自动执行：
```bash
git add -A && git commit -m "FORGE auto-commit: <step> round-<N>"
sofagent-audit --diff HEAD~1..HEAD --silent
```
- exit 0（全过）→ 进下一环节
- exit 1（有警告）→ 记录但继续（警告不阻塞）
- exit 2（有违规）→ 打回 F/B 重修，不进 V/A-verify

> auto-commit message 带 `FORGE auto-commit:` 前缀，方便事后过滤。
