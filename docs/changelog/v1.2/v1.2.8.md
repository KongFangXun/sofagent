## 定位

**v1.2.8 是 DeerFlow 设计启发的第二批落地**——聚焦记忆系统和定时任务，补齐 sofagent 在"长期记忆管理"和"自动化巡检调度"上的工程化短板。

## P1：记忆事实级分层

**痛点**：当前 knowledge/ 是目录级（entity/concept/cluster），Dream Cycle 从 think.md 抽取知识时缺事实级粒度——同一条事实散落在多个 think.md，无法去重、无法衰减、无法按用户隔离。

**DeerFlow 做法**：
- 跨会话持久记忆——用户画像、偏好、积累知识
- 文件支持的记忆分离全局用户上下文和代理事实
- 每个**用户**一个 `memory.json`，每个**事实**是独立的 Markdown 文件
- `__default__` 桶保留默认记忆
- 记忆更新跳过重复事实条目（单事实仓库操作是真正增量的）
- 检索引擎在 memory 检索适配器契约后面是可选的

**sofagent 移植方案**：
- knowledge/ 增加 `facts/` 子目录——每个事实一个 `.md`（frontmatter 带 `confidence` + `last_triggered` + `source`）
- Dream Cycle 抽取事实时写 facts/，重复事实跳过（content-hash 去重）
- 30 天无触发衰减（已有 think.md 衰减逻辑，扩展到 facts/）
- 多设备联邦时，facts/ 按 sensitivity 分级（已有机制，复用）

**实现位置**：`engine/ontology/src/` + Dream Cycle pipeline

## P2：Scheduled Tasks MVP

**痛点**：LIMITATIONS §七明确写了"定时触发做不到"——daemon cron.ts 只是占位（`@weekly`/`@daily`/`@hourly` 读 watch.yml，但行为未充分验证）。FDE Agent 的"周度巡检"靠人触发，不是真定时。

**DeerFlow 做法**：
- 工作区中的一级定时任务 MVP
- 管理路径：`/workspace/scheduled-tasks`
- 支持 `once` 和 `cron` 调度
- 后台执行为非交互式运行
- `skip` 重叠行为
- 暂停、恢复、触发、检查历史、删除任务

**sofagent 移植方案**：
- daemon cron.ts 升级为一级定时任务管理
- `sofagent-audit --schedule` CLI 管理（add/list/pause/resume/trigger/delete）
- 调度配置存 `.sofagent/schedule.json`（与 watch.yml 合并或替换）
- `skip` 重叠行为（上一个还没跑完，跳过本次）
- 巡检结果写 history.jsonl（已有机制）

**实现位置**：`engine/daemon/src/cron.ts` 升级 + 新增 schedule 管理 CLI

## P3：Workspace 变更摘要

**痛点**：每次 Agent 运行后，用户/Dashboard 看不到"这次运行改了哪些文件"——得自己跑 git diff。审计日志有规则判定，但没有"文件变更清单"。

**DeerFlow 做法**：每次运行后记录创建、修改、删除的文件清单（workspace 变更徽章）。

**sofagent 移植方案**：
- 每次 audit 运行后，在 history.jsonl 的 entry 里加 `workspace_changes` 字段（created/modified/deleted 文件列表）
- Dashboard 消费这个字段做"变更徽章"（v1.2.2+ Dashboard 数据前置）

**实现位置**：`engine/audit/src/audit-history.ts`（已有 entry 结构，加字段）

## P4：ToolOutputBudget 中间件化

**痛点**：memory 记录的 sf_read 500 行截断是单点修复——只在 sf_read 工具层做。其它工具（grep/glob/bash）输出也可能爆炸。

**DeerFlow 做法**：ToolOutputBudget 中间件——所有工具输出都经过预算控制，分层截断（不是一刀切）。

**sofagent 移植方案**：
- 把 sf_read 500 行截断抽象为 ToolOutputBudget 中间件
- 所有 sf_* 工具输出经过这个中间件
- 分层策略：前 N 行全文 + 中间摘要 + 末尾 N 行（而非硬切 500 行）
- 与 v1.2.7 的 /compact 配合（工具输出先预算，再 compact）

**实现位置**：`engine/harness/src/` 新增 ToolOutputBudget 中间件 + sf_* 工具注册时包装
