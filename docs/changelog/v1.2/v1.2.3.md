### P1 · 编排隔离底座（git worktree 四子里程碑）

**问题**：orchestrator 调度并行 SubAgent 时，多个 SubAgent 写同一个工作树会互相覆盖。v1.3.0 要做控制图波次并行，但并行前提是文件隔离。

**设计**：每个 SubAgent `git worktree add` 独立工作树 + 独立分支，完成后 audit 卡关，通过后合并回主工作树。不引入 FilesystemBackend / 虚拟文件系统 / AsyncSubAgent——纯 git worktree。

**四子里程碑**：

| 子里程碑 | 内容 | 验证标准 |
|---------|------|---------|
| **②·1 worktree 隔离原语** | orchestrator 调度并行 SubAgent 时自动 `git worktree add` | 两个 SubAgent 写不同文件，互不干扰 |
| **②·2 审计合并卡关** | 各 worktree 完成后，audit 对每棵树跑 `git diff` 硬证据卡关 | audit FAIL → 不合并，报告违规；audit PASS → 合并回主树 |
| **②·3 冲突消解策略** | 并行 SubAgent 写同一逻辑文件时的仲裁（按节点职责域划分优先 / 人工确认兜底） | 冲突检测 + 仲裁规则写入 harness 约束 |
| **②·4 filesValue 边界** | 明确"同步并行用 filesValue 自动合并" vs "跨波次并行用 worktree 隔离" | 边界文档写入 `worktree-isolation.ts` 顶部 JSDoc |

**核心接口**：

```typescript
interface WorktreeHandle {
  path: string;       // .sofagent/worktrees/wt-{uuid}
  branch: string;     // sofagent/wt-{uuid}
  agentId: string;
  create(): Promise<void>;
  cleanup(): Promise<void>;
  diff(): Promise<string>;
}
```

**文件清单**：

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/worktree-isolation.ts` | 新建 | worktree 隔离原语（WorktreeHandle）+ filesValue 边界 JSDoc |
| `engine/orchestrator/src/worktree-merge-gate.ts` | 新建 | 审计合并卡关（audit diff → merge/deny） |
| `engine/orchestrator/src/conflict-resolver.ts` | 新建 | 冲突消解策略（职责域优先 + 人工兜底） |
| `engine/orchestrator/src/loop/graph.ts` | 修改 | 调度并行 SubAgent 时调 worktree-isolation |
| `engine/orchestrator/src/__tests__/worktree-isolation.test.ts` | 新建 | 隔离+合并+冲突单测 |

**约束**：

### P1 · Fresh-Eyes Dashboard 集成

**问题**：FORGE fresh-eyes-loop 跑的时候，用户看不到进度——只能在终端等。审查可能跑 5 轮、10 分钟，过程中完全是黑盒。

**设计**：fresh-eyes-driver 运行时，A/B sub agent 将审查进度写入 `sub-progress-*.jsonl` 到 `data/forge-runs/`。Dashboard 新增 FORGE 审查 tab。

**数据流**：

```
FORGE fresh-eyes-driver 运行
  ├─ Agent A (审查模型) 写 sub-progress-A.jsonl
  │   每行: { timestamp, phase, file, findings, status }
  └─ Agent B (工程模型) 写 sub-progress-B.jsonl
      每行: { timestamp, phase, file, findings, status }

Dashboard --watch
  └─ 读取 data/forge-runs/sub-progress-*.jsonl
      └─ 渲染: 每轮发现数 + 当前审查文件 + A/B 双盲状态
```

**渲染效果**（示例）：

```
┌─────────────── FORGE 审查 ───────────────────┐
│  fresh-eyes-loop #3  ·  第 2 轮 / 共 5 轮     │
│                                               │
│  Agent A (审查模型)     Agent B (工程模型)    │
│  🔵 审查中              🔵 审查中              │
│  当前: graph.ts         当前: nodes.ts        │
│  本轮发现: 3            本轮发现: 1            │
│  累计: P0×1 P1×4       累计: P0×0 P1×2       │
│                                               │
│  状态: A/B 双盲中（互不可见）                  │
└───────────────────────────────────────────────┘
```

```markdown
## 补充修复（用户报告 · 安装缺口）

> 来源：用户实测 + fresh-eyes 独立审查视角六（Dashboard 占位 vs 实现分支并存）。

**问题**：`sofagent dashboard` 始终走占位分支，打印 "Dashboard coming in v1.2.2. Current data:" 列目录，看不到真实界面。根因是 `install.sh` 的 `install_cli()` 未将 `tools/sofagent-dashboard.sh` 软链到 `$SOFAGENT_HOME/bin/sofagent-dashboard`，导致 wrapper 的 `[ -x "$SOFAGENT_HOME/bin/sofagent-dashboard" ]` 检查失败、落 else 占位分支。

**修复**：`install_cli()` 在写入主入口 `chmod +x` 之后、PATH 软链块之前，新增 Dashboard 入口软链逻辑——将 `${SCRIPT_DIR}/tools/sofagent-dashboard.sh` 覆盖式软链（`ln -sf`）到 `$bin_dir/sofagent-dashboard`（无 `.sh` 后缀，与 wrapper 检查完全一致）并 `chmod +x`；源脚本缺失时仅 `warn` 不 `fail`，保留 wrapper 的 else 占位分支作兜底。

**影响范围**：仅 `install.sh` 安装期软链；不改 wrapper 功能逻辑、不改 `tools/sofagent-dashboard.sh`、不改 `package.json` 版本号、不新建文件。
```
