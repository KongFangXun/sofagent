### P1 · 编排隔离底座（git worktree 四子里程碑）

**问题**：orchestrator 调度并行 SubAgent 时，多个 SubAgent 写同一个工作树会互相覆盖。v1.3.0 要做控制图波次并行，但并行前提是文件隔离。

**设计**：每个 SubAgent `git worktree add` 独立工作树 + 独立分支，完成后 audit 卡关，通过后合并回主工作树。

**四子里程碑**：

| 子里程碑 | 内容 | 验证标准 |
|---------|------|---------|
| **②·1 worktree 隔离原语** | orchestrator 调度并行 SubAgent 时自动 `git worktree add` | 两个 SubAgent 写不同文件，互不干扰 |
| **②·2 审计合并卡关** | 各 worktree 完成后，audit 对每棵树跑 `git diff` 硬证据卡关 | audit FAIL → 不合并，报告违规；audit PASS → 合并回主树 |
| **②·3 冲突消解策略** | 并行 SubAgent 写同一逻辑文件时的仲裁（按节点职责域划分优先 / 人工确认兜底） | 冲突检测 + 仲裁规则写入 harness 约束 |
| **②·4 filesValue 边界** | 明确"同步并行用 filesValue 自动合并" vs "跨波次并行用 worktree 隔离" | 边界文档写入 ARCHITECTURE.md |

### P2 · Dashboard 用户可读性

**问题**：Dashboard 控制图视图不能只有技术术语（节点/边/波次），需要面向"人看一眼就懂"的语言化呈现。

**设计**：节点状态用人话标注，不用技术术语。

| 技术状态 | 用户可读状态 |
|---------|------------|
| node.state = 'completed' | ✅ 已完成 |
| node.state = 'running' | 🔄 正在工作中 |
| node.state = 'waiting' | ⏳ 排队等待 |
| node.audit = 'fail' | ⚠️ 审计发现问题，正在拦截 |
| node.audit = 'pass' | ✅ 审计通过 |

**文件清单**：

| 文件 | 改动 | 说明 |

| `engine/dashboard/src/components/control-graph-view.tsx` | 修改 | 节点显示用户可读状态 |

### P3 · Graph Engine 并行执行 + Dashboard 图视图

**⑦ 并行子图执行**：`buildLoopGraph` 新增 `parallel` 模式——同一父任务包含独立子任务时，engineer 自动拆为 N 个并发实例，各跑独立 worktree（复用 P1 编排隔离底座）→ audit → 合并结果回主工作树。扩展现有 `graph.ts` + `nodes.ts`。

**Dashboard Graph Engine 控制图**：React Flow 控制图视图新增：
- **双图同屏**：左栏 Org Graph（稳定角色节点：engineer/audit/reviewer/human_confirm），右栏 Work Graph（当前任务临时拓扑：子任务 + 并行扇出）
- **边类型标注**：数据流（实线蓝）、控制流（实线绿）、失败流（虚线红）用不同颜色/样式
- **节点六要素 tooltip**：悬停节点显示 职责/输入/输出/权限/状态/退出条件（行业前沿框架）
