## 🔗 激活链 Phase 1：ACTIVATE

### 痛点

FDE 诊断完成后交付了一堆静态文件（workflow.yml + skills/ + entities/），但没人把它们"点燃"——企业 IT 拿到 .md 和 .yml 不知道怎么跑起来。这就是**大断裂带**。

### 交付

**核心**：新增 `activate.ts`，读 FDE 交付物 → 组装企业 SubAgent 定义 → 写入 `.sofagent/data/subagents/*.yml`。

关键发现：`registry.ts` 的 `listAgents()` 从 v1.0.8 起就支持从 `.sofagent/subagents/` 目录读 YML 注册自定义 Agent。"轨道从早期就铺好了，一直没人往上面放车厢"。Phase 1 就是造车厢。

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/activate.ts` | 新建 | **核心**：读交付物 → 注册企业 Agent |
| `engine/orchestrator/src/__tests__/activate.test.ts` | 新建 | 单测 |
| `engine/mcp/src/tools/activate-workflow.ts` | 新建 | MCP `activate_workflow` tool |
| `engine/orchestrator/src/cli.ts` | 修改 | 新增 `activate` 子命令 |
| `engine/mcp/src/mcp-server.ts` | 修改 | 注册 `activate_workflow` tool |

**CLI**：`sofagent-orchestrator activate [--dry-run] [--node-filter <ids>]`
**MCP**：`activate_workflow` tool（支持 dry_run / node_filter 参数）

> 详细开发 Prompt：`~/Desktop/fde-activation-phase1-v1.2.5-prompt.md`

### 设计决策

- **不碰 LangGraph**——本版本只注册 Agent，不构建编排图
- **复用 registry.ts 的 YML 格式**——不发明新格式
- workflow.yml 缺失字段降级处理：缺 `agent` → 默认 enterprise；缺 `actions` → 默认 `[read]`；缺 `hitl` → 按 type 推断
