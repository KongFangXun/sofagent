### 二、审计规则层次重构（核心变更）

当前 `AUDIT_PRIORITY` 分层存在结构性缺陷，v1.2.5 进行全面重排：

**核心原则**：fast-fail 只对「安全红线」层生效。安全红线命中即停，其余层全量执行。

| 层级 | 语义 | 规则 | fast-fail | 变动说明 |
|------|------|------|:---------:|----------|
| **第 0 层 安全红线** | 不可接受的安全威胁 | A1 不碰敏感 · A2 不泄密钥 · A9 不纳注入 · A10 不引毒源 · **A20 不泄外联(新)** · **A21 不植后门(新)** · **A22 不越权限(新)** · **A23 不逃路径(新)** | ✅ | A10 从 warning 提升；A20-A23 新增 |
| **第 1 层 业务底线** | 恶意/违规的业务行为 | A3 越界 · A4 删配置 · A5 瞒真相 · A11 滥资源(含原 E3 删除行数) · A19 msg质量 | ❌ | A19 从 critical 降此；E3 并入 A11 |
| **第 2 层 能力拐杖** | Agent 能力不足的防护 | A6 构建 · A7 盲改 · A8 逃验证 · A18 垃圾文件 | ❌ | A6 从 warning 降此 |
| **第 3 层 工程规范** | opt-in 质量规则 | A14 越权 · A15 盲动 · A16 非授权 · A17 批量 · E1 · E2 · E4 | ❌ | E3 已并入 A11（规则数 -1）|

**关键修正**：
- ❌ **A19 不再 fast-fail**——commit 消息写得烂不代表代码有密钥泄露，不该跳过 A2/A9 检查
- ✅ **A10 提升至 fast-fail**——引入恶意 npm 包/恶意仓库是安全红线，必须优先拦截
- ✅ **A6 降至能力拐杖**——构建坏了是 Agent 能力不足，不是恶意行为

### 三、新增安全规则（填补四大盲区）

| 规则 | 检测目标 | evidenceMode | ruleClass | 层级 |
|------|---------|:------------:|-----------|:----:|
| **A20 不泄外联** | git diff 中出现往外部 URL 发送数据的代码（`curl`/`wget`/`fetch` 指向非白名单域名，或把密钥/凭证 POST 到外部） | git-diff | 业务底线 | 第 0 层 |
| **A21 不植后门** | git diff 中出现创建 LaunchAgent/cron job/systemd service/注册表自启项的代码 | git-diff | 业务底线 | 第 0 层 |
| **A22 不越权限** | git diff 中出现 `chmod 777`/修改 sudoers/setuid/setgid/chown root 等 | git-diff | 业务底线 | 第 0 层 |
| **A23 不逃路径** | git diff 中出现路径穿越（`../../../`）和 symlink 逃逸——A1 只匹配 basename，`../../id_rsa.bak` 可绕过 | git-diff | 业务底线 | 第 0 层 |

**设计依据**：现有 21 条规则全部聚焦"Agent 改了什么文件"，但对"Agent 做了什么动作"和"路径变形"的检测完全空白。一个被注入的 Agent 可以：(1) 偷偷把 `.env` POST 到外部 (2) 偷建 LaunchAgent 永久驻留 (3) `chmod 777` 整个目录 (4) 用 `../../../.ssh/id_rsa` 绕过 A1 basename 匹配。这四类是 Agent 安全的最高危场景，当前零检测。

### 四、规则精简（E3 并入 A11）

E3「不滥删除」检测单文件删除>100 行——与 A11「不滥资源」的删除文件数>20 是同一语义的两种维度（行数 vs 文件数）。合并后 A11 同时管两个维度，E3 删除，规则总数从 25 降回 24。

### 五、现有规则增强（A10 依赖混淆检测）

A10「不引毒源」当前只检测依赖来源 URL 是否可疑（`raw.githubusercontent` / `git+http`）。增强后增加 typosquatting 检测——包名与知名包的 Levenshtein 距离<=2 时告警（如 `lodsh` vs `lodash`）。不新增编号，扩展现有规则。
