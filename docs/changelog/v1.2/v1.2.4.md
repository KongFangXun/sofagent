## 交付项

### P0 · 分层巡检 L1/L2/L3 + 读写回路对标

**设计**：当前 daemon 巡检是扁平的。改为三级分层：

| 层级 | 频率 | 检查内容 | 现有 inspector 归入 |
|------|------|---------|-------------------|
| **L1 快速健康** | @daily | 审计历史 + daemon 状态 + WARN 累积 | audit-history / doctor-health / warn-accumulator |
| **L2 深度巡检** | @weekly | 知识矛盾 + 孤儿 + 死链 + 新鲜度 + Skill 陈旧度 | conflict-check / knowledge-freshness / knowledge-health / skill-staleness |
| **L3 联邦分析** | @monthly | 跨设备蒸馏趋势 + 失败模式聚类 + Ontology 覆盖度 | 新增 federation-distillation / failure-pattern / ontology-coverage |

读写回路对标（gbrain Compiled Truth 理念）：巡检结果写入 Views 层（派生视图），不污染 Ledger 层（原始记录）。

### P1 · skillopt 自动触发 + 失败清单驱动

**设计**：连续 3 次同类失败 → 自动触发 skillopt。每个 Skill 失败时记录失败场景 + 原因 + 正确做法，以负面样本驱动优化。

```typescript
if (failurePattern.repeatedCount >= 3) {
  await skillopt.optimize({
    skillId: failurePattern.skillId,
    failureMode: failurePattern.description,
    source: 'auto-trigger',
  });
}
```

### P3 · Graph Engine Checker 扩展 + 受控循环升级

**⑧ 多类型 Checker 图节点**：当前 audit 节点只做文件系统审计。新增三个 inline Checker 作为独立图节点（在 audit 之后、reviewer 之前）：
- `format-checker`：输出是否符合预期 schema（JSON/Markdown/表格字段完整性）
- `fact-checker`：引用的文件/数据源是否真实存在、内容是否匹配
- `source-validator`：信息来源可信度评分（内部 trusted vs 外部 unverified）

Checker 发现的失败模式自动喂给 P1 skillopt 失败清单。

**⑨ 受控循环升级**：当前 engineer→audit→FAIL→engineer 是单一重试圈。升级为三种循环模式：
- "补信息后继续"：audit 发现证据不足→不直接 FAIL→回到 plan 补子任务
- "降级通过"：audit WARN 时不是直接过，标记后 reviewer 带警告展示
- "循环守卫"：每种循环有独立 `maxRetries` + `degradationThreshold` + `humanHandoffTrigger`
扩展 `buildLoopGraph` 条件边 + `LoopGraphState` 新增循环守卫字段。
