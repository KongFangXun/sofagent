## FDE 架构重构（发版前增量）

发版前对 FDE 文件夹做了一轮深度架构重构，核心变化：

### 删除废文件（3 项）

- **删除** `FDE/workflow/`（整个目录）——和 FDE.md 重复，Agent 读 FDE.md 就够
- **删除** `FDE/agents/`（整个目录）——同上
- **删除** `templates/enterprise-node.yaml`——ao compose 不读 .yaml 配置文件，无消费者

### 四层实体 → 三层实体

| 旧四层 | 新三层 | 变化 |
|--------|--------|------|
| 📄 文档层 `.md` | 📄 文档层 `.md` | 合并配置表格进来 + 同时给编排引擎读 |
| ⚙️ 配置层 `.yaml` | ~~删~~ | 没人读，合并进 .md |
| 🧠 Skill 层 `SKILL.md` | 🧠 Skill 层 `SKILL.md` | 不变 |
| 🔴 运行层 session | 🔴 运行层 session | 不变 |

关键认知：**ao compose 接受自然语言描述，不读 .yaml 配置文件**。Agent 读 .md 后注入给 ao compose——`ao compose "$(cat nodes/xxx.md)"`。所以 .md 文档层同时服务两个消费者（人读 + 编排引擎读），.yaml 是多余的中间层。

### templates/ 目录结构调整（镜像实际产出）

```
FDE/templates/
├── README.md
├── enterprise-profile.md        ← 交付手册第一章（FDE 自案例）
├── deployment-plan.md           ← 交付手册第二章（FDE 自案例）
├── nodes/
│   └── node-template.md         ← 镜像 nodes/[节点名].md
└── skills/
    └── skill-template/
        └── SKILL.md             ← 镜像 skills/[节点名]/SKILL.md
```

模板目录结构 = 部署后的实际目录结构，FDE 看模板就知道产出长什么样。
