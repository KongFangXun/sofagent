## 交付内容（4 件事）

### 1. Ontology 统一层

`.sofagent/ontology/` 目录——自动从 v1.0.1-1.4 的分散定义合并生成：

```
数据源 → 合并 → .sofagent/ontology/
├── entities/（v1.0.1 frontmatter）   → ontology/objects.yml
├── workflow.yml（v1.0.3 actions）     → ontology/actions.yml
└── audit A15（v1.0.4 constraints）    → ontology/constraints.yml
```

Agent 加载时拿到完整的**当前任务的世界模型**——知道自己在跟什么对象打交道、能做哪些操作、有什么边界。

### 2. ao 正式退役

| 动作 | 说明 |
|------|------|
| `ao/` 目录标记 archive | 文件头加 `@deprecated` 注释 |
| ao 运行警告 | 启动时打印「ao 已退役，请迁移到 deepagentsjs」 |
| 全部由 DeepAgents + LangGraph 接管 | v1.0.1-1.3 已逐步验证 |

### 3. Workflow Hub——独立项目

Workflow Hub 拆为独立 GitHub 仓库 `sofagent-workflow-hub`，通过 git submodule 关联到主项目：

```bash
# 主项目中添加 submodule
git submodule add https://github.com/KongFangXun/sofagent-workflow-hub .sofagent/workflows/hub
```

**独立项目的目录**：
```
sofagent-workflow-hub/
├── README.md
├── CATALOG.md                     ← 可浏览的模板目录（Markdown 表格）
├── SPEC.md                        ← 模板格式规范（workflow.yml schema）
├── CONTRIBUTING.md                ← 社区贡献指南
├── templates/
│   ├── 制造业/
│   │   └── 应付账款审批/
│   │       ├── workflow.yml
│   │       ├── skills/
│   │       ├── knowledge/
│   │       ├── subagents/
│   │       └── README.md          ← 适配指南
│   └── ...
└── tools/
    └── validate.sh                ← 模板格式校验
```

**拆分理由**：
- 独立的版本节奏——模板更新不需要等 sofagent 发版
- 独立的贡献边界——社区 PR 清楚知道这是 Hub 不是引擎
- 未来的前端 catalog——GitHub 现在是浏览界面，量大后加 Web dashboard 

**依赖方向（单向，禁止循环）**：

| 层 | 规则 |
|---|---|
| sofagent 主项目 → Hub | 单向依赖。`sofagent hub deploy` 读 Hub 目录、执行适配。**Hub 模板不执行任何 sofagent CLI 命令** |
| Hub 模板内部 | `adapt` 脚本只做文本替换（sed/awk），不调 sofagent CLI |
| `--with-hub` 安装 | submodule clone 是可选的，不 clone 也能用 sofagent 核心功能 |

**FDE 使用**：
```bash
# 安装时自动 clone submodule
sofagent --init --with-hub

# 部署模板
sofagent hub deploy 制造业/应付账款审批
# → 适配：改供应商列表、改审批阈值
# → 部署：复制到 .sofagent/workflows/ + install skills + register agents
```

## 探索方向：多 Agent 协同可视化

v1.0.3-1.4 已经在做多 Agent 协同——FDE Sub Agent + Audit Sub Agent 同时跑、A/B 自进化同时跑两个变体。v1.0.5 探索是否需要把它变成**组织可见的能力**（Agent Dashboard）。

> ⚠️ **为什么是探索方向而非核心交付**：v1.0.5 实际只有 2 个 Sub Agent + 几个 Workflow 节点。4-5 个 Agent 时 Dashboard 有意义，但当前规模下 Dashboard 更像 CIO 卖点而非 FDE 工具。做完验证企业用户需求后再决定是否进 v2.x 前端。

**如果做的**：

```bash
$ sofagent-audit --doctor --agents

Agent 协同状态
┌──────────────────────────────────────────────────────┐
│ 🟢 FDE Sub Agent    常驻    最后一次活跃 3 分钟前       │
│ 🟢 Audit Sub Agent  空闲    下次巡检 2026-07-11 03:00  │
│ 🟡 AP-审批          运行中  处理 Payment-2026-003      │
│ 🟢 AP-执行          常驻    等待已审批任务              │
│ 🔴 工程-部署        异常    API 调用连续失败 3 次       │
└──────────────────────────────────────────────────────┘
协作链路：
  Payment-2026-003 → AP-审批(🟡) → AP-执行(⏳待审批) → Audit Sub Agent(⏳待巡检)
```

**冲突检测**：两个 Agent 同时试图操作同一对象时（如 AP-审批 和 工程-部署 同时改 Payment-2026-003），系统记录冲突并通知负责人。
