## 一、P0：task/logs JSONL 结构化日志

### 背景

v0.93 前 task/logs 为自然语言 Markdown 格式，审计工具靠正则和启发式猜测解析文件引用（`log-checker.ts:106-130` 用了 3 个正则模式）。JSONL 让审计工具做**精确匹配而非概率猜测**——误报率和漏报率才能真正可控。

### 迁移方案

- 新增 `task-record.ts`：替代 shell 版本的 task-record.sh，输出 JSONL（每行一条操作记录）
- JSONL schema：`{ ts, op: 'read'|'write'|'execute', file, context }`
- 向后兼容：旧 Markdown 日志继续可读，JSONL 与 MD 并行写入一个版本周期（v0.94），v0.95 切换为仅 JSONL
- sofagent-audit 的 log-checker.ts 新增 JSONL 解析路径，优先 JSONL，fallback 正则

### 收益

- FP/FN 率从"无法精确测量"到"可量化"
- 为 MCP server 的任务完成事件提供结构化数据源
- 为外部评估器（v1.x）提供标准化输入

## 二、P0：MCP server MVP

### 功能范围

- watch `.sofagent/task/logs/` 目录，任务完成（日志文件写入）立即检测
- 首次推送：任务摘要（任务名、模型、耗时、铁律违反数）
- webhook 客户端框架（预留企业平台接入接口）
- 对标 Claude Code 的 Slack 集成——但跨平台

### 技术选型

- Node.js + `chokidar`（文件监听） + `axios`（webhook 推送）
- 轻量级——不引入数据库，状态用 `.sofagent/mcp-state.json` 文件记录

## 三、P1：Agency Agent 模板对接

### 对接方式

Agency Agent 模板库（同一开发者 `jnMetaCode`，与 agency-orchestrator 同源）提供预定义的 Agent 角色模板。对接方式：

- `install.sh` 新增 `--with-agency` flag，安装时自动 clone 模板库
- `task-orchestrate.sh` 在 AO compose 拆解后，从模板库匹配角色并注入
- 模板库作为 git submodule 而非内嵌（保持 sofagent 仓库轻量）

### 注意事项

- 模板库的许可协议（Apache-2.0）与 sofagent（MIT）兼容
- 模板注入失败不影响编排降级路径

## 四、P1：OpenClaw 预装集成

`install.sh` 自动检测并安装 OpenClaw：

- macOS：`brew install openclaw`（如已装 Homebrew）
- Linux：检测包管理器（apt/yum/dnf/pacman）后安装
- 安装后自动注册 systemd/launchd 服务
- `install.sh --no-oc` 跳过此步骤
