  fi
done
```

### 7. 审计结果可视化升级（正式版体验）

**现状**：审计引擎全通过时只输出一行 `✅ 全部审计规则通过`——用户感知不到审计的存在。装了跟没装一样，审计的价值无法体现。

**目标**：v1.0 正式版要让用户**每次 commit 都能感知到「有个东西在帮我看门」**——通过时秀肌肉，违规时拦得住。

**改动范围**：`sofagent/audit/src/index.ts` 的 `printResults` 函数。不改规则逻辑，只改输出呈现。

#### 设计原则

| 原则 | 说明 |
|------|------|
| **通过也要有存在感** | 不是一行字消失，而是一个清晰可见的仪表盘 |
| **一眼看懂** | banner + 规则网格，不用读文字就知道状态 |
| **历史可感知** | 不只是「这次过了」，还要让用户知道「门锁挡住了多少」 |
| **不刷屏** | 11 条规则一行展示完，不用翻页 |

#### CJK 字符对齐

终端中 CJK 字符（中文）占 2 列宽度，ASCII 占 1 列。`String.prototype.padEnd` 按字符数而非显示宽度 pad，会导致右边框错位。

解决方案：在 `printResults` 中实现 `visualWidth` 辅助函数——遍历字符串，CJK 字符计 2 列、ASCII 计 1 列，基于显示宽度做 padding。Node.js 内置的 `Intl.Segmenter` 可用来判断字符是否为 CJK（Unicode 范围：CJK Unified Ideographs U+4E00-U+9FFF 等）。

### 8. 审计违规修复建议（可操作性）

**现状**：违规输出只有检测结果（如「diff 中检测到疑似 API key」），没有告诉用户怎么修。

**目标**：每条违规带修复建议——用户不需要查文档就知道下一步怎么做。

**示例**：
```
❌ A2 不泄密钥 [底线]: diff 中检测到疑似 API key
   文件: src/config.ts 第 12 行
   怎么修: 将密钥写入 .env → .gitignore 加 .env → 重新提交

❌ A1 不碰敏感 [底线]: 检测到敏感文件变更: .env
   怎么修: .env 不应提交。如确认无敏感数据，在 commit message 中说明原因
```

**改动范围**：11 条审计规则的 `details` 数组中各加一个 `建议: ...` 字符串。

| 文件 | 改动 |
|------|------|
| `rules/rule-a1-sensitive-files.ts` ~ `rule-a11-no-abuse.ts` | 每条规则加 1 行建议 |
| `reporter.ts` / `index.ts` | 输出格式确保「建议」行缩进对齐 |

**约束**：建议文字 ≤ 80 字，一行内说完，不加链接（commit 场景下终端不能点）。

  历史拦截：全新安装，审计历史将从第一次提交开始记录。
```

**改动量**：改 `post-install.sh` 中 `print_completion_summary` 函数，~20 行。

### 10. pre-commit hook 无声失败保护 🔴

**现状**：如果 `node` 不在 PATH 或 `sofagent-audit` 未正确安装，pre-commit hook **静默跳过**——用户提交成功，审计完全没有运行。这是正式版的安全隐患。

**目标**：hook 在任何失败场景下必须让用户感知到「审计没有运行」。

**改动**：hook 模板脚本加环境检测 fallback：

```bash
# 1. Node.js 检测
if ! command -v node &>/dev/null; then
  echo "❌ sofagent-audit: Node.js 未找到，审计未运行"
  echo "   请安装 Node.js ≥ 18: https://nodejs.org"
  exit 1
fi

# 2. sofagent-audit 检测
if ! command -v sofagent-audit &>/dev/null; then
  echo "❌ sofagent-audit 未安装，审计未运行"
  echo "   请运行: npx @sofagent/audit --install-hook"
  exit 1
fi

# 3. 正常运行审计
node sofagent-audit --diff HEAD~1..HEAD || exit 1
```

**改动量**：改 hook 部署模板，~10 行。

**注意**：`exit 1` 会阻止 commit——这是预期行为。如果 Node.js 都没装，审计就是形同虚设，不能让用户以为自己被保护着。

### 11. 首次提交噪音消除

**现状**：全新仓库首次 commit 时 `HEAD~1` 不存在，`git diff` 抛 `fatal:` 错误，然后审计引擎才说「没有文件变更」。用户看到红字 fatal 误以为装坏了。

实测输出：
```
fatal: ambiguous argument 'HEAD~1..HEAD': unknown revision...
无法执行 git diff: Command failed: ...
✅ 没有文件变更，无需审计。
```

**目标**：检测到首次提交时，跳过 git 错误输出，直接给清晰消息。

```
首次提交，无需审计（没有前一个版本可对比）。审计引擎已就绪，下次提交生效。
```

**改动**：`diff-parser.ts` 中区分「首次提交（无 HEAD~1）」和「真正的 git 错误」，前者静默处理 + 友好提示。

**改动量**：~5 行。

### 12. npm 包 README 版本号验证

**现状**：`sofagent/audit/README.md` 头部写 `v0.99.9`——这是用户在 npmjs.com 上看到的第一行。

**目标**：v1.0 发版时确认 bump-version.sh 的覆盖范围包含此文件，npm 页面上显示 `v1.0.0`。

**改动**：发版前跑 `grep '1\.0\.0' sofagent/audit/README.md` 确认版本号已更新。如果 bump-version.sh 未覆盖此文件，手动修改 1 处。

**改动量**：验证 1 行（可能零改动）。

### 13. `sofagent-audit --init` 一键初始化

**现状**：用户装完 sofagent 后，需要手动做 3 件事才能让审计生效：① 创建 `.sofagent/config.yml`（或依赖默认配置，但用户不知道有默认）② 安装 git pre-commit hook ③ 跑一次 verify 确认安装。步骤分散，容易漏配。

**目标**：一条命令搞定初始化——降低首次使用门槛，让用户装完 30 秒内进入可用状态。

```
$ sofagent-audit --init

sofagent-audit · 初始化

[1/3] 创建配置文件...
  → .sofagent/config.yml 已生成（11 条规则默认全部启用）
  → 想自定义？编辑 .sofagent/config.yml 后重新跑 --init

[2/3] 安装 git pre-commit hook...
  → 检测到 git 仓库: /Users/foo/my-project
  → .git/hooks/pre-commit 已安装（可执行）

[3/3] 冒烟测试...
  → ✅ 11 条规则全部加载
  → ✅ 审计引擎可用

╔══════════════════════════════════════════╗
║  sofagent-audit 初始化完成               ║
║  下次 git commit 时审计自动生效           ║
╚══════════════════════════════════════════╝

  下一步：git commit -m "test" 看效果
```

**改动**：

| 文件 | 改动 | 说明 |
|------|------|------|
| `sofagent/audit/src/commands/init.ts` | **新增** ~80 行 | 初始化命令逻辑 |
| `sofagent/audit/src/index.ts` | 注册 `--init` 分支 | ~5 行 |
| `sofagent/audit/src/config-template.ts` | **新增** ~30 行 | config.yml 模板字符串（带注释，说明每条规则） |
| `sofagent/audit/package.json` | bin 加 `sofagent-audit-init` | 1 行 |

**初始化逻辑**：
1. **配置生成**：检查 `.sofagent/config.yml` 是否存在。不存在 → 生成带注释的模板（11 条规则默认全启用 + 4 条扩展规则默认关闭）；已存在 → 跳过，提示用户
2. **hook 安装**：检查当前目录是否 git 仓库。是 → 写入 `.git/hooks/pre-commit`（含第 10 件事的无声失败保护）；否 → 提示「非 git 仓库，hook 已跳过」
3. **冒烟测试**：调用现有 verify 逻辑快速验证审计引擎可用

**config.yml 模板**（生成到 `.sofagent/config.yml`）：
```yaml
# sofagent 审计配置
# 文档: https://github.com/KongFangXun/sofagent#配置
# 生成方式: sofagent-audit --init

rules:
  # 底线规则（违反即阻止提交）
  a1-sensitive-files: true     # 不碰敏感文件（.env / .ssh / 密钥）
  a2-no-secrets: true          # 不泄密钥（API key / token）
  a3-minimal-change: true      # 最小变更（不混入无关改动）
  a4-no-delete-config: true    # 不删配置（package.json / tsconfig 等）
  a5-read-before-write: true   # 先读再用（修改前先 Read）
  a6-no-skip-context: true     # 不跳上下文（不绕过加载链）
  a7-tail-cail: true           # 有头有尾（任务闭环）
  a8-no-skip-verify: true      # 不逃验证（变更后必须验证）
  a9-human-handoff: true       # 人机交接（高风险操作交人）
  a10-commit-hygiene: true     # 提交卫生（commit message 规范）
  a11-no-abuse: true           # 不滥用（不引入非必要依赖）

  # 扩展规则（默认关闭，按需启用）
  e1-import-organization: false  # import 排序
  e2-export-size: false          # 导出文件大小限制
  e3-comment-ratio: false        # 注释覆盖率
  e4-naming-convention: false    # 命名规范
```

**幂等性**：`--init` 可以重复运行。已存在的配置不覆盖，已安装的 hook 不重复写入。每次运行都跑冒烟测试。

**与 install.sh 的关系**：install.sh 安装 sofagent 本体（Skill 文件 + 审计引擎 + CLI）。`--init` 在具体项目仓库中初始化审计配置 + hook。两者是「装软件」和「配项目」的关系——install.sh 全局装一次，`--init` 每个项目跑一次。

**约束**：
- 不新增 npm 依赖
- config.yml 模板用字符串常量，不引入 yaml 序列化库（直接写多行字符串）
- hook 模板内容与第 10 件事的无声失败保护一致
- 冒烟测试复用 verify 逻辑，不重新实现检查

### 14. `sofagent-audit --doctor` 健康诊断

**现状**：当审计不工作时（hook 没装好、config 写错语法、history 文件不可写、Node.js 版本太低），用户没有排查工具——只能看报错猜原因。

| 6 | 规则加载 | 11 条规则全部注册 | 列出缺失的规则名 |
| 7 | 冒烟测试 | 审计引擎跑一次空 diff 不报错 | 输出具体错误信息 |

**复用关系**：诊断项 #2-#3 复用 `--init` 的检测逻辑；#4 复用 `config-loader.ts` 的配置加载；#6 复用 `reporter.ts` 的规则注册表；#7 复用 verify 逻辑。不重新实现检查，只做诊断体验封装。

**退出码**：全部 ✅ → exit 0；有 ❌ → exit 1（方便 CI 中集成诊断）。
