# v0.99.5 · CI 自动化发布版

> 2026-07-03 · 版本类型：基础设施修复
> 审查来源：v0.99.4 发版过程中发现 npm publish 手动流程瓶颈

## 一句话

npm 发布从手动 OTP 升级为 OIDC Trusted Publishing 全自动。v0.99.4 的手动发版地狱不会再发生了。

## 核心交付

### CI 自动化

| 项目 | v0.99.4（旧） | v0.99.5（新） |
|------|:--:|:--:|
| 认证方式 | NPM_TOKEN secret（Granular Token） | OIDC Trusted Publishing |
| 2FA 要求 | 需要 bypass 2FA token 或不稳定地关闭 2FA | 零 2FA——OIDC 自动签发临时 token |
| 发布流程 | 手动 `npm login` → 输 OTP → `npm publish` | `git tag vX.Y.Z` → `git push` → GitHub Actions 自动发布 |
| 安全级别 | 持久 token 泄露风险 | 短期 OIDC token（自动过期） |

### 具体变更

- **release.yml**：两个 publish job 新增 `permissions: id-token: write`，移除 `NODE_AUTH_TOKEN` env
- **release.yml**：`npm ci` 后 `npm install --no-save @rollup/rollup-linux-x64-gnu || true`（解决 macOS lock 文件在 Linux CI 上漏装原生模块）
- **release.yml**：新增 `workflow_dispatch` 触发器（允许手动重跑）
- **npm 端**：`@sofagent/audit` 和 `@sofagent/mcp` 均配置 Trusted Publisher（KongFangXun/sofagent → release.yml）

### 工作流 SOP 更新

- **SOFAGENT_VERSION_SOP.md**：
  - bump-version 扫描范围：`audit/src/` → `audit/src/` + `mcp/src/`（修 P1-12）
  - shellcheck 门槛：零 warning → 零 error（降 P2 warning 不阻塞发版）
  - 检查清单规则：「强制 `[x]`」→「质量验证命令可替代」
  - 新鲜度检查标责任方（工程师自测时跑）
  - 覆盖表补 `FDE/SKILL.md` 和 `mcp/src/**/*.ts`
