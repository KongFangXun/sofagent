## 定位

v1.3.3 同时交付两件事：

1. **L2 团队协作协议**——让多个有身份的 Agent 从"各自为战"变成"一个团队"（ROADMAP「完整多设备协同」的核心：从单人约束到团队协作）
2. **✨ Refine Agent**——让 AI 节点从「能用」到「好用」（复用 Onboard Agent 循环引擎，判据从 Ontology 换成质量规则集）

> 🧠 **为什么同版交付**：Refine Agent 的质量规则集天然适合团队级反馈放大——一个 Agent 在调试中学到的质量经验（"SKILL.md 工具描述要带 example""输出不能超 500 字"），通过 §协作协议的反馈放大机制广播给全队，其他 Agent 不用重新踩坑。这是 1+1>2 的协同效应。v1.3.3 实现 **L2 团队协作协议**——让多个有身份的 Agent 从"各自为战"变成"一个团队"。这是 ROADMAP「完整多设备协同」的核心：从单人约束到团队协作。

> 🧠 **A2A 协议参考**：Google A2A 为多 Agent 协作定义三层——动态服务发现 / 能力契约对齐 / 全状态接力。MCP 解决「脑和手」，A2A 解决「脑和脑」。本版本落地 A2A 思想，但不照搬协议（保持 MIT 开源 + 开放格式）。

## P0：五大机制

| 机制 | 做什么 | 关键设计 |
|------|--------|---------|
| **共享态** | 团队成员共享一个工作状态视图 | 复用 v1.1.8 automerge CRDT（clone-fork 共享版本史收敛） |

| **触发反应** | Agent 广播意图后，相关成员自动触发反应 | 意图 → 匹配订阅 → 触发子任务 |
| **冲突消解** | 多个 Agent 想改同一目标时按规则裁决 | trust 优先 + 时间戳 + 显式优先级 |
| **反馈放大** | 一次纠正/确认回流为团队学习信号 | 复用 think.md + Dream Cycle，团队级聚合 |

## ✨ Refine Agent 完整版（FORGE 产品化第三刀）

> **设计来源**：FORGE 的 `fresh-eyes-driver.mjs`（2370 行）已验证"新鲜眼审查循环"可行性——审查发现问题 → 找另一个 agent 修 → 再审查 → 再修……循环直到质量收敛。Refine Agent 把这套能力产品化给企业。

### 与 Onboard Agent 的关系

| | Onboard Agent（v1.3.1+v1.3.2） | Refine Agent（本版） |
|---|---|---|
| **目标** | 节点从「不能用」到「能用」 | 节点从「能用」到「好用」 |
| **判据** | Ontology 本体结构（跑出来的对不对） | 质量规则集（跑出来的好不好） |
| **FORGE 原型** | release-gate-loop（发版门禁） | fresh-eyes-loop（新鲜眼审查） |
| **触发时机** | activate 后立即 | Onboard 收敛 PASS 后 |
| **循环引擎** | 自建 | **复用 Onboard 的 driver/judge/converge** |

两者串行：**Onboard 让它能干活 → Refine 让它干得好**。

### 五层（一次交付，复用 Onboard 引擎）

Onboard Agent 的 L1（工程判定）/ L3（定位）/ L4（修复）/ L5（收敛）是通用循环引擎，Refine Agent 直接复用，只换 **L2 判据层**：

| 层 | Onboard Agent | Refine Agent |
|:--:|--------------|--------------|
| L1 | crash/error/超时检测（复用） | 质量探测：跑一轮看输出规不规范 |
| **L2** | **Ontology 对比器（语义对错）** | **质量规则集判定（质量好坏）** |
| L3 | LLM 推理定位（复用） | 同 |
| L4 | 自动修复 + 审计兜底（复用） | 同 |
| L5 | 连续 N 轮 PASS 收敛（复用） | 同 |

### 质量规则集（Refine 的判据）

质量规则集不是凭空写的——来自三个来源：

| 来源 | 例子 | 怎么积累 |
|------|------|---------|
| **内置模板** | SKILL.md 工具描述必须带 example；输出不超过 500 字；few-shot 至少 2 条 | sofagent 自身开发经验固化 |
| **客户 FDE 回写** | 客户业务特定质量标准（如"金融场景必须带风险提示"） | FDE 离场时回写 delivery-report.md → 规则化 |
| **团队反馈放大** | 一个 Agent 踩过的坑广播成规则 | **本版协作协议的反馈放大机制** |

> 💡 **协同点**：质量规则集的第三个来源（团队反馈放大）正是本版 L2 协作协议的核心机制之一。这是两件事同版交付的深层原因——协作协议的反馈放大天然喂养 Refine Agent 的规则集。

### 验收标准（Refine Agent）

- [ ] Onboard Agent 收敛 PASS 后，自动触发 Refine Agent
- [ ] 质量规则集加载：内置模板 + 客户回写 + 团队反馈三个来源
- [ ] L2 质量判定：对节点输出跑规则集，生成质量差异报告
- [ ] L3-L5 复用 Onboard 引擎：定位→修复→收敛，无需重写
- [ ] **团队反馈放大**：一个 Agent 学到的质量规则，通过 §协作协议广播给全队

### 难度

⭐⭐⭐（中等）。核心工作量在质量规则集的设计和 L2 判定器；L1/L3/L4/L5 复用 Onboard 引擎，工程量小。
