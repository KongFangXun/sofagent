# v1.3.5 开发日志 — 自进化与运维闭环（MCP 覆盖度审计缺口补全）

> ⚠️ **规划中，尚未实现。** 以下内容为版本目标规划，不代表当前可用能力。

> 状态：规划中 · 2026-08-03
> 来源：MCP 覆盖度审计 13 个缺口 tool 的最后四项（P1+P2），版本归属用户已拍板

## 定位

v1.3.5 落位 v1.3.x 弹性预留区，主题是**自进化与运维闭环**——MCP server（engine/mcp）已注册 23 tools + 4 resources，但自进化链路（ab-test）与运维链路（daemon 快照）在引擎侧早已就绪，唯独缺 MCP 入口：Agent 看得见「审计结果」，却摸不到「进化的方向盘」和「回退的安全绳」。本版补上这 4 个 tool，让自进化与运维两条闭环在 MCP 侧完整可用。

## P0：自进化闭环（ab-test ×2）

`engine/ab-test` 已有 `runABTest` / `decidePromotion` 实现，缺的只是 MCP 暴露：

| tool | 所属包 | 一句话 |
|------|--------|--------|
| `run_ab_test` | ab-test | 发起 A/B 对比实验（current vs candidate + golden-set），打通自进化闭环 |
| `promote_ab` | ab-test | A/B 晋升决策执行，**强制人审** |

## P1：运维闭环（daemon 快照 ×2）

daemon 快照机制（`snapshot.ts`）已落地，补上查询 + 恢复两个 MCP 入口：

| tool | 所属包 | 一句话 |
|------|--------|--------|
| `snapshot_list` | daemon | 列出审计快照时间线（只读查询） |
| `snapshot_restore` | daemon | 恢复到指定快照，**强制人审**（破坏性操作） |

## 安全边界（用户已背书）

1. 破坏性操作（`promote_ab` / `snapshot_restore`）MCP 可触发但**强制 human-confirm 语义**——无人审确认不执行，全程审计留痕
2. daemon 类 tool 只做**只读查询**（`snapshot_list` 只读）——start/stop 等进程控制永不 MCP 化（防恶意 Agent 滥用）

## 验收标准

- [ ] `run_ab_test` 可发起 A/B 对比实验（current vs candidate + golden-set）并返回实验结果
- [ ] `promote_ab` 仅在人工确认后执行晋升决策，未确认时挂起不执行
- [ ] `snapshot_list` 返回审计快照时间线（只读，不改变任何状态）
- [ ] `snapshot_restore` 仅在人工确认后执行恢复，未确认时挂起不执行
- [ ] 4 个 MCP tool 全部走审计留痕（D1-D5 / 运行时审计日志）
