## 一、官方 AST 规则引擎（engine/rules/src/ast/）

### 背景

v1.2.9 开放规则插件接口（`type: "plugin"` + `sofagent-ruleset-*` npm 包约定）。本版官方出第一个**语义级规则引擎示范**——TS7 原生端 API 驱动的 AST 解析 + 官方示范规则集，作为社区写自定义引擎的参考实现。

### 关键工程坑：TypeScript 7 API 变迁

TS7 是 Go 原生移植（`typescript@7.0.2`），移除了 5.x 的 `createSourceFile` 同步解析 API。官方替代入口是 `typescript/unstable/sync` 的 `API` 类，但**仅能解析真实磁盘文件**（虚拟 FS 回调对 `openFiles` 路径解析不生效——实测验证）。引擎采用「扫描内容 → 写临时文件 → 走 TS server 解析」模式。

另一关键坑：TS7 snapshot 对同一路径已打开文件**缓存首次内容**——`extractExports` 多次调用若复用同路径，后台读到的全是第一个文件的内容。修复：每次调用分配**唯一临时路径**（`${seq}-${path}`，seq 自增），避免缓存污染。

## 二、meta-harness 多 harness 统一编排（engine/orchestrator/src/meta-harness/）

### 背景

v1.3.7 给单个 SubAgent 沙箱，本版升级为多 harness 统一编排——多个 SubAgent（各自带沙箱）在一个 meta-harness 下协同运行 + 跨会话协作。Omnigent「策略强制在基础设施层」启发——策略在 meta-harness 层强制（跨 harness 状态追踪 + 动作前拦截）。

### DSH RC.7/RC.8 启发的统一调度层形态

- 子代理 Profile Bundle 按需安装（运行时 `installProfile()` 触发，可重入）
- 多命名实例（同 profile 装多个并行实例，如 audit-a/audit-b）
- 子代理完成 `reportDelivery()` 主动反馈并唤醒父任务——**不轮询**（parent 端 `waitForDelivery()` 拿 promise，delivery 触发 resolve）
- L2 协作协议兼容（v1.3.3）——audit-aggregator 接收 `L2EventInput` 归一化入聚合轨迹

### 交付

| 文件 | 角色 |
|---|---|
| `orchestrator.ts` | MetaHarness 编排器——register/installProfile/submitTask/reportDelivery/waitForDelivery/onDelivery/unregister + getPolicyLayer/getAuditAggregator 接线 |
| `policy-layer.ts` | PolicyLayer 强制层——内置 4 条策略（file-lock/concurrency-cap/profile-allowlist/sensitive-tool）+ 自定义策略注册 + 拦截历史审计 |
| `audit-aggregator.ts` | AuditAggregator 聚合器——ingest/ingestL2Event（L2 协议事件归一化）/query/statsByHarness/exportAll（worklog 消费） |

### 关键工程坑

`new Promise(entry.resolve)` 会把 resolve 函数本身当值立即解析——`waitForDelivery` 的早期实现就栽在这：JS Promise 构造器把 `executor` 视为 `(resolve, reject) => {}`，`entry.resolve` 接到 resolve 函数立刻 fulfilled。修复：pending 直接持有 `deliveryPromise` 本体（`new Promise(res => { release = res })` 时 release 未被当作 executor 消费），`waitForDelivery` 直接 `await entry.deliveryPromise`——多消费者场景下所有等待方共享同一 promise。

- [x] 跨 harness 状态可追踪（动作前拦截 deny 优先 + 拦截历史可拉取）
- [x] 审计轨迹跨 harness 聚合可查（query/ingestL2Event/statsByHarness/exportAll）

## 十二、>5MB diff 缝隙修复（P0 连带 · v1.3.9）

### 背景

攻击者构造超大 diff 藏密钥，`diff-parser` `maxBuffer: 5MB` 溢出即跳过内容审计——五元教训 A1。

### 修复

`engine/core/src/diff-parser.ts` 两处溢出分支重写为「spill 落盘 + 分块读回」：

1. **spill 落盘**——`spawnSync('git', args, { cwd, stdio: ['ignore', fd, 'ignore'] })` 把 stdout 直接重定向到 spill 文件（**零内存**写）
2. **分块读回**——8MB `readSync` 循环 + 跨块残行拼接 + 字节数累计
3. **读回上限 64MB**——`SPILL_READ_CAP = 64 * 1024 * 1024`：
   - ≤64MB 全量扫描（`oversized` 不置位，无审计盲区）— A2 密钥检测不漏
   - >64MB 截断 + `oversized=true`（WARN 注入语义保留）+ `spillFile` locator（审计规则可按需取回）
4. **spill 落盘目录**——`${SOFAGENT_DATA}/spill/`（与 audit-history 同解析链）
5. **审计语义同步**——`audit/index.ts` 1163 段 WARN 文案从「5MB 跳过」改为「64MB 截断 + spill 落盘可取回」

### 关键工程坑

`readSync` 返回**数字**（字节数）——不是 `{ bytesRead }` 对象！早期 `const { bytesRead } = readSync(...)` 解构出 `undefined` → `bytesRead === 0` 永远 false → 死循环把整个 8MB buffer 当 `\u00b7` 重复 push → OOM。修复：`const bytesRead = readSync(readFd, buf, 0, CHUNK, null)`。

### 验收

- [x] >5MB 场景下 AST 引擎仍扫描全部内容，A2 密钥检测不因 maxBuffer 跳过（实测 6MB diff 全量读回 95008 行含密钥行可扫到）

## 十三、FORGE driver 进程守护（daemon + watcher，v1.3.9 增量）

### 背景

fresh-eyes-loop run-01（2026-08-21）两次静默死亡：心跳戛然而止、无 .ips 崩溃报告、latest.json stopReason=null、日志无异常——典型**外部 SIGKILL 进程树清理**（driver 挂 WorkBuddy/Electron 进程树下，主 session turn 结束被整体回收；8GB 机器内存压力是环境劣化因素）。既有 `--check-alive` 探针只能事后判死，不能防死、不能自动恢复。

### 交付（fresh-eyes-driver.mjs + release-gate-driver.mjs）

| 能力 | 说明 |
|------|------|
| `--daemon` | detached spawn 自脱离进程树（孤儿由 launchd 收养，宿主会话结束不影响存活）；日志重定向 `runDir/driver.log`（stdio 绑文件 fd）；`SOFAGENT_DAEMON_CHILD` 防递归；`--dry-run` 透传 |
| `--watch <runDir>` | watcher 主管模式：`checkDriverLiveness` 心跳判死 → 死因审计 → `--resume` 自动续跑 → `verdict.md` 产出退出。纯监控进程无 LLM 调用，不可能撞长窗口 |
| 死因审计 | 落盘 `runDir/death-audit.jsonl`（append）：`verdict` = external-kill（无 stopReason + pidfile 残留）/ signal-abort（SIGTERM 优雅）；含 heartbeatAge/lastEvent/phase/pidfile 佐证 |
| `driver.pid` | 心跳 timer 写、SIGTERM cleanup 删——残留 = 非优雅退出佐证，审计判定更准 |

> 设计取向（用户拍板）：**driver 是 Agent，由 Harness 理念管（审计死因/断点回溯/预算自调），不用 launchd 托管进程**——四能力映射：注入（启动规则）→ 审计（death-audit）→ 回溯（resume 断点）→ 进化（worker 崩溃统计）。

### 验收

- 自测：语法 ✓ / `--check-alive` 回归 ✓ / daemon dry-run（父进程退出 + 子进程脱离 + 日志落盘 + dry-run 透传）✓ / watcher 判死 + 审计（external-kill 落盘）✓
- watcher 自动拉起路径未真实 spawn（避免意外调 LLM），底层 `spawnDetachedDriver` 由 daemon 测试覆盖；release-gate 平移后以真实 run 验证跨 turn 存活
- commit `767d7c10`（fresh-eyes）+ release-gate 平移 commit（见 git log）
