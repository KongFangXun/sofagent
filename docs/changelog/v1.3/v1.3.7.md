## 一、SubAgent 完整沙箱执行环境

### 痛点

v1.3.0 的运行时审计是 **middleware 层**——包在 createReactAgent 外面，记录工具调用 + 审计日志。但 middleware 是**观测层**，不是**隔离层**。SubAgent 调用 `fs.writeFileSync` 时，middleware 能记录并告警，但**不能阻止文件被写入磁盘**——等审计 FAIL 时文件已经写了。

本版把审计从「记录+告警」升级为「**前置 allow/deny + 虚拟执行**」。

### 交付

| 组件 | 能力 | 对标 |
|------|------|------|
| **虚拟文件系统** | FilesystemBackend + virtualMode——SubAgent 写文件先写虚拟层，审批后才合并到物理磁盘 | bubblewrap / seatbelt |
| **网络出站白名单** | SubAgent 网络请求经白名单过滤，非白名单域名 deny | EnkryptAI Secure MCP Gateway |
| **工具调用中介** | 前置 allow/deny（非仅审计追踪）——高危工具调用在执行前拦截 | OpenWorker 权限模型 |
| **虚拟 key 凭证边界** | SubAgent 拿到的 API key 是虚拟 key，限速 + 限定 scope，不接触真实 key | LiteLLM 控制平面 |
| **AsyncSubAgent** | 远程 Agent Protocol 服务端——SubAgent 可在独立进程/容器运行 | Agent Protocol 标准 |
| **真·实时 A/B 双跑** | A/B SubAgent 在隔离环境同时执行，实时 diff 而非串行对比 | FORGE fresh-eyes 升级 |

### 沙箱与 v1.3.0 middleware 的关系

```
v1.3.0: createReactAgent → wrapToolCall middleware（记录+告警）→ 工具执行 → 物理磁盘
v1.3.7: createReactAgent → wrapToolCall middleware → 沙箱层（allow/deny + 虚拟执行）→ 审批 → 物理磁盘
```

v1.3.0 的 middleware **不删除**——它变成沙箱的「审计记录层」，沙箱是「执行隔离层」。两者叠加。

### 边契约「证据流 + 数据流」补全（从 v1.2.5 P6 拆入）

> 来源：v1.2.5 规划 P6「五类边契约形式化」。v1.2.5 瘦身时降级——权限流 + 失败流已在 v1.3.0 wrapToolCall 自然落地，剩余两类边随本版沙箱补全：
> - **证据流**：虚拟文件系统审批后才合并到物理磁盘（write → virtual → audit → approve → physical），每步输出留不可篡改审计记录——这正是"证据流"边契约的工程实现
> - **数据流契约**：虚拟 key 限速 + scope 约束 = 数据流边契约的显式化（SubAgent 拿到的凭证限定了它能访问的数据域，不再是隐式约定）

### 沙箱完整性自检与攻击面声明

> 📋 **2026-08-10 补充（安全基线 · 与 v1.4.1 ⑩ 训练安全基线对齐）**：沙箱是 v1.3.x 的安全核心组件，需要显式声明攻击面与防御措施——不声明 = 企业 IT 不敢用。

| 攻击面 | 防御措施 |
|--------|---------|
| **沙箱逃逸**（SubAgent 绕过虚拟 FS 直接写物理磁盘） | 启动时完整性自检（校验 FilesystemBackend hook 未被篡改）+ 运行时 fs 操作全部经虚拟层（monkey-patch fs 模块，绕过=进程级 deny） |
| **网络白名单绕过**（SubAgent 经 DNS 隧道 / ICMP 逃逸） | 网络出站经 network-gateway 全量拦截（不只 HTTP，含 DNS/raw socket）+ 白名单外域名 deny + deny 事件审计 |
| **虚拟 key 泄漏**（SubAgent 提取虚拟 key 向外发送） | 虚拟 key 限 scope + 限速（token bucket）+ key 不出现在 SubAgent 可见环境变量（host 边界注入）+ 日志脱敏 |
| **工具调用伪装**（SubAgent 伪造工具名绕过 tool-gate） | tool-gate 按工具唯一 ID（非名称字符串）判定——名称可伪造，ID 不可 |
| **沙箱资源耗尽**（SubAgent fork bomb / 磁盘填充） | 进程数限制 + 虚拟 FS 容量上限 + 超限 deny + 审计 |

**声明为后续版本职责**：
- OS 级硬隔离（bubblewrap/seatbelt）留 v1.3.9+——本版虚拟 FS 是应用层隔离，不防 kernel exploit
- 主 Agent 运行时策略强制留 v1.3.9——本版沙箱仅限 SubAgent

## 二、场景驱动权限体系（原 v1.2.5 拆入）

### 交付

权限按「场景」（任务类型 × 数据域 × 动作风险等级）动态判定：

```
判定链：身份（v1.3.1）→ 场景匹配 → 风险等级 → 放行/deny/人工批准
```

| 维度 | 说明 | 示例 |
|------|------|------|
| 任务类型 | 代码开发 / 数据处理 / 报表生成 / 测试 | 代码开发场景可写 .ts 文件 |
| 数据域 | 代码 / 配置 / 审计数据 / 用户数据 | 用户数据场景禁写审计数据 |
| 动作风险等级 | 读（低）/ 写（中）/ 删（高）/ 外传（极高） | 极高风险 → 人工批准 |

**包含**：团队场景权限（v1.3.3 L2 协作）+ 市场调用权限（v1.3.4 L3 市场）+ 动态提权到期回收。

| `engine/orchestrator/src/permission/policy-engine.ts` | 新建 | 策略引擎（放行/deny/人工批准） |
