## 决策审计 · Judgment Unit 蒸馏落地（OpenFDE #1 溢出专项）

> 状态：规划中（设计成文于 v1.3.0，实现落本版本）· 高见远（架构师）· 2026-07-27
> 来源：OpenFDE 主仓 INDUC（知识归纳阶段）+ Judgment Unit（专家判断资产化、可开关、可版本化）—— ROADMAP 第 339 行
> 前置：v1.3.0 决策日志 MVP（T01-T04）已积累决策语料；本专项为 T05 溢出实现

### 定位

v1.3.0 把「决策理由链」记下来（意图层审计 MVP）；**本版本把高复用的 `why` 蒸馏为可开关、可版本化的 Judgment Unit**——专家判断资产化，对应主仓 INDUC 把「经验→判断」显式成阶段。与 v1.3.1「本体即认知底座（可运行推理底座）」同构：Judgment Unit 是推理底座里「人类判断可复用」的那一层。

### 蒸馏路径（对应 v1.3.0 第 7 节设计）

1. **收集**：sustain / INDUC 等价物周期扫描 `data/audit/decision-log.jsonl`，聚类高频 / 同 `tags` 跨 `kind` 的 `why`（如批量 `FALLBACK_DEGRADE` + tag `model-unavailable`）。
2. **提议**：生成 Judgment Unit 候选
   ```
   interface JudgmentUnit {
     id: string;
     name: string;
     trigger: { kind: DecisionKind; tags: string[] };
     action: 'allow' | 'deny' | 'warn' | 'escalate';
     enabled: boolean;        // 默认 false，人类批准后才 true
     version: string;         // v1 / v2… 可版本化
     sourceDecisionRefs: string[];  // 溯源到原始 decision 条目
   }
   ```
3. **审批**：人类批准 → `enabled:true`，成为 `RULE_TOGGLE` 可开关资产，版本化。
4. **回流**：启用后，该 `kind+tags` 新决策可由对应 Judgment Unit 给默认 action，减少重复人工判断；其开关状态本身也经 `emitDecision({kind:'RULE_TOGGLE'})` 留证。

### 实现文件（T05）

| 相对路径 | 作用 |
|------|------|
| `engine/audit/src/decision-distill.ts` | sustain 蒸馏（扫描 + 聚类 + 候选生成） |
| `engine/audit/src/judgment-unit.ts` | Judgment Unit 资产（CRUD + 开关 + 版本） |
| `engine/audit/src/decision-distill.test.ts` | 单测 |

### 边界

- **不替换 A1-A19 静态规则**：Judgment Unit 是「可开关判断资产」新类（`KNOWLEDGE_DISTILL` kind + `ORCHESTRATION` 编排），与 A1-A19 并存。
- **复用同 HMAC 链**：Judgment Unit 自身的变更日志（开关 / 版本）也经 `emitDecision` 落 decision-log.jsonl，共用防篡改链。
- **版本判定**：v1.3.0 装「记决策」（T01-T04）；本版本装「蒸馏资产」（T05）——决策=图节点，先有 v1.3.0 语料，Graph Engine 才有输入。
