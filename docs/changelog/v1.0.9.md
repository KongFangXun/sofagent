# v1.0.9 开发日志 — 二进制文件审计 + 快照回溯 UI + MCP compose tool

> v1.0.8 建了文件系统审计的地基（isomorphic-git + daemon fs-watch + 快照），v1.0.9 在上面盖楼：二进制文件的行为级审计规则、快照时间线可视化、编排引擎通过 MCP 对外暴露。
>

## 背景

v1.0.8 实现了文件系统审计的核心——daemon 监控文件变更、isomorphic-git 做 diff、审计后自动快照。但留了三个缺口：

1. **二进制文件只能记录不能审计**——Excel/Word/PDF 变更只是写一条 `binary_change` 到 history.jsonl，没有规则判定
2. **快照有了但看不到**——`.sofagent/.git-shadow/` 里存了一堆快照，用户没有 UI 查看
3. **编排引擎只有 CLI 入口**——`sofagent-audit compose --task` 能用但不方便，Agent 平台更习惯 MCP tool

v1.0.9 补齐这三块。

## 交付内容（4 件事）

### 1. 二进制文件审计规则：A16 + A17

v1.0.8 的 17 条规则全部基于文本 diff。二进制文件（.xlsx/.docx/.pdf/.png 等）的 diff 不可读，需要行为级规则——不看改了什么内容，看改了什么文件。

**A16 非授权文件变更**（git-diff + 文件系统）：

```yaml
rule: A16
name: 非授权文件变更
description: 检测非授权目录/类型的文件被修改或删除
evidenceMode: git-diff
severity: WARN
config:
  # 保护目录——这些目录下的文件变更需要特别关注
  protected_dirs:
    - "config/"
    - ".env*"
    - "secrets/"
  # 敏感文件类型——这些类型的文件删除/修改触发告警
  sensitive_types:
    - ".xlsx"
    - ".docx"
    - ".pdf"
    - ".db"
    - ".sqlite"
```

**判定逻辑**：
- 二进制文件在保护目录下被修改/删除 → A16 WARN
- 敏感类型文件被删除 → A16 WARN
- 新增未知类型文件到保护目录 → A16 WARN

**A17 异常批量变更**（文件系统）：

```yaml
rule: A17
name: 异常批量变更
description: 检测短时间内大量文件被修改（可能是 Agent 失控或注入攻击）
evidenceMode: filesystem
severity: WARN
config:
  # 5 分钟内修改超过 50 个文件 → 告警
  bulk_threshold: 50
  bulk_window_ms: 300000
```

**判定逻辑**：
- 防抖窗口内变更文件数超过阈值 → A17 WARN
- 不是阻断——文件已经改了——而是告警 + 建议人工检查

**不做的**：
- ❌ 不解析二进制文件内容（不读 Excel 单元格、不读 PDF 文字）——那是 AgentLoop 的 Trajectory 观测做的事，不是 sofagent 的 diff 审计
- ❌ 不做 OCR——内容级审计推到 v2.x 或不做

### 2. 快照时间线可视化

`sofagent-audit --timeline` 命令输出快照时间线：

```bash
sofagent-audit --timeline
```

```
sofagent 快照时间线（最近 20 条）
═══════════════════════════════════════════════

  ✅ 2026-07-13 14:30:12  abc1234  PASS  5 文件变更
     ├── docs/report.md (+12 -3 行)
     ├── data/config.json (+1 行)
     └── 3 个文件无违规

  ⚠️ 2026-07-13 14:15:08  def5678  WARN  2 文件变更
     ├── .env (A1 敏感文件修改)
     └── config/settings.yml (A4 配置删除)

  ✅ 2026-07-13 13:45:00  ghi9012  PASS  1 文件变更
     └── docs/notes.md (+5 行)

  ...
═══════════════════════════════════════════════
回滚到任意快照：sofagent-audit --revert <SHA>
```

**设计要点**：
- 终端彩色输出（不依赖浏览器）
- 默认显示最近 20 条，`--limit N` 自定义
- `--json` 输出 JSON 格式（供其他程序消费）
- 不做 Web UI——sofagent 是 CLI 工具，不是 Web 应用

### 3. MCP compose tool 暴露

`@sofagent/mcp` 新增 `compose` tool，让 MCP 兼容的 Agent 平台通过标准 MCP 协议调用编排引擎：

```json
{
  "tool": "sofagent_compose",
  "description": "编排引擎——传入任务描述，返回编排方案",
  "inputSchema": {
    "type": "object",
    "properties": {
      "task": { "type": "string", "description": "任务描述" },
      "agent": { "type": "string", "description": "指定 Sub Agent（可选）" },
      "run": { "type": "boolean", "description": "是否执行（默认 false = dry-run）" }
    },
    "required": ["task"]
  }
}
```

**实现要点**：
- 内部调用 v1.0.7 已实现的 `sofagent-audit compose` CLI 逻辑
- 输出与 CLI 完全一致（YAML 编排方案）
- 不依赖 OpenClaw——纯 MCP 协议

### 4. Sub Agent knowledge 智能选择

v1.0.7 的 `buildConstrainedSystemPrompt()` 按 mtime 选 top-5 knowledge 文件注入。v1.0.9 升级为语义相似度选择。

**实现要点**：
- 复用 TencentDB Agent Memory（v1.0.8 集成）的 embedding 能力
- 任务描述 → embedding → 与 knowledge/ 每篇文件 embedding 算余弦相似度 → top-N
- TencentDB 未安装时降级到 mtime 方案（向后兼容）
- knowledge/ 文件数 < 10 时跳过语义搜索（不值得）
