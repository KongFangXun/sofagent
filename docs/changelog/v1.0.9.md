# v1.0.9 开发日志 — 二进制文件审计 + 快照时间线 + MCP compose tool

>
> v1.0.8 建了文件系统审计的地基（isomorphic-git + daemon fs-watch + 快照），v1.0.9 在上面盖楼：二进制文件的行为级审计规则、快照时间线可视化、编排引擎通过 MCP 对外暴露。外加 P0 安全修复（A9 中文注入 + commitMsg 取区间终点）、daemon 审计闭环、cron 定时巡检、5 项 v1.0.8 遗留补齐。

## 背景

v1.0.8 实现了文件系统审计的核心——daemon 监控文件变更、isomorphic-git 做 diff、审计后自动快照。但留了两个缺口：

1. **二进制文件只能记录不能审计**——Excel/Word/PDF 变更只是写一条 `binary_change` 到 history.jsonl，没有规则判定
2. **快照有了但看不到**——`.sofagent/.git-shadow/` 里存了一堆快照，用户没有 UI 查看
3. **编排引擎只有 CLI 入口**——`sofagent-audit compose --task` 能用但不方便，Agent 平台更习惯 MCP tool

v1.0.9 补齐这三块。

> **原计划第 4 件事（knowledge 语义选择）推到 v1.1.0**——v1.0.8 的 memory-sync.ts 只做 persona.md 文件同步，没有 embedding/vector 能力。语义选择需要新建 embedding 管道，不是简单复用。v1.0.9 聚焦文件系统审计主线。

## 交付内容（3 件事）

### 1. 二进制文件审计规则：A16 + A17

v1.0.8 的 17 条规则全部基于文本 diff。二进制文件（.xlsx/.docx/.pdf/.png 等）的 diff 不可读，需要行为级规则——不看改了什么内容，看改了什么文件。

**⚠️ 前置步骤：扩展 EvidenceMode 类型**

`sofagent/audit/src/rules/types.ts` 当前只有三种模式：
```typescript
export type EvidenceMode = 'git-diff' | 'logs' | 'hybrid';
```
A17 需要新增 `'filesystem'` 模式：
```typescript
export type EvidenceMode = 'git-diff' | 'logs' | 'hybrid' | 'filesystem';
```

**A16 非授权文件变更**（git-diff + 文件系统）：

```yaml
rule: A16
name: 非授权文件变更
description: 检测非授权目录/类型的文件被修改或删除
evidenceMode: git-diff
severity: WARN
config:
  # 保护目录——这些目录下的文件变更需要特别关注
  protected_dirs:
    - "config/"
    - ".env*"
    - "secrets/"
  # 敏感文件类型——这些类型的文件删除/修改触发告警
  sensitive_types:
    - ".xlsx"
    - ".docx"
    - ".pdf"
    - ".db"
    - ".sqlite"
```

**判定逻辑**：
- 二进制文件在保护目录下被修改/删除 → A16 WARN
- 敏感类型文件被删除 → A16 WARN
- 新增未知类型文件到保护目录 → A16 WARN

> **evidenceMode 说明**：A16 标 `git-diff`——在 git commit 场景走系统 git diff，在 daemon fs-watch 场景走 isomorphic-git diff。两种 diff 来源共用同一套 check 函数，只是 diff 提供方不同。

**A17 异常批量变更**（文件系统）：

```yaml
rule: A17
name: 异常批量变更
description: 检测短时间内大量文件被修改（可能是 Agent 失控或注入攻击）
evidenceMode: filesystem
severity: WARN
config:
  # 5 分钟内修改超过 50 个文件 → 告警
  bulk_threshold: 50
  bulk_window_ms: 300000
```

**判定逻辑**：
- 防抖窗口内变更文件数超过阈值 → A17 WARN
- 不是阻断——文件已经改了——而是告警 + 建议人工检查

**不做的**：
- ❌ 不解析二进制文件内容（不读 Excel 单元格、不读 PDF 文字）——那是 AgentLoop 的 Trajectory 观测做的事，不是 sofagent 的 diff 审计
- ❌ 不做 OCR——内容级审计推到 v2.x 或不做

### 2. 快照时间线可视化

`sofagent-audit --timeline` 命令输出快照时间线：

```bash
sofagent-audit --timeline
```

```
sofagent 快照时间线（最近 20 条）
═══════════════════════════════════════════════

  ✅ 2026-07-13 14:30:12  abc1234  PASS  5 文件变更
     ├── docs/report.md (+12 -3 行)
     ├── data/config.json (+1 行)
     └── 3 个文件无违规

  ⚠️ 2026-07-13 14:15:08  def5678  WARN  2 文件变更
     ├── .env (A1 敏感文件修改)
     └── config/settings.yml (A4 配置删除)

  ✅ 2026-07-13 13:45:00  ghi9012  PASS  1 文件变更
     └── docs/notes.md (+5 行)

  ...
═══════════════════════════════════════════════
回滚到任意快照：sofagent-audit --revert <SHA>
```

**设计要点**：
- 终端彩色输出（不依赖浏览器）
- 默认显示最近 20 条，`--limit N` 自定义
- `--json` 输出 JSON 格式（供其他程序消费）
- 不做 Web UI——sofagent 是 CLI 工具，不是 Web 应用

**实现说明**：
- `revertToSnapshot()` 核心函数**已在 `snapshot.ts` 实现**（行 112），只需在 `index.ts` 加 `--revert <SHA>` CLI 入口调用它
- `--timeline` 是统一命名（v1.0.8 changelog 原写 `--history --visual`，已统一改为 `--timeline`）

### 3. MCP compose tool 暴露

`@sofagent/mcp` 新增 `compose` tool，让 MCP 兼容的 Agent 平台通过标准 MCP 协议调用编排引擎：

```json
{
  "tool": "sofagent_compose",
  "description": "编排引擎——传入任务描述，返回编排方案",
  "inputSchema": {
    "type": "object",
    "properties": {
      "task": { "type": "string", "description": "任务描述" },
      "agent": { "type": "string", "description": "指定 Sub Agent（可选）" },
      "run": { "type": "boolean", "description": "是否执行（默认 false = dry-run）" }
    },
    "required": ["task"]
  }
}
```

**实现要点**：
- 内部调用 v1.0.7 已实现的 `sofagent-audit compose` CLI 逻辑（`index.ts:133`）
- 输出与 CLI 完全一致（YAML 编排方案）
- 不依赖 OpenClaw——纯 MCP 协议

### 4. 架构重构：编排引擎独立（compose 归位）🔧 — ⚠️ 已迁移至 v1.1.0

> 📋 **状态：待开发 · 孔放勋（2026-07-14 追加）**
> ⚠️ **本项已迁移至 v1.1.0**：实施规格改为 [`docs/changelog/v1.1.0-dev-prompt.md`](./v1.1.0-dev-prompt.md)（harness 由"推荐"改"强制"）。v1.0.9 不再包含此重构。
> 历史草稿：`docs/changelog/v1.0.9-orchestrate-refactor.md`

v1.0.9 第 3 项把编排引擎通过 MCP 暴露了，但编排入口仍挂在 `sofagent-audit compose` 下——语义错配（`audit` 是治理层，不该拥有编排）。本项把编排引擎从 `@sofagent/audit` 包彻底剥离，归位到独立新包 `@sofagent/orchestrate`（二进制 `sofagent-orchestrate`），让审计回归纯审计、FDE 与 MCP 改为消费新编排包。

**为什么做（代码证据）**：
- `composeWithDeepAgents()` 实现在 `audit/src/subagents/composer.ts`，`compose` 子命令在 `audit/src/index.ts:614`；编排 A/B 二进制 `sofagent-orchestrate-compare` 也错放在 audit 包的 `bin` 里
- FDE（`sofagent-fde` 仅是 Skill）只能反过来调 `sofagent-audit compose` 拆任务——消费者调用治理包去做编排，分层混乱
- `buildConstrainedSystemPrompt()`（四层约束加载链，sofagent 核心 IP）被 audit 的 ab-testing 与 orchestrate 共用，应独立成 `@sofagent/harness` 共享包

**范围**：
- 新建 `@sofagent/orchestrate` 包，迁移整个 `subagents/` 模块（composer / launcher / registry / builtin-agents / audit-sub-agent）+ DAG executor
- 新建 `@sofagent/harness` 共享约束层（四层加载链），audit 与 orchestrate 都依赖它
- `@sofagent/audit` 删除 `subagents/` 目录、移除 `compose` / `subagent` 子命令
- `sofagent-orchestrate-compare` bin 迁到 orchestrate 包
- `@sofagent/mcp` 的 `sofagent_compose` tool 改为调 `@sofagent/orchestrate`
- FDE / ARCHITECTURE / verify / fde-install.sh / River 指南 引用统一改为 `sofagent-orchestrate compose`

**硬约束**：orchestrate 不得反向依赖 audit；本次只做物理归位、不改编排行为（YAML 格式 / 四层约束 / Sub Agent 行为不变）；移除 `sofagent-audit compose` 为破坏性变更，需在 Release Notes 标注迁移命令。

**版本**：本重构已并入 **v1.1.0**（v1.0.9 未发版，不再单独以 v1.0.10 发布）。最终版本号由孔老师定。
