## 定位


> 🎯 **判定底座 · RLCD 训练复现**——阶段二第一版，回答「**概率从哪来**」。RLCD（Reinforcement Learning for Calibrated Decisions，用于校准决策的强化学习）与 RLHF、RLVR 的区别在**优化对象的落点**：RLHF 奖励「人更偏好的回答」、RLVR 奖励「可验证的正确结果」、RLCD 奖励「**决策本身及其概率**」——即同时要求判断得准，且准确表达不确定性。**为什么这件事不能用 RLVR 顶替**：判定的正确性往往没有廉价验证器（判据是语义性的），但**概率的良莠可以用评分规则直接度量**——评分规则就是那个廉价验证器。

> 📐 **判定底座 · 校准**——阶段二第二版，回答「**概率可不可信**」。校准的定义可以一句话说死：**让模型报出的概率值匹配真实发生的频率**——被标为 0.2 的结果，真实发生率应约等于 20%；标为 1 则代表几乎必然发生。**没有校准的概率不是「弱一点的概率」，而是没有意义的数字**——它会让下游的三段门控（高自动 / 中复核 / 低转人工）门槛全部虚设。**本版是可用性硬门槛**：本版第一章训出的模型在本版通过之前，其输出不得用于任何分流决策。与校准配套的是**弃权语义独立化**（§四）——概率不可信时系统必须有「判不了」这个出口，否则未校准的概率会被迫继续给出答案。

> 🧮 **判定底座 · 三原语概率面收口**——阶段二收口版，回答「**概率能不能用**」。本版第一章让概率有训练目标、本版第二章让概率可信，本版把三原语的概率输出**做完整并对照基线落数**，同时把「概率以什么形态进入判定链」的边界写死。**关键边界**：概率的引入**不扩大证据面**（判定层只能提高已获证据的利用率，不能凭空生成新证据），且输出形态不是 `pass` / `warn` / `fail` 三选一，而是「**概率 + 置信度 + 四态 + 建议动作**」——**只出建议，不执法**。

## 一、训练目标与评分规则（strictly proper scoring rule）


> **形态归属**：`[主干]`（判定·训练目标定义）｜ **不可拔**（奖励定义是模型行为的根约束）

### 交付

| 组件 | 能力 |
|------|------|
| **严格适当评分规则集** | 按原语类型分派损失/奖励：`Noul` 用 **log score**（对数评分，伯努利）；`Choice` 用 **log score + spherical score**（多类分布）；`Score` 用 **RPS**（Ranked Probability Score，有序分档）。**「严格适当」是关键性质**——该性质的数学含义是：报出真实概率时期望得分最优，即**诚实地报概率才是最优策略**，模型没有「虚报高置信度占便宜」的空间 |
| **非对称惩罚（校准的物理机制）** | 奖励对**过度自信**与**犹豫**的惩罚**不对称**：报极端概率（如 0.99）而判错承受**重罚**，报温和概率（如 0.55）而判错承受**轻罚**。优化目标因此不是「答对更多」，而是让**报出的概率收敛到长期统计真实胜率**——这正是「严格适当」在实现层的落法：**诚实报概率是唯一不被惩罚的策略**。副产品是不确定输入下置信度被主动拉低，**调用方因此有条件走 fallback**（与本版第四章弃权语义接续） |
| **策略梯度训练回路** | 以评分规则为奖励的策略梯度优化（**不引入人类偏好模型、不依赖外部教师模型**）——奖励信号完全来自评分规则，训练闭环内无外部依赖 |
| **概率目标消费** | 训练消费 v1.6.0 的**概率目标**（分布/区间/真值概率），而非硬标签——这是 RLCD 与常规监督分类的根本差别 |
| **标注档位加权** | 按 `label.source` 三档加权（`human` > `deterministic` > `model-judge`），权重口径写进配置且可审计 |
| **训练环境（两条路径都交付）** | ① **云端全参数微调**——算力不构成约束（同类实测量级为单卡 1 epoch 约 1.96 小时）② **本地 LoRA 档**——**单机可完成，且这是本产品交付形态的下限，不是「客户硬要才给的应急备选」**。生态已实测这条路的两半：**单机推理**——一件 9B 复刻件在 M5 Pro 64 GB 上（MLX）判定延迟中位 **444 ms** / p95 **981 ms**（324 例；同口径在 H100 上中位 106 ms）；**单机训练**——另一件的 0.5B 档在 **Apple M5 / 32 GB 统一内存 / MPS** 上完成一次训练约 **1 小时 45 分钟、功耗 30–40 W（约 0.06 kWh）**，其文档给出的单机纪律是「在 Mac 上一次只跑一个训练任务，长跑改用云卡」，而 4B / 8B / 9B 档确实迁到单卡 H100（约 40 / 70 / 91 分钟，9B 峰值显存 39.5 GB）。本地档的**可用性须实测落数**（见验收）。**为什么把它当一等形态**：判定模型的参数量天生小（判定不吃生成吞吐，吃并行打分能力），而「权重与代码一起交付、数据不出本机、客户可在自己机器上继续后训练」正是本产品线对外承诺的数据主权形态——把本地档降级为备选，等于把承诺的落点降级为妥协 |
| **训练配方纪律（生态实测倒逼，逐条可复算）** | ① **首要变量是学习率，不是容量**——某开源复刻件实测：默认 `lr 2e-4` 会把基座既有的零样本读出能力**打坏**（同批 MMLU 项 0.688 → 0.60–0.66、PAWS 0.787 → 0.56–0.71），降到 `5e-5` **恢复大部分**，作者称这是「**找到的最大单项配方改进**」，而**减 LoRA 目标模块与降 rank 的帮助都更小** ② **该复刻件的代码默认值与它自己的文档配方不一致**（argparse 默认仍是被证伪的那个高 lr）⇒ **采用他人配方时必须读代码默认值，不能只读文档**；我们的配方快照须同时记「文档值 + 实际生效值」两个数 ③ LoRA `r=16` / `α=32` / `dropout 0.05`，有效批 8、1 epoch、BF16 权重 + FP32 主权重、梯度检查点 ④ **训练耗时与峰值显存随制品提交**——不落这两个数的「能跑」不可复核 |
| **基座能力流失（训练风险，须对照落数）** | 微调**不是单调增益**：同一个基座在训练后可能在**别的读出面上变差**（上一行的实测就是实例——判定能力上去了，通用读出能力下来了）。故本版验收须**同时落两组数**：**目标能力**（判定一致率）与**保留能力**（基座既有零样本读出），两组**分列不合并**；若目标能力上升而保留能力显著下降 ⇒ 判为**配方未收敛**，先调配方再判训练成败。**为什么单列**：把两组数合成一个「综合分」会让「用基础能力换判定能力」这类**隐性代价**被平均掉——与第六章「判定质量与概率可信度分列报告」同族纪律 |
| **基座选型的第一性问题：目标硬件上有没有快核** | 单机可用性**由「目标硬件上有没有快核」决定，不由参数量决定**——同一件制品在同一台笔记本上做同一件事（五问 × 三选项 × 约 230 token 的 state），换用含线性注意力循环层的基座后**慢 3–7 倍**（4B：779 ms vs 174 ms；9B：约 2 s vs 约 300 ms），根因是该循环层在 Apple Silicon 上无 MPS 实现、框架回退到参考实现。⇒ **基座选型表须把「目标推理硬件上有无对应核」与参数量、许可证、词表规模并列**；本地档延迟读数**必须在目标硬件上实测**，不得由云卡读数外推 |
| **TrainChannel 提交** | 训练任务经既有 TrainChannel 标准接口提交（不写云厂商适配器——既有边界零改动），训练事件照常回流审计链 |
| **训练可复现** | 固定数据版本 / 评测器版本 / 随机种子 / 超参快照，训练产出自带可复现清单 |

- [ ] **保留能力对照落数**：训练前后各跑一次基座既有零样本读出，**目标能力与保留能力两组数分列报告**（禁合并成单一综合分）

### 风险与前置假设

> ⚠️ **训练量级与数据量的关系必须在动工前确认**。同类参照（开源判定模型基于 9B 基座做 LoRA，参考标签一致率从基座 66.36% 提升到 90.12%）提示：**判定能力对数据质量的敏感度高于对参数量的敏感度**。若 v1.6.0 采集的样本量不足，本版只做小规模验证训练（证明回路可用），**完整训练移交本版后续章与后续版本**，不硬凑。
>
> ⚠️ **本版不承诺准确率数字**。训练目标的科学性是本版交付物，效果数字属本版第二章（校准）与第六章（对比基线）的验收面。
>
> ⚠️ **「单机可完成」必须按内存档位说，不能笼统说「普通电脑就行」**。可训规模由**可用内存**决定，不由「是不是 Mac」决定：内存充裕的机型可覆盖到 9B 级 LoRA，内存紧张的机型只能覆盖小参数基座。验收落数时须**同时记机型 / 内存档位与可训参数量上限**——只报「在某台机器上跑通了」会让人误以为任何机型都行，这是**过度承诺**（本产品线不承诺模型性能，同样不承诺硬件门槛）。规模-内存的对照表随评测结果落册，作为客户自查「我这台能不能跑」的唯一依据。**同族的第二条口径：「单机」必须分清推理侧还是训练侧**——生态的单机读数在两侧量级差异极大（推理侧笔记本档已可直接服务，训练侧小档已跑通、大档仍在云卡），**把推理侧读数当训练侧依据，与只报机型不报规模是同一类过度承诺**。

## 二、校准实现（分桶温度拟合）


> **形态归属**：`[主干]`（判定·校准件）｜ **不可拔**（概率可信度是判定可用的前提）

### 交付

| 组件 | 能力 |
|------|------|
| **分桶温度拟合** | 按置信度分桶做温度缩放（temperature scaling）——单一全局温度对判定模型通常不够，判定置信度分布在各判据上差异大，分桶拟合可分别矫正不同置信区间的偏差。分桶粒度可配且落配置 |
| **原语分别校准** | `choice`（多类分布）/ `score`（有序分档）/ `noul`（伯努利）三类输出**分别校准**——有序分档的温度校准须保序（不得因校准破坏 RPS 优化出的序结构） |
| **校准集隔离** | 校准参数在**独立校准集**上拟合，与训练集分离（防校准参数过拟合训练分布）；集划分按轨迹/租户粒度（对齐 v1.6.0 泄漏防护） |
| **校准产物可分发** | 校准参数作为独立制品（与权重分离）——换基座或换权重时可单独重拟合，不捆绑 |
| **校准前后对照** | 同一评测器在训练后与校准后各测一次，产出三态对照（零样本基线 / 训练后 / 校准后），分桶可靠图与 ECE 并列展示 |

## 三、校准判据纪律落地（从「新纪律」到门禁）


> **形态归属**：`[主干]`（判定·判据纪律）｜ **不可拔**（未校准的置信度是误导性输出，纪律是防线）

### 交付

| 组件 | 能力 |
|------|------|
| **校准依据声明制** | 引擎内任何被消费的置信度 / 概率阈值，须携带**校准依据标注**（校准集版本 / ECE / 拟合时间）或显式标为 `uncalibrated`。**未标注来源的数字不得出现在决策路径上** |
| **门禁断言** | 新增门禁：决策路径上的阈值若标为 `uncalibrated` → **断言失败**（新增阈值走不通，除非先补校准依据）——把纪律变成机制，不靠自觉 |
| **三段门控门槛口径** | 明确定义「高自动 / 中复核 / 低转人工」三段的概率门槛与其**校准后**含义（门槛对应的是错误率区间，而非拍脑袋的 0.8/0.5/0.2）。**生态读数参照（阈值-精度换算的实证锚）**：开源兼容端点在 BoolQ 3,270 例的可恢复评测给出换算量级——90% 置信阈下放行 2,278 例、准确率 97.23%（均概率 95.55%）；99% 阈下仅放行 366 例、准确率 99.73%（第三方项目自报、本仓未复算，只作量级参照不作承诺）——**置信阈每收紧一档，放行量约收缩 6 倍而准确率升约 2.5 个百分点**，这个量级关系是三段门槛落数时的换算直觉：高自动段的覆盖率代价须与人工复核容量一起算，不能只看准确率 |
| **校准退化监测** | 校准参数随数据分布漂移会失效——监测校准后 ECE 的**时间漂移**，超阈只提示不阻断（对齐 v1.5.9 验证器老化检测的同族纪律：**只提示不阻断**） |
| **既有置信度普查（登记，不改造）** | 盘点引擎内全部既有置信度数字并登记其校准状态（多数为 `uncalibrated`）——本版只**登记与暴露**，实际收敛归 v1.9.0 |
| **统计量一致性** | 决策路径消费的统计量（归一化熵 / max-prob / margin）必须与 ECE 拟合所用统计量**一致**——不一致即等同未校准。*反例：Laya 的 choice/score 运行时用归一化熵（`common.py:201` `1 - H(p)/log k`）而 ECE 按 max-prob 算，其 README 教的 `conf >= 0.85` 门控在 choice 上消费的是**从未被校准过的量*** |
| **概率精度不得被通道截断** | 概率从模型输出到消费点的**每一跳都不得损失有效位数**：① 序列化与传输**不得对齐到固定小数位**——把两位小数当成精度上限，等于把校准的测量精度砍到 0.01 量级（真实值 0.004 与 0.000 在通道里同形）② 任何取整 / 截断须**显式标注**且在制品里可查（默认静默取整即为缺陷）。**为什么这条落在校准章**：校准的验收面是 ECE 与 Brier，两者都是**对概率数值本身**的度量——概率被通道压过，测出来的是**通道的精度**而不是模型的校准度。*生态实测：某商业判定件的 API 概率只保留两位小数，导致公开评测集里**真标签被压成 `0.00`**，该数据源的概率型指标因此不可与其它源比对（正确处置是**标注不可比并排除**，不是照算）*。**失败形态值得单记**：这类损伤**不报错、不告警**，只让所有概率指标静默劣化——与「静默失败」同族，唯一防线是**在通道契约里断言有效位数** |
| **校准集隔离可断言** | 校准拟合集与训练集交集必须为空，且**由脚本断言**；交集非空则 ECE 达阈**不算数**（阈值达标不等于校准成立——达标的分母可能是它自己训练过的样本）。*反例：Laya 温度在训练集子集上拟合（`all_items[::15][:400]`）* |
| **校准制品随行** | 校准参数（温度等）为**独立制品**，随权重一起发布并纳入哈希链；制品缺校准信息即 **fail-closed**（宁可拒绝服务，不得用未校准参数出数）。*反例：Laya 出厂 `rl_agent_config.json` 实测 `temperature: [1.0,1.0,1.0]`、`temperature_by_options: {}`——出厂零校准，而头版挂的是「拟合后 ECE 0.081」* |
| **对外数字可复现** | 对外披露的 ECE / 准确率必须能由「**已发布制品 + 公开脚本**」复现；不可复现的数字**不得对外**（数字可复现是披露的前置条件，不是事后补的脚注） |
| **数据集谱系声明** | 对外引用任何数据集之前，**谱系透明度三件套**必须在位：① **来源构成**——各部分来源与占比逐项列明（自采 / 三源采集 / 外部数据集，不得只报「总量」）② **行数对账**——各部分行数之和 == 总量，且**可脚本复算** ③ **污染声明**——已知同源 / 重复 / 与评测集的交集行数**主动声明**，含「各部分之间不独立」这类结论。三件套缺一即**不得对外引用该数据集**——「零污染」的口头承诺不作数，可复算的谱系记录才算证据。**为什么与校准同章**：数字可复现回答「这个数能不能重算出来」，谱系声明回答「这个数是从哪堆数据算出来的」——缺后者，前者复现的可能是被污染的口径。*正例：Nimble `data/manifest.json` 记录三个生成器谱系（900 + 1000 + 1000 = 2676 行）并主动声明「Sonnet 有 22 行起草用了同源 Luna 插图，releases are not independent」*。*反例：某商业判定件的头版精度来自**在评测基准训练集上微调**的 checkpoint，而其基座 zero-shot 低于多数类基线——谱系不透明使「这个数字属于哪一档」无法被判定*。*正例（对照方法论）：`arXiv:2609.23959` 的「**预注册 margin 非劣性检验** + **作者自曝测试集暴露**」应作谱系声明的正面范例——见 [v1.9.0 §五](../v1.9/v1.9.0.md)* |
| **判定制品四件套的联合版本锚点** | 一次判定的结果由**四件制品**共同决定：权重（含校准参数）+ 问句集 + 判据集 + 阈值 / 评测集。现状是**分头版本化**（权重与校准制品进哈希链、评测器与数据集版本固定），而**问句集与判据集随代码包走**——四件之间**没有联合锚点**，于是「这批判定用的是哪个问句集版本配哪个判据集版本」**不可从制品本身读出**。本版补联合锚点：单次判定记录里落四件版本号，**任一件变更即把旧锚点标记为不可比**，旧记录仍可回答「当时用的是哪四件」。**为什么归在校准章**：判据集改了而问句集未改、或阈值换了而判据集未动，都会让同一条问句的概率读数**不可比**——而「可比」正是校准的全部意义；没有联合锚点，历史记录无法自证可比性，跨版本 ECE 对照会退化成跨口径比数（与既有「能力基线版本线」同族口径，只是粒度落到**单次判定**） |

### 风险与前置假设

> ⚠️ **v1.7 校准完成是本项目的一条分界线**：在此之前，决策模型的输出**不得用于任何分流决策**。这条不是流程礼节，而是技术事实——未校准概率被用于分流，等价于用一个随机的门槛去切请求，切错的代价会沿下游放大。

## 四、弃权语义独立化与校准上线前置门


> **形态归属**：`[主干]`（判定·弃权语义）｜ **不可拔**（弃权是未校准条件下的唯一安全出口——拔掉则系统被迫在没把握时也给答案）

校准解决「概率可不可信」，本版同时要回答它的对偶问题：**概率不可信时怎么办**。答案是弃权——但弃权必须先是**一等输出**才可能被真正依赖；把「判不了」硬塞进某个选项或压成 0.5 概率，下游就无法区分「真的势均力敌」与「模型没把握」。前者是有效信息，后者是必须转人工的信号。

### 交付

| 组件 | 能力 |
|------|------|
| **弃权是一等输出** | 判定结果新增**弃权**态，与 `choice` / `score` / `noul` **并列**（不是三者的取值之一）——模型可以回答「我判不了」，且这个回答有独立语义与独立留痕 |
| **0.5 ≠ 中等** | `noul` 的概率是**真值概率**而非「把握程度」：0.5 表示成立与不成立**势均力敌**，**不表示「中等可信」**。类型层与文档同时把这个语义写死——把概率当置信度消费是判定模型最容易被误用的地方 |
| **门槛不是 0.5，且按原语分档** | 分流门槛**不得默认取 0.5**——「看起来对称」不构成理由：**模型是校准的，不是对称的**。门槛须按原语分别设定，因为三种原语的**置信剖面本就不同**：`noul` 在事实性是非题上判对时通常很自信（门槛偏高即可）；`choice` 在相似选项间重排时**普遍不确定**（门槛须明显低于 `noul`，否则几乎全体落入复核）；`score` 的安全类评分**各档概率彼此接近**，须**看整条分布**而不只看置信度。**起步锚点取自生产分布的实际峰位**，不是取自直觉中点——生态实测的反面教材：同一份语料上门槛设 0.6 会导致样本**全量**被标记复核（门控形同废掉），降到 0.4 才使该标记的被标记、噪音下降。**门槛错位的代价是门控静默失效**，而不是报错。**「confidence 值」的语义陷阱（第三方代码检视实证，2026-09-25 登记）**：某开源判定件代码里名为 `confidence` 的数值，实为**选项概率的集中度**（分布越尖值越高）——**坚定不等于正确**，集中度高也可以是坚定地错；真正的概率校准须由「批量预测中概率与实际结果的吻合度」验证（本章校准定义），受业务与样本分布影响。工程含义：消费 `confidence` 字段的门槛设计不得把「分布尖」当「可信」——两者在本章体系里是**两个独立测量**（集中度是分布形态，校准是频率吻合）；外部接口若输出名为 confidence 的单值，接入前先验明其语义（与 v1.9.0 §二「语义正名」消费侧互为表里）。**生态流传的 50/85 两档阈值先例**（<50% 转人工、>85% 自动执行的置信度门控路由）可作门槛起步的**形态参照**——但具体数值仍按「生产分布峰位」实测取，不抄数值 |
| **弃权三源** | ① **置信不足**（概率落在弃权带内）② **域外**（输入不在判据域内——OOD）③ **判据缺失**（该问题当前无对应判据）。三源**分别留痕**，因为处置不同：① 可调阈、② 要人接、③ 要补判据 |
| **弃权率可观测** | 弃权率按判据 / 域 / 时间三维可查。**弃权率是校准质量的先行指标**——弃权率异常低（几乎不弃权）通常意味着阈值过松或概率未校准，这比 ECE 更早暴露问题 |
| **门控健康度红旗群** | 单看一个比率不够——生态实证给出「门控已退化为形式」的**四联红旗**：① ASK 率趋近于零 ② **获批率恒为 100%**（同一审批人零驳回）③ **审批时延落在提示后 1–2 秒**（反射式点击而非真审）④ **人均审批量异常高**。**分开看每一项都有良性解释，合起来看没有**——四者同时出现即门控失效。这是「静默失效」在人工环节的可判定形态 |
| **弃权之外的稳定化重读** | 不确定时除「承认判不了」外还有第三条路：**逐问句看熵，超阈则带新噪声重读至上限并取平均**——用采样降方差，而非直接放弃作答。**与弃权的分工**：熵高且**在有限重读内不收敛** ⇒ 弃权；熵高但重读后收敛 ⇒ 给出稳定后的概率。**默认关闭**——重读增加延迟且改变概率语义（平均后的概率不再等价于单次前向的读数），开启须显式配置，且**校准集须按同口径重测**（否则 ECE 对应的是另一套输出，等于用一个口径的校准结论去担保另一个口径的输出）。触发粒度是**逐问句**而非全局阈值 |
| **校准上线前置门** | 本版校准未达阈（§二 ECE 硬线）时，**弃权路径必须默认开启且不可关闭**；达阈后才允许按域配置弃权带。这把「ECE 未达阈 ⇒ 本版不通过」升级为「**未达阈 ⇒ 系统行为受限**」——未校准的概率不得用于分流，而弃权是唯一不依赖概率可信度的安全出口 |
| **扩张不得放宽弃权** | 新增判据域时**弃权带默认最宽**（宁可多转人工），域内校准达阈后才收窄——判据面扩张不得以放宽弃权为代价 |

## 五、三原语概率面完整化


> **形态归属**：`[主干]`（判定·输出形态）｜ **不可拔**（输出契约）

### 交付

| 组件 | 能力 |
|------|------|
| **`Choice` 完整面** | 选中项 + **全候选项归一分布** + 分布熵（低熵=判定明确，高熵=选项间接近→可作为「需复核」信号） |
| **`Score` 完整面** | 分值 + **可信区间**（校准后的分位区间）+ 档位序信息（保序由本版第二章保证） |
| **`Noul` 完整面** | 真值概率 + **四态映射**：`成立` / `倾向成立` / `倾向不成立` / `不成立`——四态由校准后概率分段得出（分段口径 = 本版第二章的三段门控门槛） |
| **建议动作** | 判定结果附**建议动作**（放行 / 复核 / 转人工 / 阻断）——但建议动作**不具执法力**：执行权仍在既有确定性规则与审计层手里，判定层只提供输入 |
| **不扩大证据面** | 判定输入的 `state` **只含已获证据**（既有审计规则已采集的那些），判定层不新增采集动作、不访问新数据源——**纪律：只提高已获证据的利用率** |
| **结构化可审计** | 输出为结构化类型化记录（choice + 概率 + 置信度 + 四态 + 建议），直接适配既有 decision-log 留痕（类型化输出天然可审计，无需额外解析） |

### 风险与前置假设

> ⚠️ **阶段二可能不达阈，这是排期内的正常分支**。若本版第六章对照显示判定质量或概率可信度未达阈，**阶段三（v1.8.x 接线与分发）不启动**——先把阶段一/二的判据与数据修好。**接线一个不可信的判定模型，比不接线更危险**（它会静默影响分流决策）。
>
> ⚠️ **判定底座永不进信任地基**。其输出可被 `state` 内容操纵（已知失灵面），故架构顺序固定为「**确定性规则在前，语义判定在后**」——既有 24–25 条审计规则的判定面在本阶段**零改动**。
