## 定位

> 📐 **判定底座 · 校准**——阶段二第二版，回答「**概率可不可信**」。校准的定义可以一句话说死：**让模型报出的概率值匹配真实发生的频率**——被标为 0.2 的结果，真实发生率应约等于 20%；标为 1 则代表几乎必然发生。**没有校准的概率不是「弱一点的概率」，而是没有意义的数字**——它会让下游的三段门控（高自动 / 中复核 / 低转人工）门槛全部虚设。**本版是可用性硬门槛**：v1.7.0 训出的模型在本版通过之前，其输出不得用于任何分流决策。

## 一、校准实现（分桶温度拟合）

> **形态归属**：`[主干]`（判定·校准件）｜ **不可拔**（概率可信度是判定可用的前提）

### 交付

| 组件 | 能力 |
|------|------|
| **分桶温度拟合** | 按置信度分桶做温度缩放（temperature scaling）——单一全局温度对判定模型通常不够，判定置信度分布在各判据上差异大，分桶拟合可分别矫正不同置信区间的偏差。分桶粒度可配且落配置 |
| **原语分别校准** | `choice`（多类分布）/ `score`（有序分档）/ `noul`（伯努利）三类输出**分别校准**——有序分档的温度校准须保序（不得因校准破坏 RPS 优化出的序结构） |
| **校准集隔离** | 校准参数在**独立校准集**上拟合，与训练集分离（防校准参数过拟合训练分布）；集划分按轨迹/租户粒度（对齐 v1.6.1 泄漏防护） |
| **校准产物可分发** | 校准参数作为独立制品（与权重分离）——换基座或换权重时可单独重拟合，不捆绑 |
| **校准前后对照** | 同一评测器在训练后与校准后各测一次，产出三态对照（零样本基线 / 训练后 / 校准后），分桶可靠图与 ECE 并列展示 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/train/src/rlcd/calibration.ts` | 新建 | 分桶温度拟合 + 原语分别处理 + 保序约束 |
| `engine/orchestrator/src/router/calibration-report.ts` | 修改 | 三态对照（基线 / 训练后 / 校准后） |
| `engine/train/src/__tests__/calibration.test.ts` | 新建 | 拟合正确性 / 保序 / 校准集隔离单测 |

- [ ] 三类原语分别校准，`score` 档保序（校准不破坏序结构，有单测）

## 二、校准判据纪律落地（从「新纪律」到门禁）

> **形态归属**：`[主干]`（判定·判据纪律）｜ **不可拔**（未校准的置信度是误导性输出，纪律是防线）

### 交付

| 组件 | 能力 |
|------|------|
| **校准依据声明制** | 引擎内任何被消费的置信度 / 概率阈值，须携带**校准依据标注**（校准集版本 / ECE / 拟合时间）或显式标为 `uncalibrated`。**未标注来源的数字不得出现在决策路径上** |
| **门禁断言** | 新增门禁：决策路径上的阈值若标为 `uncalibrated` → **断言失败**（新增阈值走不通，除非先补校准依据）——把纪律变成机制，不靠自觉 |
| **三段门控门槛口径** | 明确定义「高自动 / 中复核 / 低转人工」三段的概率门槛与其**校准后**含义（门槛对应的是错误率区间，而非拍脑袋的 0.8/0.5/0.2） |
| **校准退化监测** | 校准参数随数据分布漂移会失效——监测校准后 ECE 的**时间漂移**，超阈只提示不阻断（对齐 v1.5.5 验证器老化检测的同族纪律：**只提示不阻断**） |
| **既有置信度普查（登记，不改造）** | 盘点引擎内全部既有置信度数字并登记其校准状态（多数为 `uncalibrated`）——本版只**登记与暴露**，实际收敛归 v1.9.0 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/core/src/calibration-registry.ts` | 新建 | 置信度登记表 + 校准依据标注 |
| `tools/check/check-calibration-claims.sh` | 新建 | 门禁：决策路径上的未校准阈值 → 断言失败 |
| `engine/core/src/__tests__/calibration-registry.test.ts` | 新建 | 登记 / 门禁 / 漂移监测单测 |

### 风险与前置假设

> ⚠️ **v1.7 校准完成是本项目的一条分界线**：在此之前，决策模型的输出**不得用于任何分流决策**。这条不是流程礼节，而是技术事实——未校准概率被用于分流，等价于用一个随机的门槛去切请求，切错的代价会沿下游放大。
>
> ⚠️ **校准不改善判定质量，只改善概率可信度**。若 v1.7.0 训练后判定准确率仍然不足，校准救不回来——本版会如实记录「判定质量」与「概率可信度」两项数字，**不把校准带来的 ECE 改善包装成判定能力提升**。
