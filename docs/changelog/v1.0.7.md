## 背景

v1.0.5 审查发现：orchestrate-compare.ts 第 6 行 TODO 写了 `CONSECUTIVE_WINS_REQUIRED = 2`，但代码只做单次对比。v1.0.6 已把 A/B 运行器从 mock 升级为模型 API 直跑（方案 B），自迭代闭环打通。但方案 B 缺工具调用和多轮推理——Skill 的某些约束（如"审计 Agent 提交"）需要工具链路才能验证。

v1.0.7 做三件事：A/B 自动切换 + A/B 运行器升级为 DeepAgents（方案 C）+ ao 完全退役。

## 交付内容（3 件事）

### 1. A/B 自动切换

orchestrate-compare.ts 实现 TODO 里写的连续计数器：

```typescript
// v1.0.7 实现
const CONSECUTIVE_WINS_REQUIRED = 2;

// 每次 compare 后：
// 1. 如果 Candidate 胜出 → consecutiveWins++
// 2. 如果 Current 胜出或 Tie → consecutiveWins = 0
// 3. consecutiveWins >= CONSECUTIVE_WINS_REQUIRED → 自动 promote
// 4. promote 后 consecutiveWins 重置
```

**实现要点**：
- 计数器持久化到 `.sofagent/orchestrator/ab-state.json`
- promote 前写一条 WARN 日志到 daemon-notice.md（可回滚）
- `--dry-run` 模式只报告"会 promote"但不执行
- promote 操作走原子写入（v1.0.5 的 atomicWriteSync）

### 2. A/B 运行器升级：DeepAgents 完整 Agent（方案 C）

v1.0.6 的方案 B（模型 API 直跑）验证了闭环可行，但缺少工具调用——Skill 中"审计 Agent 提交""跑 git diff""调 sofagent-audit"这类约束无法验证。v1.0.7 升级为 DeepAgents，让 candidate 和 current 在真实 Agent 环境里对比。

**改动文件**：`ab-runner.ts`

```typescript
// v1.0.6（方案 B）：模型 API 直跑
async function runMinimalAgent(testCase, skillPath) {
  const skillContent = readFileSync(skillPath, 'utf-8');
  return await callModel(skillContent, testCase.input);
}

// v1.0.7（方案 C）：DeepAgents 完整 Agent
async function runDeepAgent(testCase, skillPath) {
  const { createDeepAgent } = await import('deepagents');
  const agent = createDeepAgent({
    skillFile: skillPath,
    tools: [...testCase.allowedTools],  // 测试用例声明的工具集
  });
  const result = await agent.run(testCase.input, { maxSteps: 10 });
  return parseResult(result);
}
```

**方案 B → C 的渐进关系**：

| 维度 | 方案 B（v1.0.6） | 方案 C（v1.0.7） |
|------|:--:|:--:|
| 运行方式 | 模型 API 单次调用 | DeepAgents 多步 Agent loop |
| 工具调用 | ❌ 纯 prompt | ✅ 可调 git / audit / shell |
| 多轮推理 | ❌ 单轮 | ✅ maxSteps=10 |
| 验证范围 | prompt 质量 | prompt + 工具链路 |
| 依赖 | 仅 API key | deepagents 正式依赖 |
| 超时 | 60s/次 | 5min/次（多步更慢） |
| 成本 | 低 | 中（多步消耗更多 token） |

**向后兼容**：`runMinimalAgent` 保留为 fallback——deepagents 未安装或超时时降级到方案 B。

**TestCase 扩展**：
```yaml
- id: fde-audit-verify-01
  input: "检查最近的 Agent 提交是否合规"
  allowedTools: ["git", "sofagent-audit"]  # 方案 C 才生效
  expected:
    deliverable: "审计报告"
    key_checks: ["A2_secret", "A3_boundary", "A15_constraint"]
```

### 3. ao 完全退役

v1.0.6 把 compose 迁到 DeepAgents 后，ao 只剩 fallback。v1.0.7 正式移除：

| 动作 | 说明 |
|------|------|
| 移除 `agency-orchestrator` 依赖 | package.json 删除 optionalDependencies（deepagents 提升为 dependencies） |
| 移除 `execFileSync('ao', ...)` | orchestrate-compare.ts 中所有 ao CLI 调用清除 |
| 移除 `install.sh --no-ao` 选项 | 安装脚本不再检查 ao |
| SECURITY.md 更新 | 删除"第三方依赖供应链"中的 ao 段落 |
| install.sh 更新 | 不再 `npm install agency-orchestrator` |

**deepagents 提升为正式依赖**：从 `optionalDependencies` 移到 `dependencies`。用户 `npm install` 时默认安装。
