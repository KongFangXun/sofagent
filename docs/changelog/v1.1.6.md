# v1.1.6 开发日志 — LLM Wiki 3 层分层 + conflict-check

> 状态：规划中 · 孔放勋 · 2026-07-15
> 前置依赖：v1.1.5（MCP knowledge resource 已就绪）

## 背景

v1.1.5 MCP resource 让知识可以结构化查询了，但 knowledge/ 的健康度是黑的——有没有矛盾条目？有没有死链？有没有孤儿页面？v1.1.6 把 LLM Wiki 的 3 层知识范式（raw → Wiki → spec）映射到 sofagent 的 Ledger-Views-Policy，并加一个 daemon 常驻 conflict-check 脚本。

## 交付一：LLM Wiki 3 层显式映射（P0）

LLM Wiki 的 3 层（raw materials → Wiki entries → spec norms）与 sofagent 三层治理同构：

| LLM Wiki 层 | sofagent 对应 |
|------|------|
| raw materials | Ledger：task/logs（think.md / 审计历史） |
| Wiki entries | Views：knowledge/（entities / concepts / comparisons） |
| spec norms | Policy：fde.md（业务四问 / 约束） |

落地为一份 `docs/` 下的三层映射文档。

## 交付二：conflict-check 脚本（P1）

daemon 常驻 conflict-check：周期性检测 knowledge/ 的矛盾 / 孤儿 / 死链，输出报告。只读检测，不修改内容（fail-closed）。

## LUI 感知

用户通过 Agent 对话感知：「知识库有病了，Agent 主动告诉我——哪几个 entity 矛盾、哪几个链接死了、哪几个页面没人管。」

## 发布检查清单
