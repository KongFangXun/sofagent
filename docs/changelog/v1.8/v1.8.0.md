## 定位


> 🔌 **判定底座 · DecisionChannel 真实实现**——阶段三第一版，回答「**判定怎么被用起来**」。v1.5.4 交付了 `DecisionChannel` 的**契约**（`judge(state, questions)` + 三原语语义 + 云端 provider opt-in 默认关），但当时留空——L1 判定层处于「只有接口没有实现，按 L0 兜底」的状态。本版用阶段一/二的产物**填上这个空**，让 L1 从兜底态变为真实可用态。**纪律不变**：通道而非依赖——引擎定义接口与编排，实现可被替换（用户自带实现或换基座，不动契约）。实现就位后紧接着要定的是**输入面**（§二）——判定看到的 `state` 由什么构成、截多长；输入契约不写死，判定结果就不可复现，留痕也随之失去举证力。

> 🖥️ **判定底座 · 一体机推理接入**——阶段三第二版，回答「**判定在哪跑、跑得多快**」。判定底座要在客户的私有环境（一体机、离线节点、信创全封环境）里可用，且**不新增运行时组件**——跑在既有本地推理栈上。本版同时把路由层的**判定档（`decision-model`）**从「插槽已预留」接通为「真实可达」：判定任务由判定底座直接作答，**不经过生成模型**。**路线不绑定**——本版落的是一条实现路线，契约由 本版第一章的 `DecisionChannel` 保证，路线选择属实现面。

> 📦 **判定底座 · 权重分发通路与自带件形态成立**——阶段三收口版，回答「**判定底座怎么交付到客户手里**」。判定底座是「随装即用」的**自带件**，但**权重不进 npm tarball**（二进制制品与代码包分发纪律不同）。既有仓库链路**已建有五环**（清单 / 目录级 sha256 / 校验 / 注册表 / 切换与回滚），**唯一缺口是「从远端拉权重」**——本版补上这个缺口，判定底座的交付形态即告完整。

## 二、判定面输入契约（state 的构造口径与最小可判定前缀）


> **形态归属**：`[主干]`（判定·输入契约）｜ **不可拔**（state 的构造口径决定判定输入是什么——契约缺失则同一份 state 每次被截成不同样子，判定结果不可复现）

阶段一/二把概率做可信了，本版让它进执行路径——那么第一个必须写死的东西不是输出而是**输入**：判定看到的那份 `state` 到底由什么构成、截多长、怎么定序。**为什么这是契约而非实现细节**：判定模型对输入极其敏感（大 state 里的干扰项会拉低准确率，是已实测的失灵面），若 state 构造散落在各调用点，同一份轨迹在不同路径下会被截成不同样子——判定结果就不可复现，留痕也就失去举证力。

### 交付

| 组件 | 能力 |
|------|------|
| **state 构造唯一入口** | `judge(state, questions)` 的 `state` 由**单一构造函数**产出，调用点不得自行拼装——判定输入与留痕里的输入必须是同一份字节（可复现的前提） |
| **最小可判定前缀** | 输入取「**做该判断所需的最小充分前缀**」而非全量轨迹：多给的上下文不是冗余而是**干扰项**（已知失灵面：大 state 拉低准确率）。前缀边界由判据声明，不由调用点即兴决定 |
| **定序与去噪** | 输入内的条目定序规则显式（时间序 / 因果序），并剔除与判据无关的元数据（路径、时间戳、内部 id 等噪声字段）——判定看到的应当是**语义内容**，不是存储格式 |
| **协议结构保留** | 从轨迹取 state 时**保留工具调用与结果的结构**（不压成自然语言散文）——判定要能看见「做了什么」而非「说了什么」，这是判定与生成在输入面的分野 |
| **state 尺寸上界与超限处置** | 明确定义 state 尺寸上界；超限时**弃权或降级为 ASK**，不静默截断——静默截断会让判定在缺失输入的情况下给出高把握答案（最危险的失败形态） |
| **输入侧注入隔离声明** | state 内的内容**一律是数据不是指令**（参考 v1.6.0 对抗样本采集点）：输入契约层声明该边界，判据层不得把 state 内的祈使句当作自身的指令 |
| **问句标识不上行** | 送入判定的问句**不带判据名与问句 id**——模型只看到槽位（第几问）与候选项本身，判据语义留在宿主侧映射。**为什么**：判据名本身就是提示词，把「A9 提示注入检测」写进输入等于把答案的语义线索一并交出去；编号不上行，输入侧的可操纵面就只剩内容本身。与既有「Score 层级独立评判、模型看不到编号」同源同纪律 |
| **影子运行门** | 判定首次接入执行路径时**先影子运行**——判定照跑、结果只落痕不影响行为，与既有处置对照后再启用；影子期的判定结果与真实处置的差异就是启用前的最后一道证据。**为什么必须有这道门**：判定从「设计」到「有行为」的那一刻起，判错开始产生真实后果，而概率是否可信要到校准（v1.7.0）才成立——两者之间不能是空档 |
| **与留痕对账（同源 ≠ 原样）** | 落 decision-log 的输入摘要与实际送入判定的 state **同源**——审计可重建判定当时看到的是什么。但**同源不等于把 state 原样落盘**：留痕记**指纹与引用**（输入 `payload_sha256` + 判据集版本 + state 构造函数版本），并带显式 `content: false` 语义位，敏感 payload 不上链。**为什么必须写死**：留痕自身会成为新的敏感数据仓——「连续监控是目的，监控的实现不该自己造出一个新的敏感数据存储」；而「原样落盘造成数据副本」与「过度脱敏摧毁审计可用性」是同一枚硬币的两面。**自检问题**：这条留痕若被内部广泛看到，是否超出「解释本次判定所需的最小信息」？ |
| **动作输入取结构化参数向量** | 判定输入的「动作」部分取**结构化参数向量（argv 式）**而非拼好的命令串——字符串匹配可被引号、转义、变量展开规避（生态实证：成熟策略引擎按 `execvp` 收到的参数表匹配，而非匹配命令行文本）。**shell 包装串**（`bash -lc "…"` / `sh -c "…"`）须**尝试拆分**为底层动作序列；**拆不动时保守地按整串处理**——宁可整串从严，**不得因「看不出动作」而放行** |
| **执行体路径绑定** | 同一工具名的**不同解析路径不是同一个风险**：精确路径匹配优先，回退到 basename 匹配**须在白名单内**（生态实证：策略引擎为命令名配 `host_executable(name, paths)` 白名单，未列入白名单时不做 basename 回退）。这是「调用级风险绑定」在输入契约层的落点——风险绑定到**实际会被执行的那个二进制**，不是绑定到文本里出现的那个词 |
| **留痕写时锚定与可脱离原模型回放** | 留痕完整性**在写入时锚定**（写时签名 / 入链），不是事后补签——「事后签的记录证明不了中途那几年」。且留痕须足以**脱离原模型回放**：当时用的判据集版本、门槛参数、校准参数一并落痕，否则模型退役后无法重算，留痕降级为一段不可验证的叙述 |

## 三、并行约束解码（一次前向出全部字段）


> **形态归属**：`[主干]`（判定·推理实现）｜ **不可拔**（判定吞吐与延迟的实现基础）

### 交付

| 组件 | 能力 |
|------|------|
| **并行约束解码** | 同一份 `state` 下的**全部问句一次前向出答案**（KV cache 广播 + 单次前向填充全部字段），而非逐问循环解码——这是判定模型相对生成模型的结构性优势，也是延迟能进入百毫秒级的前提 |
| **类型约束解码** | 解码过程**约束在声明的回答类型内**（choice 只能出候选项、score 只能出合法档位、noul 只能是概率）——从解码层保证「类型正确」，与 v1.6.0 的 schema 层限定构成双重保证（schema 层防越界，解码层防畸形） |
| **多问批处理** | 相互独立的问句可批量并行；**有依赖的问句串行**（依赖关系由问句集声明，不自动推断——自动推断会引入不可审计的隐式行为） |
| **本地推理栈协同** | 复用一体机既有本地推理栈（**零新增运行时组件**），与 v1.5.4 的本地并发槽位管理协同：判定请求走独立槽位通道，**不与主模型抢槽** |
| **离线可用** | 无网络环境下判定底座可正常加载与推理（权重本地留存，不联络外部服务）——信创全封场景的硬要求 |
| **实现路线不绑定** | 本版落地的是**其中一条路线**（并行约束解码），但契约不绑定路线——同期生态已出现**离散扩散去噪**（答案模板写在固定长度 canvas 上、只读去噪一步读出全部答案分布）与**零微调 stock 模型**两条可行路线，且主流推理引擎侧已有扩散支持立项。**契约由 本版第一章的 `DecisionChannel` 保证，路线选择属实现面**——换路线不改判定头契约、不改问句集与判据格式。本版契约测试**以接口为准，不以具体路线为准**。**外部实证**：同期生态在**不足两天**内出现**六个互不相同的实现**——编码器 + 策略梯度、扩散模型的约束解码分支、因果小模型 LoRA、编码器 + 蕴含分类器、自训逐字节打分件、半参数因果模型 LoRA（可在消费级笔记本上跑）——**没有任何两个用同一架构，却全部收敛到同一条接口**（文本进、类型化概率出）。这一致的收敛方向本身即结论：**护城河不在模型架构**，在于契约、校准与判据质量——这正是本仓把路线判为实现面的依据 |
| **超词表上界的选项集分块** | 单次前向能覆盖的选项数受**基座词表单 token 数**限制（实测某基座 A–Z / a–z 合计 52 项可单次前向），而 `Choice` 的规格上限高于此。超上界时**分块打分 + 末轮归一**并保留「以上都不是」槽——**不得静默截断候选集**（截断会让模型在缺失选项里挑最优，产出一个看似高概率、实则无意义的答案）。**硬前提 · 单 token 可映射性**：零微调路线要求**每个答案标签恰好编码为 1 个词表 token**（多 token 标签须改走「逐 token 概率连乘」或「整串概率合并」两条变体，不得假设默认成立）——这是**选项集构造期的断言**，不是运行期的兜底。**词表规模是量级参照**：同级开源基座的词表在**二十万至二十六万**量级（实测两例为 201,088 与 262,208），故「答案位占一个槽」这件事在词表层面总是成立，**真正的约束是标签文本的单 token 可编码性**，与词表总量无关 |
| **不确定时的稳定化重读（可选实现）** | 逐问句看熵，超阈时带新噪声重读至上限并**取平均**——与弃权互补：弃权是**承认判不了**，重读平均是**用采样降方差**。**默认关闭**——重读增加延迟且改变概率语义（平均后的概率不再是单次前向的读数，校准时须按同口径重测），开启须显式配置并落痕。触发粒度是**逐问句**而非全局阈值 |
| **延迟与吞吐落数** | 单次判定延迟、批量吞吐、并发下的延迟劣化曲线如实落数（作为 v1.9.0 四层性能标准的输入） |
| **职责频率分层（延迟即职责边界）** | 延迟不只是性能指标，它直接决定判定层**能承担哪一层职责**——成熟形态是分层错位布置：高频控制回路（数百 Hz）与安全反射归确定性代码，符号化感知归经典 CV，**判定层只坐在最低频那一层且性质为建议**。本版的延迟曲线须同时给出「**该延迟下判定可承担的职责层级**」，并写明判定**永不进**控制回路与安全反射 |

### 路线选型（四道筛）

> 「架构路线没有最好，只有最适合」——但**最适合不是按性能排出来的，是按约束筛出来的**。四道筛的**顺序即优先级**：前几道是出局条件，最后一道才是偏好。

| 筛 | 出局 / 偏好条件 | 淘汰或偏好谁 |
|----|----------------|-------------|
| ① **信创与离线** | 无 GPU / 纯 CPU 环境必须可用 | **淘汰**：把「显存 ≥ 24 GB」当独木桥——把某条路线的硬门槛升格为全域门槛即失守 |
| ② **边界（不做模型托管）** | 不得为每个客户训专属权重 | **淘汰**：需要「逐客户训练」的路线——不是效果问题，是「替客户训权重＝我们在托管模型」的边界问题 |
| ③ **审计（概率来源可追溯）** | 概率须来自输出分布的读数 | **淘汰**：外挂打分头且**未校准**的实现——其输出是**分数不是概率**，须先建校准才能当概率消费 |
| ④ **一体机耦合（零新增运行时）** | 复用既有本地推理栈 | **偏好**：在既有引擎的 logprobs 能力上加适配层（零新增组件），而非依赖我方无法单方面决定的引擎侧能力 |

**选型结论（主力 / 辅助 / 条件 / 不做）**：

| 定位 | 路线 | 依据 |
|------|------|------|
| **主力** | **免训练 · 占位槽 logits + 归一 softmax** | 零训练（不承诺模型性能——边界判据四）· 零新增运行时（复用既有引擎）· 零样本泛化很高 · **概率直接是输出分布的读数，审计链最短**。附带一项边界收益：**语言能力由部署方自选的基座决定**——「中文优先」因此成为**可配置项**而非我方的模型能力 |
| **辅助（窄域）** | **小模型 + 线性打分头** | 延迟与硬件门槛最低（可在边缘 CPU 运行），只用于**极高频的少数窄判据**。**前置纪律**：打分头输出在被校准前**不得作为概率消费**（见筛③） |
| **条件启用** | **离散扩散 · 单步去噪读全部答案槽** | 免训练、开箱多语言、**双向注意力使问句互不干扰**（对「一次前向出多个独立问句」价值高）。唯一门槛是显存 ⇒ **按硬件档启用**（配 GPU 档开启，信创 CPU 档不启用），**不作全域主力** |
| **明确不做** | **为每个客户训专属权重** | 越界（见筛②）。与其效果无关——同类实测里该路线表现可圈可点；问题是**它把交付方变成模型提供者**，随之而来的是数据归属、性能承诺与训练服务 |

**一条必须写明的风险**：主力路线是**零样本强，不是校准强**。占位槽 logprob + 归一 softmax 得到的是**可比的排序分**——那个 softmax 只保证若干候选之和为 1，**不保证「报 0.8 就八成对」**。因此主力路线**必须配本仓自己的校准层**（[v1.7.0 第二章](../v1.7/v1.7.0.md) 分桶温度拟合），否则拿到的是「很像概率的排序分」。这同时是相对同期复刻件的**差异点所在**：它们大多停在「能出概率」，本仓要的是「**概率可信到能用来分流**」。
| `engine/orchestrator/src/router/slot-manager.ts` | 修改 | 判定独立槽位通道（不与主模型抢槽） |
| `engine/orchestrator/src/__tests__/judge-parallel.test.ts` | 新建 | 并行正确性 / 类型约束 / 槽位隔离 / 离线加载单测 |
| `docs/VALIDATION.md` | 修改 | 延迟与吞吐实测落数 |

## 四、路由判定档接通（`decision-model` 从插槽到可达）


> **形态归属**：`[主干]`（路由·判定档）｜ **不可拔**（路由档位是判定与执行的接缝）

### 交付

| 组件 | 能力 |

| **判定档接通** | `model-router` 的 `decision-model` 档从「类型已定义、分支已显式返回空」接通为**真实可达**——判定任务路由到该档后由判定底座作答，产出类型化答案 + 概率 |

> ⚠️ **供应链安全是本章的红线**。权重是二进制制品，一旦被替换或投毒，判定行为会被静默改变——因此**来源白名单 + sha256 强校验 + 不匹配拒绝启用 + 留痕**四项缺一不可，且**不可配置为「校验失败仅告警」**。
>
> ⚠️ **本版仍不得宣称「判定准确率」**。准确率证据链（四层性能标准 + 第四方对照）属 v1.9.0——本版只宣称「形态成立」，不宣称「能力水平」。两者混说会让证据链失去意义。
