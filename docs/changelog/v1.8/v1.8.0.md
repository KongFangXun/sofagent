## 定位


> 🔌 **判定底座 · DecisionChannel 真实实现**——阶段三第一版，回答「**判定怎么被用起来**」。v1.5.4 交付了 `DecisionChannel` 的**契约**（`judge(state, questions)` + 三原语语义 + 云端 provider opt-in 默认关），但当时留空——L1 判定层处于「只有接口没有实现，按 L0 兜底」的状态。本版用阶段一/二的产物**填上这个空**，让 L1 从兜底态变为真实可用态。**纪律不变**：通道而非依赖——引擎定义接口与编排，实现可被替换（用户自带实现或换基座，不动契约）。实现就位后紧接着要定的是**输入面**（§二）——判定看到的 `state` 由什么构成、截多长；输入契约不写死，判定结果就不可复现，留痕也随之失去举证力。

> 🖥️ **判定底座 · 一体机推理接入**——阶段三第二版，回答「**判定在哪跑、跑得多快**」。判定底座要在客户的私有环境（一体机、离线节点、信创全封环境）里可用，且**不新增运行时组件**——跑在既有本地推理栈上。本版同时把路由层的**判定档（`decision-model`）**从「插槽已预留」接通为「真实可达」：判定任务由判定底座直接作答，**不经过生成模型**。**路线不绑定**——本版落的是一条实现路线，契约由本版 §一 的 `DecisionChannel` 保证，路线选择属实现面。

> 📦 **判定底座 · 权重分发通路与自带件形态成立**——阶段三收口版，回答「**判定底座怎么交付到客户手里**」。判定底座是「随装即用」的**自带件**，但**权重不进 npm tarball**（二进制制品与代码包分发纪律不同）。既有仓库链路**已建有五环**（清单 / 目录级 sha256 / 校验 / 注册表 / 切换与回滚），**主缺口是「从远端拉权重」**（另有四项交付面缺口同章补齐：USB **A** 安装器档 / USB **B** 便携运行时档 / 可复现重放 / systemone 门面）——本版补上这个缺口，判定底座的交付形态即告完整。

## 二、判定面输入契约（state 的构造口径与最小可判定前缀）
> **machineVerdict**：`EXEMPT(covered-by: S494, S497)`（P1-3：EXEMPT=已承接）。
> **承载场景**：S494（三档开关 off 归一/shadow 不改/active 影子门）+ S497（判定头契约两路线形状逐字段一致）——state 构造口径由判定头契约断言间接承载（typed 形状=state 口径的可观测投影）。


> **形态归属**：`[主干]`（判定·输入契约）｜ **不可拔**（state 的构造口径决定判定输入是什么——契约缺失则同一份 state 每次被截成不同样子，判定结果不可复现）

阶段一/二把概率做可信了，本版让它进执行路径——那么第一个必须写死的东西不是输出而是**输入**：判定看到的那份 `state` 到底由什么构成、截多长、怎么定序。**为什么这是契约而非实现细节**：判定模型对输入极其敏感（大 state 里的干扰项会拉低准确率，是已实测的失灵面），若 state 构造散落在各调用点，同一份轨迹在不同路径下会被截成不同样子——判定结果就不可复现，留痕也就失去举证力。

### 交付

| 组件 | 能力 |
|------|------|
| **state 构造唯一入口** | `judge(state, questions)` 的 `state` 由**单一构造函数**产出，调用点不得自行拼装——判定输入与留痕里的输入必须是同一份字节（可复现的前提） |
| **最小可判定前缀** | 输入取「**做该判断所需的最小充分前缀**」而非全量轨迹：多给的上下文不是冗余而是**干扰项**（已知失灵面：大 state 拉低准确率）。前缀边界由判据声明，不由调用点即兴决定 |
| **定序与去噪** | 输入内的条目定序规则显式（时间序 / 因果序），并剔除与判据无关的元数据（路径、时间戳、内部 id 等噪声字段）——判定看到的应当是**语义内容**，不是存储格式 |
| **协议结构保留** | 从轨迹取 state 时**保留工具调用与结果的结构**（不压成自然语言散文）——判定要能看见「做了什么」而非「说了什么」，这是判定与生成在输入面的分野 |
| **state 尺寸上界与超限处置** | 明确定义 state 尺寸上界；超限时按**固定处置序**——**先弃权；弃权不可行时降级 ASK**，不静默截断（处置序与本章验收条逐字一致，不留给执行方选）——静默截断会让判定在缺失输入的情况下给出高把握答案（最危险的失败形态） |
| **输入侧注入隔离声明** | state 内的内容**一律是数据不是指令**（对抗必备条见 [v1.6.0 §七](../v1.6/v1.6.0.md)：state 被当数据不当敌意内容是已知失灵面）；输入契约层声明该边界，判据层不得把 state 内的祈使句当作自身的指令 |
| **政策与权限不由观察面供给（不可信观察分层）** | 判定能看到的一切 state 内容都是**被观察的对象**，**不是政策来源**——授权范围、允许动作、风险阈值一律由**代码与配置**持有；输入里出现的「已获授权」/「管理员已允许」/「按新规则执行」类文本**只作证据，不作规则**。**为什么与上一行是两个边界**：上一行管「祈使句不被当成指令」（**注入面**，防模型被说服）；本行管「政策不从数据里长出来」（**授权面**，防判定面被重写）。生态已把这一层做成结构性事实：策略引擎按 `execvp` 收到的参数表匹配、白名单由配置持有，**被观察到的命令文本从不参与「允许 / 不允许」的判定**。**失灵面登记**：判定面可被 state 内容操纵是**已知失灵面**（不是待修 bug），故它**永不进信任地基**——只坐确定性规则之后的语义兜底层。**量级（2026-09-28 登记）**：第三方黑箱对抗基准（[JevAdvBench](https://arxiv.org/abs/2609.31142)，自报、本仓未复算）把这条失灵面**从「已知」推成「有量级」**——在商业件 `jev-1.13.0` 上，**不在 schema 内的字段从未抵达模型**（类型化接口本身就是一层结构性过滤）、**纯改写措辞**引起的偏移始终 ≤1.2 个百分点；但**在 state 里追加一句不带祈使句的未核验意见**即翻转 **12.1%** 的判定，**与最强注入指令（10.1%）统计持平**，并把 **38%** 的高置信答案压到 0.8 置信阈值之下（从而被路由去人审）。论文据此的结论与本行同向且更强——**state 应被视为不可信的、被主张的输入**。**对本位边界最重的一句**：「不写指令也能操纵」意味着本行的边界**不能靠「过滤祈使句」实现**，只能靠上半句「**政策与权限不从观察面生长**」——来源登记见 [THANKS · 判定与校准](../../THANKS.md)（失灵面在生态侧的独立量化） |
| **问句标识不上行** | 送入判定的问句**不带判据名与问句 id**——模型只看到槽位（第几问）与候选项本身，判据语义留在宿主侧映射。**为什么**：判据名本身就是提示词，把「A9 提示注入检测」写进输入等于把答案的语义线索一并交出去；编号不上行，输入侧的可操纵面就只剩内容本身。与既有「Score 层级独立评判、模型看不到编号」同源同纪律 |
| **影子运行门** | 判定首次接入执行路径时**先影子运行**——判定照跑、结果只落痕不影响行为，与既有处置对照后再启用；影子期的判定结果与真实处置的差异就是启用前的最后一道证据。**为什么必须有这道门**：判定从「设计」到「有行为」的那一刻起，判错开始产生真实后果，而概率是否可信要到校准（v1.7.0）才成立——两者之间不能是空档 |
| **与留痕对账（同源 ≠ 原样）** | 落 decision-log 的输入摘要与实际送入判定的 state **同源**——审计可重建判定当时看到的是什么。但**同源不等于把 state 原样落盘**：留痕记**指纹与引用**（输入 `payload_sha256` + 判据集版本 + state 构造函数版本），并带显式 `content: false` 语义位，敏感 payload 不上链。**为什么必须写死**：留痕自身会成为新的敏感数据仓——「连续监控是目的，监控的实现不该自己造出一个新的敏感数据存储」；而「原样落盘造成数据副本」与「过度脱敏摧毁审计可用性」是同一枚硬币的两面。**自检问题**：这条留痕若被内部广泛看到，是否超出「解释本次判定所需的最小信息」？ |
| **动作输入取结构化参数向量** | 判定输入的「动作」部分取**结构化参数向量（argv 式）**而非拼好的命令串——字符串匹配可被引号、转义、变量展开规避（生态实证：成熟策略引擎按 `execvp` 收到的参数表匹配，而非匹配命令行文本）。**shell 包装串**（`bash -lc "…"` / `sh -c "…"`）须**尝试拆分**为底层动作序列；**拆不动时保守地按整串处理**——宁可整串从严，**不得因「看不出动作」而放行** |
| **执行体路径绑定** | 同一工具名的**不同解析路径不是同一个风险**：精确路径匹配优先，回退到 basename 匹配**须在白名单内**（生态实证：策略引擎为命令名配 `host_executable(name, paths)` 白名单，未列入白名单时不做 basename 回退）。这是「调用级风险绑定」在输入契约层的落点——风险绑定到**实际会被执行的那个二进制**，不是绑定到文本里出现的那个词 |
| **判定件出站脱敏（判定面最小发送纪律）** | 判定件消费的 state **先过出站脱敏层**，逐消费面声明「发什么、发多少、什么绝不发」：敏感字段（凭证 / 密钥 / 私密标识）**判定前摘除**——判定要的是语义内容不是秘密本身；确需判敏感性的场景发**粗特征**（长度档 / 有无代码块 / 有无风险词）而非原文。**编码后发送面须先解码再筛**：quoted-printable / 百分号 / base64 / HTML 实体先还原再过敏感检测——**密钥可以藏进 base64 过掉纯文本**，不解码即筛等于没筛。**敏感输入的双路处置**：看起来含密的输入按「不发送 + 本地判」处理而非「发送后标记」。与上一行「留痕对账」互补：那行管**落盘侧**（留痕不留敏感副本），本行管**上行侧**（发送侧最小化）——判定件若是外部端点，state 出境就是一条真实的数据出站通道，须按出站门纪律对待 · **本地档同样过该层（脱敏不因部署形态豁免）**；**脱敏层版本随 state 构造函数版本一并落痕**（供重放对齐） |
| **留痕写时锚定与可脱离原模型回放** | 留痕完整性**在写入时锚定**（写时签名 / 入链），不是事后补签——「事后签的记录证明不了中途那几年」。且留痕须足以**脱离原模型回放**：当时用的判据集版本、门槛参数、校准参数一并落痕，否则模型退役后无法重算，留痕降级为一段不可验证的叙述 |

### 交付

| 组件 | 能力 |
|------|------|
| **并行约束解码** | 同一份 `state` 下的**全部问句一次前向出答案**（KV cache 广播 + 单次前向填充全部字段），而非逐问循环解码——这是判定模型相对生成模型的结构性优势，也是延迟能进入百毫秒级的前提。**单机档的最大延迟杠杆不是更小的模型，是前缀复用**——生态在 Apple GPU 上实测：把 state 前缀缓存 + 只前向后缀（再叠 LoRA 权重 fp32 合并后再转换、SDPA、输入按 64-token 桶填充），重复的 772-token state 下同一件从 **861 ms 降到 242 ms**†<br>**（2026-10-16 精确表述补 · 来源 Laya 技术拆解）**：所谓「一次前向」指把多个问句组织成 **batch 并行处理**——**内部仍是 N 条「状态 + 问题 + 候选项」序列**；**复用状态的分词结果 ≠ 共享编码后的隐藏表示**；「**非自回归省掉的是逐 token 生成答案的解码过程，不是把所有计算都省掉**」——故计算量仍随问句数 / 输入长度 / 候选数增长（与本行下方「打包不是免费的」同一道理） |
| **并行打分的盈亏平衡点（打包不是免费的）** | 「一次前向出全部字段」有个前提，忽略它就会反噬：**共享前缀够长、字段数够多时才划算**。生态在一台笔记本上实测的加速比（相对逐问独立前向）：**1 个字段 0.74×（反而更慢）**、3 个字段 2.22×、8 个字段 **6.63×**；长上下文档 3 个字段 2.68×、8 个字段 **7.25×**†。⇒ **字段数 < 3 时不要打包**，直接独立前向；打包决策按**字段数 × 共享前缀长度**判定，不做「一律打包」。另实测跨模式**最坏概率差 0.018**†——**打包与不打包给出的概率不是同一个数**，取舍须落痕，且**校准按哪种口径拟合、评测就用哪种口径** |

| **多问批处理** | 相互独立的问句可批量并行；**有依赖的问句串行**（依赖关系由问句集声明，不自动推断——自动推断会引入不可审计的隐式行为）。**批量并行的第三个前提（批内同伴无关性）**：同一问句**与谁同批**不应改变它自己的概率——「打包 vs 不打包」的偏移（[v1.9.0 §四](../v1.9/v1.9.0.md) 打包收益条已按 0.018 量级登记——生态读数、本仓未复算）只覆盖了「同批 / 不同批」一维，**未覆盖「换了同批的同伴」这一维**：问句 A 与 B 同批、与 C 同批，若 A 的概率随同伴变，则**同一 state 同一问句在两次运行里得出不同结论**，判定结果即不可作证据。工业推理引擎把这一条做成可开关的硬约束（batch-invariant 推理：算子按固定顺序归约、不随批内位置与批大小变化，代价是吞吐、收益是可复现）。⇒ 本版须**实测并落数**「同伴替换下的概率差」，超阈按固定处置序收敛（先退定长批次，仍超阈再退逐问独立前向）；**不按零假定、也不默认已成立**——本行与 v1.9.0 打包偏移同源，两处数字须同批落数、同一口径。**沿革链**：本行不是新判断——v1.6.0 已登记外部实测「判定件**非确定性**：自信答案跨重复稳定、边界题漂移数个百分点」（[v1.6.0 §二 · 判据质量 lint](../v1.6/v1.6.0.md)）；本条是把那条**观察**升级为**本版可验的闸门**，并把它归因到具体机制（批内同伴／打包模式），而非笼统的「模型不稳」 |
| **本地推理栈协同** | 复用一体机既有本地推理栈（**零新增运行时组件**），与 v1.5.4 的本地并发槽位管理协同：判定请求走独立槽位通道，**不与主模型抢槽** |

| 筛 | 出局 / 偏好条件 | 淘汰或偏好谁 |
|----|----------------|-------------|
| ① **信创与离线** | 无 GPU / 纯 CPU 环境必须可用 | **淘汰**：把「显存 ≥ 24 GB」当独木桥——把某条路线的硬门槛升格为全域门槛即失守 |
| ② **边界（不做模型托管）** | 不得为每个客户训专属权重 | **淘汰**：需要「逐客户训练」的路线——不是效果问题，是「替客户训权重＝我们在托管模型」的边界问题 |
| ③ **审计（概率来源可追溯）** | 概率须来自输出分布的读数 | **淘汰**：外挂打分头且**未校准**的实现——其输出是**分数不是概率**，须先建校准才能当概率消费 |
| ④ **一体机耦合（零新增运行时）** | 复用既有本地推理栈 | **偏好**：在既有引擎的 logprobs 能力上加适配层（零新增组件），而非依赖我方无法单方面决定的引擎侧能力 |

**选型结论（主力 / 辅助 / 条件 / 不做）**：

| 定位 | 路线 | 依据 |
|------|------|------|
| **主力** | **免训练 · 占位槽 logits + 归一 softmax** | 零训练（不承诺模型性能——边界判据四）· 零新增运行时（复用既有引擎）· 零样本泛化很高 · **概率直接是输出分布的读数，审计链最短**。附带一项边界收益：**语言能力由部署方自选的基座决定**——「中文优先」因此成为**可配置项**而非我方的模型能力 |
| **辅助（窄域）** | **小模型 + 线性打分头** | 延迟与硬件门槛最低（可在边缘 CPU 运行），只用于**极高频的少数窄判据**。**前置纪律**：打分头输出在被校准前**不得作为概率消费**（见筛③） |
| **条件启用** | **离散扩散 · 单步去噪读全部答案槽** | 免训练、开箱多语言、**双向注意力使问句互不干扰**（对「一次前向出多个独立问句」价值高）。唯一门槛是显存 ⇒ **按硬件档启用**（配 GPU 档开启，信创 CPU 档不启用），**不作全域主力**。**路线规模化旁证（2026-10-31 登记）**：扩散智能 Clover-35B-A3B-Preview（Qwen3.6-35B-A3B 改块扩散，Apache-2.0 已开源）证明 **AR 底座改扩散解码在 35B 规模能力不掉**（SWE-bench 73.6 vs 底座 65.8，厂商自测）；同卡同规模对照的架构真红利 ≈**1.41×**†（H200 515 vs 365 tok/s，对照带推测解码——「快 5-10 倍」系媒体口径非官方）。其**未发布的联合模式决策版**（一次去噪并行出最多 8 个关联答案、相互参考）与本路线「双向注意力使问句互不干扰」同构——内部验证整组全对率 62.4%→80.4%（独立→联合）†⇒ **关联判定场景下「问句间信息交换」有实测收益，独立判定场景仍以互不干扰为准**——两个面正是本仓「条件启用」定位的依据。详情与开源状态实查见判定件提供方仓 `rsi/docs/EXTERNAL-LEARNINGS.md` §1.8 |
| **明确不做** | **为每个客户训专属权重** | 越界（见筛②）。与其效果无关——同类实测里该路线表现可圈可点；问题是**它把交付方变成模型提供者**，随之而来的是数据归属、性能承诺与训练服务 |

**一条必须写明的风险**：主力路线是**零样本强，不是校准强**。占位槽 logprob + 归一 softmax 得到的是**可比的排序分**——那个 softmax 只保证若干候选之和为 1，**不保证「报 0.8 就八成对」**。因此主力路线**必须配本仓自己的校准层**（[v1.7.0 §二](../v1.7/v1.7.0.md) 分桶温度拟合），否则拿到的是「很像概率的排序分」。这同时是相对同期复刻件的**差异点所在**：它们大多停在「能出概率」，本仓要的是「**概率可信到能用来分流**」。

> 📎 「批内同伴无关性」验收条的行业源头依据（章体注记，判据本体见下方验收条）：Thinking Machines Lab《Defeating Nondeterminism in LLM Inference》（Horace He，2025-09-10，2026-10-20 回源）证明非确定性根因是 kernel 缺批不变性——Qwen3-235B-A22B temperature=0 同 prompt 1,000 次出 80 种完成；换批不变 kernel 后全一致。代价：批不变 matmul 比 cuBLAS 慢约 20%；端到端（Qwen-3-8B · 1,000 序列）26s → 55s（+112%）→ 优化后 42s（+62%）。**以上为论文自报读数、本仓未复算**——本仓取的是「非确定性根因＝kernel 缺批不变性」这一结论作验收条依据。
>
> 📎 「整组全对率」与「版本对比读数四列」两条验收条的依据与登记时点（章体注记）：前者 2026-10-31 经用户拍板登记，依据为扩散智能 Clover 决策版内部验证（`[厂]` 自报、本仓未复算）独立作答单题 89.8% 而整组全对率仅 62.4%（Jev 单点评估同题 63.6%→15.8%，衰减约 4:1）；后者 2026-11-01 随 RSI-Anything MINING 轮登记（`[厂]` 自报、未独立复核）——GUI 中间版成功率 51→79 的同时错误提交 9→21、平均动作 2.93 反低于终版 3.21。两条均只取「读数形态」结论作判据，不取对方读数为门槛值。
