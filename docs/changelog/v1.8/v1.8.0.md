## 定位


> 🔌 **判定底座 · DecisionChannel 真实实现**——阶段三第一版，回答「**判定怎么被用起来**」。v1.5.4 交付了 `DecisionChannel` 的**契约**（`judge(state, questions)` + 三原语语义 + 云端 provider opt-in 默认关），但当时留空——L1 判定层处于「只有接口没有实现，按 L0 兜底」的状态。本版用阶段一/二的产物**填上这个空**，让 L1 从兜底态变为真实可用态。**纪律不变**：通道而非依赖——引擎定义接口与编排，实现可被替换（用户自带实现或换基座，不动契约）。实现就位后紧接着要定的是**输入面**（§二）——判定看到的 `state` 由什么构成、截多长；输入契约不写死，判定结果就不可复现，留痕也随之失去举证力。

> 🖥️ **判定底座 · 一体机推理接入**——阶段三第二版，回答「**判定在哪跑、跑得多快**」。判定底座要在客户的私有环境（一体机、离线节点、信创全封环境）里可用，且**不新增运行时组件**——跑在既有本地推理栈上。本版同时把路由层的**判定档（`decision-model`）**从「插槽已预留」接通为「真实可达」：判定任务由判定底座直接作答，**不经过生成模型**。**路线不绑定**——本版落的是一条实现路线，契约由 本版第一章的 `DecisionChannel` 保证，路线选择属实现面。

> 📦 **判定底座 · 权重分发通路与自带件形态成立**——阶段三收口版，回答「**判定底座怎么交付到客户手里**」。判定底座是「随装即用」的**自带件**，但**权重不进 npm tarball**（二进制制品与代码包分发纪律不同）。既有仓库链路**已建有五环**（清单 / 目录级 sha256 / 校验 / 注册表 / 切换与回滚），**唯一缺口是「从远端拉权重」**——本版补上这个缺口，判定底座的交付形态即告完整。

## 二、判定面输入契约（state 的构造口径与最小可判定前缀）


> **形态归属**：`[主干]`（判定·输入契约）｜ **不可拔**（state 的构造口径决定判定输入是什么——契约缺失则同一份 state 每次被截成不同样子，判定结果不可复现）

阶段一/二把概率做可信了，本版让它进执行路径——那么第一个必须写死的东西不是输出而是**输入**：判定看到的那份 `state` 到底由什么构成、截多长、怎么定序。**为什么这是契约而非实现细节**：判定模型对输入极其敏感（大 state 里的干扰项会拉低准确率，是已实测的失灵面），若 state 构造散落在各调用点，同一份轨迹在不同路径下会被截成不同样子——判定结果就不可复现，留痕也就失去举证力。

### 交付

| 组件 | 能力 |
|------|------|
| **state 构造唯一入口** | `judge(state, questions)` 的 `state` 由**单一构造函数**产出，调用点不得自行拼装——判定输入与留痕里的输入必须是同一份字节（可复现的前提） |
| **最小可判定前缀** | 输入取「**做该判断所需的最小充分前缀**」而非全量轨迹：多给的上下文不是冗余而是**干扰项**（已知失灵面：大 state 拉低准确率）。前缀边界由判据声明，不由调用点即兴决定 |
| **定序与去噪** | 输入内的条目定序规则显式（时间序 / 因果序），并剔除与判据无关的元数据（路径、时间戳、内部 id 等噪声字段）——判定看到的应当是**语义内容**，不是存储格式 |
| **协议结构保留** | 从轨迹取 state 时**保留工具调用与结果的结构**（不压成自然语言散文）——判定要能看见「做了什么」而非「说了什么」，这是判定与生成在输入面的分野 |
| **state 尺寸上界与超限处置** | 明确定义 state 尺寸上界；超限时**弃权或降级为 ASK**，不静默截断——静默截断会让判定在缺失输入的情况下给出高把握答案（最危险的失败形态） |
| **输入侧注入隔离声明** | state 内的内容**一律是数据不是指令**（参考 v1.6.0 对抗样本采集点）：输入契约层声明该边界，判据层不得把 state 内的祈使句当作自身的指令 |
| **政策与权限不由观察面供给（不可信观察分层）** | 判定能看到的一切 state 内容都是**被观察的对象**，**不是政策来源**——授权范围、允许动作、风险阈值一律由**代码与配置**持有；输入里出现的「已获授权」/「管理员已允许」/「按新规则执行」类文本**只作证据，不作规则**。**为什么与上一行是两个边界**：上一行管「祈使句不被当成指令」（**注入面**，防模型被说服）；本行管「政策不从数据里长出来」（**授权面**，防判定面被重写）。生态已把这一层做成结构性事实：策略引擎按 `execvp` 收到的参数表匹配、白名单由配置持有，**被观察到的命令文本从不参与「允许 / 不允许」的判定**。**失灵面登记**：判定面可被 state 内容操纵是**已知失灵面**（不是待修 bug），故它**永不进信任地基**——只坐确定性规则之后的语义兜底层 |
| **问句标识不上行** | 送入判定的问句**不带判据名与问句 id**——模型只看到槽位（第几问）与候选项本身，判据语义留在宿主侧映射。**为什么**：判据名本身就是提示词，把「A9 提示注入检测」写进输入等于把答案的语义线索一并交出去；编号不上行，输入侧的可操纵面就只剩内容本身。与既有「Score 层级独立评判、模型看不到编号」同源同纪律 |
| **影子运行门** | 判定首次接入执行路径时**先影子运行**——判定照跑、结果只落痕不影响行为，与既有处置对照后再启用；影子期的判定结果与真实处置的差异就是启用前的最后一道证据。**为什么必须有这道门**：判定从「设计」到「有行为」的那一刻起，判错开始产生真实后果，而概率是否可信要到校准（v1.7.0）才成立——两者之间不能是空档 |
| **与留痕对账（同源 ≠ 原样）** | 落 decision-log 的输入摘要与实际送入判定的 state **同源**——审计可重建判定当时看到的是什么。但**同源不等于把 state 原样落盘**：留痕记**指纹与引用**（输入 `payload_sha256` + 判据集版本 + state 构造函数版本），并带显式 `content: false` 语义位，敏感 payload 不上链。**为什么必须写死**：留痕自身会成为新的敏感数据仓——「连续监控是目的，监控的实现不该自己造出一个新的敏感数据存储」；而「原样落盘造成数据副本」与「过度脱敏摧毁审计可用性」是同一枚硬币的两面。**自检问题**：这条留痕若被内部广泛看到，是否超出「解释本次判定所需的最小信息」？ |
| **动作输入取结构化参数向量** | 判定输入的「动作」部分取**结构化参数向量（argv 式）**而非拼好的命令串——字符串匹配可被引号、转义、变量展开规避（生态实证：成熟策略引擎按 `execvp` 收到的参数表匹配，而非匹配命令行文本）。**shell 包装串**（`bash -lc "…"` / `sh -c "…"`）须**尝试拆分**为底层动作序列；**拆不动时保守地按整串处理**——宁可整串从严，**不得因「看不出动作」而放行** |
| **执行体路径绑定** | 同一工具名的**不同解析路径不是同一个风险**：精确路径匹配优先，回退到 basename 匹配**须在白名单内**（生态实证：策略引擎为命令名配 `host_executable(name, paths)` 白名单，未列入白名单时不做 basename 回退）。这是「调用级风险绑定」在输入契约层的落点——风险绑定到**实际会被执行的那个二进制**，不是绑定到文本里出现的那个词 |
| **判定件出站脱敏（判定面最小发送纪律）** | 判定件消费的 state **先过出站脱敏层**，逐消费面声明「发什么、发多少、什么绝不发」：敏感字段（凭证 / 密钥 / 私密标识）**判定前摘除**——判定要的是语义内容不是秘密本身；确需判敏感性的场景发**粗特征**（长度档 / 有无代码块 / 有无风险词）而非原文。**编码后发送面须先解码再筛**：quoted-printable / 百分号 / base64 / HTML 实体先还原再过敏感检测——**密钥可以藏进 base64 过掉纯文本红action**，不解码即筛等于没筛。**敏感输入的双路处置**：看起来含密的输入按「不发送 + 本地判」处理而非「发送后标记」。与上一行「留痕对账」互补：那行管**落盘侧**（留痕不留敏感副本），本行管**上行侧**（发送侧最小化）——判定件若是外部端点，state 出境就是一条真实的数据出站通道，须按出站门纪律对待 |
| **留痕写时锚定与可脱离原模型回放** | 留痕完整性**在写入时锚定**（写时签名 / 入链），不是事后补签——「事后签的记录证明不了中途那几年」。且留痕须足以**脱离原模型回放**：当时用的判据集版本、门槛参数、校准参数一并落痕，否则模型退役后无法重算，留痕降级为一段不可验证的叙述 |

## 三、并行约束解码（一次前向出全部字段）

| 组件 | 能力 |
|------|------|
| **并行约束解码** | 同一份 `state` 下的**全部问句一次前向出答案**（KV cache 广播 + 单次前向填充全部字段），而非逐问循环解码——这是判定模型相对生成模型的结构性优势，也是延迟能进入百毫秒级的前提。**单机档的最大延迟杠杆不是更小的模型，是前缀复用**——生态在 Apple GPU 上实测：把 state 前缀缓存 + 只前向后缀（再叠 LoRA 权重 fp32 合并后再转换、SDPA、输入按 64-token 桶填充），重复的 772-token state 下同一件从 **861 ms 降到 242 ms** |
| **并行打分的盈亏平衡点（打包不是免费的）** | 「一次前向出全部字段」有个前提，忽略它就会反噬：**共享前缀够长、字段数够多时才划算**。生态在一台笔记本上实测的加速比（相对逐问独立前向）：**1 个字段 0.74×（反而更慢）**、3 个字段 2.22×、8 个字段 **6.63×**；长上下文档 3 个字段 2.68×、8 个字段 **7.25×**。⇒ **字段数 < 3 时不要打包**，直接独立前向；打包决策按**字段数 × 共享前缀长度**判定，不做「一律打包」。另实测跨模式**最坏概率差 0.018**——**打包与不打包给出的概率不是同一个数**，取舍须落痕，且**校准按哪种口径拟合、评测就用哪种口径** |
| **类型约束解码** | 解码过程**约束在声明的回答类型内**（choice 只能出候选项、score 只能出合法档位、noul 只能是概率）——从解码层保证「类型正确」，与 v1.6.0 的 schema 层限定构成双重保证（schema 层防越界，解码层防畸形） |
| **多问批处理** | 相互独立的问句可批量并行；**有依赖的问句串行**（依赖关系由问句集声明，不自动推断——自动推断会引入不可审计的隐式行为） |
| **本地推理栈协同** | 复用一体机既有本地推理栈（**零新增运行时组件**），与 v1.5.4 的本地并发槽位管理协同：判定请求走独立槽位通道，**不与主模型抢槽** |
| **离线可用** | 无网络环境下判定底座可正常加载与推理（权重本地留存，不联络外部服务）——信创全封场景的硬要求 |
| **最低可用档 · 无独立 GPU 的单机** | **交付形态的下限是「一台普通笔记本」，不是「一块显卡」**。生态两件已分别把该档的两半跑出来：**单机推理**——某 9B 复刻件在 M5 Pro 64 GB 上（MLX）判定延迟中位 444 ms / p95 981 ms（324 例；同口径 H100 上中位 106 ms、120 例）；**单机训练**——另一件明确保留笔记本训练路径（Apple M5 / 32 GB 统一内存 / MPS），小档完整训练一次约 1 小时 45 分钟、功耗 30–40 W（约 0.06 kWh），其 4B–9B 档则迁到单卡 H100。⚠️ **引用这两半时不得混说**——把推理侧读数当训练侧依据，与只报机型不报规模同属过度承诺。**本版要落的是三个数而不是一句「能跑」**：① 无 GPU 档的延迟与吞吐曲线 ② 该档下**可承载与可训练的规模随内存档位的对照表**（规模由可用内存决定，不由机型品牌决定——只报「在某台机器上跑通了」会被读成任何机型都行，那是过度承诺）③ 该档是否触发降级（弃权门槛是否须放宽）。**另一条硬判据（生态实测倒逼）**：单机可用性**由「目标硬件上有没有快核」决定，不由参数量决定**——同一件制品在同一台笔记本上做同一件事，换用含线性注意力循环层的基座后慢 3–7 倍（4B：779 ms vs 174 ms），根因是该循环层在 Apple Silicon 上无 MPS 实现。故**基座选型的必答项是「目标硬件上有无对应核」**。**为什么这一档必须是硬要求**：权重交付与本地后训练能力是本产品线数据主权承诺的落点——门槛定在「有独显的机器」上，承诺就落不了地 |
| **实现路线不绑定** | 本版落地的是**其中一条路线**（并行约束解码），但契约不绑定路线——同期生态已出现**离散扩散去噪**（答案模板写在固定长度 canvas 上、只读去噪一步读出全部答案分布）与**零微调 stock 模型**两条可行路线，且主流推理引擎侧已有扩散支持立项。**契约由 本版第一章的 `DecisionChannel` 保证，路线选择属实现面**——换路线不改判定头契约、不改问句集与判据格式。本版契约测试**以接口为准，不以具体路线为准**。**外部实证**：同期生态在**不足两天**内出现**六个互不相同的实现**——编码器 + 策略梯度、扩散模型的约束解码分支、因果小模型 LoRA、编码器 + 蕴含分类器、自训逐字节打分件、半参数因果模型 LoRA（可在消费级笔记本上跑）——**没有任何两个用同一架构，却全部收敛到同一条接口**（文本进、类型化概率出）。这一致的收敛方向本身即结论：**护城河不在模型架构**，在于契约、校准与判据质量——这正是本仓把路线判为实现面的依据 |
| **超词表上界的选项集分块** | 单次前向能覆盖的选项数受**基座词表单 token 数**限制（实测某基座 A–Z / a–z 合计 52 项可单次前向），而 `Choice` 的规格上限高于此。超上界时**分块打分 + 末轮归一**并保留「以上都不是」槽——**不得静默截断候选集**（截断会让模型在缺失选项里挑最优，产出一个看似高概率、实则无意义的答案）。**硬前提 · 单 token 可映射性**：零微调路线要求**每个答案标签恰好编码为 1 个词表 token**（多 token 标签须改走「逐 token 概率连乘」或「整串概率合并」两条变体，不得假设默认成立）——这是**选项集构造期的断言**，不是运行期的兜底。**词表规模是量级参照**：同级开源基座的词表在**二十万至二十六万**量级（实测两例为 201,088 与 262,208），故「答案位占一个槽」这件事在词表层面总是成立，**真正的约束是标签文本的单 token 可编码性**，与词表总量无关 |
| **稳定化重读的实现挂接（消费设计）** | 语义与分工的设计 SSOT 在 [v1.7.0 §四](../v1.7/v1.7.0.md)（与弃权的关系 / 默认关闭 / 校准同口径重测 / 逐问句粒度）——本版只交付该设计在并行解码实现里的挂接：**单问句触发时不重跑整批**（只对该问句补前向，其余字段沿用首次结果——并行打包与重读是两个正交维度，打包的省不应被重读的补吃掉）；开启时延迟曲线落数须含重读开销（本版延迟与吞吐落数的组成部分） |
| **延迟与吞吐落数** | 单次判定延迟、批量吞吐、并发下的延迟劣化曲线如实落数（作为 v1.9.0 四层性能标准的输入）。**承诺档的参照读数（NeoHorse-Jev 官方口径，2026-09-24）**：同路线品类件自报 32 并发平均决策耗时 **74.3 ms**（服务端 Decision 计时）与 256 并发 **347 请求/秒**（6,948 次请求全成功，文本混合负载），并明确区分「服务返回的 Decision 计时」与「客户端完整请求 273.3 ms」两个口径——本版延迟落数沿用同款**双口径分列**（服务端计时 ≠ 端到端耗时，混用即虚标）；该读数同时给了 prefill-only 路线在 4B 规模的工程可行性佐证（本仓 0.3–0.5B 档更小，百毫秒级前提成立）。**厂商自报未复算**，仅作路线可行性参照与本版落数的口径模板 |
| **职责频率分层（延迟即职责边界）** | 延迟不只是性能指标，它直接决定判定层**能承担哪一层职责**——成熟形态是分层错位布置：高频控制回路（数百 Hz）与安全反射归确定性代码，符号化感知归经典 CV，**判定层只坐在最低频那一层且性质为建议**。本版的延迟曲线须同时给出「**该延迟下判定可承担的职责层级**」，并写明判定**永不进**控制回路与安全反射 |

### 路线选型（四道筛）

> 「架构路线没有最好，只有最适合」——但**最适合不是按性能排出来的，是按约束筛出来的**。四道筛的**顺序即优先级**：前几道是出局条件，最后一道才是偏好。

| 筛 | 出局 / 偏好条件 | 淘汰或偏好谁 |
|----|----------------|-------------|
| ① **信创与离线** | 无 GPU / 纯 CPU 环境必须可用 | **淘汰**：把「显存 ≥ 24 GB」当独木桥——把某条路线的硬门槛升格为全域门槛即失守 |
| ② **边界（不做模型托管）** | 不得为每个客户训专属权重 | **淘汰**：需要「逐客户训练」的路线——不是效果问题，是「替客户训权重＝我们在托管模型」的边界问题 |
| ③ **审计（概率来源可追溯）** | 概率须来自输出分布的读数 | **淘汰**：外挂打分头且**未校准**的实现——其输出是**分数不是概率**，须先建校准才能当概率消费 |
| ④ **一体机耦合（零新增运行时）** | 复用既有本地推理栈 | **偏好**：在既有引擎的 logprobs 能力上加适配层（零新增组件），而非依赖我方无法单方面决定的引擎侧能力 |

**选型结论（主力 / 辅助 / 条件 / 不做）**：

| 定位 | 路线 | 依据 |
|------|------|------|
| **主力** | **免训练 · 占位槽 logits + 归一 softmax** | 零训练（不承诺模型性能——边界判据四）· 零新增运行时（复用既有引擎）· 零样本泛化很高 · **概率直接是输出分布的读数，审计链最短**。附带一项边界收益：**语言能力由部署方自选的基座决定**——「中文优先」因此成为**可配置项**而非我方的模型能力 |
| **辅助（窄域）** | **小模型 + 线性打分头** | 延迟与硬件门槛最低（可在边缘 CPU 运行），只用于**极高频的少数窄判据**。**前置纪律**：打分头输出在被校准前**不得作为概率消费**（见筛③） |
| **条件启用** | **离散扩散 · 单步去噪读全部答案槽** | 免训练、开箱多语言、**双向注意力使问句互不干扰**（对「一次前向出多个独立问句」价值高）。唯一门槛是显存 ⇒ **按硬件档启用**（配 GPU 档开启，信创 CPU 档不启用），**不作全域主力** |
| **明确不做** | **为每个客户训专属权重** | 越界（见筛②）。与其效果无关——同类实测里该路线表现可圈可点；问题是**它把交付方变成模型提供者**，随之而来的是数据归属、性能承诺与训练服务 |

**一条必须写明的风险**：主力路线是**零样本强，不是校准强**。占位槽 logprob + 归一 softmax 得到的是**可比的排序分**——那个 softmax 只保证若干候选之和为 1，**不保证「报 0.8 就八成对」**。因此主力路线**必须配本仓自己的校准层**（[v1.7.0 第二章](../v1.7/v1.7.0.md) 分桶温度拟合），否则拿到的是「很像概率的排序分」。这同时是相对同期复刻件的**差异点所在**：它们大多停在「能出概率」，本仓要的是「**概率可信到能用来分流**」。
| `engine/orchestrator/src/router/slot-manager.ts` | 修改 | 判定独立槽位通道（不与主模型抢槽） |
| `engine/orchestrator/src/__tests__/judge-parallel.test.ts` | 新建 | 并行正确性 / 类型约束 / 槽位隔离 / 离线加载单测 |
| `docs/VALIDATION.md` | 修改 | 延迟与吞吐实测落数 |

## 四、路由判定档接通（`decision-model` 从插槽到可达）


> **形态归属**：`[主干]`（路由·判定档）｜ **不可拔**（路由档位是判定与执行的接缝）

### 交付

| 组件 | 能力 |
|------|------|
| **判定档接通** | `model-router` 的 `decision-model` 档从「类型已定义、分支已显式返回空」接通为**真实可达**——判定任务路由到该档后由判定底座作答，产出类型化答案 + 概率 |
| **判定档不进自动矩阵** | 该档**不参与「敏感度 × 复杂度」自动路由矩阵**——判定任务由上游显式请求（判定类任务发起时指定），避免判定任务被自动矩阵误路由到生成档 |
| **不落云端生成分支** | 判定档与拦截档（`block`）**绝不落到云端生成分支**（既有缺陷修复的回归锁——判定任务变成生成任务会既慢又错） |
| **判定档可观测** | 判定档的调用量 / 延迟 / 失败率 / 降级次数可观测（运维可见，数据本地不出门） |
| **与本地两档的分工声明** | 明确 `decision-model`（判定档）与 `local-executor`（本地执行档）/ `local-pipeline`（本地管道档）的分工边界：**判定档出判定，执行档出行为**——三者是任务形态区分，不是模型规格区分 |

### 风险与前置假设

> ⚠️ **一体机硬件规格可能不足**。判定底座的底座规格与并行约束解码的显存/内存占用须与客户实际硬件对齐（本版落数的延迟曲线是选型依据）。若目标硬件跑不动，**退回串行解码**（延迟上升但功能可用），并把该形态明确标注为降级档而非静默降速。
>
> ⚠️ **无 GPU 环境须保底可用**。纯 CPU 推理作为**最低可用档**亦须可跑——国内已有跨平台开源复现证明无 GPU 的 PC / Mac 可离线完成判定任务（中位耗时数秒至十余秒量级）。CPU 档延迟显著更高但形态成立，标注为最低档，**不是「不可用」**——信创与全封环境的实际硬件分布决定这一档必须存在。

## 五、权重分发通路（补唯一缺口）


> **形态归属**：`[主干]`（分发·制品通路）｜ **不可拔**（制品通路是交付形态的最后一环）

### 交付

| 组件 | 能力 |
|------|------|
| **协议面观察（生态事实标准苗头）** | 判定件的 **wire 协议正在开放化**：生态已出现兼容 TypeSafe `POST /v1/systemone` 格式的开源端点，可枚举三家——`Mapika/decider`（校准感知 RL 训练 + wire 兼容自述，持续活跃维护；PyPI 包名 **`decider-ai`**，裸名 `decider` 是 2026-06 上传的同名无关决策管线工具，引用禁混写）、`ekzhang/openjev-sglang`（sglang 预填-only 兼容端点）、`Contrastive-LM/CLM`（双塔对比式，`clm-serve` 兼容端点）。**含义**：`DecisionChannel` 的对外协议面设计时须知悉此事实标准苗头——**是否兼容该 wire 格式是本版协议面决策的一部分**（兼容 ⇒ 本仓判定件可被 System One 既有客户端直接消费，接入成本降一个量级；不兼容 ⇒ 保持自有契约，理由须写明）。**边界**：本行只是观察登记与决策提醒，**不预设兼容结论**——协议面决策随本 manifest 设计同批做，结论落 decision-log |
| **manifest 远端源字段** | `weights-manifest` 补 `remote` 字段（源地址 / 制品 id / 版本 / 期望 sha256 / 大小——「版本」语义=**模型代次号**——schema 字段名定为 `generation`（取值 `"V2"` / `"V2.1"` 式字符串，非 semver、非仓版本号，见 [v2.0.0 §四](../v2.0/v2.0.0.md) 权重版本号独立轨道）——字段名自带语义，杜绝实现时误填 `v2.0.0` 式仓版本号）——既有 `versions[]`（id / createdAt / sha256 / sizeBytes）与 `current` 结构不变，**纯增量**。**默认主载域取值形态**（Hugging Face）：源地址 = `https://huggingface.co/<org>/<repo>/resolve/<revision>/<file>`，其中 `revision` 用 tag 或 commit **钉死**——不用 `main`（移动指针会让 sha256 期望值失去意义，等于把完整性校验降级为「下载成功即信」）；期望 sha256 与 HF LFS 的 OID（同为 sha256）**同一口径**，可直接对账 |
| **下载组件** | 从远端拉取权重的下载件：**断点续传** + 失败重试 + 进度可见；接续 v1.4.2 已排期的「基座模型下载管理」 |
| **完整性与篡改检测** | 下载后按 `sha256` 校验（复用既有 `hashDir()` 目录级哈希口径），不匹配 → **拒绝启用并留痕**（fail-closed，不静默替换） |
| **多版本与回滚** | 复用既有 `model_switch` 多版本能力：可并存多版权重、可回滚到上一版（既有「供应链红线」纪律零改动） |
| **来源白名单** | 远端源须在白名单内（**既定主载域**：模型托管平台 Hugging Face——`huggingface.co` 及其 LFS/CDN 域），非白名单源须显式开启且留痕——防供应链投毒 |
| **离线与镜像源（主载域不是唯一可达源）** | 既定主载域解决的是**对外分发与公开发布**，不是**运行时唯一来源**——企业内网 / 信创全封环境下公共域不可达是常态，故下载件须支持两条替代通路：① **镜像源**——具名两形态：**hf-mirror（反向代理，公开仓库自动可拉、零运维）**与 **ModelScope 魔搭（国产托管平台，同批上传第二份制品——面向信创/国企场景的国内一等公民门）**；白名单可配置为内网镜像，「非白名单源须显式开启且留痕」的纪律不变 ② **离线介质导入**——从移动介质 / 内网制品库导入权重目录，走**同一套 sha256 校验与 fail-closed 路径**（导入路径不得成为绕过校验的后门）。与本版第三章「离线可用」（无网络可加载并推理）配套：**能离线跑**与**能离线装**是两件事，后者缺位则数据主权承诺在封闭环境下落不了地 |
| **USB 交付介质两档（离线介质导入的具名形态 · 用户拍板「机器 + USB = 无头判定节点」）** | 离线介质的最轻交付形态，按部署深度分两档：**A 安装器档**——插上即把 sofagent + 判定件 + DSH 节点装进目标机器（改造既有 install.sh 安装面：介质内读源替代联网下载，走**同一套 sha256 校验**）；**B 便携运行时档**——插上即跑、拔出零残留（复用既有 USB 骨架三件：`usb-key.ts` 便携打包 + `usb-signature.ts` 确定性全量验签 + `usb-runtime.ts` 密钥仅驻内存 / 便携 env / 拔出清零，打包对象从旧「引擎全家桶」换成「DSH 节点 + 判定件权重 + 配置」）。**为什么成立**：判定件是 encoder 单次前向（0.3–0.5B 档），本版第三章已定纯 CPU 为最低可用档——不挑机器，旧电脑 + U 盘即成判定节点，是一体机的**低成本末端形态**（先用 U 盘跑起来，跑出价值再升级一体机）。**对 U 盘随机 IO 慢的对策**：权重本就是单文件顺序读；node_modules 小文件面可自解压到临时目录再跑（牺牲零残留换启动速度）或全介质跑（牺牲速度换零残留）——两档行为都显式声明，不静默选择。**边界**：USB 装的仍是「DSH 节点 + 判定件」，**不是**旧「四位一体」节点本体（该叙事已随 [v2.0.0 §七](../v2.0/v2.0.0.md) B 表退役） |
| **版本松耦合** | 权重版本独立于 sofagent 代码版本：接口契约由 `DecisionChannel` 保证，**不由版本号保证**——v1.7 训出的权重可挂到 v1.8/v1.9 的代码，也可回挂（只要契约未变） |
| **量化分档与哈希清单的参照形态（NeoHorse-Jev 制品实测，2026-09-25）** | 同期首个全开放权重判定件 NeoHorse-Jev-4B（Apache-2.0）的制品形态可作本章施工的直接参照（[VALIDATION · 权重制品清单](../../VALIDATION.md#品类第二玩家与首个全开放权重neohorse-jev--2026-09-24)有全清单）：① **量化分档五档切法**——BF16（母版）8.48 GB / Q8_0 4.81 / Q4_K_M 3.16 / Q3_K_M 2.75 / Q2_K 2.42 GB（同族 GGUF 独立仓分发，含 `runtime/` 目录与 `LICENSE.llama.cpp` 式第三方许可声明）——本判定件 0.3–0.5B 档照此比例推算，BF16 母版 + Q8 精度档 + Q4 最低配档三档起步即可覆盖「一体机 / 无 GPU 单机 / USB 便携」三场景；② **SHA256SUMS 清单文件**——单文件聚合全部制品哈希，与本章「下载后 sha256 校验 fail-closed」的消费形态直接对齐（`weights-manifest.remote.期望sha256` 的逐制品字段 + 平台侧 SHA256SUMS 聚合清单双面在位）；③ **多通道同制品**——同修订号在 ModelScope 与 HF 双平台分发，佐证「镜像源是必需项非优化项」。**口径**：以上为对方制品观察，非本仓施工决定——量化档位取舍在施工时按目标硬件实测后定 |

### 三层分发物（制品架构）

| 层 | 载体 | 版本节奏 | 体量 |
|----|------|----------|------|
| **代码包** | npm + 仓库 tag | 随 sofagent 版本 | MB 级 |
| **规则资产** | 随代码走（判据 / 规则 / 校准声明） | 随代码版本 | KB 级 |
| **模型制品** | **权重主载于模型托管平台**（**既定主载域：Hugging Face**——权重本体）+ **仓库内只放权重清单 / sha256 / 模型卡 / 制品许可声明**（权重许可**独立于本仓 MIT 代码许可**，随模型卡一并载明——不做「仓库许可自动覆盖制品」的默认假设） | **独立版本号**（与代码松耦合） | GB 级 |

**模型卡模板（发布面形态：仓内与平台同一份内容）**：模型卡是权重制品的**对外说明书**，须两条同时满足——① **平台标准字段在位**（按模型托管平台的既有卡式规范填「许可 / 语言 / 基座 / 训练方式 / 用途与限制」，**不另创一套字段体系**）② **本仓增量字段在位**（校准依据声明 + 弃权归因 + 四层性能标准 + 判据集版本与四件套版本锚——定义与 [v1.7.0 §三](../v1.7/v1.7.0.md) / [v1.9.0 §四](../v1.9/v1.9.0.md) 同口径）。**仓内与平台写同一份内容**——两套文案即两套口径（与本版「非白名单源须显式开启且留痕」属同一条分发纪律）。**局限面必写**：已知失灵面按 [v2.0.0 §三](../v2.0/v2.0.0.md) LIMITATIONS 同口径列出——**模型卡不写局限面即不可发布**（对外数字可复现的前置条件是先声明数字的边界）

## 六、自带件形态成立（本版对外口径变化）


> **形态归属**：`[主干]`（交付形态声明——本版**首次**具备对外叙事资格）｜ —

### 交付

| 组件 | 能力 |
|------|------|
| **形态成立声明** | 判定底座具备完整交付形态：**DecisionChannel 有真实实现**（本版第一章）+ **可一体机离线推理**（本版第三章）+ **权重分发通路打通**（本版 §五）——三者齐备即「自带件」形态成立 |

| **可替换声明** | 判定底座可被替换：换基座 / 换实现 / 换用户自带件，**契约不动**（`DecisionChannel` 是接口纪律） |

### 风险与前置假设

> ⚠️ **供应链安全是本章的红线**。权重是二进制制品，一旦被替换或投毒，判定行为会被静默改变——因此**来源白名单 + sha256 强校验 + 不匹配拒绝启用 + 留痕**四项缺一不可，且**不可配置为「校验失败仅告警」**。
>
> ⚠️ **本版仍不得宣称「判定准确率」**。准确率证据链（四层性能标准 + 第四方对照）属 v1.9.0——本版只宣称「形态成立」，不宣称「能力水平」。两者混说会让证据链失去意义。
