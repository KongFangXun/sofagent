## 一、P0：审计配置化（.sofagent/config.yml）

> 来源：DeepSeek PR #2。不同项目的低风险文件不同——Java 项目不关心 package.json，Python 项目不在乎 tsconfig.json。

### 背景

v0.94 前 `LOW_RISK_PATTERNS`、`testPatterns`、规则阈值全部硬编码在 TypeScript 源码里。团队接入需要改源码 + 重新编译——这在企业部署中不可接受。

### 设计

```yaml
# .sofagent/config.yml
audit:
  low_risk_patterns:
    - package-lock.json
    - yarn.lock
    - "*.generated.*"
    - "docs/**"
  test_patterns:
    - "npm test"
    - "npm run test"
    - "pytest"
    - "go test ./..."
  careful_modify_threshold: 0.2  # 超过 20% 无关文件 → WARN
  strict_mode: false             # 默认不强制写日志
```

### 加载优先级

1. 项目根目录 `.sofagent/config.yml`（最高）
2. 用户目录 `~/.sofagent/config.yml`
3. 内置默认值（当前硬编码值，作为 fallback）

### 收益

- FDE 部署者可为每个企业定制审计规则（不碰源码）
- 不同语言项目可用不同配置（Java/Python/Go 各一份）
- 为 v0.96 GitHub Actions 模板打基础

## 二、P1：MCP server MVP

> 从 v0.94 推迟。依赖 JSONL 结构化日志先落地（v0.94 已做）。

### 功能范围

- watch `.sofagent/task/logs/` 目录（优先 JSONL，fallback MD）
- 任务完成（日志文件写入）立即检测
- 首次推送：任务摘要（任务名、模型、耗时、铁律违反数）
- webhook 客户端框架（预留企业平台接入接口）
- 对标 Claude Code 的 Slack 集成——但跨平台

### 技术选型

- Node.js + `chokidar`（文件监听） + 内置 `fetch`（webhook 推送，不引入 axios）
- 轻量级——状态用 `.sofagent/mcp-state.json` 记录

## 七、行业笔记驱动的 8 项轻量落地

### ① 铁律分级标签（P0）

> 来源：FDE Agent Harness 笔记。「业务底线要硬，能力拐杖要软。」

11 条规则标注 `ruleClass` 字段：

| 铁律 | 分级 | 原因 |
|------|------|------|
| #1 先读再用 | 能力拐杖 | 模型能力增强后可弱化 |
| #3 验证再干 | 能力拐杖 | 同上 |
| #7 谨慎修改 | 业务底线 | 改无关文件直接伤害项目 |
| #10 如实汇报 | 业务底线 | 诚信是零容忍底线 |
| #11 敏感文件 | 业务底线 | 安全硬约束 |
| R1-R5, R12 | 能力拐杖 | 当前阶段的辅助检测 |

产物：`rules/index.ts` 增加 `ruleClass` 字段，输出中包含 `[底线]` 或 `[拐杖]` 标签。

### ② 上下文成本仪表盘（P0）

> 来源：MCP 扩展架构笔记。「context 是预算，不是文件夹。」

verify.sh 或 install.sh 输出追加一行：
```
📊 治理层占用：~3,200 token（128K 窗口的 2.5%）
```

目的：让用户知道治理层本身的成本。治理层总占用承诺不超过窗口的 5%。

### ③ 审计输出审查提醒（P0）

> 来源：Loop 笔记。「理解债务：Agent 产出越快，人越容易跳过审核。」

`--ci` 模式通过后，`reporter.ts` 追加一行：
```
⚠️  本次 diff 新增 N 行代码。审计通过 ≠ 代码正确——建议人工 review 后再合并。
```

### ④ 审计效果量化锚点（P1）

### ⑤ 审计历史聚合脚本（P1）

> 来源：FDE 笔记。「FDE 的反馈回路：现场经验 → 产品迭代。」

新建 `scripts/audit-summary.sh`：
- 输入：`.sofagent/task/logs/` 目录下本月所有审计输出
- 输出：本月触发最多的 3 条规则、被标记最多的 5 个文件、该优化的信号
- 目的：审计结果反哺体系自身——规则反复触发 = 规则该调了，文件反复标记 = 代码该改设计

### ⑥ FDE Skill 商业模式建议（P1）

> 来源：FDE 研报。「中国市场的务实商业模式。」

`sofagent-fde/SKILL.md` 增加 §八「商业模式建议」：
- 阶梯收费：诊断服务（收取少量费用建立信任）→ POC 小项目（跑通一个场景）→ 长期运维（按月/按年）
- 优先五类客户：外贸 / 跨境电商 / 中小财务 / 培训 / 律所
- 避开：国央企 / 大型工程类（组织交易成本远高于技术成本）
