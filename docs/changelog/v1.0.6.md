# v1.0.6 开发日志 — 编排引擎迁移：DeepAgents compose

> ao compose 的编排逻辑迁移到 DeepAgents。Sub Agent 启动器从 optional wrapper 升级为完整编排入口。
>
> 待开发 · 孔放勋

---

## 背景

v1.0.5 审查发现：launcher.ts 仅 68 行，是 optional dependency 的 thin wrapper——`createDeepAgent()` 拿到实例后没有编排逻辑。orchestrate-compare.ts 标了 `@deprecated` 但 compose 子命令仍调 `execFileSync('ao', ['compose'])`，DeepAgents 一行没写。

v1.0.6 做这件事：把 compose 的编排逻辑从 ao CLI 迁到 DeepAgents，ao 降为 fallback。

---

## 交付内容（2 件事）

### 1. DeepAgents compose 实现

用 `createDeepAgent()` 替换 orchestrate-compare.ts 中的 `execFileSync('ao', ['compose'])`：

```typescript
// 之前（v1.0.5 及以前）
const output = execFileSync('ao', ['compose', taskDesc], { timeout: AO_TIMEOUT });

// 之后（v1.0.6）
const agent = await launch(orchestratorAgent);
const result = await agent.compose(taskDesc);
```

**实现要点**：
- compose agent 的 systemPrompt 基于 workflow.yml 的节点定义
- 输出格式与 ao compose 一致（YAML 工作流定义）
- ao 仍作为 fallback——deepagents 未安装时自动降级到 `execFileSync('ao', ...)`
- `@deprecated` 标注从"v1.0.5 移除"修正为"v1.0.6 迁移核心逻辑，ao 降为 fallback"

### 2. Sub Agent 状态管理基础

为 Sub Agent 加上最基本的运行状态跟踪：

| 能力 | 实现 |
|------|------|
| Agent 注册表 | 从 `.sofagent/subagents/` 加载 YML 定义（v1.0.4 已有 registry.ts） |
| 运行状态 | 记录启动/活跃/停止时间戳到 `.sofagent/subagents/runtime.json` |
| 基本心跳 | launcher.ts 的 Agent 实例定期写 `lastActive` 到 runtime.json |

**不做的**：
- ❌ Agent 间消息传递（推到 v1.1）
- ❌ LangGraph 状态图（推到 v1.1）
- ❌ 长任务规划（推到 v1.1）
