### 2. Lingua Word 短词锚定 A/B 实验

ROADMAP 标注「v1.0 前在 fde.md 跑 A/B 对比 token + 服从率」。

**实验设计**：
- A 组：当前铁律全文展开（fde.md ~1596 字符）
- B 组：铁律用短词别名（@A1 最小变更 / @A2 先读再用 / ...）
- 指标：token 消耗、服从率（审计引擎检出违规次数对比）

**实施方式**：
- 造 10 个典型违规场景
- A 组跑 10 次 + B 组跑 10 次
- 对比审计引擎检出率
- 如果 B 组服从率 ≥ A 组且 token 省 30%+ → v1.0 切换短词
- 如果无显著差异或服从率下降 → 保留全文展开，A/B 结果写入 LIMITATIONS

**风险**：短词太短 Agent 遗忘含义。如果实验不支持切换，文档诚实标注「尝试过短词锚定，实测无收益」。

### 3. daemon 文档校准（外部反馈驱动）

**来源**：外部用户反馈（Case 025）——daemon 实际监控 think.md/fde.md hash 变化，非直接监听 git commit 审计。文档描述与实际行为有偏差。

**改动**：
- HANDBOOK daemon 章节：描述实际监控机制（hash 变化检测）
- ARCHITECTURE daemon 相关段落：对齐实际行为
- LIMITATIONS：加一条「daemon 不直接监听 git commit，通过文件 hash 变化间接检测」
- **评估**是否在 daemon 主循环加 `sofagent-audit --diff HEAD` 定时触发（如果加，作为 v1.0 增量功能；如果不加，文档标注为 v1.x 探索方向）

### 4. FDE 隐性代价文档

v0.99.9 changelog 尾部提到：「FDE/FDE.md 隐性代价（理解债 + 认知让渡）放 v1.0——FDE 正式版首秀时一起发更合适。」

**新增内容**：FDE/FDE.md 加一节「隐性代价」

| 代价 | 说明 |
|------|------|
| 理解债 | 企业员工需要理解 sofagent 的约束模型——为什么 Agent 不能直接改代码、为什么要过审计。学习曲线 1-2 周 |
| 认知让渡 | FDE 把 workflow 设计权部分让渡给 sofagent 框架——企业不再完全自由定义 Agent 行为，需在框架约束内运作 |

**约束**：写在 FDE/FDE.md 交付物章节后，不超过 200 字。不自贬——客观陈述代价，让 FDE 做出知情决策。
