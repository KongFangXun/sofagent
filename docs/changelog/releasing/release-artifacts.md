# 发布物落盘清单（每版一表 · 唯一源）

> **为什么收口**：发布物规则原散在 08（落盘铁律）/ 09（gh release 命令引用）/ 11（收尾清理）三处——生成时跨文件对规则易漏。本页为唯一源，其余文件一律指针引用。

## 命名规范（固定，不可自创）

| 产物 | 路径 | 产出时点 | 消费时点 |
|---|---|---|---|
| Release Note body | `~/Desktop/release-note-vX.Y.Z-body.md` | 阶段八步骤六（放行前给作者过目） | 阶段九步骤七（gh release `--notes-file`） |
| 发布 prompt | `~/Desktop/vX.Y.Z-pub-prompt.md` | 阶段八步骤六 | 阶段九执行方 |
| 开发 prompt（下版） | `~/Desktop/vX+1.Y-dev-prompt.md` | 阶段十一步骤六 | 下周期阶段一 |

## 五条铁律

1. **双向一致**：body 的任何修正必须同批改 devlog 源（尾链/链接/数字皆然）——发布物与提取源不一致不算定稿。
2. **元说明剥离**：devlog 内嵌源的 🔴 元说明段（不面向用户）生成 body 时必须剥掉。
3. **放行前置**：body 必须在作者放行**前**生成并过目——放行 = 授权对外发布，作者理应过目发布物本体。
4. **结构 SSOT**：body 结构对齐上一版实际发布物（`gh release view vX.Y.Z-1 --json body` 动态拉取），不凭记忆写。
5. **收尾清理**：阶段十一把本版桌面草稿（`vX.Y.Z-*.md`）归档或删除——桌面不留隔版残留。

## 检查点（生成 body 时逐条过）

- [ ] 数字口径与 devlog 逐项对账（tests / 场景 / 断言 / 包数）
- [ ] Install 段 URL/Action ref 已指本版
- [ ] 破坏性变更显著位 + 迁移动作
- [ ] 链接有效性（仓内路径 + 外链）
- [ ] 表格/空行/锚点渲染面
