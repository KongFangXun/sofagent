## 一、P0 修复（边角误报 — 合成测试发现）

v0.92 合成检测精度测试（`src/measure-detection.ts`，27 组用例）结果：FN=0% / FP≈11%。

3 个误报需修复：

### 1. deleted 文件触发 WARN（🟡 铁律 #1）

**触发条件**：diff 中只有 deleted 文件 + 无任务日志时，rule-01 返回 WARN。

**为什么是误报**：删除不需要先读——铁律 #1 的「先读再用」针对的是修改/新增文件。deleted 文件应直接 PASS。

**修复**：`rule-01-read-before-write.ts` 中，无日志 WARN 之前先检查是否只有 deleted 文件。如果 `modifiedFiles` 为空（全是 deleted），直接 PASS。

### 2. `hasTestOrBuildExecution` 漏掉 `docker build`（🟡 铁律 #3）

**触发条件**：日志中有 `docker build .` 命令，但 `hasTestOrBuildExecution` 没识别。

**为什么是漏检**：当前只匹配常见的 test/build 命令（`npm test`/`npm run build`/`yarn test`/`make` 等），`docker build` 不在列表中。

**修复**：`log-checker.ts` 的 test/build 命令列表新增：`docker build`、`docker-compose build`、`tsc`。

### 3. 低风险文件排除未生效（🟡 铁律 #7）

**触发条件**：diff 含 README.md + 一个任务相关文件时，rule-07 应排除 README 但没排除。

**原因**：低风险文件列表可能未包含 README.md，或排除逻辑在阈值计算前未生效。

**修复**：`rule-07-careful-modify.ts` 确认 LOW_RISK_FILES 含 `README.md`、`CHANGELOG.md`、`LICENSE` 等文档文件，且在计算不相关文件比例前先排除。
