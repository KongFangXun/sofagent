## 交付内容（3 件事）

### 1. FDE Sub Agent（基于 DeepAgentsJS + LangGraph + Agency Agents）

**技术栈**：底层是 LangGraph 的状态图（graph-based 状态机），上层是 DeepAgentsJS 的 `createDeepAgent` API（batteries-included harness），岗位定义引用 Agency Agents 模板。

**不是写一个新的 Agent 定义——是用 Agency Agents 的岗位模板来定义它。**

从 Agency Agents 仓库中选工程/运维/测试部门的模板，改造成 FDE 所需的 Sub Agent 角色：

```yaml
# .sofagent/subagents/fde-sub-agent.yml
name: "FDE Sub Agent"
runtime: "deepagentsjs"      # createDeepAgent + LangGraph state graph
template: "agency-agents/engineering/engineering-devops-automator.md"
custom:
  role: "常驻 FDE 工程师——读代码、跑测试、生成交付手册、监控 Workflow"
  tools:
    - read_code           # deepagentsjs 内置
    - run_audit           # 调用 sofagent-audit
    - run_tests           # npm test / pytest
    - generate_handbook   # FDE.md 模板填充
  memory:
    - LangGraph checkpoint 持久化
    - .sofagent/task/logs/
  schedule: "always-on"   # 常驻不退出
```

**设计约束**：
- Agency Agents 模板的 install.sh 已支持 `--tool openclaw`——直接用这个转成 OpenClaw 格式
- 每个 Workflow 节点都可以孵化一个定制的 FDE Sub Agent（基于同一个模板 + 不同 skill）
- Sub Agent 的评估数据（scoring.md）自动喂给 SkillOpt（第 3 件事）
- Sub Agent 配置自身的 A/B 自进化（同一 task Agent A vs Agent B，评分胜者替换）在 v1.0.4 完整实现
- **Sub Agent 是牛马不是宠物**——任何异常状态不修复，直接销毁重建。LangGraph checkpoint 保证状态不丢失。借鉴 Anthropic Managed Agents 的大脑-双手解偶原则：「Agent 为模型写的修补代码注定过时，模型进化速度快于代码重构速度」

### 2. Audit Sub Agent（含成本审计，独立，按需启动）

独立的语义级审查 Agent。和 sofagent-audit 的 git diff 硬审计不同——它做「这个变更真的解决了问题吗？」这种软审计，**同时检查成本健康度**。

```yaml
# .sofagent/subagents/audit-sub-agent.yml
name: "Audit Sub Agent"
runtime: "deepagentsjs"
trigger: "on-audit-alert"   # A1/A2 违规时自动启动
  # 或 "scheduled" 定时巡检所有 Workflow
tools:
  - cross_repo_audit       # 跨仓库对比审计
  - semantic_review        # 语义级代码审查
  - cost_check             # 成本基线检查
  - workflow_check         # 检查所有 FDE 定义的 Workflow 是否健康
  - escalation             # 通过 OpenClaw 发消息给负责人
```

**和 sofagent-audit 的分工**：

| | sofagent-audit（v1.0） | Audit Sub Agent（v1.0.3） |
|------|------|------|
| 时机 | git commit 时（pre-commit hook） | 违规后 / 定时 |
| 速度 | 毫秒级 | 秒-分钟级 |
| 成本 | 零 token 消耗 | LLM 调用有成本 |
| 方法 | git diff 字符串匹配 | 语义分析 + 跨 repo 对比 + 成本基线 |
| 输出 | PASS/WARN/FAIL + exit code（阻断 commit） | 分析报告 + 改进建议（不阻断） |
| 覆盖 | A1-A11（硬审计） | 语义审查 + 跨 repo + 成本 + Workflow 巡检 |

**sofagent-audit 保留**——pre-commit hook 必须毫秒级出结论，不能等 LLM 返回。

#### 成本审计维度

Audit Sub Agent 定时巡检（每天凌晨），读 task/logs 提取 token 消耗数据：

```typescript
// sofagent/audit/src/cost-baseline.ts（新建 ~50 行）
function calculateBaseline(taskType: string): { mean, stddev } {
  const history = readTaskLogs().filter(t => t.type === taskType);
  const tokens = history.map(t => t.tokenUsage?.total ?? 0);
  return { mean: average(tokens), stddev: stdDeviation(tokens) };
}

function isAnomaly(current: number, baseline: Baseline): boolean {
  return current > baseline.mean + 2 * baseline.stddev;
}
```

| 检查项 | 条件 | 输出 |
|------|------|------|
| 同一 task 重复跑 | > N 轮未收敛 | ⚠️ 成本异常 |
| 单次 task Token 消耗 | 超过基线 2σ | ⚠️ 成本异常 |
| 常驻 Agent 闲置 | 24h 无活动 | ⚠️ 建议降级 |
| API 重试次数 | 超过阈值 | ⚠️ 配置可能有问题 |

**数据源**：task/logs 中的 token usage 记录（Agent 平台提供），不是 git diff。成本审计属于 Audit Sub Agent 的语义分析范畴，不改动 v1.0 审计引擎的 git diff 规则。

**冷启动**：新装系统没有历史数据，无法算 baseline。前 N 条（默认 10 条）同类 task 只做基线积累，不触发异常检测。N 条之后才开始 `mean + 2σ` 判定。

### 3. SkillOpt 自进化引擎

FDE 离场时生成的定制 Skill 不是一次性写完就固定的——接入微软 SkillOpt，让 Skill 基于真实的 Agent 运行数据自我进化。

**SkillOpt 是什么**：
- 微软开源（MIT）的 Python 框架——`pip install skillopt`
- 把 Skill 文档当成神经网络训练——有 epoch、batch size、learning rate、validation gate
- 输出 `best_skill.md`（300-2000 tokens），运行时零推理开销
- **原生支持 OpenClaw 作为执行后端**

**怎么跑**：本地安装 → daemon 通过 CLI subprocess 调用。唯一成本是训练过程中消耗的 LLM API token。

**训练流水线**：
```
daemon 检测 task/logs 累积超过阈值（config 中 trigger 值）
  → 调 skillopt-sleep（CLI subprocess）
  → 读当前 Skill + 收集 task/logs 轨迹 + scoring 数据
  → 跑训练循环：Rollout → Reflect → Aggregate → Select → Update → Evaluate
  → 输出 candidate_skill.md
  → sofagent validation gate 对比 candidate vs 现任 Skill
  → 严格提升 → 替换 Skill 文件 → git commit（审计可追溯）
  → 未提升 → 丢弃 → 记录到 think.md
```

**和 Sub Agent A/B 自进化的区别**：SkillOpt 优化的是 Skill 文档（文本内容）。Sub Agent A/B 自进化优化的是 Agent 配置（tool 组合、middleware 选择、prompting 策略）——后者在 v1.0.4 引入 eval harness 后完整实现。

**企业看到什么**：
```bash
$ sofagent-audit --doctor

Skill 自进化状态：
  AP-审批      v3 · 最近优化 2026-07-10 · 比 v2 提升 +12.3 分
  AP-执行      v1 · 已累积 8/10 条任务 · 2 条后触发首次优化
  工程-部署    v5 · 最近优化 2026-07-09 · 持平（gate 拒绝 v6）
```

## 项目结构：agents/ + LOOP/

### 设计原则：引用的不重写

v1.0.3 的 Agent 定义遵循一条核心原则：**Agency Agents 有模板的，引用模板 + 叠加差异；没有的，自创。** 不凭空造轮子。

| Agent | 模板来源 | 关系 |
|-------|------|------|
| engineering-minimal-change-engineer | `engineering/engineering-minimal-change-engineer.md` | 基座模板 + sofagent 审计约束层 |
| engineering-code-reviewer | `engineering/engineering-code-reviewer.md` | 基座模板 + sofagent CLI 审计分工说明 |
| security-compliance-auditor | `security/security-compliance-auditor.md` | 基座模板 + sofagent 定制化审计对象映射 |
| forward-deployed-engineer | 无对应模板 | ⚠️ 自创（FDE 是 sofagent 独有概念） |

### agents/ — 统一 Agent 库

```
agents/
├── README.md              ← 格式标准、模板来源、对接方式
├── forward-deployed-engineer.md           ← FDE 部署智能体（自创模板）
├── security-compliance-auditor.md         ← 合规审计智能体（security-compliance-auditor + sofagent 定制）
├── engineering-minimal-change-engineer.md        ← LOOP 执行者（engineering-minimal-change-engineer + sofagent 约束）
└── engineering-code-reviewer.md        ← LOOP 审查者（engineering-code-reviewer + sofagent 分工）
```

每个 Agent 是单个 `.md` 文件，遵循 Agency Agents 的 frontmatter + 结构化章节格式。文件中标注了基座模板的链接和 sofagent 的差异部分。转换为 OpenClaw 格式通过 `agency-agents-zh/scripts/convert.sh --tool openclaw`。

### LOOP/ — 实验性自迭代编排

```
LOOP/
├── README.md              ← 实验说明、怎么用、欢迎修改
└── LOOP.md                ← 完整设计：Mermaid 流程图 + DeepAgentsJS 伪代码 + 6 步验证计划
```

LOOP 是用 sofagent 自己的 Agent 和审计引擎开发 sofagent 的实验。核心循环：

```
人类下任务 → engineering-minimal-change-engineer 写代码 → git commit
    → sofagent-audit (pre-commit hook) 硬证据审计
    → engineering-code-reviewer 代码审查
    → 人类确认 → git push → 下一轮
```

4 层防线：engineering-minimal-change-engineer 自检（build + test）→ sofagent-audit 硬证据审计 → engineering-code-reviewer 语义审查 → 人类最终确认。

### DeepAgentsJS 集成（计划中）

当 engineering-minimal-change-engineer 和 engineering-code-reviewer 各自通过 OpenClaw 跑通后，用 DeepAgentsJS 的 `createDeepAgent()` API 和 LangGraph `StateGraph` 串成自动化流程（伪代码见 `LOOP/LOOP.md`）。DeepAgentsJS 负责 Agent 的运行基础设施（中间件、工具系统、子 Agent 管理），LangGraph 负责状态流转和条件路由。

### LOOP 作为独立 Skill（五件套 + package.json）

LOOP 镜像 FDE 结构：SKILL.md + LOOP.md + README + quick-start + loop-install.sh + package.json。`package.json` 声明子项目身份（`private: true`），含 `sofagent.dependsOn` / `sofagent.optionalDependsOn` / `sofagent.platforms` 字段。`bump-version.sh` 升级时自动覆盖 FDE/ 和 LOOP/ 的 package.json。

### 安装隔离

LOOP 不会随 sofagent 主项目自动安装。三者独立安装：sofagent 底座（必装）→ FDE（外层循环需要）→ LOOP（需要自迭代时装）。`loop-install.sh` 检查前置依赖但不强制。

4 份文件移入 `docs/verification/`：releasing.md / fresh-eyes-review.md / regression-checklist.md / openclaw-acceptance-test.md。LOOP 文档中已更新路径引用。
