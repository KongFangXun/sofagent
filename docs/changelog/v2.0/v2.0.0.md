## 二、网络出口治理面（Codex Guardian 网络审批启发 · 2026-09-16 用户拍板排期本版）

> **形态归属**：`[主干]`（判定·出站裁决 + 留痕挂链；边界自述「策略契约 + 审计，不自建拦截器」）**+ `[通道]` 成分**（拦截器接口——裁决契约留约束层、egress proxy / OS 沙箱实现出约束层，章节原文自陈「对齐 TrainChannel 通道形态」）｜ L1 关档


> 📋 **研究收编**（codex-rs [protocol/src/approvals.rs](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/approvals.rs) 网络审批类型）：Codex 给网络访问定义了 host 粒度的审批面——`NetworkApprovalContext{host, protocol}` 按 host 裁决 Allow/Deny，配 `NetworkPolicyAmendment` 增量修正。与本版主题同源：数据主权不只要「管进」（G10 授权读取白名单——读什么要授权），也要「管出」（Agent 能访问哪些 host 无人管时，数据外泄通道敞开）。
>
> ⚠️ **马鞍边界（四问过筛已过，边界在此）**：只做**策略契约 + 审计挂链**（host 白名单声明面、裁决事件落审计链）——不自建 egress proxy / 网络拦截器（对齐「router 本体由工程交付、约束层不自研」既有边界，拦截器实现是执行面，开源生态已有成熟轮子）。

### 交付

| 组件 | 能力 |
|------|------|
| **host 白名单声明面** | workflow/节点声明允许出站的 host 清单（默认空 = 全拒，opt-in——对齐 G10 模式） |
| **出站裁决审计** | 出站访问裁决（host×Allow/Deny）落审计链（HMAC 挂链——与 G10 读取审计对称，「管进」+「管出」两翼齐备） |
| **拦截器接口** | 裁决接口开放给外部拦截器（egress proxy / OS 沙箱，对齐 TrainChannel 通道形态——接口+事件契约+审计留约束层，实现在外） |

### 验收标准

- [ ] host 白名单声明面可用（默认空全拒，声明后放行）
- [ ] 出站裁决进审计链（与 G10 读取审计对称）
- [ ] 外部拦截器可接入裁决接口（通道形态，不绑实现）
- [ ] `npm test` 全绿
