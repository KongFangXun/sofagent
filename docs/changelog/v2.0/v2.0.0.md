## 一、模型路由层（Harness 路由 · 云端/本地分流）

> 📋 **ROADMAP 分层模型架构**：云端 32B+ 负责规划推理 → 本地 7B 执行多步 workflow → 本地 0.5B 跑管道层。**引擎层只做模型路由（model-router.ts 已有四档插槽），精调 pipeline 属模型层非开源范围。路由层可提前到 v2.x 做（不依赖精调模型）。**

### 交付

| 组件 | 能力 |
|------|------|
| **路由策略引擎** | 任务分级路由：规划类→云端大模型 / 执行类→本地 7B / 管道类（模板/格式/字段提取）→本地 0.5B——按任务类型+数据敏感度双维决策 |
| **敏感度路由** | 数据分级（公开/内部/敏感）自动决定可否走云端——敏感数据强制本地（fail-closed） |
| **路由可解释** | 每次路由决策附 routeReason（复用 v1.3.6 EndpointProfile + route-policy 模式） |
| **降级梯队** | 云端不可用→本地承接（复用 v1.3.6 分级降级梯队） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/router/policy-engine.ts` | 新建 | 任务×敏感度双维路由决策 |
| `engine/orchestrator/src/model-registry.ts` | 修改 | 本地模型端点注册（7B/0.5B 档位） |

### 验收标准

- [ ] 三级任务路由可用（规划→云/执行→本地7B/管道→本地0.5B）
- [ ] 敏感数据强制本地路由（fail-closed，配置错误时拒绝执行）
- [ ] 每次路由附 routeReason
- [ ] 云端不可用自动降级本地
- [ ] `npm test` 全绿

## 三、凭证隔离 Vault（OMA 启发）

> 📋 **探索方向表收编**：沙箱发 HTTP 请求时动态注入凭证、Agent 代码碰不到 token——执行层安全基础设施，v1.3.7 虚拟 key 凭证边界已部分覆盖，完整 Vault 属 v2.x+ 方向 → 本版收编。

### 交付
