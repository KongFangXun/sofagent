## 背景

### v1.0.7 留下的缺口

v1.0.7 首次预装了 FDE 和 Audit 两个 Agent。但有一个根本问题没回答：

**FDE 离场之后，谁来持续优化客户的 AI workflow？**

v1.0.7 的 FDE Agent 只在部署时有用——FDE 进场，用 @sofagent-fde 梳理工作流，FDE 离场，Agent 也走了。客户的 AI 节点跑起来之后，没有人读 audit 报告的趋势，没有人识别"上周 3 个节点有 knowledge-domain 漏洞"，没有人提出优化建议。

v1.0.8 的核心突破：**FDE Agent 获得两个模式**。

### 文件系统审计

v1.0.7 及以前，审计引擎只在 `git commit` 时触发（commit-msg hook）。这意味着：
1. **非开发者用不上**——客服、运营、数据分析人员用 AI 改 Excel/Word/报告，不产生 git commit
2. **审计只在开发者世界工作**——电脑上必须装 git，用户必须有 commit 行为

v1.0.8 内嵌 `isomorphic-git`（纯 JS Git 实现，~2MB），daemon 监控指定目录的文件变更，变更发生时直接跑审计——不需要 git commit，不需要用户操作，完全被动。

## 交付内容（6 件事）

### 1. FDE Agent 双模式：部署 + 持续优化（⭐ 核心）

FDE Agent 从"部署工程师"升级为**基础设施 Agent**——和 Audit Agent 平级，所有 workflow 节点都必须引用。

**两种模式**：

```
部署模式（v1.0.7 已有）
  @sofagent-fde 梳理采购流程
    → 四阶段十一��步：进场 → 挖掘 → 交付 → 离场
    → FDE 工具：识别 AI 节点、构建知识库、配置约束层

持续优化模式（v1.0.8 新增）
  @sofagent-fde sustain
    → 自动读 audit 报告（.sofagent/history.jsonl）
    → 自动读 think.md 趋势（"最近两周什么操作反复出错"）
    → 自动读 scoring 趋势（"哪个节点评估分在下降"）
    → 生成优化建议："建议调整销售节点的 knowledge-domain.include，最近 5 次 audit 发现它读到了不属于它的 entity"
```

**双 Agent 闭环**：

```
每个 AI 节点完成任务后：
  ├── @sofagent-audit    → "你做得合规吗？"（底线，P0/P1 分级）
  └── @sofagent-fde sustain → "你能不能做得更好？"（上限，优化建议）

Audit 防止退步，FDE Agent 推动前进
```

**实现要点**：
- `builtin-agents.ts` 中 FDE Agent 新增 `mode` 字段：`deploy` | `sustain`
- sustain 模式下的 systemPrompt 从持续优化师角度定义权重：audit 报告趋势 > think.md 反思趋势 > scoring 数据
- `sofagent-audit subagent run fde --mode sustain --task "巡检所有节点"`
- 定时任务：daemon 支持 `cron: "@weekly"` 触发 FDE Agent 周度巡检
- 所有 Agent 的 SKILL.md 强制引用 Audit + FDE 两个基础设施 Agent

### 2. 内嵌 isomorphic-git

`@sofagent/audit` 的 dependencies 新增 `isomorphic-git`（MIT，纯 JS 实现）。

**为什么不用系统 Git**：

| 方案 | 体积 | 需要系统装 Git？ | 二进制依赖 |
|------|------|:---:|:---:|
| 系统 `git` 命令 | 0（已有） | ✅ 必须 | ❌ |
| **isomorphic-git** | ~2MB | ❌ 不需要 | ❌ 纯 JS |
| libgit2（node-git） | ~5MB | ❌ | ✅ native addon 需编译 |

sofagent-audit 已有 Node.js 运行时，内嵌 isomorphic-git 后用户零额外安装。

**改动文件**：
- `package.json`：dependencies 加 `"isomorphic-git": "^5.x"`
- `diff-parser.ts`：新增 `generateDiff()` 函数，内部用 isomorphic-git 在临时 repo 做 diff

**实现要点**：
- 非开发者场景：daemon 在工作目录下 init 隐藏 repo（`.sofagent/.git-shadow/`），每次文件变更后 add + diff
- 开发者场景：仍然优先用系统 git（性能更好），isomorphic-git 仅作为 fallback
- 不暴露 git 操作给用户——用户永远不需要知道有 git 存在

### 3. daemon 文件系统监控（fs-watch）

daemon 新增文件系统监控模块，监听配置的目录变更：

```typescript
// daemon/fs-watch.ts（新增）
import chokidar from 'chokidar';

const watcher = chokidar.watch(watchPaths, {
  ignored: [/node_modules/, /\.sofagent\/\.git-shadow/, /\.git/],
  persistent: true,
  ignoreInitial: true,
});

// 防抖：连续变更合并为一次审计
let debounceTimer: NodeJS.Timeout;

watcher.on('all', (event, path) => {
  clearTimeout(debounceTimer);
  debounceTimer = setTimeout(() => {
    runFilesystemAudit(changedFiles);
  }, 5000); // 5 秒防抖
});
```

**配置文件**（`.sofagent/watch.yml`，新增）：

```yaml
# 监控的目录（相对于项目根）
paths:
  - "./"
  - "./docs/"

# 排除的文件/目录
ignore:
  - "node_modules/"
  - ".sofagent/.git-shadow/"
  - "*.tmp"

# 防抖时间（毫秒）
debounce_ms: 5000

# 审计模式：text-only | all
# text-only: 只审计文本文件（.md/.ts/.js/.json/.yaml/.csv 等）
# all: 也审计二进制文件（行为级规则，v1.0.9 实现）
mode: text-only
```

**设计要点**：
- `chokidar` 跨平台（macOS fsevents / Linux inotify / Windows ReadDirectoryChangesW）
- 5 秒防抖：AI 批量改文件时合并为一次审计，避免逐文件触发
- 文本文件判定：按扩展名 + MIME type（`text/*` + 常见代码/文档格式）
- 文本文件变更 → 生成 diff → 跑现有 A1-A15 规则
- 二进制文件变更 → v1.0.8 只记录到 history.jsonl（`"binary_change"` 事件），v1.0.9 加行为级规则

**审计语义变化**（诚实声明）：

| 维度 | git commit 审计（v1.0.7） | 文件系统审计（v1.0.8） |
|------|------|------|
| 触发 | 用户主动 commit | 文件写入自动触发 |
| 拦截能力 | ✅ 阻断 commit | ❌ 文件已改完，只能告警 |
| 回溯能力 | ✅ git 历史 | ✅ isomorphic-git 快照 |
| 证据 | git diff（硬证据） | 文件 diff（硬证据） |
| 适用人群 | 开发者 | 开发者 + 非开发者 |

**文件系统审计是事后告警，不是事前拦截**——文件已经改完了，审计发现违规后告警 + 可选回滚建议。这是架构层面的诚实声明。

**监控盲区**：daemon 只能监控 `watch.yml` 中配置的目录。Agent 把文件写到不被监控的目录时，审计引擎完全无感知。这不是运行时沙箱，不能保证覆盖所有文件变更。需在 SECURITY.md 中诚实声明。

### 4. 快照回溯

每次文件变更审计完成后，daemon 自动做一次 git 快照（`isomorphic-git commit`）：

```typescript
// daemon/snapshot.ts（新增）
async function createSnapshot(repoDir: string, auditResult: AuditResult): Promise<string> {
  const { commit } = await import('isomorphic-git');

  // 审计通过 → 快照标记为 verified
  // 审计告警 → 快照标记为 warned（仍然快照，只是标记不同）
  const sha = await commit({
    fs,
    dir: repoDir,
    message: `audit-snapshot: ${auditResult.exitCode === 0 ? 'PASS' : 'WARN'} ${new Date().toISOString()}`,
    author: { name: 'sofagent-daemon', email: 'daemon@sofagent.local' },
  });

  return sha;
}
```

**快照用途**：
- 用户可以 `sofagent-audit --revert <snapshot-sha>` 回滚到任意快照
- `sofagent-audit --history --visual` 查看快照时间线（v1.0.9 实现可视化）
- 快照存储在 `.sofagent/.git-shadow/`，不污染用户的 git 仓库

**不做的**：
- ❌ 不自动回滚——回滚是人的决策
- ❌ 不上传快照到任何远端——纯本地
- ❌ 不对用户的 .git 做任何操作——隐藏 repo 是独立的

修复（`sofagent/audit/src/verify/checks.ts`）：改为「部署锚点优先 + 从 `__dirname` 向上遍历查找含 cleanup.sh/audit.sh 的 scripts/ 父目录」+ 3 级兜底。

修复后复验：
- `node sofagent/audit/dist/verify.js` → §10 cleanup.sh/audit.sh **PASS**，39 通过 / 7 警告 / 0 失败（警告均为非阻断项：7 天无任务记录、daemon 未运行等）
