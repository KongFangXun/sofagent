# v1.0.8 开发日志 — TencentDB Agent Memory 集成：L3 用户画像自动注入

> sofagent 的 knowledge/ 从"手写百科"变成"自动生长的知识库"。装上 TencentDB Agent Memory 后，daemon 自动同步 persona.md，加载链注入用户画像。
>
> 待开发 · 孔放勋

---

## 背景

sofagent 的知识库有 L0（think.md 原始）→ L1（entities 事实）→ L2（concepts 场景），缺 L3 用户画像。L3 是 FDE 离场后"AI 节点越用越聪明"的关键——没有用户画像，AI 节点每次对话都从零开始，不知道用户的偏好、习惯、业务边界。

[TencentDB Agent Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory)（MIT，OpenClaw 原生插件）已经解决了这个问题：每次对话结束自动提取原子事实（L1），每 50 条触发画像生成（L3），下次对话前自动召回注入。Token 消耗降 61%，任务成功率提升 51%。

v1.0.8 做这件事：把 TencentDB 的 L2/L3 产物（Markdown 文件）接入 sofagent 的加载链和 daemon Ingest。

## 交付内容（3 件事）

### 1. daemon Ingest 加扫描源

检测 `~/.openclaw/memory-tdai/persona.md` 的文件 hash 变化。变了就同步到项目的 `knowledge/entities/persona.md`。

**实现要点**：
- 跟现有 daemon Ingest 检测 `think.md` hash 变化是同一个模式，不引入新机制
- persona.md 通常 500-2000 字，同步开销可忽略
- `scene_blocks/` 下的 L2 场景文件同理同步（可选，默认开启）
- 同步方向单向：`~/.openclaw/memory-tdai/` → `.sofagent/knowledge/`，sofagent 永远不写 TencentDB 的文件

**防断裂机制**（解决 daemon Ingest 依赖外部插件的问题）：

| 风险 | 解法 |
|------|------|
| TencentDB 未安装或 `memory-tdai/` 不存在 | daemon 启动时检测目录存在性，不存在则静默跳过（不报错、不告警） |
| TencentDB 升级后改了文件名或格式 | daemon 只读文件内容做 hash 比较 + 内容同步，不解析文件内部结构。文件名变了的检测方式：扫描 `memory-tdai/` 下所有 `.md` 文件，按 mtime 排序取最新 |
| persona.md 正在被 TencentDB 写入（写一半） | hash 比较 + 文件大小稳定检查（连续两次扫描大小一致才同步） |
| 多个 OpenClaw agent 产生不同的 memory-tdai 子目录 | 按 agent name 分目录同步到 `knowledge/personas/{agent-name}.md` |

### 2. 加载链第 4 层注入 persona.md

在现有加载链（L1 宪法 → L2 规则 → L3 知识库 → L4 ontology）的基础上，第 3 层 knowledge/ 注入时额外读 persona.md 前 500 字。

```typescript
// 加载链第 3 层：knowledge/（已有）
const knowledgeContent = loadKnowledge(knowledgeDir);

// v1.0.8 新增：注入 persona.md 前 500 字（如果有）
const personaPath = join(knowledgeDir, 'entities', 'persona.md');
if (existsSync(personaPath)) {
  const persona = readFileSync(personaPath, 'utf-8').slice(0, 500);
  knowledgeContent += `\n\n## 用户画像（自动生成）\n${persona}\n`;
}
```

**实现要点**：
- persona.md 不存在时静默跳过（不影响未安装 TencentDB 的用户）
- 500 字上限防止 persona 过长吃掉 context（persona.md 通常 1000-3000 字）
- 注入位置在 knowledge/ 层尾部，优先级低于 entities/concepts（用户画像是参考信息，不是硬约束）

### 3. install.sh 加 --with-memory 可选参数

```bash
# 安装 sofagent + 自动装 TencentDB 插件
./install.sh --with-memory

# 不加参数 = 纯 sofagent 安装（默认行为不变）
./install.sh
```

**实现要点**：
- `--with-memory` 先检查 `openclaw` 命令是否可用
- 可用则跑 `openclaw plugins install @tencentdb-agent-memory/memory-tencentdb && openclaw gateway restart`
- 不可用则输出提示："TencentDB Agent Memory 需要 OpenClaw 底座。请先安装 OpenClaw，或跳过此选项手动安装。"
- 不影响现有安装流程（无参数 = 行为不变）

## 和现有组件的关系

| 组件 | 受影响 | 说明 |
|------|:----:|------|
| daemon (daemon.sh) | ⚡ 增强 | Ingest 规则加 `memory-tdai/` 扫描路径 |
| 加载链 (config-loader.ts) | ⚡ 增强 | 第 3 层注入 persona.md |
| install.sh | ⚡ 增强 | 加 `--with-memory` flag |
| knowledge/ 目录结构 | 不变 | persona.md 作为 entities/ 下的一个文件 |
| 审计引擎 | 不变 | persona.md 是知识库内容，不参与审计规则 |
| ontology 合并引擎 | 不变 | persona.md 不含 frontmatter relations，合并引擎自动跳过 |

## 不做的

- ❌ **不直接依赖 TencentDB 的 SQLite**——只读 Markdown 产物，不碰 DB。SQLite 是 TencentDB 的实现细节
- ❌ **不调 TencentDB 的 HTTP API**——不走 `tdai_memory_search` tool。sofagent 读文件，不调 API
- ❌ **不做 L1→L2 自动提炼**——TencentDB 自己做 L1 提取和 L2 场景归纳，sofagent 只消费最终产物
- ❌ **不做多设备 persona 合并**——v1.2.x 多设备协同时才需要

## 技术细节：TencentDB 实际数据结构

基于源码分析（v1.0.0）：

```
~/.openclaw/memory-tdai/
├── conversations/
│   └── 2026-07-12.jsonl       # L0 原始对话记录
├── records/
│   └── 2026-07-12.jsonl       # L1 提取的原子事实
├── scene_blocks/
│   ├── 工具偏好.md             # L2 场景归纳（Markdown）
│   └── 代码风格.md
├── persona.md                  # L3 用户画像（Markdown）← sofagent 读这个
├── vectors.db                  # SQLite + sqlite-vec（L0/L1 检索用）← sofagent 不碰
├── .metadata/
│   ├── scene_index.json
│   ├── checkpoint.json
│   └── manifest.json
└── .backup/                    # 自动备份
    ├── persona/
    └── scene_blocks/
```

**sofagent 只读两个东西**：
1. `persona.md` — L3 用户画像（注入加载链）
2. `scene_blocks/*.md` — L2 场景归纳（同步到 knowledge/concepts/，可选）

**关键配置**（来自 `openclaw.plugin.json`）：
- `persona.triggerEveryN`：默认 50 条新记忆触发画像生成
- `pipeline.everyNConversations`：默认每 5 轮对话触发 L1 批处理
- `pipeline.enableWarmup`：新 session 从 1 轮触发开始翻倍加速
