# v1.4.9 开发日志 — 设备接入版（多设备 Harness 中间层）

> 📋 **已排期。** 前置依赖：v1.3.1（Agent 身份码 Ed25519）+ v1.3.8（daemon 心跳探针 `--check-alive`）+ v1.4.4（通用脱敏管线）+ v1.4.7（G6 可见性 / G7 租户路径 / G8 cron 模板）

## 定位

> 商业产品层的多设备数据协同诉求：企业数据散落在**个人电脑（BYOD）**、**AI 节点设备**（Mac Mini 常驻）、**AI 模型一体机**（内置数据）上，平台要从这些设备读取数据做协同。**平台不直连设备**——设备侧必须有约束层承接：身份、授权、脱敏、审计、计量。本版把引擎层定位为多设备 Harness 中间层（承上启下：设备数据经治理后上平台，平台任务经治理后下设备）。
>
> **与 v1.4.7 平台接口版的关系**：v1.4.7 管「平台要的数据」（缺口/绩效/可见性/租户/账单——面向平台消费），v1.4.9 管「设备给的数据」（注册/心跳/授权读取/主动上行——面向设备供给）。两版合起来构成完整的平台-引擎-设备三层协同。

| 设备类型 | 形态 | 引擎侧角色 |
|---------|------|-----------|
| **个人电脑（BYOD）** | 装用户侧 Agent（DSH / WorkBuddy），经 CLI + MCP 协同 | 任务执行端 + 数据源（经 G10 授权白名单读取） |
| **AI 节点设备** | Mac Mini 常驻一起跑 | 常驻执行节点：daemon 巡检 + 首部署 cron（G8）持续产出 + 计量出账 |
| **AI 模型一体机** | 内置模型 + 数据的盒子 | 本地推理 + 本地数据面（数据不出设备，只有脱敏后的结果/结论上行） |

## 一、设备注册/发现与心跳（G9 · MCP `device_register` / `device_list`）

### 定位

> 设备接入的第一步：谁在线、能干什么、健康吗。设备身份复用 v1.3.1 Agent 身份码 Ed25519（设备 = 一个 Agent 实例，身份体系零新建），健康复用 v1.3.8 daemon 心跳探针。

### 交付

| 组件 | 能力 |
|------|------|
| **`device_register` MCP tool** | 设备上线注册：身份码验签（fail-closed）+ 设备类型（pc / node / appliance）+ 能力声明（挂载的 MCP / skill / 数据源清单） |
| **`device_list` MCP tool** | 设备清单查询：按租户/类型/能力过滤，含最后心跳时间与在线状态 |
| **心跳上报** | daemon 心跳探针定期上报（复用 v1.3.8 `--check-alive` 语义），超时判定离线 |
| **离线告警** | 离线判定触发 webhook 推送（复用 daemon 推送通道） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/mcp/src/tools/device-register.ts` | 新建 | `device_register` tool |
| `engine/mcp/src/tools/device-list.ts` | 新建 | `device_list` tool |
| `engine/daemon/src/device-registry.ts` | 新建 | 设备注册表（身份 + 能力 + 心跳状态，HMAC 留痕） |
| `engine/daemon/src/__tests__/device-registry.test.ts` | 新建 | 单测（验签 fail-closed / 心跳超时 / 能力声明边界） |

### 验收标准

- [ ] 设备注册后 `device_list` 可查（身份/类型/能力/最后心跳/在线状态）
- [ ] 伪造身份码注册被拒（fail-closed）
- [ ] 心跳超时判离线并触发 webhook 告警
- [ ] 注册表 HMAC 留痕可追溯

## 二、设备侧数据面授权读取（G10 · 数据目录白名单 + `device_data_query`）

### 定位

> 设备上的数据怎么「被授权地」给平台——G6 visibility 管 workflow 节点级可见性，G10 管设备数据目录级授权。**默认空白名单 = 全不暴露**（opt-in 模型）；读取全程过审计引擎，这是「平台直连设备裸奔 vs 过约束层治理」的分界线。

### 交付

| 组件 | 能力 |
|------|------|
| **数据目录白名单** | 设备配置声明可暴露的数据目录/数据源（config.yml 数据面清单，默认空 = 全不暴露，opt-in 授权） |
| **`device_data_query` MCP tool** | 按白名单 + 请求方授权范围读取，结构化返回（不落原始路径） |
| **脱敏联动** | 敏感字段出设备前经 v1.4.4 通用脱敏管线处理 |
| **审计留痕** | 每次读取进 audit history（谁/何时/读了什么/依据什么授权）——HMAC 链天然覆盖 |
| **计量进账** | 读取动作进 worklog + cost（商业平台计量计费数据源） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/core/src/device-data-policy.ts` | 新建 | 数据面白名单解析 + 授权判定（默认空 = 全拒） |
| `engine/mcp/src/tools/device-data-query.ts` | 新建 | `device_data_query` tool（白名单校验 → 脱敏 → 返回） |
| `engine/core/src/__tests__/device-data-policy.test.ts` | 新建 | 单测（空白名单全拒 / 白名单边界 / 授权越界拒绝） |

### 验收标准

- [ ] 空白名单设备对任何读取请求返回拒绝（fail-closed）
- [ ] 白名单内路径可读、白名单外路径拒绝
- [ ] 返回内容经脱敏管线（敏感字段不出设备）
- [ ] 每次读取在 audit history 有完整留痕
- [ ] 读取计量进 worklog/cost

## 三、数据上行通道（G11 · 采集声明 opt-in → WAL 暂存 → 加密上行 → 审计计量）

### 定位

> G10 管「平台**拉**数据」（平台发起、白名单校验、拉取式读取），G11 管「设备**推**数据」（设备/节点侧发起、主动上报）。两类场景：① 一体机本地推理的**结果/结论上行**（原始数据不出设备，只有脱敏后的结论上平台）② AI 节点持续产出的**计量/心跳/审计摘要上行**（G8 首部署 cron 持续出账的云端回传）。地基已有八成——白名单授权（G10 同源）、WAL 断点续传（v1.3.8 daemon 通道复用）、加密（AES-256-GCM v1.3.8）、审计（HMAC 链）、计量（worklog/cost）、设备身份（Ed25519 v1.3.1）——缺的是把这些散落能力补成**一等公民 tool 化**的上行通道。

### 交付

| 组件 | 能力 |
|------|------|
| **采集声明（opt-in）** | 设备配置声明「哪些数据可上行」（config.yml 采集清单：数据类别 + 频率 + 目的地，默认空 = 不上行，opt-in 模型与 G10 白名单同源） |
| **WAL 暂存** | 上行队列本地预写日志（复用 v1.3.8 daemon WAL 通道语义）——断网/平台不可达时先落盘不丢，恢复后续传 |
| **断点续传** | 按 WAL 游标续传（offset + ack 确认，已确认段不重传） |
| **加密上行** | 出设备前 AES-256-GCM 加密（复用 v1.3.8 静态加密栈），平台侧验签解密 |
| **`device_data_push` MCP tool** | 上行通道 tool 化：手动/定时触发上行（daemon 定时器或 skill 侧显式调用），push 前过白名单校验 + 脱敏管线 |
| **审计留痕** | 每次上行进 audit history（谁/何时/推了什么/依据什么声明）——HMAC 链覆盖 |
| **计量进账** | 上行动作进 worklog + cost（上行数据量/次数进计量） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/core/src/device-upload-policy.ts` | 新建 | 采集声明解析 + 上行白名单判定（与 G10 device-data-policy 同源，默认空 = 不上行） |
| `engine/mcp/src/tools/device-data-push.ts` | 新建 | `device_data_push` tool（声明校验 → 脱敏 → 加密 → push） |
| `engine/daemon/src/upload-wal.ts` | 新建 | 上行 WAL 暂存 + 断点续传（复用 v1.3.8 scheduler/WAL 通道语义） |
| `engine/daemon/src/__tests__/upload-wal.test.ts` | 新建 | 单测（断网暂存 / 恢复续传 / 游标 ack / 越界拒绝） |
| `engine/core/src/__tests__/device-upload-policy.test.ts` | 新建 | 单测（空声明全拒 / 声明边界 / 目的地越界拒绝） |

### 验收标准

- [ ] 空采集声明设备对任何 push 请求返回拒绝（fail-closed）
- [ ] 声明内数据可上行、声明外拒绝
- [ ] 断网暂存不丢（落盘可查）、恢复后按游标续传（不重传已 ack 段）
- [ ] 出设备内容经脱敏 + AES-256-GCM 加密（原始数据不出设备）
- [ ] 每次上行在 audit history 有完整留痕
- [ ] 上行动作（上行数据量/次数）进 worklog/cost
