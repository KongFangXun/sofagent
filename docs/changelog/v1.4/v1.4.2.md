## 一、企业数据 → 训练集管道

### 痛点

需要专属模型的企业客户常常是「有数据没能力」——电芯充放电曲线 CSV、产线校准参数、工艺配方等**异构数据进不了训练框架**。数据管道是训练引擎的入口。

### 交付

| 组件 | 能力 |
|------|------|
| **异构数据接入** | CSV / Excel / JSON / 文本 → 统一中间格式（列映射 + 类型推断 + 空值处理） |
| **DB / API 数据源** | 企业 ERP / 数据库 / API 数据接入（PostgreSQL / MySQL / REST API）——文件接入之外的第二入口（企业客户数据常在企业系统里，不只文件） |

> 🔗 **商业平台 接口预留 G5（2026-08-17 补充）**：本版「DB / API 数据源」是商业产品层 商业平台 存量系统对接（OA/CRM/ERP）的技术基础（商业平台 平台接口规划 §9.1 G5）——商业平台 的 MCP 连接器注册/发现（`connector_list` + 第三方连接器注册）挂靠本版扩展：企业系统经 MCP 暴露数据 → 既供训练（本版）也供 workflow 编排（商业平台 §3.2）。**本版先打通「接入」，连接器注册/发现机制随 商业平台 SaaS 需要再补**。
| **训练集构建** | 中间格式 → instruction / 偏好对（DPO）/ RL 提示集——按算法选型（衔接 v1.4.4 语料导出格式） |
| **数据校验** | 训练集质量闸门：字段完整性 / 样本量 / 标签分布（不达标拒绝提交） |
| **训练入口脱敏** | 复用 v1.4.4 通用脱敏管线（redactor）——客户数据进训练前的语义脱敏 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/train/data-ingest.ts` | 新建 | 异构数据 → 中间格式（文件 + DB/API） |
| `engine/orchestrator/src/train/db-source.ts` | 新建 | DB/API 数据源适配（连接串 → 拉取 → 中间格式，只读连接不落库） |
| `engine/orchestrator/src/train/dataset-builder.ts` | 新建 | 中间格式 → 训练集（按算法） |
| `engine/orchestrator/src/train/dataset-validator.ts` | 新建 | 质量闸门 |
| `engine/orchestrator/src/__tests__/dataset-builder.test.ts` | 新建 | 单测（CSV→instruction + DB 拉取 + 质量闸门拦截） |

### 验收标准

- [ ] CSV / Excel / **DB / API** 数据 → instruction 训练集（列映射 + 类型推断）
- [ ] DPO 偏好对 / RL 提示集两种构建路径可用

| **版本对比** | 两版训练集差异概览（样本数/分布变化）——判断"数据变了导致分数变了" |

### 验收标准

## 三、训练中 eval 闭环（不 eval 的训练是盲训）

### 定位

OpenAI `prove` 思想：训练必须连着评估。**机制开源、阈值外部化**（2026-08-10 拍板）：本版提供 eval 运行机制（复用 v1.3.1 Benchmark 评测体系），「什么指标算合格」的验收阈值由商业侧配置（机制是通用工程能力，阈值是商业壁垒）。

### 交付

| 组件 | 能力 |
|------|------|
| **训练后自动 eval** | train job 完成后自动跑 Benchmark（读 statement/rubric，隔离执行 read-only） |
| **继续 / 停止判定** | eval 分数 vs 目标阈值 → 继续训练（调整超参）或停止（产出权重） |
| **eval 报告** | 训练前后对比（SFT 基线 vs RL 后）——写入 evaluation-log（v1.3.1 格式）+ 引用训练集版本（第二章） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/train/train-eval-loop.ts` | 新建 | 训练-eval 循环（复用 v1.3.1 case-evaluator） |
| `engine/orchestrator/src/__tests__/train-eval-loop.test.ts` | 新建 | 单测（eval 触发 + 阈值判定） |

### 验收标准

- [ ] train job 完成后自动触发 Benchmark eval（read-only 隔离执行）
- [ ] 阈值判定 → continue / stop 分支正确
- [ ] eval 报告写入 evaluation-log（v1.3.1 格式，HMAC）+ 引用训练集版本

### 交付

| 组件 | 能力 |

## 五、训练 dry-run 与配置预检（train dry-run · 失败前预防）

### 定位

> 📋 **2026-08-10 补充（首次使用体验）**：长任务训练最怕跑了一半发现配置错（显存不够、数据格式错、学习率发散）。v1.4.1 有 job.json schema 校验（格式对不对），v1.4.3 有 train diagnose（失败后诊断），但**缺失败前的预检**。企业第一次用训练引擎，配置没填对，跑 2 小时崩了才知道哪里错——这个体验直接劝退。diagnose 是「事后诊断」，dry-run 是「事前预防」，两者互补。

### 交付

| 组件 | 能力 |
|------|------|
| **train dry-run** | 用极小数据集（10 条）跑通整条管线（数据→训练→eval），不真的训练——验证管线连通性（数据能读、格式能解析、训练脚本能 spawn、eval 能跑） |
| **显存预检** | batch size × 模型大小 → 估算显存占用，超 GPU 上限提前告警（不是 OOM 崩了才知道） |
| **数据预检** | 训练集提交前快速抽样检查：字段完整性 / 标签分布是否离谱 / 样本量是否达标——复用 v1.4.2 ① 质量闸门的轻量版 |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/train/train-dryrun.ts` | 新建 | dry-run 编排（极小数据集跑通管线 + 显存估算 + 数据抽样） |
| `engine/mcp/src/tools/train-dryrun.ts` | 新建 | MCP `train_dryrun` tool |
| `engine/orchestrator/src/__tests__/train-dryrun.test.ts` | 新建 | 单测（管线连通 + 显存估算 + 数据预检拦截） |

### 验收标准

- [ ] `train dry-run` 用 10 条数据跑通整条管线（不真训练，验证连通性）
- [ ] 显存预检：batch size × 模型大小 → 估算占用，超限告警
- [ ] 数据预检：字段缺失 / 标签分布离谱 / 样本量不足 → 结构化告警
- [ ] `npm test` 全绿

## 八、FDE 引擎化（方法论 → 可执行引擎 · 2026-08-25 收编）

### 定位

> 🔴 **现状诊断**：FDE 方法论 1173 行在 `FDE/GUIDE.md`，但引擎层只有 `fde_compose` 一个工具真实现（`fde_interview/classify/quantify/derive/distill/deploy` 六 tool 全是「规划中形态」）——**方法论是文字，Agent 读了一本手册，但没有 FDE 工作台**：访谈不落库、判定不计算、量化靠心算、交付靠手搓。本版把 GUIDE 六章方法论变成 6 个可执行引擎，让 FDE 从「.md 驱动」升级为「引擎驱动」。

### 交付（六引擎 · 全部做成 MCP tool）

| # | 引擎 | 方法论来源 | 做什么 | 产物落盘 | 复用底座 |
|---|------|-----------|--------|---------|---------|
| 一 | **fde_interview 访谈引擎** | GUIDE 第二章 五要素深挖 | 访谈引导（追问话术）+ 记录结构化（岗位/环节 × 输入/输出/负责人/耗时/痛点）→ 企业画像自动生成 | `data/fde/<企业>/interview.json` + 企业画像 | 复用 fde_compose 骨架 |
| 二 | **fde_classify 判定引擎** | GUIDE §4.1 三问判定 + §3.2 适配性判断 | 五要素 → 三问规则化判定（🔄 自动 / ⚡ 强化 / 👤 暂不动）+ 六步分解法切最小工作单元 | 节点方案（AI 节点 / Human 节点）`nodes.json` | 复用 classifyAutomation 逻辑 |
| 三 | **fde_quantify 量化引擎** | GUIDE §4.3 量化四字段 | `年节省 = 岗位年薪 × 接管工时占比` 计算器 + ROI 排序 + 量化四字段（当前成本/AI 后成本/年节省/回本周期） | `quantification.json`（喂训练报告与 dashboard） | 复用 v1.4.2 第六章训练报告量化四字段 |
| 四 | **fde_derive 本体推导引擎** | GUIDE 第三章 本体构建 | 五要素 + 访谈 → entity/concept/relations 推导建议（机器初稿 + 人确认） | ontology YAML 草稿 | **复用 ontology_import 完整链路** |
| 五 | **fde_distill 沉淀引擎** | GUIDE 第五章 三层交付 + sustain | 跑通过程 → SKILL.md 模板 + 交付手册自动生成 | 文档层 + Skill 层交付物 | 复用 GUIDE 第五章模板 |
| 六 | **fde_deploy 部署引擎** | GUIDE 第五章 运行层 | 三层交付物 → workflow.yml + 激活部署 | 运行层交付物 | **复用 workflow_submit + activate_workflow** |

### 关键设计决策
