## 一、企业数据 → 训练集管道

### 痛点

需要专属模型的企业客户常常是「有数据没能力」——电芯充放电曲线 CSV、产线校准参数、工艺配方等**异构数据进不了训练框架**。数据管道是训练引擎的入口。

### 交付

| 组件 | 能力 |
|------|------|
| **异构数据接入** | CSV / Excel / JSON / 文本 → 统一中间格式（列映射 + 类型推断 + 空值处理） |
| **DB / API 数据源** | 企业 ERP / 数据库 / API 数据接入（PostgreSQL / MySQL / REST API）——文件接入之外的第二入口（企业客户数据常在企业系统里，不只文件） |
| **训练集构建** | 中间格式 → instruction / 偏好对（DPO）/ RL 提示集——按算法选型（衔接 v1.4.4 语料导出格式） |
| **数据校验** | 训练集质量闸门：字段完整性 / 样本量 / 标签分布（不达标拒绝提交） |
| **训练入口脱敏** | 客户数据进训练前的语义脱敏——本版先落地最小可用版（见下方注记） |

> ⚠️ **脱敏前向依赖注记**：v1.4.4 通用脱敏管线（redactor）尚未交付——本版先实现训练入口脱敏最小可用版（复用现有审计脱敏能力），v1.4.4 通用管线落地后升级对齐（复用同一套语义脱敏规则，接口预留）。

> 🔗 **商业平台接口预留 G5（2026-08-17 补充）**：本版「DB / API 数据源」是商业产品层存量系统对接（OA/CRM/ERP）的技术基础（商业平台接口规划 §9.1 G5）——商业平台的 MCP 连接器注册/发现（`connector_list` + 第三方连接器注册）挂靠本版扩展：企业系统经 MCP 暴露数据 → 既供训练（本版）也供 workflow 编排（商业平台 §3.2）。**本版先打通「接入」，连接器注册/发现机制随商业平台 SaaS 需要再补**。

## 五、训练 dry-run 与配置预检（train dry-run · 失败前预防）

### 定位

> 📋 **2026-08-10 补充（首次使用体验）**：长任务训练最怕跑了一半发现配置错（显存不够、数据格式错、学习率发散）。v1.4.1 有 job.json schema 校验（格式对不对），v1.4.3 有 train diagnose（失败后诊断），但**缺失败前的预检**。企业第一次用训练引擎，配置没填对，跑 2 小时崩了才知道哪里错——这个体验直接劝退。diagnose 是「事后诊断」，dry-run 是「事前预防」，两者互补。
>
> 📋 **2026-08-26 补充（算力外推预检 · ScaleRL 论文方法论收编）**：dry-run 还差一个维度——**成本外推**。企业提交训练前最想知道「这次训练大概要花多少算力/钱、值不值」，但训练的真实成本只有跑完才知道。ScaleRL（arxiv 2510.13786，Meta/UT Austin 等，论文公开可复现）给出方法：算力-性能遵循 sigmoid 缩放律，**用几个小规模 pilot run 的数据点拟合曲线，即可外推大规模 run 的性能天花板与算力需求**。这把训练预算控制从「超了暂停」（v1.4.1 预算控制，事后）升级为「投之前先算」（事前）。

### 交付

| 组件 | 能力 |
|------|------|
| **train dry-run** | 用极小数据集（10 条）跑通整条管线（数据→训练→eval），不真的训练——验证管线连通性（数据能读、格式能解析、训练脚本能 spawn、eval 能跑） |
| **显存预检** | batch size × 模型大小 → 估算显存占用，超 GPU 上限提前告警（不是 OOM 崩了才知道） |
| **数据预检** | 训练集提交前快速抽样检查：字段完整性 / 标签分布是否离谱 / 样本量是否达标——复用 v1.4.2 ① 质量闸门的轻量版 |
| **算力外推预检** | `train dry-run --extrapolate`：跑 2-3 个递增规模的 pilot run → 采集（算力, 性能）数据点 → 拟合 sigmoid 缩放律 → 外推目标规模的性能天花板与算力/成本估算，附置信区间（数据点不足时明示「外推置信低」不硬报）。预算控制（v1.4.1）衔接：外推成本超预算 → 提交前告警。参考实现：ScaleRL 官方曲线拟合工具（devvrit.com/scalerl_curve_fitting） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/orchestrator/src/train/train-dryrun.ts` | 新建 | dry-run 编排（极小数据集跑通管线 + 显存估算 + 数据抽样 + 算力外推编排） |
| `engine/orchestrator/src/train/scale-curve.ts` | 新建 | 缩放律拟合（sigmoid 参数拟合 + 外推 + 置信区间，数据点不足降级——2026-08-26 补） |
| `engine/mcp/src/tools/train-dryrun.ts` | 新建 | MCP `train_dryrun` tool |
| `engine/orchestrator/src/__tests__/train-dryrun.test.ts` | 新建 | 单测（管线连通 + 显存估算 + 数据预检拦截 + 外推降级） |

### 验收标准

- [x] `train dry-run` 用 10 条数据跑通整条管线（不真训练，验证连通性）
- [x] 显存预检：batch size × 模型大小 → 估算占用，超限告警

> 无头设备（树莓派 / NAS / 旧电脑 / 服务器）上没有屏幕没有键盘，**远程指挥是唯一操作方式**——FDE Harness 层必须能被 IM 对话驱动（微信 / 钉钉 / 飞书 / 企微）。成熟底座已有现成通道，**不写一行 IM 协议代码**：DSH 侧 `@xmanrui/dsh-im`（9 渠道扫码接入 + AI Office Connector 无公网 IP）+ OpenClaw 侧 `@openclaw-china/channels`（国产 IM 聚合层）。本版做「接入 + 适配 + 安全审计」，把远程指挥变成 FDE Harness 层的标准执行通道。

### 交付

| 组件 | 能力 |
|------|------|
| **IM 桥接入** | 以 DSH `dsh-im` 为主通道（与训练 Agent 走 DSH 为主的架构主线同生态）：扫码接入微信 / 钉钉 / 飞书 / 企微 → 消息驱动 FDE Harness 层（派活 / 查进度 / 审批） |
| **AI Office Connector 适配** | dsh-im 的「本机 Harness 主动连公网 Office」能力（SSE 下行 + 90s 任务租约 + 工具审批进人工面板）——**无公网 IP / 无端口转发**，天然命中无头设备定位 |
| **安全审计** | dsh-im 是第三方社区插件（非 DSH 官方）——接入前代码审计（凭据只进本机存储声明需核实）+ 机器人命令白名单（/new /models /stop 等）+ 可信用户限制 |
| **FDE 指挥面** | 基于 IM 的 FDE 业务命令：派活（梳理/审计/巡检）、查状态、审批（HITL 远程化）——把「语言对话驱动训练/FDE」操作面定位落到 IM |

## 九、DSH 执行深化（FORGE loop 全量切 DSH · 2026-08-26 排期）

> 前置已交付（v1.4.1，commit 2fb524c7）：**工具注入**——`registerSofagentTools()` 把 sofagent 自定义工具（gate-tools / FORGE worker 工具面）经 `ctx.get('tools').register()` 挂进 DSH 会话全局层，端到端实测 agent 在会话内真实调用注入工具。这是本块三步的接线地基。
>
> **双轴目标（run-01 性能评估拍板）**：① **性能**——run-01 实测墙钟耗时中相当比例耗在非模型环节（轮询等待 + 串行长尾）；步一/步二落地后墙钟压向 LLM 耗时等值。② **稳定一次走完**——run-01 人工停轮的根因是结构性不收敛（worktree 钉死基线 + b-fix 写不回），跑满 max-rounds 也是在陈旧快照上重复发现；步零修复数据流地基 + 重复率熔断让机器自判停轮，不再依赖人工盯。

| 步 | 内容 | 验收 |
|---|------|------|
| 零、数据流地基（稳定性前置） | 三债修复：① worktree 逐轮 re-sync 主仓库新 commit（消除「钉死基线」——修复收编后下一轮基于新基线审）② b-fix sandbox workspace 对准 worktree（消除「修复落不回基线」——run-01 round-03+ 全在陈旧快照上空转的根因）③ summary-batch 中间产物落 runDir（消除主仓库残留）。**findings 重复率熔断进 driver**：相邻轮同 finding（文件+问题指纹）重复率超阈值 → 自动停轮 + verdict 标注 `repeat-convergence`——结构性不收敛由机器自判。注：#13 加权收敛（detectWeightedConvergence）管「发现数降下来」，管不了「修复没生效」，两维度互补不替代 | 同 finding 跨轮重复出现时 run 自动停轮报警；修复收编后下一轮 worktree 基线同步；主仓库全程无 loop 中间产物残留 |
| 一、流式面重建 | 消费 `session.events`（tool/call、tool/result、assistant/message）重建 LangGraph streamHandler 三职责：报告捕获（gotReport 即收工）/ 软硬熔断判定 / 逐步 usage 记账；`dsh-events.mjs` 事件订阅从骨架转正（notify_session 联调，消除 120s 轮询盲区） | fresh-eyes 审查 worker 在 DSH 后端下产出与 langgraph 后端等深的报告（工具预算消耗、熔断行为对齐） |
| 二、审查类 step 分级切 | 按流式依赖从弱到强：a-verify（有限任务）→ a-consolidate（长输出）→ check worker（流式依赖最重）；check 切换前必须双后端镜像验证（同 prompt 两后端跑，findings 一致性比对——v1.3.9 backend-ab 方法论复用） | `resolveFreshEyesBackend` 全 step 走 dsh，langgraph 降级链保留且产物不丢 |
| 三、治理面收口 | usage 自动计量（DSH 运行时级 token 数据接 usage.jsonl——「driver 逐步手记」升级为运行时自动记；run-01 实测全部调用 usage 缺失，成本盲拍）；rc→正式版守卫解除演练（DSH 正式版发布后守卫自动放行零代码变更） | usage.jsonl 记账零手记；release-gate-driver 同步受益 |

> 📌 **2026-08-28 拍板**：步一~三正式移交 v1.4.3 承接（登记见 [v1.4.3 开发日志第六章](./v1.4.3.md#六forge-dsh-执行深化步一三自-v142-拍板移交--2026-08-28)），本版实交付止于步零三债 + 重复率熔断 + A 侧收敛指令。

**性能辅助项（随步一顺带，零成本）**：A 侧 prompt 追加「先写报告骨架、再探查验证」收敛指令——run-01 实测 A 侧碎片率持续高位（多数 worker 撞硬熔断，次轮才减半），根因是探查行为与预算错配（预算耗尽前来不及写报告），prompt 层把行为从「探查完预算尽」掰到「报告保底」。

**既有守护确认够用（不新增）**：daemon 模式（detached 自脱离）+ watch 主管（心跳停 → death-audit 审计死因 → 自动 resume）+ 断点续跑（completedWorkers 跳过已完成 worker）+ 连续降级守卫（连续 2 轮 isDegraded → 优雅退出）——「稳定走完」的缺口不在守护面在数据流（步零），守护把无意义的轮跑满恰是结构性不收敛的症状。

**后续版本观察项（本版不做，等数据）**：模型分层（check worker 切低成本档、consolidate/b-fix 留强模型——待步三 usage 计量上线后按真实 token 账拍板）；增量审查（round-02+ 只扫上轮基线→当前 HEAD diff，findings 收敛后全量 24 视角重扫属浪费）；并发 1→2（FORGE_MAX_CONCURRENCY 放宽前先实测 DSH 单 session 内存曲线——8GB 机器 OOM 前科）。

**红线（不动）**：编排层永远不切（LangGraph StateGraph DAG = sofagent 自有面，2026-08-23 拍板「LangGraph 做编排，DSH 做执行」）；每步带降级验证（DSH 路径异常 fallback LangGraph 且产物不丢）；并发内存先实测（24 check worker 若各自 boot ctx，须单 worker 内存曲线外推——8GB 机器 OOM 前科）。

**已知待修（端到端实测发现）**：`summarizeSession` 提取 assistant 文本为空（事件结构字段与预期不符）——步一「流式面重建」的输入，不是阻塞项。
