## 一、插件来源白名单（原案 · Codex marketplace_policy 启发）

### 定位

> sofagent 的 ClawHub/SkillHub 分发（SKILL + DSH plugin + OpenClaw plugin 三通道）目前无企业级「谁能装、从哪装」管控。Codex Harness 的 `MarketplaceAllowedSource` 三类来源白名单是现成参考——**管控在安装侧生效，不依赖平台侧**。

### 交付

| 组件 | 能力 |
|------|------|
| **来源白名单** | 企业侧配置 `plugin_sources.allowlist`（Git URL / 主机模式 / 本地路径三类）——白名单外的插件来源安装时拒绝 |
| **托管 hook 独裁模式** | `allow_managed_hooks_only` 等价物——企业部署后忽略用户自定义 hook，只跑 sofagent 托管审计 hook |
| **分发通道统一管控** | 同时覆盖 ClawHub（OpenClaw plugin 家族）+ SkillHub（DSH plugin 家族） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|

| `engine/audit/src/cli/plugin-gate.ts` | 新建 | 插件来源白名单校验（安装前检查） |
| `engine/audit/src/cli/plugin-gate.test.ts` | 新建 | 白名单三类来源 + 拒绝路径测试 |

### 验收标准

- [ ] 白名单外的插件来源安装被拒绝（Git URL / 主机模式 / 本地路径三路各测）

## 三、多 Agent 协作阵型库（ccteam 启发）

### 定位

> 把协作模式抽象为**可配置阵型**——六种内置阵型覆盖常见协作拓扑。v1.3.6 SubAgent 托管 SDK（harness.wrap）已交付，阵型配置层的地基就绪。Codex collaboration-mode-templates（default.md / plan.md 可切换）是现成参考形态；Codex agent-graph-store 的边生命周期管理（Open/Closed）提供编排图状态参考。

### 交付

| 阵型 | 拓扑 | 适用 |
|------|------|------|
| **commander & crews** | 一主多从，主 Agent 拆解派发 | 任务可并行分解的场景 |

| **cross-review** | 双 Agent 互审 | 产出质量敏感（代码/文档） |
| **bake-off** | 多 Agent 同题竞作 + 择优 | 方案探索期（复用 v1.3.5 A/B 基建） |
| **research-triangulation** | 三方独立调研 + 交叉验证 | 事实核查/零信任复核 |
| **cost-pyramid** | 便宜模型打底、贵模型兜底关键节点 | 成本敏感的分层任务 |

| 组件 | 能力 |
|------|------|

| **阵型实例化** | 读配置 → spawn SubAgent 拓扑（走 v1.3.6 SDK）+ 边生命周期管理 |
| **阵型审计** | 每次阵型运行记 who-派发-who / 交接留痕（跨成员信息流可回溯） |

## 四、自动上下文压缩（加载链预算落地 · Codex compact 启发）

### 定位

> 加载链 ≤3% 总占用预算（ROADMAP 跟踪项）已披露「尚未全量落地」——本版补**自动压缩**：窗口超预算触发摘要压缩，对齐 memory 分层「写入笨、派生灵活」哲学。参考 Codex compact（ARC-AGI-3 两大调整之一）：`pre-compact`/`post-compact` hooks + 摘要 prompt + 多触发策略 + 压缩替代历史保留 initial context。

### 交付

| 组件 | 能力 |
|------|------|
| **预算检测** | 加载链注入前算 token 占用，超预算（3%）触发压缩 |
| **压缩执行** | 摘要生成（保留红线/铁律/最近决策，压缩历史细节）+ initial context 保留 |
| **压缩标记** | 注入上下文带 start/end markers（context-fragments 参考）——事后可识别哪些内容来自压缩 |
| **压缩留痕** | 压缩事件记审计（何时压、压了多少、保留了什么） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/harness/src/load-chain/budget.ts` | 新建 | 预算检测 + 触发策略 |
| `engine/harness/src/load-chain/compactor.ts` | 新建 | 摘要生成 + 标记注入 |
| `engine/harness/src/__tests__/load-chain-compact.test.ts` | 新建 | 超预算触发 + 标记可识别测试 |

### 验收标准

- [ ] 加载链超 3% 预算自动触发压缩，红线/铁律内容不丢
- [ ] 压缩后的上下文带 start/end 标记，事后可识别
- [ ] 压缩事件进审计日志
- [ ] 未超预算时不压缩（零开销路径）

## 五、shell 提权分级策略（Codex shell-escalation 启发）

### 定位

> 危险命令从「沙箱内直接跑」升级为「**提权策略决策后跑**」。参考 Codex shell-escalation 完整框架：`EscalationPolicy`（决策）+ `EscalationDecision`（allow/prompt/forbid）+ 权限位 + execve wrapper。与 v1.3.7 场景驱动权限（身份→场景→风险→放行）衔接——那套管工具调用，这套管 shell 命令。

### 交付

| 组件 | 能力 |
|------|------|
| **命令分级器** | shell 命令三态分级：safe（只读/无副作用）/ risky（写操作/网络）/ dangerous（删除/提权/密钥接触） |
| **EscalationPolicy** | 按分级路由：safe → 直接跑 · risky → 场景策略判定 · dangerous → HITL 审批队列（复用 v1.3.8 审批队列） |
| **决策留痕** | 每次提权决策记 DecisionKind.ESCALATION（命令 + 分级 + 决策依据） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/core/src/escalation/classifier.ts` | 新建 | 命令三态分级 |
| `engine/core/src/escalation/policy.ts` | 新建 | EscalationPolicy 路由 + HITL 联动 |
| `engine/core/src/__tests__/escalation.test.ts` | 新建 | 三级命令各走各路径测试 |

### 验收标准

- [ ] 三级命令各自命中正确路径（直接跑 / 策略判定 / HITL 队列）
- [ ] dangerous 级命令未经审批不执行（fail-closed）
- [ ] 每次决策留审计痕（命令 + 分级 + 依据）
- [ ] 分级规则可配置（企业可加自定义危险模式）

## 六、成本 quota 事前门禁（Loop Engineering 控制面启发）

### 定位

> 成本管控从「事后记账」（v1.4.0 cost_query WARN only）前移为「**事前问路**」——每轮执行前先问配额，验证过的回写才记 spend。与 v1.3.7「守卫先于事件分发」哲学同向。

### 交付

| 组件 | 能力 |
|------|------|
| **事前配额检查** | 任务执行前查当前周期配额余量——超额按策略处理（WARN 放行 / HARD 拦截，企业可配） |
| **验证回写** | 只有验证过的执行结果才记 spend（失败/重试的重复消耗不重复计） |
| **配额看板数据** | quota 状态进 cost_query 查询面（余量/已用/周期） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/core/src/cost/quota-gate.ts` | 新建 | 事前检查 + 回写语义 |
| `engine/mcp/src/tools/cost-query.ts` | 修改 | 查询面加配额字段 |
| `engine/core/src/__tests__/quota-gate.test.ts` | 新建 | WARN/HARD 两模式 + 回写测试 |

### 验收标准

- [ ] 任务执行前配额检查生效（HARD 模式超额拦截）
- [ ] 只有验证过的结果记 spend
- [ ] cost_query 可查余量/已用/周期
- [ ] 未配置 quota 时行为与现版一致（单机不破坏）
