## 四、自动上下文压缩（加载链预算落地 · Codex compact 启发）

### 定位

> 加载链 ≤3% 总占用预算（ROADMAP 跟踪项）已披露「尚未全量落地」——本版补**自动压缩**：窗口超预算触发摘要压缩，对齐 memory 分层「写入笨、派生灵活」哲学。参考 Codex compact（ARC-AGI-3 两大调整之一）：`pre-compact`/`post-compact` hooks + 摘要 prompt + 多触发策略 + 压缩替代历史保留 initial context。

### 交付

| 组件 | 能力 |
|------|------|
| **预算检测** | 加载链注入前算 token 占用，超预算（3%）触发压缩 |
| **压缩执行** | 摘要生成（保留红线/铁律/最近决策，压缩历史细节）+ initial context 保留 |
| **压缩标记** | 注入上下文带 start/end markers（context-fragments 参考）——事后可识别哪些内容来自压缩 |
| **压缩留痕** | 压缩事件记审计（何时压、压了多少、保留了什么） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/harness/src/load-chain/budget.ts` | 新建 | 预算检测 + 触发策略 |
| `engine/harness/src/load-chain/compactor.ts` | 新建 | 摘要生成 + 标记注入 |
| `engine/harness/src/__tests__/load-chain-compact.test.ts` | 新建 | 超预算触发 + 标记可识别测试 |

> **两个实现纪律**：① **harness 是全仓唯一零依赖包（最底层）**——「压缩事件进审计」不得让 harness import audit（违反第七章方向门禁），走回调/事件出口由调用方（daemon/orchestrator）落审计痕；② **加载链双实现同步**（engine/hooks/sofagent-load-chain/src/handler.ts 头注既定纪律）：harness（npm API 形态）与 OpenClaw hook 形态两份实现不合并、改动需两处同步评估——本章只动 harness 侧，OpenClaw hook 路径是否消费 compactor 开发时显式裁定（纳入或明确 out of scope），禁静默跳过。

### 验收标准

- [x] 加载链超 3% 预算自动触发压缩，红线/铁律内容不丢
- [x] 压缩后的上下文带 start/end 标记，事后可识别
- [x] 压缩事件进审计日志
- [x] 未超预算时不压缩（零开销路径）

> **交付边界（与 ROADMAP 口径已对齐）**：本版交付「**预算检测 + 自动压缩 + 标记 + 留痕**」四件；ROADMAP「加载链预算目标跟踪」段（[ROADMAP §加载链预算目标跟踪](../../ROADMAP.md#加载链预算目标跟踪)）另列的「**窗口超预算拒载/降级机制**」**不在本版范围**——ROADMAP 该段现写「**仍未排期、无版本单元格**（触发条件=自动压缩落地后实测仍频繁越线）」，本版只收口「压缩」一件，拒载/降级另占版本单元格，三处（开发日志四 / ROADMAP 跟踪段 / 版本规划表 v1.4.8 行）口径现已一致。

## 五、shell 提权分级策略（Codex shell-escalation 启发）

### 定位

> 危险命令从「沙箱内直接跑」升级为「**提权策略决策后跑**」。参考 Codex shell-escalation 完整框架：`EscalationPolicy`（决策）+ `EscalationDecision`（allow/prompt/forbid）+ 权限位 + execve wrapper。与 v1.3.7 场景驱动权限（身份→场景→风险→放行）衔接——那套管工具调用，这套管 shell 命令。

### 交付

| 组件 | 能力 |
|------|------|
| **命令分级器** | shell 命令三态分级：safe（只读/无副作用）/ risky（写操作/网络）/ dangerous（删除/提权/密钥接触） |
| **EscalationPolicy** | 按分级路由：safe → 直接跑 · risky → 场景策略判定 · dangerous → HITL 审批队列（复用 v1.3.8 审批队列） |
| **决策留痕** | 每次提权决策记 `DecisionKind.ESCALATE_REPORT` + `DecisionCategory='escalate'`（命令 + 分级 + 决策依据）——复用既有分型与既有判断时刻维度，**不新增成员** |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/core/src/escalation/classifier.ts` | 新建 | 命令三态分级 |
| `engine/core/src/escalation/policy.ts` | 新建 | EscalationPolicy 路由 + HITL 联动 |
| `engine/core/src/__tests__/escalation.test.ts` | 新建 | 三级命令各走各路径测试 |

> **落点归属（实测核定，对齐第二章 ToolGate 先例）**：`DecisionKind`/`DecisionCategory` 定义在 `engine/audit/src/decision-schema.ts`（core 的 dependencies 不含 audit），HITL 审批面在 rules 及以上层——**core 内只做纯函数**（classifier 三态分级 + policy 返回判定枚举与依据，零跨包 import）；审计落痕（记 DecisionKind）与 HITL 入队由**调用层**（orchestrator/daemon 执行侧）承接。core 一旦 import audit 即违反第七章依赖方向门禁。
