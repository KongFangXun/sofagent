### 扩展：技能按模型分级门控（WikiSkill 负迁移防御 · Google Research arXiv:2608.27454）

> WikiSkill 跨模型迁移实验实锤：4B 模型进化的技能把 Gemini-3.5-Flash 从 50.5% 拉到 18.1%——小模型技能编码的低层 workaround（单行 Python 命令）帮助小模型避免执行失败，却**束缚强模型写端到端脚本**，且碎片化诊断流程引入冗余工具调用耗尽交互预算。结论：「技能发现与技能执行是两种独立能力」。sofagent 覆盖多供应商多模型（v1.3.6 模型注册表），技能不能全局通用投放——与本章 `modelPreference` 字段同族收编。

- **技能生效面声明**：SKILL.md frontmatter 增可选 `modelScope`（如 `min-capability: advanced` / 显式 provider 列表）——进化来源为弱模型的技能默认不注入强模型执行面
- **投放前校验**：技能发布（promote/SkillHub 分发）时校验目标模型与 `modelScope` 兼容，不兼容显式拒绝或降级为「仅提示不注入」
- **依赖衔接**：门控量化与 skill-impact 台账在 [v1.4.5 第七章四）](./v1.4.5.md)交付，本项消费其 `solves:`/台账数据做迁移预判

### 扩展二：跨 harness 协作阵型注册表（ACP Registry 启发 · 2026-09-01 拍板）

> ACP（Agent Client Protocol，Zed 主导 JetBrains 联合，agent 界的 LSP）2026-01 上线 Agent Registry——实现一次协议、编辑器内直接安装 agent，冷启动分发问题被注册表消解。对 sofagent 的启发不在编辑器场景，而在**「实现一次、处处可用」的分发形态**：v1.3.9 meta-harness 编排的多 harness 生态若按 ACP Registry 模式组织，每个 harness（或协作阵型）就是注册表里的一个可安装条目——FDE 进场时按客户环境拼装组合，而不是每次从零配置。

- **阵型注册表**：六种内置阵型（③交付）以注册表形态组织——`formation.yml` 声明阵型定义，注册表统一索引；后续社区/客户自建阵型可注册进表（治理走 SkillHub 分发同款审批链）
- **ACP 接入评估（调研项）**：sofagent 编排的 SubAgent 若暴露 ACP server 形态，外部编辑器（Zed/JetBrains/Neovim）可直接把 sofagent 的审计执行面当 agent 用——审计能力反向输出到开发者日常工具链，扩大约束层辐射面。**仅评估不承诺**，需验证 ACP 会话模型与审计留痕的兼容性
- **与五维检查清单对照**：统一接入（meta-harness 编排已交付）/ 安全隔离（PolicyLayer）/ 调度编排（本项注册表）/ 可观测审计（AuditAggregator）/ 状态恢复（v1.4.5 第八章 FDE 记忆目录）——五维齐则对外可比

### ⑩ 自研技能进化 gate 验证器——去 skillopt-sleep 外部依赖（2026-09-01 拍板）

> **背景**：dream-cycle 候选技能验证现为 CLI 子进程外部依赖（`skillopt-sleep run --target-skill-path --auto-adopt`，pip 安装自 microsoft/SkillOpt）——自研包 `@sofagent/skillopt` 仅复用其验证执行器，编排层在外面套备份/对比/回滚。**评估结论：可替换、值得替换**——理由有二：① 部署确定性（FDE 交付环境多一道 pip 安装即多一分不确定，用户环境无 Python 或版本漂移直接卡死 dream-cycle）② 去外部运行时依赖（微软 SkillOpt 演进不可控，其 CLI 契约变更即破坏我们编排层）。
>
> **替换路径**：v1.4.5 第七章四）的 eval 门控恰是自研 gate 的雏形——技能变更须过 eval 验证集、分数超历史最优才收编。把它做成独立验证器后，`skillopt-integration.ts` 的 `runSkillOpt` 收敛为薄适配层，dream-cycle Stage 5 换调内部 gate。**前置依赖：v1.4.5 第七章四）交付**（eval 门控在位才有东西可接）。

- **自研 gate 验证器**：`engine/skillopt/src/` 内实现「跑 eval 验证集 → 出分数 → 与历史最优比对 → 接受/回滚」完整闭环，替代 `skillopt-sleep run` 子进程
- **外部依赖摘除**：`skillopt-integration.ts` 降级为可拔插适配层（保留 CLI 形态做向后兼容 + `SOAGENT_SKILLOPT_GATE=native` 切自研，默认 native），文档同步删除 pip install skillopt 安装指引
- **dream-cycle 链路切换**：Stage 5 skillopt-backfill 默认走自研 gate，staging/备份/回滚编排不变，验证执行器换成内部实现
- **与 WikiSkill 的关系**：论文只提供三层架构与门控思想，无开源实现可装——「装 Google 的 wiki」不存在，能落地的是「把论文验证过的结构用自家 eval 体系实现」。本项即该路径的验证器部分
