## 四、自动上下文压缩（加载链预算落地 · Codex compact 启发）

### 定位

> 加载链 ≤3% 总占用预算（ROADMAP 跟踪项）已披露「尚未全量落地」——本版补**自动压缩**：窗口超预算触发摘要压缩，对齐 memory 分层「写入笨、派生灵活」哲学。参考 Codex compact（ARC-AGI-3 两大调整之一）：`pre-compact`/`post-compact` hooks + 摘要 prompt + 多触发策略 + 压缩替代历史保留 initial context。

### 交付

| 组件 | 能力 |
|------|------|
| **预算检测** | 加载链注入前算 token 占用，超预算（3%）触发压缩 |
| **压缩执行** | 摘要生成（保留红线/铁律/最近决策，压缩历史细节）+ initial context 保留 |
| **压缩标记** | 注入上下文带 start/end markers（context-fragments 参考）——事后可识别哪些内容来自压缩 |
| **压缩留痕** | 压缩事件记审计（何时压、压了多少、保留了什么） |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/harness/src/load-chain/budget.ts` | 新建 | 预算检测 + 触发策略 |
| `engine/harness/src/load-chain/compactor.ts` | 新建 | 摘要生成 + 标记注入 |
| `engine/harness/src/__tests__/load-chain-compact.test.ts` | 新建 | 超预算触发 + 标记可识别测试 |

> **两个实现纪律**：① **harness 是全仓唯一零依赖包（最底层）**——「压缩事件进审计」不得让 harness import audit（违反第七章方向门禁），走回调/事件出口由调用方（daemon/orchestrator）落审计痕；② **加载链双实现同步**（engine/hooks/sofagent-load-chain/src/handler.ts 头注既定纪律）：harness（npm API 形态）与 OpenClaw hook 形态两份实现不合并、改动需两处同步评估——本章只动 harness 侧，OpenClaw hook 路径是否消费 compactor 开发时显式裁定（纳入或明确 out of scope），禁静默跳过。

### 验收标准

- [x] 加载链超 3% 预算自动触发压缩，红线/铁律内容不丢
- [x] 压缩后的上下文带 start/end 标记，事后可识别
- [x] 压缩事件进审计日志
- [x] 未超预算时不压缩（零开销路径）

> **交付边界（与 ROADMAP 口径已对齐）**：本版交付「**预算检测 + 自动压缩 + 标记 + 留痕**」四件；ROADMAP「加载链预算目标跟踪」段（[ROADMAP §加载链预算目标跟踪](../../ROADMAP.md#加载链预算目标跟踪)）另列的「**窗口超预算拒载/降级机制**」**不在本版范围**——ROADMAP 该段现写「**仍未排期、无版本单元格**（触发条件=自动压缩落地后实测仍频繁越线）」，本版只收口「压缩」一件，拒载/降级另占版本单元格，三处（开发日志四 / ROADMAP 跟踪段 / 版本规划表 v1.4.8 行）口径现已一致。

## 五、shell 提权分级策略（Codex shell-escalation 启发）

### 定位

> 危险命令从「沙箱内直接跑」升级为「**提权策略决策后跑**」。参考 Codex shell-escalation 完整框架：`EscalationPolicy`（决策）+ `EscalationDecision`（allow/prompt/forbid）+ 权限位 + execve wrapper。与 v1.3.7 场景驱动权限（身份→场景→风险→放行）衔接——那套管工具调用，这套管 shell 命令。

### 交付

| 组件 | 能力 |
|------|------|
| **命令分级器** | shell 命令三态分级：safe（只读/无副作用）/ risky（写操作/网络）/ dangerous（删除/提权/密钥接触） |
| **EscalationPolicy** | 按分级路由：safe → 直接跑 · risky → 场景策略判定 · dangerous → HITL 审批队列（复用 v1.3.8 审批队列） |
| **决策留痕** | 每次提权决策记 `DecisionKind.ESCALATE_REPORT` + `DecisionCategory='escalate'`（命令 + 分级 + 决策依据）——复用既有分型与既有判断时刻维度，**不新增成员** |

### 涉及文件（预估）

| 文件 | 改动 | 说明 |
|------|------|------|
| `engine/core/src/escalation/classifier.ts` | 新建 | 命令三态分级 |
| `engine/core/src/escalation/policy.ts` | 新建 | EscalationPolicy 路由 + HITL 联动 |
| `engine/core/src/__tests__/escalation.test.ts` | 新建 | 三级命令各走各路径测试 |

> **落点归属（实测核定，对齐第二章 ToolGate 先例）**：`DecisionKind`/`DecisionCategory` 定义在 `engine/audit/src/decision-schema.ts`（core 的 dependencies 不含 audit），HITL 审批面在 rules 及以上层——**core 内只做纯函数**（classifier 三态分级 + policy 返回判定枚举与依据，零跨包 import）；审计落痕（记 DecisionKind）与 HITL 入队由**调用层**（orchestrator/daemon 执行侧）承接。core 一旦 import audit 即违反第七章依赖方向门禁。

### 债 1 · ✅ **已修复** · `check-test-count.sh` 双口径校验「守卫空转」+ 错误换算式

**位置**：`tools/check/check-test-count.sh`（CHANGELOG 索引行「② 双口径对齐」块）

**根因（两处叠加）**：

1. **错误换算式**：原块在 workspace 快照对齐之外，另加一条「全量口径 = workspace + 27(DSH) + 17(OpenClaw)」校验——**该假设与 CHANGELOG 实际写法不符**：索引行里的数字本身即 workspace 口径（实测 `4429` = 开发日志快照 `4429`）⇒ 一旦补上「workspace 口径 NNNN」标注激活校验，该条必红（`4429 ≠ 4429+44`）。
2. **守卫空转**：整块以 `if [ -n "$CL_WS_MARK" ]` 包裹，当前索引行无该标注 ⇒ 提取为空 ⇒ **整块静默跳过**、输出仍显示 ✓（看着有校验、实际不校验）。

**修复（本版）**：

- **删除**错误的全量换算校验（连带其写死的 `27 + 17` 加数）；留注释说明「索引行数字即 workspace 口径」，插件不计入由「标注与快照同源」隐含保证
- 无标注分支由「静默跳过」改为**显式声明跳过**（不判红，但让「未校验」可见、可被审计发现）
- **故障注入验证**：注入「workspace 口径 9999」→ 门禁**必红**（`workspace 口径声称 9999，开发日志快照 4429`，EXIT=1）；还原后复绿（注入用 `/tmp` 备份 `cp` 还原，**未用 `git checkout --`**）

### 债 3 · 机器级信任锚与双份 audit 二进制（**处置结论：保留现状**）

**现象**：全局装有 `@sofagent/audit@1.4.7` + `@sofagent/core@1.4.7`；信任锚 `~/.sofagent/internal/audit-hash.txt` = 仓内 `engine/audit/dist` 哈希。在**临时仓库**（acceptance 场景自建的 TMP_REPO）中 hook 的 `require.resolve` 落空 → fallback `npm root -g` → 命中全局旧版 → 与锚不符 → 该 commit 恒被拦、审计实际未跑（场景 51 / A18 由此不触发）。

**实测澄清**：
- **主仓 commit 正常**——`.git/hooks/commit-msg` 头部注释即写明「优先用仓库本地 `engine/audit/dist/`，避免全局旧版版本漂移」，且 `node_modules/@sofagent/audit → ../../engine/audit` 软链在位 ⇒ 主仓解析命中仓内
- `~/.sofagent/bin/sofagent`（CLI 入口）**不依赖全局 npm 包**（仅 node 读 json）；`install.sh` 里 `npm root -g` 只用于**权限检查告警**
- 故全局包**仅在「临时仓库 fallback」这一条路径上起作用**

**处置：保留全局包不动。** 理由：① 卸载只能让临时仓库场景从「静默用错版本」变为「显式报审计器不可用」，**不会使其转绿** ② 会影响**非本仓** git 仓库的 hook fallback（其他会话可能依赖）③ 收益 < 风险。

**复发判据**（下次遇同类现象先查三条）：① 报错是否**只在临时/新克隆仓库**出现？② 该仓库有无 `node_modules/@sofagent/audit` 软链（无则必然 fallback）？③ 锚哈希是否等于本机某一份 dist 的哈希（相等则只需对齐解析源，不必改锚）。

### 债 4 · ✅ **已修复** · `install.sh` 两处写入跟随「执行时的源目录」（易失路径）

**现象（两处，同根因）**：

1. `~/.sofagent/bin/sofagent-dashboard` 软链 → `/tmp/sofagent-rescue-mCAmNC/tools/dashboard/sofagent-dashboard.sh`（抢救拷贝——当时从 `/tmp` 运行 install.sh）：`/tmp` 清理或重启即断链，`sofagent dashboard` 随之失效。
2. **`~/.sofagent/REPO_PATH` 同值** —— 该标记按代码注释「供升级时定位引擎源码位置，升级脚本读它执行 `git pull + rebuild`」。**错得比缺更危险**：写入易失路径会让未来升级脚本去**错目录** pull。当前该文件零消费者（`sofagent-update` 尚未实现），无即时故障，但属**预留接口的错误初值**。

**根因**：两处写入均取 `${SCRIPT_DIR}`（执行时的源目录），未区分该目录是否持久。

**修复（本版）**：

- `install.sh` 新增 `is_volatile_dir()` 检测（`/tmp` · `/private/tmp` · `/var/tmp` · `/var/folders`），两处**按用途分别降级**：
  - **REPO_PATH**：易失源 → **不写标记**（宁缺勿错；读取端应 fail-safe 退出并提示重装）+ 显式 warn
  - **dashboard 入口**：易失源 → **改拷贝**（自包含、装完即用；代价是不随源更新，warn 已说明）
- **本机现状已修**：`REPO_PATH` 与软链均改指 `/Users/kongfangxun/Workbuddy/sofagent`，入口 `--help` 实测可响应
- **正例反测**：4 类易失路径全部识别、2 类持久路径全部排除；`bash -n` OK；check-version / check-docs / check-guards / check-shell-injection / check-literals 全 EXIT=0
