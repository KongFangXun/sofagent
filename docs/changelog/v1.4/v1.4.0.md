## 定位

v1.4.0 是**多设备协同系列的收尾 + 生产级执行环境**——三件事一体：把 orchestrator 内置为完整沙箱运行时，把多设备协同的场景权限体系落地，把代理网关硬边界做成沙箱的网络边界。审计引擎从「事后」扩展到「运行时」（**范围限定 SubAgent，主 Agent 仍事后审计**）。

> **版本内容来源**：原 v1.2.5 规划的"场景驱动权限体系 + 代理网关硬边界"拆至此，与沙箱主题天然一体（代理网关 = 沙箱的网络边界）。

## P0：SubAgent 完整沙箱执行环境

- **虚拟文件系统隔离**：FilesystemBackend + virtualMode（SubAgent 只看到虚拟目录）
- **网络出站白名单**：SubAgent 网络访问仅限白名单域名
- **工具调用中介**：前置 allow/deny（非仅审计追踪）——工具调用先过门禁再执行
- **虚拟 key 凭证边界注入**：真实凭证 host 边界注入，SubAgent 只拿临时虚拟 key
- **AsyncSubAgent**：远程 Agent Protocol 服务端（跨设备执行）
- **真·实时 A/B 双跑**：候选方案并行执行实时对比（替代当前日志统计法）

## P1：场景驱动权限体系

- **场景定义**：权限不再按 Agent 全局配置，而是按"场景"（任务类型 × 数据域 × 动作风险等级）动态判定
- **权限判定链**：Agent 身份（v1.3.2）→ 场景匹配 → 动作风险等级 → 是否放行
- **团队场景权限**：L2 团队（v1.3.3）内的成员按团队角色授权，跨团队需显式授权
- **市场调用权限**：L3 市场（v1.3.4）调用能力的权限判定（谁能调用谁的能力）
- **动态提权**：任务触发、限时授权、到期自动回收（复用权限四原则 + 零凭证沙箱）

## P2：代理网关硬边界

- **网关层**：SubAgent 所有外部请求（网络 / 文件 / 凭证）经代理网关，网关是唯一出入口
- **边界策略**：allow/deny 白名单 + 风险分级（低/中高）+ 超阈值动作须人工批准（红线制度）
- **审计集成**：网关每次放行/拦截记审计日志（叠加身份 + 场景 + 动作等级）

## 验收标准

- [ ] SubAgent 在虚拟文件系统中操作，真实文件系统不可见
- [ ] 网络请求仅白名单域名可达，其余被网关拦截 + 审计
- [ ] 工具调用过前置门禁（deny 的调用不执行、只记审计）
- [ ] 权限按场景动态判定：同一 Agent 在不同场景权限不同
- [ ] 动态提权到期自动回收（约 2 小时后过期）
- [ ] 代理网关每次放行/拦截有审计记录（身份 + 场景 + 动作等级）
