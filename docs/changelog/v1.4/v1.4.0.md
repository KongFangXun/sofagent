## 🔌 Dashboard HTML 产品化——随 install.sh 安装到用户机（2026-08-16 新增排期）

> 背景：v1.3.5 已把 dashboard.html 归位 `tools/`（与其服务器 serve-dashboard.mjs 同目录，修正 v1.3.3「docs/demo/」的错误命名——demo 名不副实，README 三入口表早已把 Web 版列为产品入口）。但当前 HTML 版**不随 install.sh 安装**（install 只装 bash 版 `sofagent-dashboard.sh` → `~/.sofagent/bin/`），用户想看 Web 版必须在仓库里跑 `node tools/serve-dashboard.mjs`——**装完即用的用户没有仓库**，Web Dashboard 对他们是不可达的。本版补上这一环。

| 1 | **install.sh 安装 HTML 版三件套** | `dashboard.html` → `$SOFAGENT_HOME/web/` + `serve-dashboard.mjs` → `$SOFAGENT_HOME/bin/` + 现有 `sofagent` CLI 加 `web` 子命令（`sofagent web` = 起服务开浏览器，复用 start-dashboard.command 逻辑） |
| 2 | **serve-dashboard.mjs 安装态路径解析** | 服务器按安装位置解析 dashboard.html（`$SOFAGENT_HOME/web/`）与 data/（`$SOFAGENT_HOME/data/`）——当前硬编码仓库相对路径，安装后需按 SOFAGENT_HOME 解析；开发态（仓库内跑）行为不变 |

## 💰 成本审计（ccteam 启发 · 正交新维度 · WARN only）

> 📖 **来源**：ccteam——每会话追踪 token + 费用、每日预算上限、钱花完自动停工。sofagent 的 A1-A23 审的是 git diff **行为**（改了什么文件、有没有越权），完全不审**成本**。企业部署 Agent，「失控烧钱」和「越权改文件」是同等级风险。本版补这个盲区。

### 核心设计决策：WARN only，不拦截

成本超支**不阻断任务执行**——企业 Agent 跑着跑着超预算了，任务还得做完，不能因为"钱花完了"就中途扔了半截工作。

| 维度 | 做不做 | 理由 |
|------|:--:|------|
| 超支告警（WARN） | ✅ 做 | 让成本从不可见变可见，企业能知道"超了" |
| 告警推送（webhook/IM） | ✅ 做 | 超了要通知到人，对齐现有 PASS/WARN/FAIL 推送 |
| 超支拦截（FAIL/阻断） | ❌ 不做 | 超支不等于任务不该做——任务必须完成，账后算 |
| `--warn-as-error` 可选阻断 | ✅ 做 | 复用 v1.3.1 既有机制，企业自己选要不要 CI 阻断 |

**与训练预算控制（v1.3.6 train_budget）的区别**：训练是算力密集型长任务，超预算 SIGINT 暂停是合理的（训练可以存 checkpoint 接着跑）；运行时 Agent 任务一旦开始就有业务承诺，不能中途扔——所以运行时成本审计只告警不拦截，两个场景两套机制。

### 交付

| 组件 | 能力 |
|------|------|
| **预算配置** | workflow 级设 `budget: {maxTokensPerRun, maxCostPerDay}`——写 workflow.yml 的可选字段，不设则不审计成本 |
| **成本审计模块** | 新建 `engine/audit/src/cost-audit.ts`——读 v1.3.9 worklog 聚合数据 + 预算配置，判定是否超支，产出 WARN 级发现（不进 A1-A23 规则体系，是正交新维度） |
| **COST DecisionKind** | `decision-schema.ts` 新增 `COST` kind——成本告警记决策日志（`kind=COST`），可 kind-wise back 追溯 |
| **`cost_query` MCP tool** | 查预算 / 实际消耗 / 超限记录——数据口（对齐 v1.3.9 `worklog_query` 模式） |
| **Web 工作明细页加成本预警** | dashboard.html「工作明细」区块加红色预警标记——超支的 Agent/Workflow 标红，hover 看超支额度 |

### 审计规则体系升级联动

成本审计是正交新维度（不是 A 类规则的扩展），但"审计规则体系"对外口径需要同步更新：

| 升级项 | 原口径 | 新口径 |
|--------|--------|--------|
| 审计维度 | 「24 条 git diff 行为规则」 | 「24 条 git diff 行为规则 + 成本审计维度（WARN only）」 |
| severity 体系 | PASS / WARN / FAIL（规则级） | 不变（成本审计复用 WARN，不新增 severity） |
| DecisionKind 枚举 | 11 种（SPEC_CHANGE...TEAM） | 12 种（加 COST） |
| check-version 规则数校验 | `TOTAL_RULES_COUNT=24` | **不变**（成本审计不是 A 类规则，不进 rules/index.ts） |
| SKILL.md 审计能力段 | 「24 条规则行为审计」 | 「24 条规则行为审计 + 成本审计维度」 |

> 📖 **来源**：DataFlow——Dashboard 补「workflow 可视图」，会话 Agent 与 DAG 画布实时同步同一 pipeline 表示。

### 定位

v1.4.0 已交付 Web 工作明细页（工作记录视图），DAG 画布是其天然扩展——工作明细页是「表格视角」（按 Agent/Workflow/周列出任务），DAG 画布是「图视角」（同一 pipeline 用节点+边可视化）。两个视角共享同一数据源（worklog.json），只是渲染方式不同。

### 交付

- DAG 渲染：读 workflow.yml + 运行时状态（worklog.json），渲染为节点+边的有向无环图
- 节点状态实时同步：running（高亮）/ done（绿色）/ failed（红色）/ hitl-waiting（黄色脉冲）
- 会话 Agent 与画布双向同步：Agent 跑到哪步 → 画布对应节点高亮；点击画布节点 → 跳到该节点的审计日志
- 拖拽布局：用户可手动调整节点位置（保存到 `.sofagent/dashboard-layout.json`）
