## 定位

> 商业产品层（商业平台接口规划 §9.1）需要 sofagent 预留的平台接口。v1.4.0/v1.4.2/v1.4.4 已分别覆盖 G3（`cost_query`）/ G5（DB/API 数据源）/ G1（模型注册器扩展），本版承载剩余四项——**G2 能力缺口查询 · G4 绩效数据导出 · G6 节点级可见性 · G7 多租户抽象层 v0**，外加 **G13 PR 生命周期接口**（2026-09-01 收编）与 **audit 专职面文档化**（第九章，2026-09-03 登记）。G2-G7 全部是「读数据 + 元数据」类接口，不改引擎执行内核；G13 是「提交-审阅-合并」动作面（写接口），补齐 PR 作为商业平台核心协同单位的一等公民地位。

## 行业定位（2026-08-19 红杉 Neo-Lab 分享吸收）

> 📖 来源：红杉美国合伙人 Sonya Huang 闭门分享——「研究由业务驱动，研究为业务服务」，Neo-Lab 的数据全是「业务里跑出来的真实私有数据、真实用户反馈，通用实验室拿不到的宝贵资产」。

商业平台是四层主权框架里**评测迭代主权 + 数据主权**的载体（四层框架见 [v1.4.0 商业侧定位节](./v1.4.0.md)）：绩效/可见性数据（G4/G6）让企业看到 Agent 哪好哪坏；双图谱托管让业务语义不出边界；worklog/绩效数据正是 Neo-Lab「真实私有数据」的沉淀形态——数据先被看见（商业平台），才谈得上被研究（商业侧训练）。

### 定位

> 商业平台 DKP 价值轨（§七）的数据源——算每人/每 workflow 的贡献度。对齐 v1.4.5 FDE 训练交付包的量化四字段（当前成本 / AI 后成本 / 年节省 / 回本周期）。

### 交付

| 组件 | 能力 |
|------|------|
| **`contribution_query` MCP tool** | 读审计（git diff 证据）+ decision-log（判定记录）→ 按人/按 workflow 聚合贡献度 |
| **贡献度算法** | PR 合并数 × 权重（节点复杂度/节省小时数）——人和数字员工同标准 |
| **DKP 对接** | 输出贡献度 → 商业平台换算 DKP（后台按 C7 基准映射薪酬参考）。已知局限：audit_files 按 diff 文件数计分的口径对大重构误提交有正向偏置（500 文件被拦 = +25 分 > 干净合并 2 分），反作弊权重校准排期后续版本 |

### 扩展：PR 触发绑定 confidence 两态（商业平台机制对账 · 2026-09-08 排入）

> 📋 **背景**：商业平台机制文档 §2.2 定义了「触发绑定按置信度分级」（对标 wemux GitHub 资源绑定三权威模型），引擎侧零排期——随 G13（PR 生命周期主题章）一并落地。每条 PR 出生即带「触发源绑定」：由哪个节点、哪条 workflow、哪次运行触发。

- **confidence 字段**：PR 元数据加 `triggerBinding: { source, confidence }`——**启发式只产生 `suggested`**（分支名匹配、时间相关性等推断）；**显式动作才产生 `confirmed`**（提交时声明、人手选关联）
- **三条铁律**：① 显式 confirmed / rejected 决策**永不被启发式同步覆盖**；② 后来的显式决策可以替换早先的显式决策；③ 同一外部资源（GitHub PR / issue / run）永远 upsert 同一条规范记录，不产生第二份表示
- **平台消费**：商业平台 PR 卡片的「建议关联 / 已确认」两态呈现即消费本字段（建议态可一键确认/否决）——商业交互红线 13 已定义
- **验收追加**：启发式绑定标 suggested、显式绑定标 confirmed；suggested 被人工否决后启发式重跑不复活（注入测试）；同一 source 多次绑定 upsert 单条记录（无第二份表示）（✅ 四用例实测：铁律一 confirmed 不被 suggested 覆盖 / 铁律二 后来显式可替换 suggested / 铁律三 同资源 upsert 单条 / isHeuristicallyBlocked 否决后不复活）
