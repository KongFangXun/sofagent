## 定位

> 🚀 **后训模块 · 分布式与云端**——让训练从「单机单卡」升级到「多卡 / 多云 VM」：租云 GPU VM 做多卡分布式训练（verl/DeepSpeed），引擎「Node 控制面 + Python 执行面」天然支持控制面与执行面分离——**控制面本地、执行面云上**。这是「全托管」交付模式（商业侧出算力）的技术底座。

## 背景：云端租 VM 做多卡/分布式（2026-08-10 确认）

| 维度 | 结论 |
|------|------|
| **云 GPU VM 形态** | AWS p4d（8×A100）/ Azure ND 系列 / 腾讯云 GN 系列 / 阿里云 GPU 实例——租一台 8 卡 VM = 多卡节点；租多台 VM 组集群 = 分布式 |
| **分布式训练软件** | verl / DeepSpeed / FSDP 原生支持多机多卡（阶段 2 选型 verl 就是干这个的） |
| **引擎架构契合** | 「Node 控制面 + Python 执行面」天然支持分离——控制面在本地/小服务器，执行面 spawn 到云 VM（ssh 远程 spawn 或云 API 触发训练 job） |
| **数据主权边界** | ⚠️ **敏感数据不能上公有云**（合规红线）——云训练适合非敏感/合成数据；敏感数据走客户机房联合训练（v1.4.3 沙箱 + 离线）。这是交付模式分层的核心 |

## 一、多卡 / 分布式训练（train multi · 规模化）

### 痛点

v1.4.3 GPU 队列是**单卡预算排队**——一张 4090 一个任务。阶段 2 规模化（14B/27B 基座、GRPO 大采样组）需要**多卡 / 多机**（verl 集群）。「全托管」交付模式（商业侧出算力）也要求引擎能调度多卡。

### 交付

| 组件 | 能力 |
|------|------|
| **多卡训练配置** | train submit 支持 `gpu: {count: 8, type: 'A100'}` / `nodes: 2`——写入 job.json（协议扩展，schema version+1） |
| **分布式 spawn** | 多机多卡训练经 verl/DeepSpeed 启动（torchrun / verl 集群入口）——协议②事件流不变（每个 rank 的进度汇总） |
| **GPU 队列升级** | 从单卡预算排队升级为**多卡拓扑感知**：卡数 + 类型 + 显存 → 分配/排队（单卡任务可插空） |
| **多卡诊断** | 分布式训练失败诊断扩展：rank 级日志 / NCCL 错误分类（对齐 v1.4.3 train diagnose） |

## 二、云端 VM 执行面（train cloud · 控制面本地 / 执行面云上）

### 定位

「Node 控制面 + Python 执行面」的**远程形态**——这是「全托管」交付模式（商业侧出算力帮企业训练）的技术底座，也是「提供训练管线」模式的可选升级（企业有云账号，引擎帮它在云上跑）。

### 交付

| 组件 | 能力 |
|------|------|
| **云 VM 注册** | `train cloud add --name training-1 --endpoint <vm>`——注册云 VM（ssh 或云 API 凭据），train doctor 远程体检 |
| **远程 spawn** | train submit 指定 `cloud: training-1` → 引擎 ssh/API 远程拉起训练进程（协议三约定不变，stdout JSON 流走 ssh 通道） |
| **数据上传/隔离** | 训练数据上传云 VM（加密传输）+ 训练后清理（不留敏感残留）——合规闸门（v1.4.5）前置拦截敏感数据 |
| **分拣闸门（上云前置 · 2026-09-05 拍板）** | 数据上云前过分拣闸：**敏感档**（客户名单/具体价格/财务数字）拦截留本地（挪知识库走 RAG），仅**脱敏档/公开档**可上云；分拣依据（为什么拦/为什么放）入 train_job 审计 HMAC 链可追溯。与 v1.4.5 合规扫描闸**分层不合并**：合规闸管「能不能训」（提交入口），分拣闸管「在哪训」（上云前置）。保密证书编号挂链（技术+法律双证据）同章交付 |
| **标准数据推送接口** | 企业存储/业务系统按标准格式（约定 schema）向引擎推送训练语料与知识数据——经分拣闸+合规闸双闸入库（v1.4.2 dataset-builder 多源接入的推送面标准化）；**深度定制连接器不做**，统一走本接口（2026-09-05 拍板） |
| **成本核算** | 云 VM 训练记成本（VM 时薪 × 时长）——预算控制（v1.4.1 ④）在云端同样生效，超预算暂停 |

> 🧱 **结构约束**：本版新增文件全部落在 `engine/orchestrator/src/train/` 下——保持 `train` 子目录边界清晰（不新增跨子目录耦合），为后续按子目录物理拆包留退路。背景：`orchestrator` 已占引擎源码 **48.8%**（92,718 / 190,051 行、约 27 个关注面），继续无边界膨胀会让 ROADMAP v1.4.8 的「依赖方向架构测试」建不起来（先拆后锁）。
