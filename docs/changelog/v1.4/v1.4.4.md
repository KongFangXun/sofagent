### 规则 → reward/verifier 映射（样本到 reward 配方的最后一公里 · 2026-08-26 补）

> 📋 **2026-08-26 补充**：三件套导出了**样本**（什么行为被判 FAIL/PASS），但 RL 训练还需要 **reward 定义**（用什么函数给行为打分）。sofagent 的天然优势：24+3 条审计规则的判定逻辑本身就是机器可执行的 verifier——**规则导出（第一件）从「给人看的规则定义」升级为「可挂进训练循环的 reward 骨架」**。

| 组件 | 能力 |
|------|------|
| **规则 → reward 骨架导出** | 每条审计规则导出时附带 `reward_hint` 段：判定函数签名（输入=工具调用序列/产物文本，输出=PASS/FAIL 三态）+ 严重度权重 + 可判定性标注（机器可判 / 需人审 / 启发式） |
| **verifier 清单** | 规则导出附 `verifiers.json`——哪些规则可直接当 reward 函数（机器可判类）、哪些只能当训练后验收（需人审类）——训练管线按清单接线，不混用 |
| **与 RL 配方模板衔接** | reward 骨架 + v1.4.3 RL 配方模板（grpo/dapo/cispo）= 完整训练配置——商业侧「reward 配方」的开源对应物（开源导骨架，商业侧调权重） |

**边界（不做）**：本版只导「规则 → reward 骨架」的映射格式与清单，**不实现训练循环本身**（那是计算面，复用开源框架——v1.4.1 拍板的「轮子全复用」边界）；也不做自然语言指令直转权重（self-distillation 属商业模型层）。

### 通用脱敏管线（业务语义脱敏）

现役脱敏只有 A2 规则的**格式匹配**（AKIA / sk- / ghp_ / PEM 块）+ decision-log `sanitizeWhy`——企业业务语义脱敏（客户名/内部代号/API 响应体业务字段）无通用管线。本版新增 `engine/core/src/export/redactor.ts`：

- **三类红名单**：格式类（复用 A2 检测）/ 语义类（实体名库，FDE 梳理辅助可录入）/ 结构类（API 响应体字段）
- **验收**：样本导出后 grep 原始企业专有名词 0 命中

### 合规红线（仅脱敏聚合，不落个体级数据）

| 红线 | 规则 |
|------|------|
| **不落个体级数据** | 样本导出仅脱敏聚合，可反推具体企业/具体请求的原始字段一律剥离 |

## 八、spec-first 硬禁令（OpenFDE 启发 · transcript 永不直驱代码 · 2026-08-30 排入）

> 📋 **2026-08-30 用户拍板**：探索方向表挂了多时的「spec-first 硬禁令（OpenFDE 启发 · 设计约束）——单一事实源：transcript 永不直驱代码，spec 才是唯一驱动」一直停在方向格。本版把断言基建已就绪（第六章 check-anchors 文件存在性断言同批交付）的条件用上，落成可执行的门禁 + 纪律双层交付。

### 定位

单一事实源纪律的工程化：**代码变更必须可追溯到 spec**（业务流声明 / 任务书 / 变更说明），conversation transcript（对话记录、访谈原文）本身永远不是改代码的依据——transcript 先沉淀为 spec（workflow.yml / fde.md / task 书），spec 才驱动实现。这与 SKILL 既有「先读再用」纪律同源，补的是「留痕可对账」这层机制。

### 交付

| 层 | 组件 | 能力 |
|------|------|------|
| **门禁层** | check-spec-first.mjs（tools/check/） | 扫 commit message / PR 描述与变更文件：涉及 `engine/*/src` 的代码提交，message 须含 spec 关联标记（`spec:` 前缀引用 workflow/fde/task 文件路径，或 `no-spec: <理由>` 显式豁免声明）；无标记无豁免即 WARN——**只提示不阻断**（新机制渐进纪律，跑一个版本观察误报率再议升级 FAIL） |
| **纪律层** | SKILL/skills/ 规范升级 | 五步循环的「实现」步前插入 spec 引用要求：Agent 改代码前先声明「本变更对应哪个 spec」——transcript 直出的口头需求须先落 fde.md/task 书再动代码；SKILL.md 加载链 L1 铁律区同步一行 |
| **对账层** | doctor 联动 | `--doctor` 输出近期 N 条 commit 的 spec 关联覆盖率（纯展示，不判 FAIL）——让「多少代码变更是 spec 驱动的」从不可见变为可运营的数字 |
