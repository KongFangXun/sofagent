## 交付一：LOOP 双 Agent 串联（P0 · 核心）

**串起来就够，不需要 LangGraph**。V1.1.1 先用已有的 DeepAgents compose CLI 把两个 Agent 串起来：

```
人类下达任务
  → engineering-minimal-change-engineer（写代码 + build + test + git commit）
  → sofagent-audit（commit-msg hook 自动触发）
  → engineering-code-reviewer（读 git diff + 输出审查报告）
  → 人类确认 → git push → 下一轮
```

## LUI 感知

用户通过 Agent 对话感知：「我下达任务后，Agent 自己写代码、自己 build+test、自己提交、审查员自动审完弹出报告。我只需要看最后一眼。」

校验标准：工程师 Agent 收到「在 README 里加一行版本号」→ 自动完成代码修改 + build + test + commit → audit 通过 → 审查员输出审查报告 → 人类看到报告。

## 交付四：Harness 可见性——签名机制（P0 · 产品）

**问题**：sofagent 的引擎在正常工作，但用户看到好结果时不知道是 harness 层在起作用——"证据可见"做了，但证据没有"签名"。

**方案**：三层签名机制——
- **审计结果签名**：CLI PASS/WARN/FAIL 输出加引擎身份行，Webhook PASS 也推送且以 `sofagent` 开头，MCP 工具返回值首行加 `[sofagent]` 前缀
- **能力清单签名**：list_capabilities 的 description 标注引擎来源
- **审查报告签名**：engineering-code-reviewer 报告顶部加 sofagent 签名段

改动 5 个文件（纯输出格式层），不改审计逻辑。详见开发 prompt。

**发版后补强（P0-5~P0-7）**：初见审查发现能力清单描述过期（写"A1-A14"漏了 A15-A17），以及剩余高价值触点未签名：
- **能力清单描述修正**：run_audit 的 MCP capabilities 描述从 `A1-A14 + E1-E4` → `sofagent 审计引擎 · 19 条规则 · 0 token 纯正则`（`mcp-server.ts`）
- **think.md 条目签名**：自动生成的反思记录 → `#审计结果(sofagent-audit v1.1.1): PASS`（`think-generator.ts`）
- **history.jsonl 溯源字段**：审计记录新增 `"engine": "sofagent-audit v1.1.1"` 字段（`audit-history.ts` + `index.ts`）
- **daemon 产出签名**：weekly-report + lessons-extract 生成的文件末尾加 `> 由 sofagent daemon v1.1.1 生成`（`weekly-report.ts` + `lessons-extract.ts`）
- **--init 输出前缀**：初始化关键确认消息加 `sofagent:` 前缀（`init.ts`）

## 交付五：think.md 记忆契约 + 全仓质量审计修复（P0 · 质量地基）

**背景**：v1.1.1 开发期对未提交 worktree 做全仓质量审计，发现 6 类"静默失败"问题（markdown 照建、git 不拦、测试照过），以及 think.md 记忆契约只停留在文档约定、代码层有写入方绕过。本交付把契约钉成代码级单一事实来源，并把审计发现收口进两份审查文档。

**① think.md 记忆契约——代码级单一事实来源（`sofagent/core/src/memory-contract.ts`，新增）**
把"路径 + Ledger / 只追加 / 多写入方 / 派生单向"五条不变量从文档约定提升为代码强制：
- `getThinkPath(dataBase?)`：think.md 路径唯一来源，杜绝各包硬编码 `path.join(dir,'think.md')`
- `appendThinkEntry(thinkPath, entry)`：强制只追加写入点（内部 `appendFileSync`，永不 `truncate`/`writeFileSync`）
- `THINK_MD_LAYER='ledger'` / `KNOWLEDGE_DIR_LAYER='views'`：层级归属常量

**② think-generator 路由经 core 契约（`sofagent/think/src/think-generator.ts`）**
审计后反思生成器 `generateThinkEntry` 原本自己 `join(dataDir,'think.md')` + 直接 `appendFileSync`，**绕过 append-only 不变量**。改为路径走 `getThinkPath(dataDir)`、写入走 `appendThinkEntry(thinkPath, entry)`，保留原 `mkdirSync` 建目录逻辑。

**③ audit 假注释修正（`sofagent/audit/src/index.ts:696`）**
原注释"generateThinkEntry 已迁移到 @sofagent/core"为误述——core 中无此函数。改为准确说明：生成由 `@sofagent/think` 负责、内部经 core 契约写入、audit 不直接写 think.md。

**④ 维度 306 落地：check-docs.sh 全仓死链扫描（`tools/check-docs.sh`）**
新增第 1b 节全仓相对路径死链扫描（bash 内联，不新建文件），围栏感知、跳过 http/https/mailto/纯锚点。原第 1 节 rules.md 专项收敛为"仅匹配真正 markdown 链接"（避免把我们审查文档散文里的 "rules.md" 字样误判为死链）。

**⑤ 全仓质量审计 6 类问题 → 审查文档加固**
`docs/verification/regression-checklist.md` 新增维度 301–306（死链全量扫描 / 跨包重复 / Ledger-Views 归属 / 文档规范源 DRY / 迁移四动作 / check-docs 扩展）；`docs/verification/fresh-eyes-review.md` 视角五·任务15 升级为自动化全量扫描、视角八 新增任务24（跨包重复）+ 任务25（归属一致性）。
