## 概述

v0.96 是 sofagent 的「诚实收缩」版本——不做大功能，做减法。核心动作围绕三件事：

1. **铁律重排**：6 条铁律按读者重要性重新排序，去掉（底线）（拐杖）标签，精炼描述。
2. **审计规则扩展设计**：两份审查各自独立指出审计 A1-A8 未覆盖 prompt injection、供应链投毒、资源耗尽。v0.96 完成 A9/A10/A11 规则草案，实现推 v0.97。

v0.96 的哲学基础来自两条独立但交汇的技术线（Ralph 循环 + 人与 Agent 系列），详见 §十。

## 三、P0：审计 A9/A10/A11 规则草案

> 来源：两份审查各自独立指出审计层覆盖面的缺口。审查一：「prompt injection、供应链攻击、资源耗尽——完全不在规则里。」审查二：「审计层没有覆盖 Agent 被攻击了的情况，只覆盖了 Agent 粗心。」

### 当前审计覆盖（A1-A8）

| 规则 | 覆盖范围 | 覆盖什么 |
|:--:|------|------|
| A1-A2 | 敏感文件 + 密钥泄漏 | ✅ Agent 粗心 |
| A3-A4 | 越界修改 + 配置删除 | ✅ Agent 粗心 |
| A5-A6 | 占位 commit + 构建破坏 | ✅ Agent 粗心 |
| A7-A8 | 盲改 + 逃验证 | ⚠️ Agent 粗心（依赖日志） |
| — | prompt injection | ❌ **未覆盖——Agent 被攻击了** |
| — | 供应链投毒 | ❌ **未覆盖——Agent 被攻击了** |
| — | 资源耗尽 | ❌ **未覆盖——Agent 被攻击了** |

### 新增规则草案

#### A9：不纳注入（prompt injection 检测）

扫描 Agent 生成的代码注释和字符串中是否包含已知注入模式：
- 「忽略之前的指令」「Ignore all previous instructions」
- 「你是 DAN」「You are now DAN」
- 「从现在开始你的新角色是」

实现方式：纯文本正则匹配，--silent 模式可跑。不依赖语义分析（那是 LLM 裁判的事）。

#### A10：不引毒源（供应链检测）

检测 package.json / requirements.txt / Cargo.toml 等依赖文件：
- 新增依赖是否为已知恶意包（对 NPM / PyPI 恶意包名单）
- 依赖版本是否从 `^1.0.0` 改成了指向特定 git commit（供应链攻击常见模式）

实现方式：v0.96 只做规则草案和 POC。v0.97 做完整实现。初期版本不维护恶意包名单——那是独立安全服务的事。检测「指向非官方源的依赖」即可。

#### A11：不滥资源（资源消耗检测）

检测单次任务的行为模式：
- 新增文件 > 50 个 → WARN
- 单文件 > 10,000 行 → WARN
- 批量删除 > 20 个文件 → FAIL

实现方式：纯 git diff 统计，--silent 模式可跑。

## 四、P1：编排引擎定位澄清 + 精简设计

> 来源：两份审查对编排引擎的质疑 + 作者对 FDE 场景编排引擎价值的确认。

### 两份审查的观点

审查一：「编排引擎应该从 sofagent 核心拆出来，变成独立的可选项。默认只装纪律层。编排是纪律之上的一层，不是纪律本身。」

审查二：「砍掉一半的编排概念——四级编排深度 + 三档自由度 + 两轮澄清 + 渐进减薄 + 信任等级四档——这套系统设计得像一个企业级编排平台，但实际用户是一个产品经理 + 几个 AI。」

### 作者的 FDE 场景确认

编排引擎在 FDE 场景下确实不可替代——FDE 梳理完企业 workflow 后，对每个 AI 可切入的节点需要任务拆解和编排。但这不是个人开发者的需求。

关键洞察：**编排引擎对个人开发者是零价值的概念噪音，对 FDE 部署者是不可或缺的核心能力。** 当前把它绑在 sofagent 核心里，结果两类用户都不舒服——个人开发者嫌重，FDE 嫌不够专业。

### v0.96 定位决策

**编排引擎从 sofagent 核心拆出，定位为 FDE 场景专用能力。**

```
当前：  sofagent = 纪律层 + 编排引擎 + 审计层（全绑在一起）

决策：  sofagent-core     = 纪律层（4→3 底线 + think.md + rules.md）
        sofagent-audit    = 审计 CLI（git diff，独立运行）
        sofagent-fde      = FDE 部署 Skill（编排引擎 + skillopt + 十步流程）
```

### 编排引擎精简设计

| 精简后 | 原来 | 理由 |
|------|------|------|
| 两档拆解（拆 vs. 不拆） | 四级编排深度（L1-L4） | FDE 场景下 workflow 节点粒度已定，不需要渐进减薄 |
| AO compose 自动拆解 | 保留 | 核心能力 |
| Agency Agent 模板匹配 | 自建 → **引用 AO Compose 自带模板库** | 「厚在治理，薄在复用」——不自己造几百个模板 |
| think.md → 编排引擎反馈回路 | 无 → 新增 | 上次反思驱动下次编排 |
| — 三档自由度 | 删除 | FDE 场景用户不参与编排 |
| — 渐进减薄 | 删除 | FDE 场景下 workflow 节点固定 |
| — 信任等级四档 | 删除 | skillopt 替代 |

### Agency Agent 模板匹配策略

不自己维护 Agent 模板库。AO Compose 本身自带 Agency Agent 的几百个模板（数据分析型、文档生成型、代码审查型、客服回复型等）。编排引擎直接引用——不改模板、不加 wrapper、不建中间层。这是「厚在治理，薄在复用」在编排层的直接体现。

### v0.96 交付物

- 编排引擎精简设计文档（本文 §四）
- 编排引擎从 sofagent/SKILL.md 的 🔴 点火条件中移除（个人开发者不再触发编排）
- sofagent-fde/SKILL.md 增加编排引擎使用说明
- **代码实现推 v0.97**（编排引擎重构 + think.md 反馈回路一起做）

## 五、P1：4 平台「装完做 3 件事」checklist

> 来源：v0.95 R2-5（两份审查各自标注为 P0 的遗留项）。

### 问题

sofagent 的差异化主张是「跨平台」，但非 OpenClaw 平台只有 30-40% 实际价值。用户装完发现 Agent 没变化——因为加载链在非 OpenClaw 平台靠 Agent 自觉 Read。

### v0.96 动作

为 4 个非 OpenClaw 平台各写一份「装完之后做这 3 件事」checklist，让每个平台的用户装完都能**感受到约束力**：

| 平台 | checklist 核心动作 | 存放位置 |
|------|------|------|
| WorkBuddy | ① @skill:sofagent 显式激活 ② 配置 MEMORY.md 内联核心规则 ③ 跑 verify.sh 验证 | HANDBOOK §三 |
| Claude Code | ① 添加 AGENTS.md 种子指令 ② 手动 Read SKILL.md ③ 跑 sofagent-audit 验证 git diff | HANDBOOK §三 |
| Codex | ① 配置种子指令 ② 任务后手动跑审计 ③ 注册 pre-commit hook | HANDBOOK §三 |
| Hermes Agent | ① 配置种子指令 ② 任务后手动跑审计 ③ 审查 think.md 写入手动触发 | HANDBOOK §三 |

> 诚实标注：checklist 不能把 30% 拉到 60%——它只能让 30% 的用户知道他们只有 30%，并教他们如何最大化利用这 30%。真正的提升要等各平台支持 Hook 机制（见 LIMITATIONS.md 平台依赖）。
