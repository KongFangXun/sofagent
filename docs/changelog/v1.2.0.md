## 背景

v1.1.0 完成包结构纯度重构 + 轻量多设备四件事（经验共享 / 自迭代周报 / 权限作用域化 / daemon 主动巡检）。但 daemon 当前的记忆沉淀仍是**两个分散脚本**（`weekly-report` 从 think.md 汇总周报、`lessons-extract` 从 think.md 提取踩坑经验），没有**分阶段结构化的记忆整合**。

2026-07-14 行业对标（2 份 deep research：RAG→LM Wiki→Gbring 范式 + gbrain 开源仓库）带来两个外部验证：

1. **gbrain 与 sofagent 同生态、可直接对标**——gbrain 是 OpenClaw/Hermes 生态的「Agent Brain」，和 sofagent 的 skillopt / Ontology / audit / daemon / entity-linking 高度同构，且已被工业项目验证。
2. **gbrain 有两点领先**：① 结构化的多阶段「Dream Cycle」记忆整合（21 阶段 pipeline）；② 显式的知识库分层 + 周期性健康巡检（矛盾/孤儿/死链）。

sofagent 已有能力（skillopt 自进化 / Ontology 内嵌语义层 / audit 约束 / daemon 夜沉 / 轻量实体关联）全部被外部验证为正确方向。本版本把 gbrain 的**两点领先**摘取吸收，做**精简版**（不照抄 21 阶段），为 v1.2.x「完整多设备协同」的多设备蒸馏记忆聚合铺好认知底座。

> 🛡️ **差异化铁律（对标时必守）**：gbrain 是「agent 自己的脑」，sofagent 是「约束中间件」（数据主权 + 第三方独立 + MIT 可审计）。本版本吸收其**方法**（分阶段整合、分层巡检），不吸收其**定位**（不变成 agent runtime）。

---

## 目标

把 daemon 的散点记忆沉淀升级为**显式分阶段的结构化记忆整合**，并把现有的隐式三层治理**显式化**为知识运维动作。下游消费者是约束系统（A 规则的「经验」能从历史沉淀）与未来检索子系统，不是某个 agent 的对话流畅度。

| 维度 | v1.1.0（轻量多设备） | v1.2.0（认知底座铺垫） |
|------|:--:|:--:|
| 记忆沉淀 | ❌ 分散脚本（weekly-report / lessons-extract） | ✅ 分阶段结构化整合（Dream Cycle 精简版） |
| 知识分层 | ⚠️ 隐式（Ledger/Views/Policy 概念存在未显式化） | ✅ 显式 3 层运维 + 周期冲突巡检 |
| 检索 | ❌ 无 | ⚠️ 仅记录默认架构约束（P2 条件项，不实现） |
| 多设备蒸馏聚合 | ❌ | 📋 本版本建好整合管道，聚合在后续 v1.2.x 增量 |

## 交付一：Dream Cycle 精简结构化记忆整合（P0 · 核心）

> 💡 **范围声明**：本交付是**流水线升级**（把现有分散脚本整合为显式多阶段 pipeline），不是从零造存储。不做详细实现规格（避免设计文档），任务分解与改动文件由开发期架构师产出后补入 `v1.2.0-dev-prompt.md`。

gbrain 的 21 阶段（extract_facts → extract_atoms → patterns → synthesize_concepts → conversation_facts_backfill → skillopt → embed）对「约束沉淀」真正有用的前半段。sofagent 摘取为 **6 阶段 MVP**：

```
extract_facts ──→ extract_atoms ──→ cluster_patterns
             ──→ synthesize_concepts（喂 @sofagent/ontology）
             ──→ skillopt_backfill（回灌自进化）
             ──→ embed（向量化，供未来检索）
```

- **落点（复用现有包，不新建）**：
  - `@sofagent/daemon`：新增 stage 状态机 + 配置，替换现有 `weekly-report` / `lessons-extract` 两个分散脚本
  - `@sofagent/ontology`：加 `synthesize` 接口（概念合成入口）
  - `@sofagent/skillopt`：加 `backfill` 钩子（整合结果回灌自进化）
- **验收标准**：nightly 跑通全流程；输出结构化 `knowledge/` 沉淀（fact / atom / concept 分目录，可审计、可注入加载链）；LLM 失败降级为跳过当前阶段 + 写日志（沿用 v1.1.0 weekly-report 的降级策略）
- **不做**：gbrain 全量 21 阶段；对话事实回填（conversation_facts_backfill，sofagent 非对话型）；实时检索（留给 P2 / 未来检索子系统）

## 交付二：LM Wiki 3 层显式分层 + Link 冲突检查（P1）

把现有隐式 `Ledger-Views-Policy` 三层记忆治理**显式化**为知识运维动作。LM Wiki 的 3 层（raw materials → Wiki entries → spec norms）与 sofagent 三层高度同构：

| LM Wiki 层 | sofagent 对应 | 当前状态 |
|------|------|:--:|
| raw materials（原始材料） | Ledger：task/logs（think.md / 审计历史） | ✅ 已存在 |
| Wiki entries（知识条目） | Views：knowledge/（entities / concepts / comparisons） | ✅ 已存在 |
| spec norms（规范约束） | Policy：fde.md（业务四问 / 约束） | ✅ 已存在 |

- **落点（几乎零新存储）**：复用 `knowledge/` 目录；`@sofagent/daemon` 新增常驻 `conflict-check` 脚本
- **交付物**：
  ① 一份三层映射文档（`docs/` 下，Ledger/Views/Policy ↔ raw/Wiki/spec）
  ② `conflict-check` 脚本：周期性检测知识库**矛盾 / 孤儿 / 死链**，输出报告（复用 v1.1.0 daemon 巡检的开关机制）
- **验收标准**：脚本可配置开关；跑通一轮输出矛盾/孤儿/死链清单；不修改知识内容（只读检测，符合 fail-closed）

## 交付三：混合检索架构（P2 · 条件项，本版本不实现）

gbrain 用 vector + BM25 + knowledge graph 混合检索。sofagent **当前没有** memory retrieval 子系统，建检索本身是巨大新模块。

- **本版本动作**：仅把「混合检索作为默认架构约束」记录进 ROADMAP「未来方向」，不写代码。
- **触发条件**：若检索子系统立项，MVP = 检索层抽象接口，默认实现 vector + BM25 双路 + Ontology 图扩展。
- **为何降为 P2**：用户原文标注「if memory retrieval built」；在检索未立项前列为 P1 会稀释焦点。
