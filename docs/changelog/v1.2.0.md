### 编排引擎内嵌（双节点架构工具层拦截）

v1.1.x 解决了「文件系统层」和「MCP 协议层」的审计可见性——daemon 监控磁盘文件变更，MCP pipe 拦截 Agent 的文件编辑动作。但还有一个盲区：**Agent 平台自带的编排引擎（tool scheduler）**。

WorkBuddy / CodeBuddy / Cursor 这些 Agent 平台都有自己的工具调度层——决定「先调用哪个 tool、传什么参数、怎么处理返回值」。这层 sofagent 完全看不到。

v1.2.0 的方案：把 sofagent 的核心规则引擎内嵌成 Agent 平台的「tool 拦截器」（interceptor），而不是外部独立工具。架构上等价于 OpenClaw 的「orchestrator 层」从外部旁路变成内部插件。

**双节点架构对应**：
- **自动运行节点**（OpenClaw + sofagent 全栈）：OpenClaw 的 orchestrator 直接加载 sofagent 规则作为 tool pre-condition，每个 tool call 执行前过 sofagent 检查
- **个人增强节点**（第三方 Agent + sofagent）：通过 Agent 平台的 hook 机制（WorkBuddy 的 `<user-prompt-submit-hook>` / CodeBuddy 的 pre-tool-use hook）注入 sofagent 检查

**关键设计**：
- 规则引擎从 `@sofagent/audit` 抽出为独立包 `@sofagent/rules-engine`（无 fs / git 依赖，纯函数）
- Agent 平台通过 hook 在 tool call 前调用 `rulesEngine.check({ tool, args, context })`
- 失败 → Agent 平台阻止 tool 执行，返回违规说明给 Agent
- WARN → Agent 平台允许执行但记录，可配置阈值转 FAIL

**与 v1.1.x 的关系**：
- v1.1.3 修好 daemon 物理可见性（plist + WorkingDirectory + PATH）
- v1.1.5 加 MCP pipe（Agent 编辑即时审计）
- v1.2.0 内嵌编排引擎（tool call 前置拦截，从「事后审计」升级为「事前拦截」）

这是 sofagent 从「独立审计工具」变成「Agent 平台原生能力」的关键一跳。审计引擎不再是个外部旁路，而是 Agent 平台工具调度层的内置组件。

- **LOOP 自迭代**：engineering-minimal-change-engineer + engineering-code-reviewer 双 Agent 自动循环开发（v1.1.1~v1.1.5）

- **双节点架构落地**：自动运行节点（OpenClaw orchestrator 原生加载）+ 个人增强节点（Agent 平台 hook 注入）（v1.2.0）
- **事前拦截**：tool call 执行前过 sofagent 规则检查，从「事后审计」升级为「事前拦截」（v1.2.0）
