# v1.1.0 开发日志 — 包结构纯度重构（audit 只做 audit）+ 轻量多设备

> ⚠️ **状态：已完成** — 此版本已于 2026-07-14 正式发版。
>
> v1.1.0 是 sofagent 的**架构纯度版本**：把 `@sofagent/audit` 这个"上帝包"彻底拆干净，让 audit 只做审计；同时在拆干净的新结构上落地轻量多设备四件事。
>
> 待开发 · 孔放勋
>
> 发布时间：2026-07-14（UTC）

---

## 背景

v1.0 定位升级：sofagent 不再是"Agent 审计工具"，而是 **Agent Harness 中间件**——不管企业用 OpenClaw / DeepAgents / Cloudtag 还是其他什么 Agent 平台，sofagent 是独立审计标准层。

但现实里 `@sofagent/audit` 名义叫"审计"，实际是整个**运行时**：审计规则 + 编排引擎（subagents/）+ 四层约束加载链（launcher.ts）+ 本体模型（ontology/）+ 后台引擎（daemon/）+ A/B 自进化（ab-test/）+ Work模板市场 分发（commands/hub）+ Skill 优化（skill-safety-check/skillopt-integration）+ 反思生成（think-generator）+ 评分引擎（eval/）+ 自检（verify/doctor/hitl）+ 一堆运行时基础设施（config/run-envs/env-check/model-client/log-*）。一个包里塞了至少 9 个领域。

**v1.1.0 目标**：audit 只做审计。其余一律拆成独立包，按"基础层 / 运行层 / 协议层"清晰分层。同时在此新结构上落地轻量多设备四件事。

v1.2.x 再做完整多设备协同（Agent 独立身份码 + 跨设备审计轨迹聚合 + 场景驱动权限体系 + 代理网关硬边界）。

## 目标包结构（终态）

```
基础层（不依赖任何 sofagent 包）
  @sofagent/harness      四层约束加载链 buildConstrainedSystemPrompt()
  @sofagent/ontology     知识图谱 / 本体模型（merge-engine / ontology-view / types）
  @sofagent/eval         评分引擎（ScoreBreakdown 等，被 ab-test 依赖）
  @sofagent/core         运行时基础设施 + 自检（verify / doctor / hitl / config /
                        run-envs / env-check / cost-baseline / model-client /
                        log-* / diff-parser / reporter / 通用 utils）

运行层（单向依赖基础层或彼此）
  @sofagent/orchestrator  编排 / 拆解 / SubAgent（composer / launcher / registry /
                        builtin-agents / audit-sub-agent / DAG executor）
                        + orchestrator-compare            → harness
  @sofagent/daemon       常驻引擎 / 定时巡检（cron / fs-watch / run-fs-audit /
                        snapshot / lessons-extract / weekly-report / inspectors）
                                                        → audit, harness, ontology, core
  @sofagent/ab-test   A/B 自进化（ab-runner / ab-promoter）
                                                        → orchestrator, harness, eval
  @sofagent/work模板市场          Work模板市场 模板分发（list / deploy）
                                                        → orchestrator, ontology, eval
                                                        （可选 → skillopt，提供 work模板市场 skillopt 包装）
  @sofagent/think        审计后反思生成（think-generator：基于 diff + AuditResult 写 think.md）
                                                        → audit（AuditResult）, core（diff-parser）
  @sofagent/skillopt     Skill 优化（skill-safety-check / skillopt-integration）
                                                        → ontology, core

协议层
  @sofagent/mcp          MCP 暴露（compose → orchestrator；可暴露 work模板市场 / ab）
                                                        → orchestrator, work模板市场

纯审计（叶子，只被依赖，不依赖其他运行包）
  @sofagent/audit        rules/ + webhook/ + filesystem/ + audit-{history,log,
                        regression,root-cause} + fix-suggestions + 权限作用域化(permission/)
                                                        → ontology（知识感知规则处）, core（基础设施）
```

**依赖铁律**：所有箭头单向，严禁循环。`harness / ontology / eval / core` 是叶子（不 import 任何 sofagent 包）；`orchestrator` 只依赖 `harness`；`daemon` 依赖 `audit + harness + ontology + core`；`ab-test` 依赖 `orchestrator + harness + eval`；`work模板市场` 依赖 `orchestrator + ontology + eval`（可选依赖 `skillopt`）；`think` 依赖 `audit + core`；`skillopt` 依赖 `ontology + core`；`mcp` 依赖 `orchestrator + work模板市场`；`audit` 仅依赖 `ontology`（知识感知规则）+ `core`（基础设施）。**关键解耦**：`audit` 不反向依赖 `think`（`generateThinkEntry` 的调用从 `audit/src/index.ts` 移除，改由 daemon 跑完 fs-audit 后 / 或独立 `sofagent-think` CLI 触发）；`skillopt` 不反向依赖 `work模板市场`。

## 交付一：包结构纯度重构（P0 · 核心）

> 💡 **详细实现规格（给开发者）**：本交付的任务分解、改动文件、验证命令、硬约束与验收标准，由架构师产出后补充进 `v1.1.0-dev-prompt.md`（交付 ⑤ 扩展）。本文档仅记录设计边界与各包归属。

### 1. harness 独立 → `@sofagent/harness`

- **现状证据**：`buildConstrainedSystemPrompt()`（四层约束加载链：SKILL.md + fde.md + think.md + knowledge + persona）原在 `audit/src/subagents/launcher.ts:210`，被 orchestrator 与 ab-test 共用。
- **目标**：新建 `@sofagent/harness`，把约束加载链整体迁入并导出（含类型与读取函数）。
- **硬约束**：🔴 **必须独立成包**，不允许留在 orchestrator 内 fallback。orchestrator / ab-test / daemon 的约束需求统一从 `@sofagent/harness` 导入。

### 2. ontology 独立 → `@sofagent/ontology`

- **现状证据**：`audit/src/ontology/`（merge-engine.ts + ontology-view.ts + types.ts），定义 `OntologyObject/Action/Constraint/MergedOntology`，从 entities/ 的 frontmatter `relations` 合并知识图谱。是"本体模型"核心。
- **目标**：新建 `@sofagent/ontology`，承载知识图谱模型与合并/视图逻辑。
- **消费方**：harness（加载知识图谱）、daemon（新鲜度巡检、关联图合并）、knowledge 共享层（① 的 `relations` 合并）。

### 3. eval 独立 → `@sofagent/eval`

- **现状证据**：`audit/src/eval/`（types.ts 含 `ScoreBreakdown`），被 `ab-test/types.ts` `import` 依赖。
- **目标**：新建 `@sofagent/eval`，承载评分引擎。ab-test 改从本包导入。

### 4. core 独立 → `@sofagent/core`（边界项收敛）

- **现状证据**：`audit/src/` 下散落大量"运行时基础设施 + 自检"——`verify/`、`commands/doctor`、`hitl/`、`config/`、`config-loader.ts`、`run-envs.ts`、`env-check.ts`、`cost-baseline.ts`、`model-client.ts`、`log-*`、`diff-parser.ts`、`reporter.ts`、以及 `compress-memory/rename/add-mod-del` 等 utils。
- **目标**：新建 `@sofagent/core`，统一收纳运行时基础设施与自检。这些算"边界项"，不是审计逻辑本身，但也不是独立领域，归到 core 最干净。
- **硬约束**：core 不依赖任何运行包（只依赖基础层 ontology 若需要）。

### 5. orchestrator 独立 → `@sofagent/orchestrator`

- **现状证据**：`audit/src/subagents/`（composer / launcher / registry / builtin-agents / audit-sub-agent）+ `orchestrator-compare.ts`；`compose` / `subagent` 子命令在 `index.ts`。编排 A/B 二进制 `sofagent-orchestrator-compare` 也错放 audit 的 bin。
- **目标**：新建 `@sofagent/orchestrator`，迁入 subagents + DAG executor + orchestrator-compare，二进制 `sofagent-orchestrator` + `sofagent-orchestrator-compare`。约束从 `@sofagent/harness` 导入。
- **硬约束**：orchestrator 不得反向依赖 audit；本次只做物理归位，不改 YAML 输出格式 / 四层约束 / Sub Agent 行为。

### 6. daemon 独立 → `@sofagent/daemon`

- **现状证据**：`audit/src/daemon/`（cron / fs-watch / run-fs-audit / snapshot）。
- **目标**：新建 `@sofagent/daemon`，迁入 daemon 全部逻辑（`think-generator` 不在此包，见交付 ⑨）。它依赖 audit 跑审计、harness 注入约束、ontology 做新鲜度/合并、core 做日志/运行。
- **为什么现在拆**：轻量多设备 ①/②/④ 的代码全写在 `src/daemon/` 里。不先拆 daemon，这 3 件事会继续在 audit 内长肉，以后更难抽。
- **think-generator 的归宿**：反思生成是"审计跑完之后的后处理"，与 daemon 的"定时/文件监听触发审计"是不同关注点（一个被动触发、一个主动生成）。daemon 在跑完 fs-audit 后**调用** `@sofagent/think`，但 think 不归属 daemon 包。详见交付 ⑨。

### 7. ab-test 独立 → `@sofagent/ab-test`

- **现状证据**：`audit/src/ab-test/`（ab-runner / ab-promoter / types），依赖 eval。
- **目标**：新建 `@sofagent/ab-test`，迁入 A/B 自进化逻辑。依赖 `orchestrator + harness + eval`。

### 8. work模板市场 独立 → `@sofagent/work模板市场`

- **现状证据**：`audit/src/commands/hub.ts`（`sofagent-audit hub list/deploy <模板>`——Work模板市场 模板列举/部署）。这就是 Hub 的本质：**Work模板市场 模板分发器**——列出可部署的 Workflow 模板、把模板部署出去（底层调用 `@sofagent/orchestrator` 跑编排）。
- **目标**：新建 `@sofagent/work模板市场`，只收纳 Work模板市场 分发。依赖 `orchestrator + ontology + eval`。Skill 优化（skillopt）不在此包，见交付 ⑩。
- **硬约束**：work模板市场 是编排的**消费者**，文档表达"work模板市场 调用 sofagent-orchestrator 部署 Workflow"，不要写成 work模板市场 自己生成 Workflow。可选依赖 `@sofagent/skillopt` 以对外提供 `sofagent-work模板市场 skillopt` 便利包装，但 skillopt 不反向依赖 work模板市场。

### 9. think 独立 → `@sofagent/think`（审计后反思生成）

- **现状证据**：`audit/src/think-generator.ts`（212 行）。`generateThinkEntry(diffFiles: DiffFile[], results: AuditResult, task?, opts?)`：审计跑完后，基于 git diff + 审计结果自动写 think.md 条目（v0.98 方案 A，幂等：同 task + 同分钟不重复）。依赖 `./diff-parser`(DiffFile) + `./reporter`(AuditResult)。
- **为什么独立**：它是"审计后的反思生成"，与 daemon 的"常驻引擎 / 定时巡检"是**两个不同关注点**。daemon 负责触发审计，think 负责审计完写反思——前者被动监听、后者主动生成。硬塞进 daemon 会让 daemon 包既管调度又管内容生成，违背"单一职责 + audit 只做 audit"。
- **目标**：新建 `@sofagent/think`，迁入 think-generator。依赖 `@sofagent/audit`（AuditResult 输出类型）+ `@sofagent/core`（diff-parser + fs utils）。**audit 不反向依赖 think**——`generateThinkEntry` 的调用从 `audit/src/index.ts` 移除，改由上层（daemon 跑完 fs-audit 后 / 或独立 `sofagent-think` CLI）触发。
- **硬约束**：think 是 audit 输出（AuditResult）的**消费者**，不是 audit 的一部分；audit 保持纯叶子。

### 10. skillopt 独立 → `@sofagent/skillopt`（Skill 优化）

- **现状证据**：`audit/src/skill-safety-check.ts` + `skillopt-integration.ts`（对应 `sofagent-audit skillopt-run` 子命令）。SkillOpt 自动优化管道：读取 SKILL.md → 安全校验 → 调用 skillopt 引擎就地演化 → 产出候选。
- **为什么独立**：Skill 优化是"对 Skill 文件做进化"，与 Hub 的"Workflow 模板分发"完全无关。Hub 部署的是 Workflow，skillopt 优化的是 Skill——两个不同领域，硬塞进 work模板市场 是偷懒归并。
- **目标**：新建 `@sofagent/skillopt`，迁入 skill-safety-check + skillopt-integration。依赖 `@sofagent/ontology`（Skill / 知识结构设计）+ `@sofagent/core`（model-client / fs utils）。不依赖 work模板市场。
- **硬约束**：skillopt 与 work模板市场 单向解耦——work模板市场 可选依赖 skillopt 提供 `sofagent-work模板市场 skillopt` 包装，skillopt 绝不反向依赖 work模板市场。

### 11. audit 收敛为纯审计

- **移除**：`src/subagents/`、`orchestrator-compare.ts`、`ab-test/`、`ontology/`、`daemon/`、`eval/`、`work模板市场` 子命令、`skillopt-run` 子命令、`think-generator.ts`、`skill-safety-check.ts`、`skillopt-integration.ts`、`verify/`、`commands/doctor`、`hitl/`、以及 config/run-envs/env-check/cost-baseline/model-client/log-*/diff-parser/reporter/utils（迁 core）。
- **保留**：`rules/`（A1–A17）、`webhook/`（审计通知）、`filesystem/`（文件系统审计）、`audit-{history,log,regression,root-cause}.ts`、`fix-suggestions.ts`、`evidence-mode.ts`、`sensitive-env` 相关、`qa-boundary-verify.ts`、`permission/`（权限作用域化落在 audit，见交付三）。
- **依赖方向**：audit 仅（知识感知规则处）import `ontology`、（基础设施处）import `core`。不依赖 orchestrator/daemon/ab-test/hub。

## 交付二~五：轻量多设备（4 件事）

> 设计背景与边界见下方各节；代码落点已映射到上面的新包。详细实现规格见 `v1.1.0-dev-prompt.md`（交付 ①–④）。

### ① 经验共享：跨设备 knowledge/ + think.md 同步（落点：harness + ontology + daemon）

A 设备的 Agent 踩了坑写了 think.md，B 设备的 Agent 不应再踩同样的坑。

**设计原则**：不搞 P2P 协议、不搞消息队列——用文件同步层（git submodule / NAS / 云盘挂载）解决物理传输，sofagent 只管语义合并。

**落点**：
- 知识图谱关联合并 → `@sofagent/ontology`（entities/concepts/comparisons 的 `relations` 字段合并）
- 加载链注入顺序（shared 优先于本机 think.md）→ `@sofagent/harness` 的 constraint-loader
- lessons 提取（think.md → knowledge/shared/lessons-{date}.md）→ `@sofagent/daemon` 的 lessons-extract

**合并策略**：同名冲突 → git merge（人工 resolve）；`relations` 字段 → ontology 关联图合并；`lessons-*.md` → 按日期追加不合并。

### ② 自迭代周报：daemon 汇总 think.md 生成 lessons-missteps（落点：daemon）

daemon（新包）新增 weekly cron 任务：扫描本周 think.md → LLM 汇总 → 写 `knowledge/shared/lessons-missteps-{YYYY-WW}.md` → 下期加载链注入。复用 ① 的 lessons 提取。只读聚合，LLM 失败降级为跳过本期 + 写日志。

### ③ 权限作用域化：项目级 permission override（落点：audit · permission/）

全局 `permission.json`（组织默认层）+ 项目级 `permission.local.json`（工作区级 override）。优先级 项目级 > 默认层，**无自动降级**（窄权限 401/403 宁可失败，绝不隐形越权）。频道级留给 v1.2.x。

### ④ daemon 主动巡检：从被动监工到主动告警（落点：daemon · inspectors）

daemon（新包）新增 4 项定时巡检，结果写入 lessons-missteps 或 daemon 通知：

| 巡检项 | 触发 | 告警方式 |
|--------|------|---------|
| 审计历史分析 | 每日 | 近 7 天同类规则 ≥3 次 → 写 lessons-missteps |
| doctor 健康度 | 每日 | 调 `@sofagent/core` 的 doctor，问题入 daemon 通知 |
| 知识库新鲜度 | 每周 | knowledge/ 最新 mtime > 30 天 → 提醒 FDE 更新 |
| Skill 过时检测 | 每周 | eval.md 近 10 次评分趋势下降 → 提醒优化 |

不做的：实时告警（IM/邮件），留给 v1.2.x。

## 规模与实现波次建议（风险提示）

v1.1.0 同时做"11 包拆分 + 4 新功能"，爆炸半径很大。虽然目标是在 v1.1.0 一次抽干净，但**实现建议分波**，每波可独立验证、独立回归：

| 波次 | 内容 | 关键依赖 |
|:--:|------|------|
| 🌱 Wave 1 基础层 | harness + ontology + eval + core 独立 | 无（叶子） |
| 🔧 Wave 2 运行层 | orchestrator + daemon 独立（audit 去掉对应代码） | Wave 1 |
| 🧪 Wave 3 实验层 | ab-test + work模板市场 + think + skillopt 独立 | Wave 2 |
| 🎯 Wave 4 功能 | 轻量多设备 ①–④（落在新包上）+ audit 最终收敛 | Wave 2–3 |
| ✅ Wave 5 收口 | 全量回归 + 文档（ARCHITECTURE/DEVELOPMENT/HANDBOOK/verify/fde-install/River）+ Release Notes 破坏性变更标注 | 全部 |

> ⚠️ 即使分波实现，v1.1.0 仍是"架构版本"，建议发版前 `pre-push-check.sh` + 三包（audit/orchestrator/daemon）+ 其余新包 `npm test` 全绿，且保留 v1.0.9 作为最后一个单包功能版的回退点。

## Release Notes · v1.1.0

### 🔨 核心变更

#### 架构重构 🔧
`@sofagent/audit` 拆分为 12 个独立 npm 包，按基础层/运行层/协议层/纯审计四层清晰分层。

#### 新功能
- **权限作用域化**：新增 `permission.local.json` 项目级权限 override，优先级 项目级 > 默认层，无自动降级
- **经验共享**：跨设备 knowledge/shared/ + think.md 语义合并，shared knowledge 优先注入加载链
- **自迭代周报**：daemon 从 think.md 自动提取踩坑经验，生成 lessons-missteps 周报
- **主动巡检**：daemon 新增 4 项定时巡检（审计历史分析/doctor 健康度/知识库新鲜度/Skill 过时检测）

#### 继承修复
v1.0.9 发布后修复的 19 项文档/代码问题

以下 CLI 命令已迁移到新包二进制：
