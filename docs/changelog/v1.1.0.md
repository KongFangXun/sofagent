## 背景

v1.0 定位升级：sofagent 不再是"Agent 审计工具"，而是 **Agent Harness 中间件**——不管企业用 OpenClaw / DeepAgents / Cloudtag 还是其他什么 Agent 平台，sofagent 是独立审计标准层。

Cloudtag / Sierra / Shopify 三家企业不约而同验证了"Agent 从工具变数字员工"的趋势。多设备是中间件的必修课。但完整多设备（独立身份 + 场景权限 + 代理网关）工程量太大，v1.1.x 先做轻量版——不碰身份/权限协议/协同线程，只做四件事：

1. **经验共享**：跨设备同步 knowledge/ + think.md
2. **自迭代周报**：daemon 汇总 think.md 生成 lessons-missteps.md
3. **权限作用域化**：项目级 permission override
4. **daemon 主动巡检**：从被动监工升级为主动告警

v1.2.x 再做完整多设备协同（Agent 独立身份码 + 跨设备审计轨迹聚合 + 场景驱动权限体系 + 代理网关硬边界）。

---

## 交付内容（4 件事）

### 1. 经验共享：跨设备 knowledge/ + think.md 同步

A 设备的 Agent 踩了坑写了 think.md，B 设备的 Agent 不应再踩同样的坑。

**设计原则**：不搞 P2P 协议、不搞消息队列——用文件同步层（git submodule / NAS / 云盘挂载）解决物理传输，sofagent 只管语义合并。

**实现方案**：

```
设备 A (.sofagent/)
├── knowledge/          ← 共享层（git submodule 或 NAS 挂载）
│   ├── entities/       ← 实体页
│   ├── concepts/       ← 概念页
│   └── comparisons/    ← 对比页
├── think.md            ← 设备本地（不共享原始反思）
├── task/logs/          ← 设备本地（不共享原始日志）
└── knowledge/
    └── shared/         ← 共享反思摘要（从 think.md 提取的可公开经验）

设备 B (.sofagent/)
├── knowledge/          ← 同一个 git submodule / NAS 挂载
├── think.md            ← B 自己的反思
└── task/logs/          ← B 自己的日志
```

**关键决策**：
- think.md 原始内容不直接共享（可能含设备特定的路径、密钥片段、调试细节）
- daemon 从 think.md 提取可公开经验写入 `knowledge/shared/lessons-{date}.md`
- knowledge/ 目录通过 git submodule 或 NAS 挂载实现物理同步
- 加载链注入时优先读 `knowledge/shared/`（跨设备经验）再读本机 think.md

**合并策略**：
- 同名文件冲突 → git merge（人工 resolve，不自动覆盖）
- entities/concepts/comparisons 页面 → frontmatter `relations` 字段做关联图合并
- lessons-*.md → 按日期追加，不合并

### 2. 自迭代周报：daemon 汇总 think.md 生成 lessons-missteps.md

借鉴 Cloudtag 的"每周失误周报"——Agent 自己追踪自己的失误，避免下次再犯。

**实现方案**：

daemon 新增定时任务（每天/每周可配）：
1. 扫描本周所有 think.md
2. 提取"踩了什么坑 / 下次怎么办"段落
3. LLM 汇总为 `knowledge/shared/lessons-missteps-{YYYY-WW}.md`
4. 加载链下次注入时带上最新一期周报

**周报格式**：

```markdown
---
type: lessons
period: 2026-W28
device: macbook-pro
generated: 2026-07-14T03:00:00+08:00
---

# 周报复盘 2026-W28

## 反复出现的问题（≥3 次）
1. **路径穿越**：Agent 多次尝试写入项目目录外的文件 → A3 已拦截，但 root cause 是 fde.md 权限描述不够清晰
2. **think.md 格式不规范**：反思缺少"下次怎么办"段 → 考虑加模板校验

## 新发现问题
1. npm install 超时未处理 → 加 120s 超时 + 重试

## 已改善
1. Secret 检测本周 0 次漏报（上周 2 次）→ A2 规则有效
```

### 3. 权限作用域化：项目级 permission override

借鉴 Cloudtag 三层能力叠加——权限不跟随 Agent 走，挂在工作空间上。

**当前状态**：全局 `permission.json`，一份管所有场景。

**v1.1.0 方案**：

```
.sofagent/
├── permission.json              ← 组织默认层（基线）
└── projects/
    └── {project-name}/
        └── permission.local.json ← 工作区级 override
```

**叠加规则**（对齐 Cloudtag）：
- 优先级：项目级 > 组织默认层
- **优先级覆盖、无自动降级**：项目级窄权限凭证调用失败（401/403），系统不自动降级到默认层宽权限。宁可失败，绝不隐形越权
- 项目级只声明 override 项，未声明的继承默认层

**示例**：
```json
// 默认层 permission.json
{
  "allowedPaths": ["src/**", "docs/**"],
  "forbiddenPaths": ["**/.env", "**/secrets/**"]
}

// 项目级 .sofagent/projects/payment-api/permission.local.json
{
  "allowedPaths": ["src/**", "docs/**", "infra/terraform/**"],
  "forbiddenPaths": ["**/.env", "**/secrets/**", "infra/terraform/prod/**"]
}
```

**频道级**（Cloudtag 第三层）不在 v1.1.0 实现，留给 v1.2.x。

### 4. daemon 主动巡检：从被动监工到主动告警

**当前状态**：daemon 每 30 秒检查 think.md/fde.md 文件 hash 变化并通知——被动响应。

**v1.1.0 升级**：

| 巡检项 | 触发条件 | 告警方式 |
|--------|---------|---------|
| **审计历史分析** | 每日定时跑 | 扫描最近 7 天 audit history，发现同类规则连续触发 ≥3 次 → 写入 lessons-missteps.md |
| **doctor 健康度** | 每日定时跑 | sofagent-audit --doctor，发现问题写入 daemon 通知 |
| **知识库新鲜度** | 每周定时跑 | knowledge/ 最新文件 mtime > 30 天 → 提醒 FDE 更新 |
| **Skill 过时检测** | 每周定时跑 | scoring.md 最近 10 次评分趋势下降 → 提醒 Skill 需要优化 |

**不做的**：实时告警（IM 推送/邮件通知）——这是 v1.2.x 多设备协同时的事。

| 维度 | v1.1.0（轻量） | v1.2.x（完整） |
|------|:--:|:--:|
