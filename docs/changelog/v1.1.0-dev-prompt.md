## 交付 ① — 经验共享：跨设备 knowledge/ + think.md 同步

### ①.1 目标与现状

- **现状**：每个设备的 `.sofagent/knowledge` 与 `think.md` 是孤岛。A 设备踩的坑，B 设备重踩。
- **目标**：跨设备同步 `knowledge/`（实体 / 概念 / 对比页）与「从 think.md 提取的可公开经验摘要」`knowledge/shared/lessons-{date}.md`；`think.md` 原始内容**不**共享。

### ①.2 设计决策（不可变，详见 changelog）

- 物理同步用 **git submodule 或 NAS 挂载**，sofagent 只管语义合并——不搞 P2P 协议、不搞消息队列。
- `think.md` 原始不共享（可能含设备特定路径 / 密钥片段 / 调试细节）；daemon 从 `think.md` 提取可公开经验写入 `knowledge/shared/lessons-{date}.md`。
- **加载链注入顺序**：先 `knowledge/shared/`（跨设备经验），再本机 `think.md`。
- **合并策略**：同名文件冲突 → `git merge`（人工 resolve，不自动覆盖）；`entities/concepts/comparisons` 页面用 frontmatter `relations` 字段做关联图合并；`lessons-*.md` 按日期追加，不合并。

### ①.3 具体任务

**任务 1.1 — knowledge 共享目录约定 + 同步引导文档**
- 在 `.sofagent/` 下明确 `knowledge/shared/` 子目录（语义层，存放 `lessons-*.md`）。
- 写 `docs/guides/knowledge-sync.md`：说明 git submodule / NAS 挂载两种物理同步方式、`ignore` 规则（`think.md`、`task/logs/` 不进共享层）。
- 改动文件：`.gitignore` / `.sofagent/.gitignore`（若本地 repo）；新增 `docs/guides/knowledge-sync.md`。
- 验证：`cat docs/guides/knowledge-sync.md` 结构完整；`git check-ignore .sofagent/think.md` 命中（确认不进共享层）。

**任务 1.2 — 加载链注入顺序调整（依赖 ⑤ harness）**
- 在 `@sofagent/harness` 的 `buildConstrainedSystemPrompt()` 中，将 `knowledge/shared/` 的读取放在本机 `think.md` **之前**。
- 改动文件：`sofagent/harness/src/constraint-loader.ts`（交付 ⑤ 抽到此包后改；改造前 `grep "think.md" src/` 确认实际位置）。
- 验证（单测）：给定 `knowledge/shared/lessons-x.md` 与本机 `think.md` 都含「路径穿越」经验，注入结果中 shared 段落排在前。

**任务 1.3 — lessons 提取（daemon 子任务，供 ② 复用）**
- 提取逻辑独立成 `sofagent/daemon/src/lessons-extract.ts`（daemon 独立包，见交付 ⑤ ⑤.5.6），从 `think.md` 抽取「踩坑 / 下次怎么办」段落写入 `knowledge/shared/lessons-{date}.md`。
- 验证：`node -e` 跑一个 `think.md` 样本，确认生成 lessons 文件且**不含**密钥片段 / 设备绝对路径。

### ①.4 硬约束

1. **不共享原始反思**：`think.md`、`task/logs/` 永不进入共享层（物理同步层 ignore 强制）。
2. **不内置传输**：物理同步机制不内置于 sofagent 二进制——只提供引导文档 + ignore 模板，避免引入 P2P / 传输依赖。
3. **shared 优先**：加载链必须 `knowledge/shared/` 优先于本机 `think.md`，防本机旧经验覆盖跨设备新经验。

### ①.5 验收标准

- [ ] `knowledge/shared/` 在 2+ 设备经 git submodule 同步后双方可见
- [ ] 加载链注入顺序单测通过（shared 在前）
- [ ] lessons 提取不泄露 `think.md` 原始私密段落（人工 review 样本）

## 交付 ② — 自迭代周报：daemon 汇总 think.md 生成 lessons-missteps

### ②.1 目标与现状

- **现状**：`think.md` 只在本机积累，无跨周期复盘。
- **目标**：daemon 定时汇总本周 `think.md`（及 ① 的 lessons），LLM 生成 `knowledge/shared/lessons-missteps-{YYYY-WW}.md`，下期加载链注入。

### ②.2 设计决策（不可变）

- 周报 frontmatter：`type: lessons` / `period: YYYY-WW` / `device` / `generated`。
- 三段结构：**反复出现的问题（≥3 次）** / **新发现问题** / **已改善**。
- 复用 ①.3 的 lessons 提取作为素材来源。

### ②.3 具体任务

**任务 2.1 — daemon 周报 weekly cron 任务**
- 在 daemon 调度里新增 `weekly` 任务，调用 lessons 汇总（LLM）。
- 改动文件：`sofagent/daemon/src/scheduler.ts`（daemon 独立包，见交付 ⑤ ⑤.5.6）；新增 `sofagent/daemon/src/weekly-report.ts`。
- 验证：`DEBUG=daemon` 手动触发一次，确认生成 `lessons-missteps-{YYYY-WW}.md`。

**任务 2.2 — LLM 汇总 prompt + 格式校验**
- 汇总 prompt 产出规定 frontmatter；加格式校验（`period` 正则、三段齐全）。
- 验证：给定 3 周 `think.md` 样本，输出符合周报格式 schema（可用 `ajv` 或最小正则校验）。

**任务 2.3 — 加载链注入周报（依赖 harness）**
- 在 harness 加载链中，将最新一期 `lessons-missteps-{YYYY-WW}.md` 注入（位于 `knowledge/shared/` 之后、本机 `think.md` 之前或并列）。
- 改动文件：`sofagent/harness/src/constraint-loader.ts`。

### ②.4 硬约束

1. **只读聚合**：周报不写回本机 `think.md`（不改反思源）。
2. **失败降级**：LLM 调用失败必须降级为「跳过本期周报 + 写 daemon 日志」，不得阻塞 daemon 主循环。

### ②.5 验收标准

- [ ] 周报格式稳定（跑 ≥2 期，schema 校验通过）
- [ ] 加载链注入周报单测通过
- [ ] LLM 失败降级路径单测 / 手动验证

## 交付 ③ — 权限作用域化：项目级 permission override

### ③.1 目标与现状

- **现状**：全局 `permission.json` 一份管所有场景。
- **目标**：项目级 `permission.local.json` override，优先级 **项目级 > 组织默认层**，**无自动降级**。

### ③.2 设计决策（不可变）

- 目录：`.sofagent/projects/{project-name}/permission.local.json`。
- 叠加规则：优先级覆盖；项目级窄权限凭证调用失败（401/403），系统**不自动降级**到默认层宽权限——宁可失败，绝不隐形越权。
- 项目级只声明 override 项，未声明的继承默认层。
- 频道级（Cloudtag 第三层）不在 v1.1.0，留给 v1.2.x。

### ③.3 具体任务

**任务 3.1 — 权限叠加解析器**
- 新增 `sofagent/audit/src/permission/resolve.ts`：读取默认 `permission.json` + 项目级 override，做深度合并（项目级覆盖同键，未声明继承）。
- 改动文件：原 permission 读取入口（`grep "permission.json" src/` 确认）。
- 验证（单测）：默认 `allowedPaths=[src,docs]`，项目级加 `infra/terraform` → 结果合并；项目级 `forbiddenPaths` 加 `prod/**` → 结果合并。

**任务 3.2 — 无降级硬规则**
- 在 resolve 阶段：项目级声明的凭证 / 路径被拒绝时，直接抛 `PermissionDenied`（带 context），**不得 fallback** 到默认层。
- 验证（单测）：项目级 `forbiddenPaths` 含 `infra/terraform/prod/**`，尝试写入该路径 → 拒绝，且对照「默认层允许」不触发。

**任务 3.3 — CLI / 文档校验**
- 在 `verify` / `doctor` 中校验 `permission.local.json` 格式合法（JSON schema）。
- 改动文件：`sofagent/core/src/verify/checks.ts` 增一项；`docs/ARCHITECTURE.md` 权限章节更新。

### ③.4 硬约束

1. **永不自动降级**到默认层宽权限。
2. **override 缺失 / 格式错误**时，回退到默认层（不报错），但 daemon 告警提示。

### ③.5 验收标准

- [ ] 合并单测通过（覆盖 / 继承 / 冲突）
- [ ] 无降级单测通过（401/403 不越权）
- [ ] `permission.local.json` schema 校验接入 `verify`

## 交付 ④ — daemon 主动巡检：从被动监工到主动告警

### ④.1 目标与现状

- **现状**：daemon 每 30s 检查 `think.md/fde.md` 文件 hash 变化并通知——被动响应。
- **目标**：新增 4 项定时主动巡检，结果写入 `lessons-missteps` 或 daemon 通知。

### ④.2 设计决策（不可变）

| 巡检项 | 触发条件 | 告警方式 |
|--------|---------|---------|
| **审计历史分析** | 每日定时跑 | 扫描最近 7 天 audit history，同类规则连续触发 ≥3 次 → 写入 `lessons-missteps.md` |
| **doctor 健康度** | 每日定时跑 | `sofagent-core --doctor`（doctor 已迁 core，见交付 ⑤ ⑤.5.4），发现问题写入 daemon 通知 |
| **知识库新鲜度** | 每周定时跑 | `knowledge/` 最新文件 mtime > 30 天 → 提醒 FDE 更新 |
| **Skill 过时检测** | 每周定时跑 | `eval.md` 最近 10 次评分趋势下降 → 提醒 Skill 需要优化 |

**不做的**：实时告警（IM 推送 / 邮件通知）——留给 v1.2.x 多设备协同时。

### ④.3 具体任务

**任务 4.1 — 巡检调度框架**
- daemon scheduler 支持 `daily` / `weekly` 两类 cron；新增 `sofagent/daemon/src/inspectors/` 目录（daemon 独立包，见交付 ⑤ ⑤.5.6），每巡检项一个模块。
- 改动文件：`sofagent/daemon/src/scheduler.ts`。

**任务 4.2 — 审计历史分析 inspector**
- 读近 7 天 audit history（`grep` audit log 目录确认路径），统计同规则触发计数 ≥3 → 写 `knowledge/shared/lessons-missteps-{YYYY-WW}.md`（追加「反复出现的问题」）。

**任务 4.3 — doctor 健康度 inspector**
- 调 `sofagent-core --doctor`（doctor 已迁 `@sofagent/core`，见交付 ⑤ ⑤.5.4；或内部 API），问题写入 daemon 通知队列。

**任务 4.4 — 知识库新鲜度 inspector**
- 扫 `knowledge/` 最新 mtime > 30 天 → daemon 通知「提醒 FDE 更新」。

**任务 4.5 — Skill 过时检测 inspector**
- 读 `eval.md` 近 10 次评分，趋势下降 → 通知「Skill 需优化」。

### ④.4 硬约束

1. **隔离失败**：巡检失败不影响 daemon 主循环（各自 try/catch，错误进 daemon 日志）。
2. **不引入外部通道**：仅 daemon 本地通知 / 日志，IM 推送留给 v1.2.x。

### ④.5 验收标准

- [ ] 4 项巡检均可配置开关（config 字段 `inspect.auditHistory` / `doctor` / `knowledgeFreshness` / `skillStaleness`）
- [ ] 各 inspector 单测：给定样本输入，产出预期通知 / 写入
- [ ] daemon 主循环在 inspector 抛错时持续运行

## 交付 ⑤ — 架构重构：11 包拆分（audit 只做 audit）🔧

> ⚠️ 本项原在 v1.0.9 第 4 项规划、建议以 v1.0.10 发版。经评估后并入 **v1.1.0**（v1.1.0 尚未发版，开发中）。v1.0.9 仅交付 MCP compose tool（编排经 MCP 暴露），编排的**物理归位**与本次轻量多设备四件事都并入 v1.1.0。
>
> 终态以 [`v1.1.0.md`](./v1.1.0.md)「目标包结构（终态）」为准：11 包分层（基础层 harness/ontology/eval/core · 运行层 orchestrator/daemon/ab-test/workflow-hub/think/skillopt · 协议层 mcp · 纯审计叶子 audit）。

### ⑤.1 背景与目标

`@sofagent/audit` 名义叫"审计"，实际是整个 sofagent **运行时**——审计规则 + 编排引擎（subagents/）+ 四层约束加载链（launcher.ts）+ 本体模型（ontology/）+ 后台引擎（daemon/）+ A/B 自进化（ab-test/）+ Workflow Hub 分发（commands/hub）+ Skill 优化（skill-safety-check/skillopt-integration）+ 反思生成（think-generator）+ 评分引擎（eval/）+ 自检（verify/doctor/hitl）+ 一堆运行时基础设施（config/run-envs/env-check/model-client/log-*）。一个包里塞了至少 11 个领域，形成"上帝包"。

**目标**：audit 只做审计。其余 10 个领域拆成独立包，按"基础层 / 运行层 / 协议层"清晰分层。各包依赖方向严格单向，严禁循环。

### ⑤.2 目标架构（11 包终态，含关键文件）

```
基础层（叶子，不依赖任何 sofagent 包）
  @sofagent/harness       src/constraint-loader.ts  buildConstrainedSystemPrompt()
                          （SKILL.md + fde.md + think.md + knowledge + persona 四层约束）
  @sofagent/ontology      src/{merge-engine,ontology-view,types}.ts
                          （OntologyObject / Action / Constraint / MergedOntology）
  @sofagent/eval          src/{types,eval-scorer,eval-runner,eval-reporter}.ts
                          （EvalBreakdown 评分引擎）
  @sofagent/core          src/{verify/,doctor.ts,hitl/,config/,run-envs,env-check,
                          cost-baseline,model-client,diff-parser,reporter,log-*,
                          utils,shared/}  运行时基础设施 + 自检  bin: sofagent-core

运行层（单向依赖基础层或彼此）
  @sofagent/orchestrator   src/{composer,launcher,registry,builtin-agents,
                          audit-sub-agent}.ts + DAG executor + orchestrator-compare.ts
                          bin: sofagent-orchestrator / -orchestrator-compare        → harness
  @sofagent/daemon        src/{cron,fs-watch,run-fs-audit,snapshot,lessons-extract,
                          weekly-report,inspectors/}.ts   bin: sofagent-daemon    → audit, harness, ontology, core
  @sofagent/ab-test    src/{ab-runner,ab-promoter,types}.ts   bin: sofagent-ab-test  → orchestrator, harness, eval
  @sofagent/workflow-hub           src/hub.ts（list / deploy）  bin: sofagent-workflow-hub          → orchestrator, ontology, eval（可选→skillopt）
  @sofagent/think         src/think-generator.ts   bin: sofagent-think            → audit（AuditResult）, core（diff-parser）
  @sofagent/skillopt      src/{skill-safety-check,skillopt-integration}.ts
                          bin: sofagent-skillopt                                    → ontology, core

协议层
  @sofagent/mcp           src/mcp-server.ts（sofagent_compose → orchestrator；可暴露 workflow-hub / ab）
                                                                                    → orchestrator, workflow-hub

纯审计（叶子，只被依赖）
  @sofagent/audit        rules/ webhook/ filesystem/ audit-{history,log,regression,
                          root-cause}.ts fix-suggestions evidence-mode sensitive-env
                          qa-boundary-verify permission/   bin: sofagent-audit        → ontology, core
```

### ⑤.3 依赖铁律（11 包单向依赖 + 禁止循环）

- **叶子层**（绝不 import 任何 sofagent 包）：`harness` / `ontology` / `eval` / `core`。
- **单向依赖方向**（只能按箭头方向 import）：
  - `orchestrator → harness`
  - `daemon → audit + harness + ontology + core`
  - `ab-test → orchestrator + harness + eval + core`
  - `workflow-hub → orchestrator + ontology + eval`（可选 `→ skillopt`）
  - `think → audit + core`
  - `skillopt → ontology + core`
  - `mcp → orchestrator + workflow-hub`
  - `audit → ontology + core`（知识感知规则处 import ontology；基础设施处 import core）
- **关键解耦**：
  - `audit` 绝不反向依赖 `think`：`generateThinkEntry` 的调用从 `audit/src/index.ts` 移除，改由 daemon 跑完 fs-audit 后 / 或独立 `sofagent-think` CLI 触发。
  - `skillopt` 绝不反向依赖 `workflow-hub`：hub 可选依赖 skillopt 提供 `sofagent-workflow-hub skillopt` 包装，反之不可。
  - `core` 不依赖任何运行包（本版不引入 ontology 依赖，保持纯叶子）。

- `sofagent/audit/src/subagents/` 含 5 个文件：`composer.ts` `launcher.ts` `registry.ts` `builtin-agents.ts` `audit-sub-agent.ts`。
- `audit/src/index.ts` 是"上帝入口"，集中 dispatch 了全部子命令与动态 import（当前实测行号，开发者动手前请重新 `grep` 确认）：

#### ⑤.5.17 向后兼容 shim（CLI deprecation 桥接）

> `sofagent-audit compose` 等子命令直接消失对存量用户是硬伤。为 doctor / verify / compose 三条最常用的加 deprecation shim。

- **实现方式**：在 `@sofagent/audit` 的 `index.ts` 中保留 compose / doctor / verify 子命令入口，但内部转发到新包二进制，并打印 deprecation 警告：
  ```typescript
  // audit/src/index.ts — compose 子命令 shim
  if (subcommand === 'compose') {
    console.error('⚠️ [sofagent] "sofagent-audit compose" 已迁移到 "sofagent-orchestrator compose"（v1.1.0）。将在 v1.2.0 移除此兼容入口。');
    const { execFileSync } = require('child_process');
    execFileSync('sofagent-orchestrator', process.argv.slice(3), { stdio: 'inherit' });
    process.exit(0);
  }
  ```
- **shim 覆盖范围**：`compose` → `sofagent-orchestrator`；`doctor` → `sofagent-core`；`verify` → `sofagent-core`。其余子命令（`subagent` / `hub` / `ab-test` / `skillopt-run`）使用面窄，直接移除 + Release Notes 标注迁移。
- **shim 生命周期**：v1.1.0 加 shim + 警告 → v1.2.0 移除 shim（用户有 1 个版本周期迁移）。
- **硬约束**：shim 不引入对新包的编译期依赖（用 `execFileSync` 子进程调用 + `require('child_process')` 内置模块），保持 audit 纯审计。

#### ⑤.5.19 跨包 config 读取策略

> `config-loader.ts` 迁到 core 后，daemon / orchestrator / skillopt 都需要读 `.sofagent/config.yml`。需明确读取策略避免重复读取 + 配置不一致。

- **统一入口**：`@sofagent/core` 暴露 `loadConfig(projectRoot?: string): SofagentConfig`，所有包统一调用此函数读取配置。
- **缓存**：`loadConfig()` 内部做进程级缓存（`Map<projectRoot, SofagentConfig>`），同一进程内多次调用只读一次文件。daemon 长驻进程通过 `invalidateConfig(projectRoot)` 在文件变更时清缓存（复用 `watch-config.ts` 的 fs.watch）。
- **类型导出**：`SofagentConfig` 类型从 `@sofagent/core` 导出，各包 `import type { SofagentConfig } from '@sofagent/core'`。
- **依赖方向**：daemon / orchestrator / skillopt / audit → core（`loadConfig`），不形成循环。

### ⑤.6 跨包硬约束汇总（不可违反）

1. **🔴 禁止循环依赖**：依赖方向严格单向——`harness/ontology/eval/core` 为叶子（绝不 import 任何 sofagent 包）；`orchestrator → harness`；`daemon → audit+harness+ontology+core`；`ab-test → orchestrator+harness+eval+core`；`workflow-hub → orchestrator+ontology+eval`（可选→skillopt）；`think → audit+core`；`skillopt → ontology+core`；`mcp → orchestrator+workflow-hub`；`audit → ontology+core`。任何 `audit → think` / `orchestrator → audit` / `harness → *` / `core → 运行包` 的反向 import 一律禁止。

5. **skillopt 与 workflow-hub 单向**：workflow-hub 可选依赖 skillopt 提供 `sofagent-workflow-hub skillopt` 包装，skillopt 绝不反向依赖 workflow-hub。
6. **向后兼容 / 破坏性标注**：`sofagent-audit compose/subagent/workflow-hub/ontology/ab-test/skillopt-run/doctor/verify` 全部移除或改指向新包二进制。其中 compose/doctor/verify 保留 **deprecation shim**（⑤.5.17），打印警告 + 转发，v1.2.0 移除。其余直接移除。必须在 changelog / Release Notes 标注迁移命令（见 v1.1.0.md「破坏性变更清单」）。

8. **不改动编排行为**：本次只做物理归位，不改 `composeWithDeepAgents` 的 YAML 输出格式、不改四层约束加载逻辑、不改 Sub Agent 行为、不改审计规则 A1–A17。
