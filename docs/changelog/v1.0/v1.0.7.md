# v1.0.7 开发日志 — 双节点架构 + Sub Agent 约束自加载 + 预装 Agent + ao 完全退役

> ✅ **已正式发版** · 2026-07-13（UTC）· 孔放勋
>
> sofagent 从"只有 OpenClaw 能用编排"升级为"任何 Agent 平台都能用"。Sub Agent 启动时自己读约束，不再依赖宿主平台注入。首次预装 FDE 部署工程师 + 合规审计员两个内置 Agent。ao 作为编排引擎的 fallback 路径正式移除，DeepAgents 成为唯一编排引擎。

---

## 背景

v1.0.6 完成了编排迁移的里程碑——compose 逻辑从 ao CLI 迁到 DeepAgents，A/B 运行器从 mock 升级为模型 API 直跑。但 v1.0.6 留了两个问题：

1. **ao 仍作为 fallback 残留**——orchestrate-compare.ts 中 ao 代码路径、install.sh 的 ao 安装逻辑、package.json 的 optionalDependencies 全部还在。deepagents 不是正式依赖。
2. **编排引擎只服务 OpenClaw 节点**——企业里有大量"个人增强节点"用第三方 Agent（WorkBuddy/Codex/Claude Code），这些节点既装不了 OpenClaw，也没法用 sofagent 的编排能力。Sub Agent 的约束注入依赖宿主平台的 Skill 系统，平台换了约束就丢了。

v1.0.7 的核心突破：**Sub Agent 自带约束**。启动时通过 `buildConstrainedSystemPrompt()` 读取 `.sofagent/` 下的约束文件，不依赖任何 Agent 平台的 Skill 注入机制。这让 sofagent 从"OpenClaw 专属"变成"所有 Agent 平台通用"。

## 交付内容（8 件事）

### 1. Sub Agent 约束自加载

**核心改动**：`launcher.ts` 新增 `buildConstrainedSystemPrompt()` 函数。Sub Agent 启动时主动读取约束文件，拼装成 system prompt 的一部分。

```typescript
// launcher.ts 新增
function buildConstrainedSystemPrompt(skillDir: string): string {
  const parts: string[] = [];

  // 1. 宪法层：SKILL.md（4 底线 + 7 铁律）
  const skillContent = tryRead(join(skillDir, 'SKILL.md'));
  if (skillContent) parts.push(`# 宪法约束\n${skillContent}`);

  // 2. 规范层：fde.md（企业专属规则）
  const fdeContent = tryRead(join(skillDir, 'fde.md'));
  if (fdeContent) parts.push(`# 企业规则\n${fdeContent}`);

  // 3. 反思层：think.md（历史踩坑）
  const thinkContent = tryRead(join(skillDir, 'think.md'));
  if (thinkContent) parts.push(`# 历史经验\n${thinkContent}`);

  // 4. 知识库：knowledge/ top-N（按 mtime 排序）
  const knowledgeFiles = listKnowledgeTopN(join(skillDir, 'knowledge'), 5);
  for (const file of knowledgeFiles) {
    parts.push(tryRead(file));
  }

  return parts.join('\n\n---\n\n');
}

// createDeepAgent 调用时注入
const agent = createDeepAgent({
  systemPrompt: buildConstrainedSystemPrompt(skillDir),
  tools: [...],
});
```

**设计要点**：
- **平台无关**：不调用任何平台 API（OpenClaw Hook、WorkBuddy Skill 加载器等），纯文件系统读取
- **启动时注入**：约束在 `createDeepAgent()` 调用时一次性加载，不是运行时动态注入（避免 IO 开销）
- **缺失静默**：任何文件不存在时静默跳过（`tryRead` 返回 null），不报错
- **Token 预算**：knowledge/ top-N 限制 5 篇（每篇 ≤2000 token），总注入量控制在 ~4000 token 以内

**与加载链的关系**：

| 层 | 原有（宿主平台注入） | v1.0.7（Sub Agent 自加载） |
|:--:|------|------|
| 宪法层 | SKILL.md（宿主平台读取注入） | `buildConstrainedSystemPrompt` 直接读 |
| 规范层 | fde.md（宿主平台读取注入） | 同上 |
| 反思层 | think.md（宿主平台读取注入） | 同上 |
| 知识库 | knowledge/（宿主平台按需注入） | launcher 自选 top-N |

两种路径并存：OpenClaw 节点仍走宿主平台 Hook 注入（更精确），个人增强节点走自加载（够用）。

### 2. CLI 编排入口：`sofagent-audit compose`

新增 `compose` 子命令，让任何 Agent 平台通过 tool call 调用编排引擎：

```bash
# 基本用法：传入任务描述，输出编排方案
sofagent-audit compose --task "审计最近 5 次提交的合规性"

# 指定 Sub Agent
sofagent-audit compose --task "梳理工作流" --agent fde-orchestrator

# 运行编排（不只是生成方案）
sofagent-audit compose --task "..." --run
```

**输出格式**：
```yaml
# 编排方案（YAML）
workflow:
  - step: 1
    agent: engineering-code-reviewer
    input: "git diff HEAD~5..HEAD"
    tools: ["git", "sofagent-audit"]
  - step: 2
    agent: security-compliance-auditor
    input: "step-1 output"
    tools: ["sofagent-audit"]
```

**设计要点**：
- `--task` 必填，`--agent` 和 `--run` 可选
- 无 `--run` 时只输出编排方案 YAML，不执行（dry-run 语义）
- `--run` 时调用 DeepAgents 的 `agent.compose()` + `agent.run()`（v1.0.6 已实现）
- 输出到 stdout（方便其他 Agent 程序管道处理），错误到 stderr
- 不依赖 OpenClaw 的任何 API——纯 Node.js + DeepAgents

**适用场景**：
- WorkBuddy/Codex 用户通过 Bash tool 调用 `sofagent-audit compose --task "..."` → 拿到编排方案 → 按方案执行
- CI/CD 中 `sofagent-audit compose --task "deploy check" --run` 自动编排部署审计
- OpenClaw 节点仍走内部 API（性能更好），CLI 入口主要服务非 OpenClaw 节点

### 4. A/B 自动切换

orchestrate-compare.ts 实现 TODO 里写的连续计数器：

```typescript
const CONSECUTIVE_WINS_REQUIRED = 2;

// 每次 compare 后：
// 1. Candidate 胜出 → consecutiveWins++
// 2. Current 胜出或 Tie → consecutiveWins = 0
// 3. consecutiveWins >= CONSECUTIVE_WINS_REQUIRED → 自动 promote
// 4. promote 后 consecutiveWins 重置
```

**实现要点**：
- 计数器持久化到 `.sofagent/orchestrator/ab-state.json`
- promote 前写一条 WARN 日志到 daemon-notice.md（可回滚）
- `--dry-run` 模式只报告"会 promote"但不执行
- promote 操作走原子写入（v1.0.5 的 atomicWriteSync）

### 7. 审计规则 fast-fail 优化

当前审计规则按编号顺序跑（A1→A2→A3→...→A17），命中 FAIL 后仍跑完全部 17 条规则才退出。v1.0.7 改为按严重度分三优先级，FAIL 规则命中即停：

```typescript
// 审计执行顺序（v1.0.7）
const AUDIT_PRIORITY = {
  // 第一优先级：FAIL 规则——命中即停，不跑后续
  critical: ['A1', 'A2', 'A9', 'A4'],
  // 第二优先级：WARN 规则——全部跑完
  warning:  ['A3', 'A5', 'A6', 'A10', 'A11'],
  // 第三优先级：拐杖规则——依赖日志，最慢
  crutch:   ['A7', 'A8'],
  // 扩展规则（启用时，分两组独立开关：E 工程规范 / A 扩展审计）
  // E 组：FAIL 规则优先（E3），其余按编号
  // A 组：按执行速度排序（A15 读配置快 → A14 读日志慢）
  extended: ['E3', 'E1', 'E2', 'E4', 'A15', 'A14'],
};
```

**实现要点**：
- critical 层规则逐条跑，任一命中 FAIL → 立即返回 exit code 2，跳过所有后续规则
- critical 全 PASS → 跑 warning 层（全部跑完，WARN 不阻断后续）
- warning 跑完 → 跑 crutch 层
- 所有规则的结果仍然全部记录到 history.jsonl（包括跳过的规则标 `SKIPPED`）

**性能影响**：
- git commit 审计：命中 FAIL 时从跑 17 条变跑 1-4 条
- 文件系统审计（v1.0.8）：daemon 频繁触发场景下显著降低开销
- 正常提交（无违规）：不受影响，仍然跑全量

### 8. 预装 FDE + Audit Agent

v1.0.7 首次将 Agent 作为内置模块随 npm 包分发。装完 sofagent 就能用，不需要额外安装。

**两个 Agent**：

| Agent | Skill | CLI | 职责 |
|------|------|------|------|
| FDE 部署工程师 | `@sofagent-fde` | `sofagent-audit subagent run fde --task "..."` | 梳理工作流、识别 AI 节点、构建知识库、交付离场 |
| 合规审计员 | `@sofagent-audit` | `sofagent-audit subagent run audit --task "..."` | Workflow 巡检、铁律覆盖验证、知识库健康度检查 |

**实现要点**：
- Agent 定义嵌入 `builtin-agents.ts`，由 `registry.ts` 的 `listAgents()` 自动加载
- systemPrompt 从 `agents/SKILL/{name}/SKILL.md` 动态加载，改文件即改行为，不用改代码
- front matter 字段（name / description / triggers / scenarios / not_when）转为身份标签注入，Agent 知道自己是什么、何时该干活、何时该闭嘴
- 每个 Agent = 一个 SKILL.md 文件，既是 Skill（第三方平台 @ 调用），也是 DeepAgents 的角色定义（编排引擎加载）
- `fde-install.sh` 安装时自动部署两个 Agent Skill 到 `~/.workbuddy/skills/` 和 `~/.openclaw/skills/`
- Audit Agent 作为必调 Agent，所有其他 Agent（FDE / engineer / reviewer）的 SKILL.md 中内置审计引用——部署或变更完成后自动触发合规检查

**第三方调用**：任何 Agent 平台（WorkBuddy / Codex / OpenClaw 等）安装 Skill 后 `@Agent名` 即可调用。不支持 Skill 的平台可复制 SKILL.md 内容到 system prompt，或直接用 CLI `sofagent-audit subagent run ...`。
