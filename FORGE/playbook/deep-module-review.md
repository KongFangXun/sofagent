# 深模块审查 Playbook

> **这是设计熵勘测工具，不是 bug 审查**——它不问「有没有错」，问「形状好不好」。
>
> 前提认知：修改速度越快，软件熵增速越快。改得最勤的地方，熵增最快。本 playbook 的做法是：先用改动频次找到熵增最快的区域，再用「删除测试」把真正的债挑出来，画成带证据的候选摆在你面前。
>
> **它只报告不修复**——勘测不是施工。候选经人裁定、进了版本才动工。

---

## 一、它在审查体系里的位置

三种审查问三个不同的问题，互不替代：

| 机制 | 问什么 | 产出 |
|------|--------|------|
| 独立审查（22 视角） | 交付物**对不对** | bug、风险、文档/感知面问题 |
| 视角二十 · 死代码猎人 | 它**还活着吗** | 断链尸骸、零消费导出 |
| 视角二十一 · 未来架构师 | 该**往哪去** | 方向建议、投资排序 |
| **本 playbook** | 形状**好不好改** | 可施工的加深候选（带证据的债单） |

一句话分工：独立审查管正确性，死代码猎人管存亡，未来架构师管方向，本 playbook 管**模块形状与设计熵**。

它不替代上述任何一个，也不并入发版单盲四角色流水线（那条链的角色与预算为发版固定）——它是独立的一轮，按需跑。

---

## 二、怎么用（三种用法）

### 用法 A · 全仓体检

季度体检、大版本收口时使用。热点全扫，全量报告。

- 按包/层分区，**每个分区一个独立 worker**（互不通气，避免结论互相锚定）
- worker 数量 = 热点区数量，通常 2-4 个
- 产出全量报告，人一次性挑候选

### 用法 B · 单区精扫

怀疑某处臃肿时使用（改一处要动三个文件、加一个功能要抄一段代码、新人对某目录反复问同样的问题）。

- 指定一个目录/模块，直接跳过热点推断
- 单 worker，分钟级
- 产出聚焦报告，通常 1-3 个候选

### 用法 C · 候选跟进

报告出具后，挑一个候选深谈（grilling）——盘清约束、依赖、加深后的接口形状、什么留在缝后、哪些测试能活下来。

- 谈清 → 写成正式版本条目（走正常开发流程）
- 谈不拢 → 明确作废并记下原因（**不留「以后再说」的灰色地带**）

### 什么时候跑

- 大功能合入后（一次合入容易带进一片拷贝）
- 发版收口后（可选，非必跑项）
- 「改起来越来越费劲」的体感出现时
- 季度全仓体检

## 三、流程四步

### 一 · 定范围（YAGNI 前置）

先决定**看哪里**，再看：

- 用户指定了方向（模块/子系统/痛点）→ 直接用，跳过推断
- 没指定 → 用改动频次推断：`git log --name-only --since=<数周前> -- <范围>`，按目录聚合排序，取 top 区
- 读写项目术语后再开工——术语错了，全文都错

**不要全仓平推**：范围越宽，结论越浅。

### 二 · 并行深扫

每个分区一个独立 worker，任务书必须自包含（背景、热点依据、审查清单、输出格式一次给全）。

对每个疑似浅模块执行：

1. **删除测试**（唯一裁决器，见第四节）
2. **接口 vs 实现**：导出方法/参数数量 vs 内部逻辑行数；接口里有多少「只是转发」
3. **局部性**：理解一个概念要跳几个文件
4. **缝的真假**：只有一个实现的接口层是不是过度设计
5. **测试面**：哪些部分测不到，或只能绕过接口测
6. **注册漂移**：同一概念在几处登记、是否已不一致
7. **重复拷贝**：同一骨架逐字出现在几处
8. **上帝文件**：单文件超长且多职责

**worker 输出硬要求**：每条 finding 附**真实证据**——文件路径 + 行号 + 实际读到的代码或实测命令输出。**禁凭文件名想象**。审查类 worker 禁用低成本档：证据层大面积虚构，复核成本反超审查成本。

### 三 · 零信任抽验

主理人**逐条独立复测**关键数字（不许转写 worker 的结论）：

- 抽验不过的数字，其所属候选**整条打回**
- 否定式发现（「某能力未实现」「某处是死的」）必须当轮重验——并发开发时代码面结论有保质期，期间被他人推进则整条作废
- 抽验记录写进报告页脚（哪些数字被独立复测过）

### 四 · 成报告与分流

- HTML 报告落**操作系统临时目录**，不进仓库、不加 git 跟踪
- 候选卡六要素齐备（见第五节）
- 报告末尾给出**首推**：先做哪个、为什么
- 人挑一个候选 → 进入用法 C

## 四、判据

### 删除测试（唯一裁决器）

想象删掉这个模块：

- 复杂度**消失**了 → 它是传话筒（浅，候选）
- 复杂度在 N 个调用点**重新冒出来** → 它在真干活（深，保留）

### 深浅

**深模块** = 小接口 + 大量行为藏在背后 → 调用方得到杠杆（leverage），维护者得到局部性（locality）。

**浅模块** = 接口复杂度 ≈ 实现复杂度 → 纯传话。

### 缝

**一个适配器 = 假缝，两个适配器 = 真缝。** 只有一个实现的接口层不引入，除非确有东西会在缝上变化。

**缝的三种病**（本 playbook 最常见的产出）：

| 病 | 症状 | 处方 |
|----|------|------|
| 幽灵缝 | 接口在、接线断了、零生产消费 | 做实或退场，**不留第三种状态** |
| 假缝 | 生产装配旁路注册表，直接连实现 | 走注册表，或砍掉注册表 |
| 漂移缝 | 同一概念多处登记且已不一致 | 收敛为单源，其余派生 |

## 五、候选卡格式（六要素）

每个候选必含：

1. **加深名称**：一句话说清加深动作（「合并注册式工具分发」优于「重构 mcp-server」）
2. **涉及文件**：路径 + 行数（`font-mono` 呈现）
3. **问题**：一句话说清什么在疼
4. **方案**：一句话，**具体到接口形状**（新接口长什么样、什么藏到缝后）
5. **收益**：三条以内，用受控词——局部性 / 杠杆 / 可测性（禁「更易维护」「更干净」这类非受控词）
6. **Before/After 图**：图的重量大于文字。图需要一段话才能看懂 → 重画图，不写话
7. **推荐强度**（置信度分级，非优先级）：

| 强度 | 判据 |
|------|------|
| **Strong** | 删除测试直接通过、证据齐、收益可量化 |
| **Worth exploring** | 方向明确但有前置条件（设计未定、契约牵扯、需先定新接口形状） |
| **Speculative** | 需先考古：调用方不明、各部分可能各有存活理由 |

**强度不是优先级承诺**：候选要么写进版本（进去就做完），要么明确移出——不留「按需」「弹性储备」的灰色地带。

## 六、审查铁律

1. **只报告不修复**。审查任务禁改一行生产代码——与发版铁律同构。
2. **报告落临时目录**，不进仓库、不进交付物。报告是一次性的，要留存的结论提炼进版本条目。
3. **证据必须是当轮的**。路径、行号、计数、命令输出全部当轮实测；转写即失真。
4. **审查类 worker 禁用低成本档**。
5. **否定式发现必重验**（并发仓库时代码面结论有保质期）。
6. **术语受控**：模块 / 接口 / 实现 / 缝 / 适配器 / 深度 / 局部性 / 杠杆——不引入 component、service、boundary 这套平行词汇，术语一致本身就是产品。
7. **范围 YAGNI**：只扫热点，不平推全仓。
8. **勘测不是施工**：候选经人裁定，进版本条目才动工。
9. **图优先**：能画的不写。
10. **机械面不人肉**：可正则可判定项（重复骨架计数、注册表一致性、导出零生产消费）建议收口 check 脚本，工具做机械面，审查留语义面。

---

## 七、输出规范

- 单文件 HTML 落临时目录：`<临时目录>/architecture-review-<日期>.html`（每次新文件名，不覆盖）
- 样式：浅色底深字、留白充足、编辑感优先于仪表盘感；颜色克制（一个强调色 + 红表失效 + 琥珀表警示）
- 结构：头部（仓库/日期/扫描范围/图例）→ 按层分组的候选卡 → 首推一节 → 页脚方法论（含抽验记录）
- 打开方式：直接交给用户浏览器打开，并在报告中给出绝对路径
- 报告不写版本号考古、不写 run 编号

## 八、常见坑

| 坑 | 后果 | 规避 |
|----|------|------|
| 把强度当优先级 | 违反「写进去就做完」的版本纪律 | 强度只表置信度；去留由人裁定 |
| 报告写进仓库 | 仓库污染 + 文档预算挤占 | 一律临时目录 |
| 单 worker 全仓平推 | 上下文耗尽，结论浅 | 分区分 worker |
| 转写他人数字 | 失真（复核时全对不上） | 当轮独立复测 |
| 只看热点不看形状 | 把「改得多」误判成「必须重构」 | 每条候选过删除测试才成立 |
| 幽灵缝留原地 | 每个后来者都要重新确认它是死是活 | 做实或退场，二选一 |
| 加深动作过大 | 一次动太多面，风险失控 | 一次只做 1-2 个候选，转版本条目分版本施工 |
