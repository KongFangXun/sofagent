# standards · 家族标准层

> **本目录是家族里文档标准的唯一源。** 各仓同名同路径的文件是它的渲染产物——产物可以存在，源只有这一份。与 `tools/STANDARD.md`（工具面标准）成对，同属主仓家族治理层。
>
> **路径约定**：`standards/<路径>` 对应各仓的 `<路径>`。源与目标同构，故不需要任何映射表。

## 一、两条纪律

| # | 纪律 | 判据 |
|---|---|---|
| **S1** | **源唯一** — 同一份标准正文只在本目录出现一次 | 全仓除本目录与登记目标外，找不出第三份同名模板 |
| **S2** | **产物只由机器写** — 副本由源渲染；模板类副本在第 2 行标注来源 | 副本与源逐字节相等；手改即不等即红 |

> 不设「登记哈希」这一跳：源永远在主仓，直接比源就是最强的锚。登记值只会变成第二处需要同步的东西。

## 二、分发规则

本目录**不随分仓迁出**，各仓也**不持有本目录的副本**。跨仓只分发渲染产物。

把 standards 目录复制到各仓，等于在更高一层重新制造 N 份副本，与 S1 直接冲突。故分三面：

| 面 | 住哪 | 各仓拿到什么 |
|---|---|---|
| 标准条款 + 模板源 | 主仓 `standards/` | 不拿 |
| 渲染产物（同名同路径） | 各仓原位 | 拿到，且只读 |
| 判据实现 | 主仓 `tools/check/` | 薄包装 + 配置（既有范式） |

## 三、现行标准

| 编号 | 标准 | 载体（源） | 适用仓 | 强制级 | 判据 |
|---|---|---|---|---|---|
| D1 | changelog 写法与判级（X/Y/Z/R、退役地板、棘轮） | `changelog/_TEMPLATE.md` | 全仓 | blocking | 待实现 |
| D2 | devlog 写法（任务书驱动、单路径、边界声明） | `devlog/_TEMPLATE.md` | 全仓 | blocking | 待实现 |
| D3 | changelog 目录形态与纪元说明 | `changelog/README.md` | 全仓 | warn | 待实现 |
| D4 | 家族工具薄包装形态 | `tools/install-hooks.sh` | 全仓 | warn | 待实现 |

> 强制级：**blocking** = 违反即红；**warn** = 只报不拦；**frozen** = 已冻结不再执行。
> 判据列为「待实现」是现状而非遗漏——按 `tools/STANDARD.md` R1，指不到判据的条款只是登记，不是护栏。

## 四、变更门槛

1. 改标准 = 改源 + 重新渲染全部副本 + 同批过门禁，**一次提交**；不得只改某一个仓。
2. 新增标准须过 `tools/STANDARD.md` R8 三件齐：触发事故 / 机械判据式 / 处置动作。缺一不入。
3. 标准正文禁写**任何随家族规模变化的数字**（仓数 / 工具数 / 版本号）——这类事实一律走插值或移出模板。去数量化不是洁癖：写死仓数的模板已在建仓当天漂移过一次。
