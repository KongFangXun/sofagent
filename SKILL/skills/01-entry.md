# FDE 阶段 1 · 进场（§1-§3）

## 本阶段目标

首次接触企业，摸清底子：业务是什么、平台有哪些、现状如何。建立企业画像 entity 作为贯穿全流程的活文档。达成后进入深挖。

## 前置检查

如果你不是在 [做 FDE 首次进场 / 了解企业基本情况 / 回答"你们做什么的"]，回到主 SKILL.md 重新判断阶段。

## 执行步骤

### §1 确定场景（只聊业务，不聊 AI）

1. 调 `search_knowledge`（query: 企业名称）→ 返回是否已有历史档案
2. 确认四件事：企业名称 / 行业 / 规模 / 参与部门
3. 确认关键岗位及主要产出 → 记录为「企业画像」：一段话 + 部门/岗位清单
4. 引导话术：「先不聊 AI。告诉我你们公司主要做什么业务，哪些岗位最忙？」

> ⚠️ 注意：这一轮不要聊 AI、不要聊工具——只聊业务。信息记录成「企业画像」：一段话 + 部门/岗位清单。

### §2 盘点平台

5. 确认协同平台（钉钉/飞书/企业微信/Slack……）
6. 确认业务系统（ERP/CRM/自研/Excel……）
7. 确认数据可达性（有 API / 可导出 / 手动 / 不可达）
8. 确认知识库平台在哪——后续部署时知识库就落在这里
9. 产出：「技术环境清单」

> 💡 第三代 AI 数据源：如果企业用飞书多维表格智能体或钉钉 AI 表格，优先作为 AI 节点的直接数据源和输出目标——不需要额外搭桥，数据在企业已有平台上跑。

### §3 建档

10. 用 `FDE/templates/enterprise-profile.md` 搭骨架，填入 §1 + §2 信息：

```markdown
企业名称：
所在行业：
团队规模：
本次覆盖范围（全公司 / 某部门 / 某项目）：

协同平台（钉钉/飞书/企微/其他）：
业务系统（ERP/CRM/自研/Excel/其他）：
数据可达性（有API/可导出/手动/不可达）：
已有知识库平台：

关键岗位清单：
  1. [岗位名] — 人数：[N] — 主要产出：[描述]
  2. ...
```

11. 调 `list_entities` 查现有实体 → 调 `read_lessons` 读踩坑记录主动规避
12. 调 `create_entity`（type: enterprise, 含 frontmatter: created_at + updated_at）写入档案
13. 与用户确认画像信息准确

> 📌 画像是活文档，不是一次性填完就锁死：后续每个阶段的新发现都要回写——§4 梳理的工作流、§5 判定的 AI 节点、§6 算出的价值数据、§10 验证后的运行状态，全部回写。离场时交给企业的画像，会比进场时丰富数倍。

## MCP 工具调用指引

> 已连接 MCP Server：

- §1 后：`search_knowledge`（query: 企业名称）查历史数据
- §3 前：`list_entities`（查现有实体） + `read_lessons`（读历史教训）
- §3 建档：`create_entity`（name: 企业名, type: enterprise, domain, relations, knowledge-domain）
- 数据安全：`data_sovereignty_report`（date: "today"）检查数据流向，减少追问轮次

> 未连接 MCP Server：

- 用对话/笔记人工记录企业信息，画像直接写成 Markdown 文档落盘到项目目录

## 阶段完成标志

- [ ] 企业画像 entity 已创建：名称/行业/规模/平台清单/关键岗位 五项齐全
- [ ] 数据主权报告已查看（数据流向清楚）
- [ ] 用户确认画像信息准确

> ⚠️ Gotcha：进场阶段最容易犯的错是「问完基本信息就急着聊 AI」——§1 只聊业务，AI 的话题留给 §6 判定。另一个是「画像建完就锁死」——画像必须持续回写，否则 §7 出方案无据可依。
