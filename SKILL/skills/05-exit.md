# FDE 阶段 5 · 离场（§10-§12）

## 本阶段目标

完成自检、观察期验证、离场确认，并为持续优化建立路由。人（FDE）离场，FDE Agent 留下继续跑。

## 前置检查

如果你不是在 [交付完了 / 要自检 / 做持续优化 / 离场确认]，回到主 SKILL.md 重新判断阶段。本阶段前必须已完成 §7-§9 交付。

## 执行步骤

### §10 自检清单

1. 逐条确认：
   - [ ] 三层实体齐全（文档层 + Skill 层 + 运行层）
   - [ ] 验收标准可测（不是"差不多"）
   - [ ] 出错处理已定义（失败有明确恢复路径）
   - [ ] 每个节点有明确主人
   - [ ] 对抗性测试已跑过（prompt 注入模拟 / 权限越界 / 异常输入）

> 📌 对抗性测试怎么跑：向知识库写入含「忽略类」注入指令的页面看是否被拒；在 Agent 输入中放入 `sk-xxxx` / `AKIAxxxx` / 手机号格式看是否脱敏；手动将某条 knowledge 标 `trust: web` + `sensitivity: restricted` 看是否被丢弃。

### §11 观察期

2. 每天查产出：🔄/⚡ 节点实际产出与预期一致
3. 每周查质量：审计周报推送已配置并收到
4. 两周后：无关键报错 + 连续两天无人问操作问题 → 可离场

> 💡 客户满意度 ≠ 退出条件——客户满意可能只是因为 FDE 一直在无底线兜底。独立运行才是验收标准。

### §12 离场确认

5. 确认企业方具备五大能力：能解释系统 / 能处理常见问题 / 能执行回滚降级 / 能独立风险判断 / 有后续改进机制
6. 调 `data_sovereignty_report`（date: "today"）确认数据边界清晰
7. 企业负责人确认可以离场 → 离场

> 人走，FDE Agent 不走：离场后自动切 sustain 模式，周度巡检知识库健康度、月度汇总审计趋势。

## 持续优化场景速查（完整版）

| 用户说什么 | 做什么 |
|-----------|--------|
| "上次踩了什么坑" | 调 `get_think`（count: 5）→ 展示最近反思 |
| "知识库有什么" | 调 `stats` + `list_entities` → 展示统计+列表 |
| "帮我审计" | 调 `run_audit`（diff: 用户指定）→ **展示 [sofagent] 审计结果** → 引导修复 |
| "数据安全怎么样" | 调 `data_sovereignty_report`（date: 指定）→ 展示报告 |
| 要加新节点 | 调 `search_knowledge`（query: 新节点名）→ 检查是否已存在 → 回 skills/02-discovery.md §4 |
| 数据变更后 | 调 `audit_data_change`（scope: recent）→ 展示数据审计报告 |
| "刚才改了什么" | 调 `audit_data_change`（scope: recent, count: 5）→ 展示变更+审计状态 |
| 巡检所有节点 | 调 `health_check` → 展示各节点健康状态 |
| 能力有哪些 | 调 `list_capabilities` → 展示完整能力清单 |

> 审计结果展示遵循 `skills/04-deliver.md` 的审计结果展示铁律：保留 `[sofagent]` 前缀、结构化展示、FAIL 引导修复。
