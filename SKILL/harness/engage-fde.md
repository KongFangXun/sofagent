# engage-fde.md · FDE 场景引导 · v1.3.9

> FDE 部署场景的主动引导逻辑。检测到 FDE 场景时自动激活。
> 与 FDE/GUIDE.md 互补——GUIDE.md 是知识文档（被动），本文件是引导逻辑（主动）。

---

## 场景检测

| 信号 | 判定 | 行为 |
|------|------|------|
| "FDE 部署""企业 AI 部署""帮企业做 FDE" | 强信号 | 激活引导 |
| "工作流梳理""Agent 节点规划""sofagent 配置" | 弱信号 | 询问是否 FDE 部署 |
| FDE/GUIDE.md 存在 + 企业/部署相关词 | 弱信号 | 询问是否 FDE 部署 |
| 无 FDE 信号 | 非 FDE | 不激活 |

---

## 激活后行为

**第一步**：Read `FDE/GUIDE.md`——获取四阶段十二步完整说明。引导逻辑引用文档，不复制内容。

**第二步**：按 §1~§12 顺序引导，每步结束自动产出文档：

| 阶段 | 步骤 | 引导行为 | 自动产出 |
|------|------|---------|---------|
| 进场 | §1-§3 | 确认企业信息 + 盘点平台 + 建档 | `enterprise-profile.md` 骨架 |
| 挖掘 | §4-§6 | 逐岗位追问五要素 → 三问判定 → 量化 | 工作流节点图 + 分类清单 + 价值清单（回写画像） |
| 交付 | §7-§9 | 逐节点生成三层实体 → 装 sofagent → 检查点 → 打包 | `nodes/*.md` + `skills/*/SKILL.md` + 交付手册（4 章） |
| 离场 | §10-§12 | 逐条打勾 → 两周无报错 → 企业确认 | 离场检查记录 |

---

## 三层实体（每个 🔄/⚡ 节点）

| 层 | 形式 | 给谁读 | 创建时机 |
|----|------|--------|---------|
| 📄 文档层 | `nodes/[节点名].md` | 人读 + 编排引擎读（注入 sofagent-orchestrator compose 拆任务） | §7 |
| 🧠 Skill 层 | `skills/[节点名]/SKILL.md` | AI 读（节点的大脑） | §7-§8 |
| 🔴 运行层 | 设备上的 session | 活的（sub-agent / AI 领航员） | §8 |

> 没有单独的 .yaml 配置层——节点文档（.md）同时服务人读和编排引擎读，配置信息用表格写在 .md 里。

## 与编排引擎的衔接

```
engage-fde.md 引导 §7 → 产出 nodes/[节点名].md
    ↓ engage.md 点火 → Agent 读 .md → 注入 sofagent-orchestrator compose 拆任务 → 逐节点执行
    ↓ 审计引擎 → think.md 反馈 → 编排引擎下次优化
```

- **衔接点**：§7 产出的 `.md` 是编排引擎的输入
- **反馈点**：节点执行后审计引擎写 think.md，下次编排优化

> §8 起节点全部交编排引擎，engage-fde.md 只负责引导和文档产出。

## Gotcha

- **误把 FDE 引导当闲聊**——用户说"帮企业做 FDE 部署"，Agent 当普通问题回答概念，没激活引导。后果：十二步没走，零产出。
- **忘了自动产出文档**——引导了 §4 五要素追问半小时，没写 `enterprise-profile.md` 持续回写区。后果：§7 出方案无据可依。
- **跳步直奔 §8 部署**——§4-§6 没走完，用户说"直接部署吧"，Agent 就跳到 §8。后果：没识别清楚 AI 节点就部署，返工量巨大。
- **弱信号没确认就激活**——用户说"工作流梳理"，Agent 直接启动引导。后果：用户可能只想理清自己的工作流，激活引导反而打扰。
