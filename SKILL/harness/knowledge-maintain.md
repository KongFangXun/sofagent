# Knowledge Maintain

> AI 知识库维护指南——写页面、更索引、记日志。`knowledge/` 是 Agent 积累经验的地方。
> 触发：daemon Ingest / 手动维护知识库时

---

## 页面写法

frontmatter 必填字段：
```yaml
---
title: "页面标题"
category: "entities|concepts|comparisons|summaries"
created: "2026-07-11"
updated: "2026-07-11"
sources: ["task/logs 2026-07-11", "think.md"]
accessible-to: ["AP-审批", "AP-执行"]  # 可选：哪些业务流节点可访问
relations:                              # 可选（v1.0.1 Ontology）：实体关联
  has_many: ["Payment-2026-001"]
  belongs_to: "采购/华南区"
---
```

正文结构：定义 → 关键属性 → 关联实体 → 来源标注

## 双向链接

- `[[页面名]]` 引用其他知识页面
- **先查 index.md 确认目标页面存在**，不存在则标 `[[页面名|TODO]]` 不创建死链
- 链接方向自动双向——不需要两边都写

## 新建 vs 更新

| 场景 | 动作 |
|------|------|
| 发现新模式（之前没记录的） | 新建页面 |
| 已有模式有新数据 | 更新页面（追加，不覆盖） |
| 与已有页面矛盾 | 标注矛盾 `> ⚠️ 矛盾：...`，不自动合并 |

## index.md 更新

新建页面后**必须**同步加 index 条目（示例为纯文本路径，非链接语法——朴素扫描器按链接处理会误判死链）：
```markdown
| 示例供应商（<entities/示例供应商>） | 采购/供应商 | AP-审批, AP-执行 |
```

## log.md 追加

每次操作追加一行：
```markdown
| 2026-07-11 14:30 | Ingest | entities/供应商-示例 | 新建，来源 task/logs |
```

## Lint 检查（loop-evaluate 顺带执行）

| 检查 | 做什么 |
|------|--------|
| 断链 | `[[页面名]]` 指向的页面是否存在 |
| 矛盾 | 同一概念在不同页面是否有冲突 |
| 孤立 | 没有其他页面链接到它 |
| 缺失 | 正文提到但没创建的概念 |
| 过期 | sources 引用的 evidence 已过期 |

---

## Gotcha

- **不覆盖人工标注**——页面中人工写的 `> 备注：` 不覆盖，只追加 AI 提取的内容。
- **矛盾不合并**——标注矛盾留给人决定，AI 不自动选一边。
- **死链标 TODO**——目标页面不存在时标 `[[页面名|TODO]]`，不创建空页面填充。
