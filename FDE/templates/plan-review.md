# 计划自梳理模板 · Plan Review

> **用途**：对任何商业计划 / 产品规划 / 重大决策做 FDE 式预检——在动工前用五要素拆节点、三问判定现状、五问预检边界，避免「顺序搞反」。
> **适合谁**：一人公司 / 小团队审视自己的产品计划；FDE 给客户做规划前的自检；任何「想上 AI 但不知道从哪下手」的计划。

---

## 怎么用（五步）

| 步骤 | 做什么 | 产出 |
|------|--------|------|
| ① 进场画像 | 这个计划是谁？做什么？最痛的点？（不聊 AI，只聊业务/目标） | 一页画像 + 痛点清单 |
| ② 拆业务流 | 把「计划 → 落地」拆成 N 个节点，每个节点填五要素（输入/输出/负责人/耗时/最卡） | 节点表 |
| ③ 三问判定 | 每节点问三问：输入能自动取？规则能写清？输出能自动推？→ 🔄 / ⚡ / 👤 | 现状判定列 |
| ④ ROI 排序 | 建设成本 × 商业价值 → 排「先做什么」 | ROI 表 |
| ⑤ 五问预检 | 五问边界审计（离场版前置到开工版）→ 能不能开工？ | 开工结论 |

> 核心纪律：**三问判定的是现状，不是目标**。你想让 AI 做的节点，现在判定多半是 👤——这不是坏事，是告诉你「先跑流程，AI 后上」。

---

## 一、进场画像

| 要素 | 回答 | 追问 |
|------|------|------|
| 做什么 | 一句话说清计划/业务 | 说不清 = 还没想透 |
| 团队 | 几个人？谁最忙？ | 一个人撑全链 = 优先找重复性节点 |
| 最痛 | 只能解决一个问题，解决哪个？ | 聚焦，别「全都要」 |
| 技术环境 | 平台 / 系统 / 数据可达性 | 有 API？可导出？手动？不可达？ |

> **案例（商业模型层）**：以绩效为核心量化指标的 FDE Harness，把人类 FDE 进场变成模型自己进场。个人起步。最痛：模型自动进场无实测证据、冷启动无答案、专属模型边界模糊。约束层 ✅ / 模型层 🔴 / 平台层 🔴。

## 二、拆业务流（五要素 × 三问）

| # | 节点 | 输入 | 输出 | 负责人 | 三问判定 | 现状 |
|---|------|------|------|--------|----------|------|
| N1 | … | … | … | … | 输入? 规则? 输出? | 🔄 / ⚡ / 👤 |
| N2 | … | … | … | … | … | … |

> 追问节奏：每天第一件事做什么 → 做完上一步下一步是什么——像串珍珠一样串完整条链。

> **案例（商业模型层）**：N1 确认（⚡）→ N2 代码同源（🔄）→ N3 合规红线（⚡）→ N4 PoC 签约（⚡）→ N5 模型冷启动（⚡）→ N6 自动采集（👤，目标🔄）→ N7 workflow 生成（👤，目标🔄）→ N8 薪酬基准（🔄）→ N9 绩效量化（⚡→🔄）→ N10 专属模型训练（👤）→ N11 平台链路（🔄）→ N12 eval（🔄）。

## 三、关键洞察：现成的 🔄 节点

把判定为 🔄 的节点单列出来——**这些是「三问全 ✅、现在就能干」的节点，不依赖最大的不确定性**。先做它们。

> **案例（商业模型层）**：N8 薪酬基准（唯一壁垒，最先动工）、N12 eval（验证前提）、N2 代码同源（解锁一切）、N9 绩效量化（改动最小）。而产品目标节点 N6/N7 判定 👤——先把 🔄 跑起来，再用 PoC 逐级升级。

## 五、五问预检（开工版）

> 五问原本是 FDE 离场前审计（见 GUIDE §6 F1），**前置到开工前**用法相同：五问全答得清 → 开工；≥2 问答不清 → 先补边界再动工。

| # | 五问 | 回答 | 状态 |
|---|------|------|------|
| ① | 规则/数据谁说了算？ | | 🔴/🟡/🟢 |
| ② | 谁负责把结果写回系统？ | | |
| ③ | 涉钱/权益/合规/人事/医疗/法律？ | | |
| ④ | 旧方案能否切回？崩了怎么办？ | | |
| ⑤ | 接手的人能否独立理解/配置/监控？ | | |

**结论**：🟢≥3 且无 🔴 → 开工；否则列出待补边界，先补再动。

> **案例（商业模型层）**：Q3/Q7/Q6 未拍 → 3/5 问答不清 → **不能开工**，验证了 商业模型层.md §6.9「Q3/Q7 立即拍」的优先级。

## 六、落盘清单

| 增量 | 放哪 | 说明 |
|------|------|------|
| 自梳理全文档 | 与计划文档并列（如 `商业模型层.md` 自梳理篇） | 完整拆解留档 |
| 修订意见 | 改计划文档本身（如 商业模型层.md V0.0.3） | 真实增量回写，不另起炉灶 |
| 方法论增量 | FDE/GUIDE.md（如五问前置 F1b） | 可复用才进方法论 |
| 模板 | FDE/templates/（本文件） | 下次直接套 |
