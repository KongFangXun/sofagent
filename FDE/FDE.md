# FDE.md · Forward Deployed Engineer 部署手册

> **这是什么**：FDE（或企业 CIO/网管）的操作手册。读它 → 帮企业梳理 workflow → 识别 AI 节点 → 生成部署方案。Agent 全程辅助——你负责和人聊，Agent 负责记录、分析、出方案。
>
> **谁读**：人读（FDE / 企业 IT）+ Agent 读（通过 `@skill:sofagent-fde` 或种子指令激活，Agent 自动加载本文档并按 §一~§十一引导）。
>
> **怎么装**：
> ```bash
> clawhub skill install KongFangXun/sofagent-fde   # ClawHub
> skillhub install sofagent-fde                    # SkillHub
> cp -r FDE/ ~/.workbuddy/skills/sofagent-fde/    # WorkBuddy 手动
> ```
> **怎么用**：OpenClaw 自动就绪；WorkBuddy 输入 `@skill:sofagent-fde`；其他平台复制 [README.md](./README.md) 中的种子指令。
>
> **范围声明**：sofagent 覆盖 Agent 质量层（代码纪律 + 审计 + 经验沉淀）。不覆盖运维层（监控 / 告警 / 重启 / 日志轮转）。
>
> **为什么 FDE 重要**：组织推进 AI 化时，真正的痛点不是缺少 AI 聊天入口，而是缺少能把历史逻辑、协作关联方、共享上下文和组织记忆串联起来的**公共协作环境**。FDE 部署的不是单个 AI 工具——是整个组织的 Agent 协作环境。sofagent 是这个协作环境里约束 Agent 行为的那一层。

> **状态**：FDE 十步流程框架已完成，审计引擎已可用。端到端验证计划在 v1.0 前完成。详见 [LIMITATIONS.md](./LIMITATIONS.md)。

## 编排引擎（engage.md）

> FDE 部署场景专用。当部署流程进行到 🔄/⚡ 节点执行时，编排引擎根据节点复杂度选择「拆」或「不拆」。

- **什么时候点火**：FDE workflow 中的 🔄/⚡ 节点触发
- **两档拆解**（拆 vs. 不拆）
- **AO Compose**：拆解时调 `ao compose` 一次性生成 DAG
- **think.md 反馈回路**：每次节点执行后自动写入反思记录，下次同一节点点火时自动调整策略

## §一 进场：确定场景

你需要向部署专家确认：

- 企业叫什么、做什么行业、多少人
- 哪个部门/团队参与本次部署
- 关键岗位有哪些、每个岗位主要产出什么

注意：这一轮不要聊 AI、不要聊工具——只聊业务。你把这些信息记录成「企业画像」：一段话 + 部门/岗位清单。

---

## §二 盘点平台与工具

你需要向部署专家确认：

- 协同平台（钉钉/飞书/企业微信/Slack……）
- 业务系统（ERP/CRM/自研/Excel）
- 数据可达性（有API/可导出/手动/不可达）
- 知识库平台在哪——后续部署时知识库就落在这里

产出：「技术环境清单」。§一和 §二都是先做、不关门——后续深挖时补进对应清单即可。

---

## §三 工作流深挖 ← 循环在这里

引导部署专家逐个岗位、逐段流程地深挖，直到每个节点的五要素全部填满。

### 五要素

1. **输入**：这个节点接收什么信息/数据？
2. **输出**：这个节点产出什么？
3. **负责人**：谁在做这件事？
4. **耗时**：每次花多长时间？每天/每周做几次？
5. **最痛的地方**：最大的痛点是什么？

### 追问话术

- 「这个岗位每天第一件事做什么？」
- 「做完上一步，下一步是什么？」
- 「这一步输入是什么？谁给你的？输出是什么？交给谁？」
- 「这一步花多长时间？最烦人的地方是什么？」

五要素全部填满 → 换下一个岗位。所有关键岗位全部填满 → 进入 §四。

产出：「完整工作流节点图」——每个节点有完整五要素，按岗位分组。

---

## §四 识别 AI 节点

对 §三 产出的每一个工作流节点，逐一过这个判定：

| 类别 | 特征 | 例子 |
|------|------|------|
| 🔄 **自动执行** | 规则明确、高频重复、输入输出可结构化 | 数据拉取、报表生成、定时检查 |
| ⚡ **强化岗位** | 需要判断但规则可描述，AI 做领航员 | 设计稿审核、合同条款检查 |
| 👤 **暂时不动** | 依赖直觉经验，或数据不可达 | 战略决策、面对面谈判 |

### 三问判定法

1. 输入能从系统自动取到吗？
2. 处理规则能写清楚吗？（让一个新人照着做，能做对吗？）
3. 输出能自动推到人手里吗？

三个全「是」→ 🔄，两个「是」→ ⚡，否则 → 👤。

产出：「节点分类清单」——每个节点标注 🔄/⚡/👤 + 判定理由。

---

## §五 价值量化

对每个 🔄/⚡ 节点，向部署专家确认以下信息：

| 节点类型 | 量化口径 | 追问 |
|------|------|------|
| 🔄 自动执行 | **替人成本** | 这个节点现在谁在做？什么职级、大致薪资？ |
| ⚡ 强化岗位 | **升级成本** | 这个人要升级到「能用 AI 高效完成」的水平——招一个这样的人年薪多少？培训周期多长？ |

按小时算：以时薪为基准，`日耗时 × 时薪 × 年工作日` = 释放的人力价值。

产出：「节点价值清单」——每个 🔄/⚡ 节点一行：当前成本 / AI 后成本 / 年节省 / 回本周期。

---

## §六 出方案

基于 sofagent 的能力，给每个 🔄/⚡ 节点生成配置方案：

| 配置项 | 需要你判断 |
|------|------|
| sofagent 版本 | 🔄 → `full`（编排+审计）；⚡ → 宪法层 |
| 铁律重点 | 这个节点的 Agent 最容易违反哪几条铁律？ |
| 审计周期 | 日报/周报/事件触发 |
| 输入源/输出目标 | 从哪个系统读数据？产出推到哪个平台？ |
| 企业专属 Skill | 是否需要定制企业自己的 Skill？ |

产出：「节点→方案对照表」+ **workflow.yaml**：

```yaml
nodes:
  - id: node-1
    name: "节点名称"
    type: 🔄
    input:
      source: "API/数据库/文件"
      format: "JSON/CSV/..."
    output:
      target: "钉钉/飞书/邮件"
      format: "报表/通知/..."
    owner: "节点负责人"
    audit:
      period: "daily/weekly/event"
      focus_rules: [A3, A7]
    skill: "enterprise-custom-skill-name"
```

## §七 部署与交付

**先搭底座**：找一台闲置设备（旧电脑、服务器、Nas 都行），装好 OpenClaw + sofagent——这台设备就跑着 sofagent 的 harness 层，上面是你梳理出来的 AI 节点。

1. **逐节点部署**：🔄 创建 sub-agent session 跑通一次；⚡ 配置 AI 领航员确认岗位人员会用；企业 Skill 注入行业术语/业务规则
2. **知识库搭建**：五个静态文档（工作流全景图 / 节点手册 / 运维手册 / 上手文档 / 故障排查），落地到 §二 盘点的企业平台。部署后 Agent 自动产出的内容（执行产出、审计周报、异常记录）持续追加
3. **检查点配置**：每个 🔄/⚡ 输出端设检查点，默认抽检 10%。不合格 → 标记任务 → 反馈主人 → 记录异常 → 触发 skillopt 分析
4. **教会一个人**：每个 AI 节点指定企业方主人，退出信号为连续两天无人问「怎么用」

## §八 交付物清单

离场前逐条确认三样东西：

### 📄 部署方案书（一份 .md 文件）

| 章节 | 来源 | 内容 |
|------|------|------|
| 企业现状 | §一 + §二 | 企业画像 + 技术环境清单 |
| 工作流全景 | §三 | 完整工作流节点图 |
| AI 节点识别 | §四 | 节点分类清单 |
| 价值分析 | §五 | 节点价值清单 |
| 部署方案 | §六 | 节点→方案对照表 + workflow.yaml |

### 📚 知识库（五个 .md 文档，落在企业自有平台）

五个静态文档（§七 第二阶段）全部创建后写入 §二 盘点的知识库平台。

### ⚙️ 运行时（在跑的 AI 节点）

| # | 是什么 | 确认什么 |
|---|------|------|
| 🔄 节点 | 每个一个 sub-agent session | 已创建、已跑通 |
| ⚡ 节点 | 每个一个 AI 领航员 | 已配置、已使用 |
| 企业 Skill | 每个节点一个专属 Skill | 已创建、已注入 |
| 检查点 | 每个节点配置检查规则 | 已配置抽检率、已跑通 |
| 审计 | 周报推送 | 已配置、已收到第一期 |

## §十一 离场检查清单

- [ ] 所有 🔄 节点 sub-agent session 已创建、已跑通至少一次
- [ ] 所有 ⚡ 节点 AI 领航员已配置、岗位人员已使用至少一次
- [ ] 所有企业专属 Skill 已创建并注入
- [ ] 每个 AI 节点有明确的主人
- [ ] 工作流检查点已配置（抽检率、质检员、不合格处理流程）
- [ ] 知识库五个静态文档已创建并落地到企业自有平台
- [ ] 审计周报推送已配置并收到第一期
- [ ] 近期连续两天无人主动找部署专家问操作问题
- [ ] 企业负责人确认可以离场

> 你不是在盖章——你是在帮部署专家确认「走之后不会出事」。
