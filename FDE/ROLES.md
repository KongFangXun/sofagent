# FDE 职能的五岗位沉淀（AI 时代的组织分工图谱）

> **一句话**：FDE 是外部进场的一次性角色（判断的**生成相位**）；FDE 离场后，它的职能不会蒸发，而是在企业内部分化沉淀为**五个常设岗位**（判断的**驻留相位的组织形态**）。本文是这张「生成 → 沉淀」图谱的 SSOT。
>
> 外部锚：BCG《Five Ways That AI Front-Runners Change How Work Gets Done》（2026-09-24，50+ 家 AI 领先公司定性访谈——23 家 AI 原生 / 18 家数字平台 / 9 家传统改造；方法论=九主题半结构化访谈，只计「已落地」不计「意向」）。报告原文一句定调：**「不可能人人都是 FDE，企业也不只需要 FDE」**——五岗位就是这句话的答案。

## 一、五岗位 × FDE 三重角色 × 三层架构（对照表）

| BCG 岗位 | 中文 | 沉淀自 FDE 的哪重角色 | 三仓对应产品面 | BCG 实例 |
|---|---|---|---|---|
| **Workflow Designer** | 工作流设计师 | ①梳理（五要素深挖 + 三问判定） | 约束层产品面：fdeing 流程 N1/N2；本体数据建模 | Writer：Agent 从销售通话提取客户问题、对照既有内容找缺口；Greenhouse：各部门设「创新负责人」重画端到端流程 |
| **Domain Anchor** | 领域知识负责人 | ①梳理（本体建模）+ ③养护（知识资产） | 约束层产品面：ontology 三层 YAML、think.md 蒸馏、knowledge/ | Walmart：岗位「数字孪生」应对 18–24 个月轮岗的知识流失；Workera：博士级专家把领域理解写成文档供 Agent 调用 |
| **Citizen Builder** | 业务自建者 | ②部署（能力梯度的「业务自建」档） | 平台层模板库：fork 模板改内容；六引擎工作台 | Cursor：市场人员自建应用批量生成数千份营销素材，取代代理商；DevRev：零技术背景的销售运营做出读写 CRM 的 Slack Bot |
| **AI Guardian** | AI 治理者 | ③养护（审计面） | 约束层治理面：25 条规则 + HMAC 链 + 快照回溯（**已交付**） | Scale AI：专职团队对自有模型与 Agent 系统做攻击测试（幻觉/数据泄漏）；云服务公司：AI 委员会审查新用例 |
| **Agent Shepherd** | Agent 运营负责人 | ③养护（运维面） | 约束层治理面：daemon 7×24 巡检 + 插件生命周期 + 裁剪（**已交付**） | Bolt.new：中央角色管 Agent 托管、权限、异常监控与下线；Walmart：编排岗位管理大量互联 Agent |

**读法三则**：

1. **FDE 三重角色被五岗位完全覆盖且更细**——梳理拆成 Designer（流程视角）与 Anchor（知识视角）；养护拆成 Guardian（风险视角）与 Shepherd（运维视角）；部署对应 Builder（自建视角）。FDE 是这五项职能的**总承包人**，五岗位是**分包后的常设编制**。
2. **相位关系**：五岗位全部活在驻留相位（SUSTAIN）——FDE 进场做判断（生成），离场后判断由约束层 7×24 执行（驻留），五岗位是驻留期「判断的养护与进化」的人员形态。没有 FDE，五岗位没有初始判据可养；没有五岗位，FDE 的判断随人离场蒸发——这是相位论在**组织维度**的展开。
3. **五岗位是职能不是头衔**：BCG 明确「未必是五个正式岗位，但职责已有人承担」。企业可以一人兼多岗（小企业常见）、也可一岗多人（大企业）。

## 二、五岗位与 sofagent 体系的关系

### 三仓 = 五岗位的工具化

| 岗位组合 | 工具落在哪 | 已交付形态 |
|---|---|---|
| Designer + Anchor | **约束层产品面** | fdeing 流程、ontology、判据 schema、知识沉淀管线 |
| Builder | **平台层模板库** | workflow 模板 fork 改内容锁结构、六引擎工作台 |
| Guardian + Shepherd | **约束层治理面** | 审计规则 + HMAC 举证 + 快照回滚 + daemon 巡检 + 插件生命周期 |

对外叙事口径：**别的公司在招 Guardian 和 Shepherd；装了约束层的公司，这两个岗位的大部分工作已经是机器在干**——五岗位中治理与运维两岗的自动化，恰是本仓已发版的存量能力。

### 能力梯度的组织学含义

五岗位给「FDE 能力梯度」（见 [README](./README.md)）补了终局：FDEing 的目标不是把每个人都训练成全能 FDE，而是**FDE 能力按五个方向分化沉淀到组织里**——不写代码的人可以成为 Builder（用模板与工作台）和 Anchor（判据与本体是人写的）；懂工程的人向 Designer 与 Guardian/Shepherd 深入。「万物皆可 FDEing」的完整表述从此是：**每个业务对象都能被 FDEing 一遍，而 FDEing 本身会沉淀为组织的五种常设能力**。

## 三、BCG 报告的三个定量锚（引用纪律：BCG 自报口径，本仓未复算）

- **TSR +11pp**：能用 AI 重做工作与人才机制的公司，行业调整后年度股东总回报率比同行高出 11 个百分点以上（收入扩张 + 利润率改善双驱动）——「先梳理重构、再上 AI」的行业定价。
- **80% 的受访公司至少已在五维度（目的/工作/决策/协同/回报）中的三个上发生变化**——变化不是选择题而是进行时。
- 五分之四的受访公司在记录核心专家知识（Anchor 职能渗透率最高的证据）。

**边界声明**：五岗位是 BCG 对 50+ 家公司的定性归纳（原型 archetype），非统计抽样调查；引用时称「BCG 访谈归纳的五种角色原型」。与本仓的对应关系是本仓的解读，BCG 未提本仓及任何 Harness 类产品。

## 四、FDE 服务商的交付含义（给做 FDE 的人）

1. **进场时的组织预期管理**：FDE 交付的终点不是「系统上线」，是「企业里有人接得住五岗位」——交付手册（N4 三层实体）应指认每个 AI 节点对应的岗位归属（谁 Shepherd、谁 Guardian）。
2. **离场判据新增一条**：传统五问（健康/人审/证据/专注/配额）之外，可加「五岗位有归属吗」——没人接的岗位对应的能力面就是养护真空。
3. **商业杠杆**：五岗位 = 五条产品需求线——Designer 要工具（模板/工作台）、Anchor 要沉淀（知识管线）、Builder 要自建面（低代码）、Guardian 要审计（举证链）、Shepherd 要运维（巡检/监控）。FDE 报价单可以按岗位拆产品面。
