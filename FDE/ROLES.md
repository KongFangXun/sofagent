# FDE 职能的五岗位沉淀

> FDE 是外部进场的一次性角色（判断的**生成相位**）；离场后其职能不蒸发，而是沉淀为企业内部分化的**五个常设岗位**（驻留相位的组织形态）。本文是这张「生成 → 沉淀」图谱的 SSOT。

## 一、五岗位对照表

| BCG 岗位 | 中文 | 沉淀自 FDE 的 | 三仓对应产品面 | BCG 实例 |
|---|---|---|---|---|
| Workflow Designer | 工作流设计师 | ①梳理（五要素 + 三问） | 约束层：fdeing 流程、本体建模 | Greenhouse 各部门「创新负责人」重画端到端流程 |
| Domain Anchor | 领域知识负责人 | ①梳理 + ③养护（知识资产） | 约束层：ontology、think.md、knowledge/ | Walmart 岗位「数字孪生」应对轮岗知识流失 |
| Citizen Builder | 业务自建者 | ②部署（业务自建档） | 平台层：模板 fork、六引擎工作台 | DevRev 零技术销售运营做出 CRM Bot |
| AI Guardian | AI 治理者 | ③养护（审计面） | 约束层：25 规则 + HMAC + 快照回溯（已交付） | Scale AI 专职团队对 Agent 系统做攻击测试 |
| Agent Shepherd | Agent 运营负责人 | ③养护（运维面） | 约束层：daemon 巡检 + 插件生命周期（已交付） | Bolt.new 中央角色管 Agent 托管与异常下线 |

三条读法：

1. **总分关系**——梳理拆为 Designer（流程）与 Anchor（知识），养护拆为 Guardian（风险）与 Shepherd（运维），部署对应 Builder（自建）。FDE 是总承包人，五岗位是分包后的常设编制。
2. **相位关系**——五岗位全部活在驻留相位：FDE 进场做判断，离场后判断由约束层 7×24 执行，五岗位是驻留期「判断的养护与进化」的人员形态。没有 FDE，五岗位没有初始判据；没有五岗位，判断随人离场蒸发。
3. **职能非头衔**——一人可兼多岗（小企业），一岗可多人（大企业）。

## 二、三仓 = 五岗位的工具化

| 岗位组合 | 工具落点 |
|---|---|
| Designer + Anchor | 约束层产品面（fdeing / ontology / 判据 / 知识管线） |
| Builder | 平台层模板库（fork 改内容锁结构）+ 工作台 |
| Guardian + Shepherd | 约束层治理面（审计 / HMAC / 回滚 / daemon / 插件管理） |

对外口径：**别的公司在招 Guardian 和 Shepherd；装了约束层的公司，这两岗的大部分工作已经是机器在干**。

## 三、能力梯度的组织学含义

FDEing 的终局不是人人成为全能 FDE，而是**能力按五个方向分化沉淀**：不写代码的人可以胜任 Builder 与 Anchor（判据与本体是人写的）；懂工程的人向 Designer / Guardian / Shepherd 深入。完整表述：每个业务对象都能被 FDEing 一遍，而 FDEing 本身沉淀为组织的五种常设能力。

## 四、定量锚（BCG 自报，本仓未复算）

- TSR +11pp——用 AI 重做工作与人才机制的公司，年度股东总回报高出同行 11 个百分点以上。
- 80% 受访公司至少已在五维度中的三个上发生变化；五分之四在记录核心专家知识（Anchor 渗透率最高的证据）。

边界：五岗位为 BCG 对 50+ 家公司的定性归纳（原型，非统计抽样）；三仓对位是本仓解读。

## 五、FDE 服务商的交付含义

1. **交付终点**：不是「系统上线」，是「有人接得住五岗位」——交付手册应指认每个 AI 节点的岗位归属。
2. **离场第六问**：传统五问（健康/人审/证据/专注/配额）之外加「五岗位有归属吗」——没人接的岗位就是养护真空。
3. **报价杠杆**：五岗位 = 五条产品需求线，报价单可按岗位拆产品面。
