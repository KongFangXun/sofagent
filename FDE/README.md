# FDE Agent · 企业 AI 治理诊断框架

## 这是什么

**sofagent FDE（Forward Deployed Engineer）**帮你解决一个核心问题：**企业上了 AI，但没人用**。多数企业先选模型、搭平台、买 Agent，结果没人用——因为还没搞清楚自己的业务流程，就想让 AI 接管。

FDE 把这件事倒过来：进场逐岗位梳理工作流 → 判定哪些环节该上 AI → 部署 AI 节点并持续审计养护 → 离场后节点 7×24 自运转。**从"AI 很强"到"AI 在替我干活且干得对"**。

**一句话**：sofagent FDE 帮你的企业梳理 AI 该在哪些岗位干、怎么干、干了之后怎么审计——让企业长出一棵**会自我养护的 AI 能力树**。

## 解决什么问题

很多企业上 AI 的路径是反的：先选模型、搭平台、买 Agent，结果发现没人用。问题不在技术，在于**企业还没搞清楚自己的业务流程，就想让 AI 来接管**。

FDE 把这件事倒过来：先逐岗位梳理工作流，用五要素（输入/输出/负责人/耗时/痛点）把每个环节摸清；再用三问判定法识别哪些环节适合上 AI（🔄 自动执行 / ⚡ 强化岗位 / 👤 暂不动），算清每个节点的年节省金额；最后交付三层实体（文档层 + Skill 层 + 运行层），让 AI 节点真的跑起来。

部署完不等于结束。每个 AI 节点带审计引擎（每次变更自动审计）+ 反思库（think.md 沉淀经验）+ 数据主权边界（企业数据不外传）+ 明确的养护人（谁维护、谁能改、失效谁负责）。人离场后，FDE Agent 留下继续跑——巡检、审计、优化，7×24 在线。

> 💡 **FDE 的三重角色**：① 梳理（五要素 + 三问判定，让企业看清自己的 workflow）；② 部署（激活链，让交付物自动运转）；③ **养护（能力资产管理，让 AI 节点长成组织共同维护的能力树）**——前两层管「能不能跑」，第三层管「这棵树长得健不健康、往哪长」。详见 [GUIDE.md §5.12 能力资产管理](./GUIDE.md)。

## AI 时代的组织：从「飞书式」到「GitHub 式」

过去的企业协作是**飞书式**——一座协同办公楼：聊天是走廊，群组是项目房间，人走进不同房间问清背景、同步进度、把接力棒交给下一个人。这套模式擅长「让很多人对同一件事保持连接」，但它的基本工作单位是「人和人协作」。

AI 时代变了：一个「人 + AI Agent」的工作单元能更快完成更多事，局部尝试变多、变快——协作的重点不再是「把每一棒交接清楚」，而是「**哪些快速生产的局部尝试，值得成为组织共同维护、反复复用的能力资产**」。

GitHub 式组织就是管这件事的：它像一棵不断长大的树。**树干**是团队共同维护的基线，**枝条**（branch）是有明确目标、范围和生命周期的变更空间，**审阅 + 合并**（PR + review）保证改动不会悄悄混进主线，**根系**让每个能力说清楚「解决什么、输入什么、产出什么、怎么算通过、谁能用、哪些数据不能用」，**养护**让每条能力有 owner、有回退权。

放大了看，企业不是一棵树，而是一片**仓库森林**——每个最小工作单元（一个任务/一件事/一个项目）是一棵树，而**人 + AI 是穿梭在树之间的园丁**：既能种自己的树（主导一个仓库），也能给别人的树提 PR（跨树贡献）。这里的「仓库」和「提 PR 的人」都可能是**纯自动的 AI 节点**，也可能是**人 + AI 共同维护**——身份不再按组织架构的岗位划分，而是凭「人 + AI 的能力」流动。树有横向流动（跨树提 PR），也有纵向生长（枝条长成树干）；把整片森林串起来的那张**能力地图**，就是 ontology 本体结构——哪棵树长了什么能力、谁在维护、能不能复用，一眼可查。

> ⚠️ **仓库 ≠ 部门**：部门是工业时代的产物——它存在的两个前提（人的能力局限 + 利益局限）在 AI 时代都消失了（AI 无专业边界、无个人利益诉求），所以「按部门拆 Agent」是旧地图找新大陆。仓库的正确粒度是**最小工作单元**——有明确输入、输出、验收的一件事，不是按职能划分的部门。

**sofagent FDE 帮企业做的，正是长出这片森林、并教会组织在森林里流动的第一根枝条。**

## 两条上手路径


FDE 支持两种使用方式——根据你的需求选择：

### 15 分钟最短路径（FDE Skill 独立入口，不装主包）

1. **装 Skill**：在你的 AI 工具里安装 FDE Skill——[ClawHub 页面](https://clawhub.ai/kongfangxun/skills/sofagent)一条命令安装（或 SkillHub 搜 `sofagent`）
2. **开口**：对 AI 说「帮我做 FDE 诊断」——Agent 按 SKILL.md 阶段路由从进场开始引导（梳理 → 深挖 → 量化 → 交付）
3. **首个产出物**：一份企业画像（岗位 × 五要素表）+ 候选 AI 节点清单（🔄 自动执行 / ⚡ 强化岗位 / 👤 暂不动，含年节省估算）
4. **不需要 Node.js**：FDE Skill 是纯方法论 Skill，零依赖；之后要审计/回滚/daemon 常驻再装主包（[install.sh](../install.sh)，装在企业设备）
   > ⚠️ **完整 clone 要求**：主包依赖仓库内全套资产（SKILL/ 发布源 + engine/ 源码 + tools/ 工具链），FDE 无独立安装包——装主包需 `git clone` 完整 sofagent 仓库（不能只拷 install.sh），在企业设备上执行 `bash install.sh`。

> 💡 完整方法论（四阶段十二步）见 [GUIDE.md](./GUIDE.md)——最短路径走的是 §1-§2 的浓缩版；想纯手动梳理（Excel + 人脑）也按 GUIDE 逐步走即可。

### 路径 B · 工具路径（需 Node.js ≥ 18）

如果你想用 sofagent 工具链辅助（自动审计 + 知识沉淀 + Dashboard）：

1. **安装**：`npm install -g @sofagent/audit && sofagent-audit --init`
2. **连接**：在你的 AI Agent 平台加载 FDE Skill（WorkBuddy 搜 `sofagent`，或 `bash install.sh`）
3. **对话**：跟 Agent 说"帮我做 FDE 诊断"，它会从 §1 进场开始引导你

> 💡 不想安装？先看 [GUIDE.md](./GUIDE.md) 了解方法论，再用你喜欢的 AI 平台手动操作——FDE 方法论本身不依赖工具，Excel + 人脑也能跑。

## 效果对比

| | 没有 FDE | 有 FDE |
|--|---------|--------|
| AI 在干什么 | 每次任务从零开始 | 按岗位 SOP 执行，节点有明确边界 |
| 该上哪些 AI | 凭感觉拍脑袋 | 五要素 + 三问判定，按 ROI 排出优先级 |
| 审计 | 没有 | 每次变更自动审计，责任到人 |
| 经验沉淀 | 全靠人记 | 自动写 think.md，进化能力持续迭代中 |
| 数据安全 | 说不清数据去哪了 | 数据主权审计，企业数据不外传 |
