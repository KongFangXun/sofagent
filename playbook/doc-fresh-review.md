# Doc Fresh Review · 核心文档体系独立审查

> **为什么叫 Fresh**：审查者必须是**未参与这些文档编写的人（或新 session）**——编写者的视角已被施工过程污染（每处改动都是"当时认为该这样"），只有 fresh 视角能看见习焉不察的结构性问题。这与 fresh-eyes-review（代码审查）同一纪律：**新鲜的眼睛是审查的第一资源**。

> **定位**：对核心文档体系（README 双语 / CHANGELOG / WIKI / HANDBOOK / FDE/GUIDE / guides/ / ARCHITECTURE / PHILOSOPHY / VALIDATION / API / LIMITATIONS / SECURITY / DEVELOPMENT / ROADMAP / CONTRIBUTING / THANKS / COMMUNITY + **dashboard.html**）做独立人读视角审查的标准 prompt 模板。
>
> **来源**：发版前四轮实跑沉淀（r1 宏观 → r2 结构 → r3 终读+回归 → r4 收敛判定），每轮发现的修复回归率从 37% 降至收敛。
>
> **用法**：复制下方「审查 Prompt 模板」到**新 session**（fresh 纪律：严禁在参与过编写/修复的 session 里跑；审查只报告不修复）；多轮迭代时按「轮次策略表」选当轮重点。报告统一落 `~/Desktop/docs-review-vX.Y.Z{-rN}.md`。

---

## 轮次策略（多轮迭代时的重点轮换）

| 轮次 | 重点 | 为什么 |
|:--:|------|--------|
| 第 1 轮 | **宏观信息架构**（读者动线/职责边界/分层合规） | 先定结构，别陷进错别字 |
| 第 2 轮 | **结构与跨文档一致性**（数字口径/术语/指针/双语对称） | 结构定了查一致性 |
| 第 3 轮 | **单文档终读 + 上轮修复回归** | 修复自身会引入新伤（实测 r3 的 P1 中 37% 是 r1/r2 修复的回归） |
| 第 N 轮 | **收敛性判定**（GREEN/YELLOW/RED 前置） | 防「每轮都找到点什么」的无限循环——判据是「值得修吗」闸门，不是「有没有问题」 |
| 任意轮 | **修复批回归检查**（git 范围 = 上轮报告时点..HEAD） | 每轮修复后必带 |

## 判级口径
- P0：会导致读者做出错误的安全/数据/质量决策，或声称与仓库实物相反
- P1：事实错误或结构问题，影响可用性与信任，但不致危害性误判
- P2：打磨项（格式、冗余、语感、内部腔调）
- P3（不阻断）：只影响极少数读者的阅读愉悦；修复需重写大段文字收益风险不成比；纯风格偏好

## 审查维度（五维框架）
一、信息架构：读者动线断点 / 职责竞争与真空 / 六层（门面/导航/用户/深读/边界/开发）分层合规
二、单文档质量：头部 30 行第一眼 / 目录章节逻辑 / 段落表格可读性（≥800 字符墙式段落、≥500 字符单元格）
三、跨文档一致性：同一事实多处声明（测试数/工具数/场景数/包数/版本/日期/状态）口径统一；一处全文他处一句锚
四、新鲜度与考古债：旧版本状态描述 / 已移除能力残留 / 规划完成状态与实际不符
五、语调与身份：内部腔调泄漏（批次代号/内部脚本名/维护者黑话进用户文档）/ 中英混排风格统一

## 复核与修复的对接协议

1. **审查报告 → 零信任复核**：修复完成后由第三方（或主 session）按报告逐条实测——不采信 commit message；判断类改动单列请作者裁定；独立通道复算数字（门禁脚本 vs npm 实跑 vs 逐包数）
2. **误报处理**：复核证伪的发现标记「审查方误报」留痕（如「翁荔应为翁丽莲」——web 多源证实仓内正确），不静默丢弃
3. **修复批纪律**：内容只迁不删（删的要有接收方）；优化触发门禁红时先判「真漂移改文档」还是「守卫失明改守卫」；每轮修复后全量门禁复跑
4. **收敛退出**：GREEN 判定 → 回发版 SOP（阶段八放行）；连续两轮无 P0/P1 新发现也可判收敛

## 已知坑（审查者自带工具的坑，前三轮实锤）

- macOS/zsh：`$t:engine/…` 的 `:e` 被 zsh 当修饰符吞路径 → 用 `${t}:…`
- 中文长 heredoc 经 shell 传输可能 Non-UTF-8 静默不执行 → 落 /tmp/*.py 再跑
- `cmd | tail; echo $?` 取的是 tail 的退出码 → 分开跑
- check-seam-contract.mjs 必须 node 执行（bash 跑得 EXIT=2 是调用错）
- grep 计数工具数时注意排除注释行（uses: 含行内注释，动作行才是真值）
