# subagent-review-loop.md · 子代理审查循环 SOP

> **定位**：版本施工收尾的独立 review 循环——绿灯全过之后、勾选验收之前，用**无施工上下文的 subagent** 找「施工方自认为已完成」面背后的漏洞。
> **一句话**：施工方自验与独立 review 的盲区差异是系统性的（施工者脑中有"我做了什么"的预期，会顺着预期读代码；reviewer 只有代码本身）——这不是补一道重复验证，是换一双眼睛。
> **与既有工具的关系**：`check-*.sh` 门禁查"规则是否被满足"，本 SOP 查"绿灯背后的实现是否真的成立"；`deep-module-review.md` 是单模块深潜，本 SOP 是全交付面轮扫；fresh-eyes 面向文档/产品，本 SOP 面向刚落的 commit 区间。可叠加使用。
> **使用方式**：任务书收尾节引用本 SOP（例："收尾 review 按 `playbook/subagent-review-loop.md` 执行"），施工方按轮次剧本开 subagent、主方修发现、循环至收敛。

---

## 一、适用判据（什么时候开循环）

满足任一即值得开（不满足则门禁 + 主方自验即够）：

1. **改动面大**：单批 ≥10 commit 或跨 ≥2 个包/模块；
2. **风险域命中**：改动触及契约（接口/schema/协议）、安全（校验/白名单/信任模型）、分发（下载/校验/离线介质）任一面;
3. **能力宣称与实现的间距大**：commit message 或 SSOT 声明了能力（"支持断点续传"式），而实现链路跨 ≥3 个文件才闭合。

**定位写死**：循环的目的是**找施工方漏掉的问题**，不是重复验证绿灯——subagent 的 prompt 里必须带这句，否则它会把时间花在复跑测试上。

## 二、轮次剧本（固定分工，审查面不重叠）

| 轮 | 定位 | 审查面 | 限时 |
|---|---|---|---|
| r1 | 高危面深扫 | 正确性（数学/并发/边界）+ 安全（校验绕过/信任模型）+ 声称与实现一致性 | 15 分钟 |
| r2 | 换视角扫盲区 + 复验上轮修复 | r1 未覆盖的面（如：生产装配链路/死代码/语义边界）+ 逐条验证 r1 修复是否引入新问题 | 12 分钟 |
| r3 | 纯复验 + 残余盲区 | 验证 r2 修复无引入 + 前两轮都没看到的最后角落（如：跨包字段映射 typo/SSOT 已勾条目实证） | 12 分钟 |
| 收敛轮 | 三面极简 | commit 清单一致性 / 关键测试面现跑绿 / 工作区干净 | 8 分钟 |

**效率关键**：每轮 prompt 的审查面清单**不重叠**——r1 扫过的面 r2 不再扫（只复验修复），否则 review 会退化为同一批问题反复确认。轮次间隔主方立即修复（见 §四），修复 commit 是下一轮的复验输入。

## 三、Review prompt 七要素（模板化）

1. **角色与限时**：独立审查员 + 明确分钟数（防漫游）+ 只读（不改文件）；
2. **审查面清单**：逐条编号，每条带落点提示（文件/行为/commit），"逐面输出『无发现』或问题"——强制全覆盖；
3. **commit 范围与 git 命令**：`git show <hash>` 逐笔看 diff，不给范围 reviewer 会扫全仓浪费时间;
4. **「找漏不是复验」定位**：测试与门禁主方已跑绿——你的任务是找**我们漏掉的**，并明说"绿灯已过仍可能有问题"；
5. **分级标准**：P0（安全/数据损坏）/ P1（正确性/交付面声明与实现脱节）/ P2（形态成立语义弱——备案不阻断），每条发现须带证据（文件:行号/实测命令与输出）+ 修法建议；
6. **收敛语义**：预告"若本轮零 P0/P1 即达成收敛"——reviewer 知道自己在收敛判定中的位置，不会为凑数报 P2；
7. **输出格式**：发现清单 + 总结论（CLEAN / ISSUES）。

**模板全文见附录**——下一版施工直接复制，改 commit 范围与审查面即可。

## 四、修复纪律（主方义务）

1. **P1 先行**：P1 全修后才进下一轮；P2 逐条判断——落地修或写明不修理由（如"属 SSOT 既有语义/威胁模型外"），**不允许静默忽略**；
2. **每修复带行为锁**：修一个 P1 至少一条测试断言锁住修复语义（例：原型键拒收 → constructor/prototype 字面量键两态拒的用例）；
3. **commit 溯源**：修复 commit message 逐条编 P1-N/P2-N 对应 review 发现——未来考古能从 commit 反查发现原文；
4. **修复后回归受影响包**：不重跑全仓（测试数收口留收尾），但受影响包必须全绿 + 类型检查零真实错；
5. **测试数漂移**：循环净增的测试在收敛后用官方通道（`check-test-count.sh --fix`）统一回填一次，不逐修复回填。

## 五、收敛判据（退出条件）

**「连续两轮零新问题」= 独立零发现轮 + 修复复验无引入轮，两者缺一不可**：

- 只有一轮零发现不够——可能那轮恰好扫的是干净面；
- 只有复验无引入不够——复验轮不看新面，新问题仍可能在盲区。

收敛后的残余义务：P2 备案项逐条有去向（修/不修理由），汇总报告列"建议复核面"交项目负责人。

## 六、异常处置（agent 生命周期）

| 情形 | 处置 |
|---|---|
| review agent 超时未归 | 等待窗口（2×限时）后放弃；**主方按其 prompt 自验**（逐条跑它该跑的检查）开替补收敛轮 |
| 超时 agent 留有 commit | **必须被后续轮代审**——超时≠未工作，遗留物无审查不得计入交付；代审结论写进收敛轮回执 |
| review 与主方判断冲突 | 以证据为准：reviewer 给了实测命令与输出的从 reviewer；主方有更强实测的从主方——冲突本身写进汇总报告 |

## 七、命中数据（判据支撑）

六章施工实测（5 轮：17m / 11m / 11m / 超时 / 1m）：抓 **6 P1 + 14 P2**，全部修复，净增约 60 条行为锁测试。P1 命中类型分布：数学边界 1（softmax 下溢）/ 状态漂移 1（双源单例缺失）/ 死代码 1（.part 只读不写）/ 声明与实现脱节 2（非阻断校验、生产链路断链）/ 校验绕过 1（原型键）。**全部 6 个 P1 都通过了施工方自验与全部门禁**——这是本 SOP 存在的理由。

## 附录 · Review Prompt 模板（全文，复制即用）

```
你是 <仓库名> 的独立代码审查员（<版本号/批次名> 第 <N> 轮 review）。
仓库：<绝对路径>（macOS，注意大小写）。限时 <分钟数> 分钟，只读审查，不改文件。

背景：<一句话交付范围>（commit <起>..<终>，共 <n> 笔）。全部测试与门禁
主方已跑绿——你的任务是**找我们漏掉的问题**，不是重复验证绿灯。

重点审查面（git show 逐笔看 diff）：

1. <审查面 A：落点文件/行为/为什么高危——例：XX 函数的 YY 分支在 ZZ
   组合下是否可达，找真实漏判路径>
2. <审查面 B：例：XX 校验逻辑有无绕过形态（键名怪异/类型混淆/顺序依赖）>
3. <审查面 C：例：XX 数学的边界行为独立推演一遍（极端分差/空集/全同值）>
4. <审查面 D（r2 起）：复验上轮修复 <commit hash> 是否引入新问题>
5. <审查面 E：例：声称与实现对账——commit message 说的能力在代码里
   链路真的闭合吗（找断点：写了读口没写口/挂载无人挂/调用零消费方）>

输出：发现清单（P0/P1/P2 + 证据 + 修法建议）或逐面「无发现」；
总结论 CLEAN 或 ISSUES。若发现属「形态成立但语义弱」，标 P2 备案而非 P1。
```

收敛轮模板（追加替换审查面）：

```
任务（极简三面，<分钟数> 分钟）：
1. git log <起>..HEAD --oneline 全列——数 commit、扫 message 有无互相矛盾；
2. 抽验关键现态：<一两条 grep/测试命令>（关键面绿）；
3. 工作区 git status --porcelain 空 + git log --oneline -1。

输出：零发现 → CLEAN（review 循环达成收敛）；有 P0/P1 → ISSUES 清单。
P2 观察备案不阻断。
```

**主方收尾**：收敛后把循环摘要（轮次/发现/修复 commit/终态读数）写进施工汇总报告，SSOT 勾选仍归验收方——review 收敛不代替验收。
