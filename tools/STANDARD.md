# STANDARD.md · 家族工具标准

> **这份文件是家族里唯一被「约束」的东西。** 一切工具（门禁 / 生成器 / 安装器 / 巡检器）都是它的**投影**——不新增标准，只在本文件内找依据。

## 0. 地位与用法

| 问 | 答 |
|---|---|
| **它管什么** | 只写「**什么必须成立**」，不写「怎么做」。实现自由，成立条件不自由 |
| **谁被它管** | 家族内**所有**工具，含写这份文件的人自己写的工具（下 §6 自评即证） |
| **怎么用它** | 检查任意工具 = **拿本文件逐条对**（流程见 §3）。没有第二个检查依据 |
| **怎么改它** | 门槛最高：仅维护者可改，须挂版本 + 说明**哪一条为什么变**。改一条即全家族重查（§7） |
| **它不做什么** | 不描述任何具体工具。具体工具自述写在各自 `README`，引本文件条号，不复制条文 |

**为什么只有它需要被约束**：约束工具的是人；约束人的应该是**一份短、稳、可复述的文件**。工具会随需求增删，标准不该跟着抖——否则每次加一个检查都要重新谈判原则。

## 1. 第一性命题

> **工具 = 一次被违反过的事实的固化。**

两条反向推论，同等强制：

1. **指不出「哪一次被违反」的判据没有存在理由**——那是想象出来的检查，只会制造噪声与豁免。
2. **每一条禁止性规则必须能被一个判据执行**——指不到判据的禁令是装饰，写进仓规只会稀释规则的可信度。

## 2. 八条（三组）

> 每条的「判据」= 怎么验它成立；「反例」= 实测过的违反形态。

### 组一 · 有效性：它必须真在判，且只判它该判的

| # | 要求 | 判据（怎么验） | 反例（实测形态） |
|---|---|---|---|
| **R1** | **事故溯源**——每条判据指向至少一次真实违反：事故记录 / 实测复现 / 负向探针 | 判据表每行有「触发事故」列且非空；抽查 3 条能当场复现 | 凭空写的「应该检查一下」类判据 |
| **R2** | **机械可判定**——同一输入在任何机器、任何调用路径下结论相同。**参数只许改变扫描面，不许改变口径** | 两种调用路径（带参 / 不带参）对**同一份含边界样本的文件**各跑一次，结论逐字相同 | 同一文件加不加参数得出不同结论（因为留了两套口径） |
| **R3** | **失灵可见**——扫描面塌陷 / 依赖不可得 / 口径不可得 → **显式非零退出**；禁止静默通过、禁止静默降级为另一套口径 | 制造三种失灵：非 git 仓 · 扫不到文件 · 外部口径缺失——三种都须 `exit≠0` 且输出领域化错误 | 抛未捕获异常栈；或「拿不到 A 就悄悄用 B」 |

### 组二 · 不可绕过：谁能改判据

| # | 要求 | 判据（怎么验） | 反例（实测形态） |
|---|---|---|---|
| **R4** | **不可自助**——被管理者不得拥有绕过权。豁免必须 ①**台账化**（文件 + 匹配式 + 理由 + 日期 + 批准人）②有额度上限 ③进输出可见 ④粒度不可越级（行级豁免不得绕过节级判据） | ① 台账外用标记不生效；② 超额度即红；③ 每次运行打印豁免清单与计数；④ 节级判据只认整篇豁免 | 行内加一个忽略标记就能绕过全部门禁 |
| **R5** | **单一实现**——同一判据全家族只有一份实现；各仓只持有配置；**口径住实现，不住配置** | ① 全家族 `grep` 该实现文件名，只有一处；② 把某仓配置改到极端值，同一份文件的结论不变（变的是扫描面） | 四个仓各持一份逐字相同的副本，改一处不改三处 |

### 组三 · 可运维：它自己也要被管住

| # | 要求 | 判据（怎么验） | 反例（实测形态） |
|---|---|---|---|
| **R6** | **可自证**——工具能证明自己在此环境真的工作：`--selftest`（**必含负向用例**：构造必违规样本，确认它红）+ `--version` + `--help`；安装器幂等、跨形态（clone / worktree / submodule）、跨布局（仓目录调整后引用方仍能定位实现——引用一律软引用，**判据不得写死实现或标准的绝对路径**） | ① 自检输出「正向绿 + 负向红」两半；② 在 `git worktree` 里装得上；③ 连跑两次安装器产物逐字相同；④ 移动实现所在目录后，引用方仍能运行或显式报明缺什么（不得静默通过） | worktree 里 `.git` 是文件 → `mkdir` 失败 → 钩子静默装不上 |
| **R7** | **规则-判据双向可追溯**——仓规/模板里每一条**禁止性**条款指向一个判据；每个判据指回一条规则。**两侧无孤项** | 对照表逐行核对无空列 | 仓规写着「须双版同批」而全家族零强制 |
| **R8** | **判据准入**——新增判据须三件齐：① 触发事故 / 违反样本 ② 机械判据式 ③ 处置动作（用户怎么修）。**缺一不入** | 判据表每行三列齐；新增判据须附可复现样本 | 为一个尚未发生的风险预先写检查（按 R1 它不该存在） |

## 3. 拿它检查任意工具：五步

1. **列判据表** —— 该工具每条判据填三列（事故 / 判据式 / 处置）。空列即 R1 或 R8 违反。
2. **验 R2** —— 换一种调用路径、换一台机器，对含边界样本的文件复跑，结论须逐字相同。
3. **验 R3** —— 人为制造三类失灵，看退出码与错误形态。
4. **验 R4** —— 试图绕过：写一个台账外的忽略标记；再写一条纯行级豁免去打节级判据。
5. **验 R6** —— 跑 `--selftest`；在 `git worktree` 内跑安装器并连跑两次比产物。

**通过 = 八条全中。** 某条确不适用 → 按 §5 写明，**不适用 ≠ 不写**。

## 4. 新建一个工具：八项最小清单

| # | 交付物 | 对应 |
|---|---|---|
| 1 | 判据表（事故 / 判据式 / 处置 三列） | R1 · R8 |
| 2 | 实现（一份，住家族工具位） | R5 |
| 3 | 配置 schema（消费方只填配置） | R5 |
| 4 | 失明码与领域化错误分支 | R3 |
| 5 | 豁免台账文件 + 额度 | R4 |
| 6 | `--selftest`（正向 + 负向）· `--version` · `--help` | R6 |
| 7 | 安装器（幂等 + 跨形态） | R6 |
| 8 | 规则 ↔ 判据对照表（进该工具 `README`） | R7 |

## 5. 某条不适用时怎么写

在该工具 `README` 里写「不适用的条 + 为何不适用」。**禁止沉默**——沉默就是 R7 的孤项。

## 6. 自评：标准能不能判自己

> 标准若不能拿来判它自己，就不可信。下表是**写作本文件时所依据的工具实例**。

| 条 | 文档债务门禁 | 可读性口径 | 钩子安装器 |
|---|---|---|---|
| R1 事故溯源 | ✅ 八类判据各有来源 | ✅ 口径分歧实测 | ✅ worktree 安装失败实测 |
| R2 机械可判定 | ✅ 双路径结论一致 | ✅ 纯函数，无参数影响口径 | — 无判据 |
| R3 失灵可见 | ✅ 三类失灵均 exit 2 + 领域化错误 | ✅ 缺文件显式告警 | ✅ 失败即非零退出 |
| R4 不可自助 | ✅ 台账 + 额度 + 输出可见 + 不越级 | — 无判据 | — 无判据 |
| R5 单一实现 | ✅ 族内唯一 | ✅ 唯一口径 | ✅ 唯一安装器 |
| R6 可自证 | ✅ selftest / version / help + 幂等跨形态 | — 无 CLI 面 | ✅ worktree 可用 + 幂等 |
| R7 双向可追溯 | ✅ 对照表见其 README | — 无判据 | — 无判据 |
| R8 判据准入 | ✅ 候选区按 R1/R8 拒收 | — 无判据 | — 无判据 |

**改造前的自评（对照用）**：八条中 **五条不达标**（R2 双口径 · R3 异常栈 · R4 无锁豁免 · R5 四份副本 · R6 worktree 装不上）——**这正是八条不是空话的证据**。

## 7. 元规则（改这份文件的规则）

1. **只有维护者能改**，且须挂版本号 + 说明「哪一条为什么变」。
2. **改一条即全家族重查**——标准是投影的源，源变了所有投影要重新对齐。
3. **只增不减要付代价**：新增一条须说明它拦的是**已经发生**的哪一次，以及它会增加什么成本；**加条比减条危险**。
4. **本文件不含任何具体工具的名字与实现**——一旦写出某个工具，它就开始随那个工具漂移。
