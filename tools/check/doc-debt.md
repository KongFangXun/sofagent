# 文档债务门禁 · 判据表与规则对照

> 本文是 `check-doc-debt.mjs` 的自述：判据表（三列齐 = R1 + R8）+ 规则 ↔ 判据对照（R7）。
> 标准：主仓 `tools/STANDARD.md`（R1–R8）。实现：`tools/check/check-doc-debt.mjs`（v1.0.0）。
> **本工具唯一实现住主仓 `tools/check/`；消费仓只持 `tools/doc-debt.config.json` + `tools/install-hooks.sh` 薄包装。**

## 一、判据表（事故 / 判据式 / 处置 —— 三列缺一不入）

| # | 触发事故（实测） | 判据式 | 处置动作 |
|---|---|---|---|
| C1 断链 | 一次全仓收敛清出 4 处指向已删文件的链接 | 相对链接必须可解析（基准 = 文件所在目录） | 改指向，或删该引用 |
| C2 术语旧称 | 两仓对同一术语各写一版旧缩写 | 命中配置 `termBlacklist` | 改为 SSOT 术语 |
| C3 计数口径 | 同批清出 13 处旧计数（规则数 / tool 数） | 命中配置 `counts` 且值 ≠ SSOT | 改为 SSOT 值 |
| C4 版本状态 | 文档称「未发版」而总仓 tag 已存在 | 含状态词的行若提到已存在 tag | 改状态，或去掉版本号 |
| C5 可读性棘轮 | 单行 315 字符 / 表格单元格 205 字符实存 | 墙式计数 > 基线即红（只许降不许升） | 断行 / 拆表 |
| C6 退役节 | 模板要求「每版 ≥3 项」而家族内零强制 | 版本记录须含退役节且数据行 ≥3 | 补退役表 ≥3 行 |
| C7 双语同步 | **四仓实测：只改中文版 README 门禁 rc=0**；且四仓中文版均未指回英文版 | 双语对的 H2 数 / 围栏数 / **互指对称** / 除互指外链接集合必须一致 | 双版同批改，补回指行 |
| C8 根级白名单 | **实测：根级加未登记文件门禁 rc=0**（仓规写「代理不得自主创建」） | 根级条目必须已在 `rootWhitelist` 登记 | 补登记，或删文件 |
| C6 仓型例外 | **实测：AIR（研发/文档仓）首次接入时 C6 因「无 `changelog/v*/` 版本记录」失明**——它是文档仓，**没有「按版本发布记录」这一对象** | `cfg.repoKind === 'docs'` 时 C6 记 **N/A 并写入 notes**（默认可见；`--strict` 下升为失败）；**其他仓型仍按失明处理** | 在配置声明 `repoKind`；不得靠改路径蒙过 |

## 二、规则 ↔ 判据对照（R7：两侧不得有孤项）

| 规则出处（禁止性条款） | 由哪个判据执行 |
|---|---|
| 仓规：README 改动须双版同批 | **C7** |
| 仓规：新增根级文件须许可，代理不得自主创建 | **C8** |
| 仓规：完成即提交——中文 conventional 提交信息 | `install-hooks.sh` 的 **commit-msg** 钩子 |
| 仓规：所有断言可实测 / 禁旧计数 | **C3** |
| 模板：四禁（不符事实 / 无归属过程叙述 / 悬空引用 / 与实测不符的固定计数） | **C1 · C3 · C4** |
| 模板：Retirement floor（每版处置 ≥3 项） | **C6** |
| 既有门禁：可读性只降不升 | **C5** |
| 标准 R6：引用一律软引用，判据不得写死绝对路径 | 安装器两条腿（同级布局 → 绝对路径回落 → 都失效则 exit 2） |

> **孤条款如实标注**：仓规里的行为底线四则（不泄露隐私 / 不执行危险操作 / 不生成有害内容 / 不冒充人类）属**人工判断面**，不由机械判据执行。

## 三、判据准入与候选区（R8）

**新判据须三件齐**：触发事故 / 机械判据式 / 处置动作。缺一不入。

| 候选 | 状态 | 为何暂不入 |
|---|---|---|
| **生成物禁手改**（比对生成器输出与仓内文件） | ⏸ 待入 | **R1/R8 不满足**：家族内尚无生成物落地，无触发事故、无违反样本。**按标准，没有事故的判据不得存在**——待真落地并发生一次漂移后加入 |

## 四、用法与退出码

```bash
node tools/check/check-doc-debt.mjs --selftest                     # R6：正向绿 + 负向红
node tools/check/check-doc-debt.mjs --sofagent ~/WorkBuddy/sofagent  # 在消费仓内运行
node tools/check/check-doc-debt.mjs --version | --help
```

**退出码**：`0` 全绿 · `1` 有违规 · `2` 失明（口径或扫描面不可得 —— R3）。

## 四之一、配置字段（`tools/doc-debt.config.json`）

| 字段 | 作用 | 备注 |
|---|---|---|
| `repo` | 与目录名比对，**防错挂配置** | 不符即失明 |
| `repoKind` | 仓型。缺省按代码仓（C6 必须存在 `changelog/v*/`）；`docs` ⇒ C6 记 N/A 且可见 | 新增（R1 事故：AIR 接入时 C6 失明） |
| `termBlacklist` / `counts` | 术语旧称 / 计数口径 | — |
| `bilingualPairs` | 双语配对；**无双语版的仓须写 `[]`**，不得留一个不存在的配对 | 留空差异会一直报「一侧缺席」 |
| `rootWhitelist` | 根级白名单（按 git 实际顶层登记，**不得自造条目**） | 假条目=放水 |
| `exemptQuota` | 豁免额度 | 超额度即红 |

## 五、豁免台账（R4）

`{消费仓}/tools/doc-debt-exempt.json`：

```json
{
  "_why": "豁免是例外不是常态：每条须有理由与批准人，且总条数不得超过 config 的 exemptQuota",
  "entries": [
    { "file": "docs/foo.md", "line": 42, "reason": "引原文说明该旧值已被废弃", "approved": "维护者", "date": "2026-10-16" }
  ]
}
```

四条硬性：① **台账为权威**——台账外写行内忽略标记**不生效**；② 条数 > `exemptQuota` 即红；③ 每次运行打印豁免清单与计数；④ **行级豁免不得绕过节级判据**（C6 只能整篇豁免）。
